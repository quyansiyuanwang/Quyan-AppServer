# 用户管理

用户管理用于维护平台用户的资料、所属群组和状态，并提供创建、重置密码、删除和进入账户操作。创建的普通用户是独立主账号；为自己账户创建 RAM 子用户，请使用 [RAM 管理]({{DOCS_BASE_URL}}/zh-CN/ram-management)。

## 使用前提

打开访问控制下的用户管理页面。用户列表和各项操作分别授权；按钮可见不代表具备目标资源的操作权限。

| 操作                 | 所需权限                                          |
| -------------------- | ------------------------------------------------- |
| 查看用户目录、详情   | `USER_READ`                                       |
| 创建用户             | `USER_CREATE`                                     |
| 编辑资料、状态或群组 | `USER_UPDATE`                                     |
| 删除用户             | `USER_DELETE`                                     |
| 重置他人密码         | `USER_CHANGE_OTHERS_PASSWORD`                     |
| 进入账户             | `USER_IMPERSONATE_VIEW` 或 `USER_IMPERSONATE_ACT` |
| 加载群组选择项       | `GROUP_READ`                                      |

写入接口要求重放保护。重置密码时，已启用 2FA 的操作者可能还需二次验证，有效受信任窗口按当前安全规则处理。IAM 强制模式下还需下文列出的独立动作及管理资格。

## 查找并核对用户

列表在桌面端显示表格，移动端显示卡片，包含用户名、姓名、邮箱、状态、群组和创建时间。创建时间按浏览器本地时间显示。

1. 输入关键词后按 Enter，可按用户名、RAM 用户名、姓名、邮箱或用户 ID 的部分文字查询；没有独立的用户 ID 输入框。
2. 按需选择群组。搜索、清空关键词、切换筛选或调整每页数量会返回第一页。
3. 使用分页查找，默认每页 10 人，接口每页最多 100 人，页码最多 10,000。

“显示RAM角色”在本页实际按 **RAM 子用户类型**筛选；关闭时默认排除 RAM 子用户。它与权限管理页按 RAM 权限筛选的同名开关含义不同。当前操作者不显示在列表中，停用用户仍可显示，已删除用户不显示。

刷新会清空全部筛选并返回第一页，不重新加载群组选项。IAM 强制模式下，群组下拉框只加载群组接口的默认页，可能缺少可用选项；下拉框可见也不证明可以向该群组分配用户。群组名称无法解析时可能显示原始组 ID。

页面没有自动刷新、批量操作或导出。加载失败时可能保留旧记录和总数，请重新查询后再操作。

## 创建普通用户

1. 单击创建用户，输入用户名和初始密码。
2. 按需填写姓名、邮箱并选择群组。未选组时使用系统普通注册组。
3. 单击确认，成功后重新查询核对账号。新用户状态为正常，页面不返回或发送一次性密码凭证。

| 字段             | 限制                                                                      |
| ---------------- | ------------------------------------------------------------------------- |
| 用户名           | 去除首尾空格后为 3～20 个字符，仅字母、数字和下划线，不能与已有用户名冲突 |
| 初始密码、新密码 | 6～50 个字符                                                              |
| 姓名             | 可选，最多 50 个字符                                                      |
| 邮箱             | 可选，须为有效邮箱格式，最多 200 个字符                                   |
| 用户组           | 可选，另受可分配范围、等级及委派检查限制                                  |

请自行通过合适渠道交付初始密码。新建窗口不提供权限覆盖项、指定用户 ID 或所属账户的入口。创建成功后仅重新加载当前页，不会自动定位用户；原筛选可能隐藏新账号。

## 编辑资料、状态与群组

1. 找到目标用户，单击编辑。
2. 修改姓名、邮箱、群组或状态。正常、禁用为两种可选状态；此窗口不能修改用户名或密码。
3. 单击确认，重新查询核对。姓名或群组变化可能使该用户不再符合原筛选。

表单使用已加载的列表数据，不会打开时重新读取详情。其他管理员修改后应先刷新再编辑，避免旧值覆盖新值。把已有姓名、邮箱或群组留空再保存会保留原值，不能据此清空字段或取消所属群组。

IAM 强制模式下，**表单每次都会提交状态，以及非空的邮箱和群组**。因此，即使只改姓名，也可能需要 `SetUserStatus`、`SetUserEmail`、`AssignUserGroup` 等独立动作。具有 `UpdateUser` 并不保证这个表单可以保存；集成若只更新姓名，应只提交需要修改的字段。

禁用会限制账户使用，不会清空余额、资源或其他业务数据。IAM 强制模式还检查主账户有效状态：主账户禁用或删除后，仍处于正常状态的子用户也无法继续通过 IAM 授权，包括其 JWT、已认证 AccessKey 和角色会话。重新启用需具备状态修改权限。

提交失败会保留输入，关闭会清空输入，页面不自动保存。写入成功后列表重新加载可能失败，应重新查询确认，不要立即重复提交。

## 重置密码

1. 在目标用户行单击重置密码，核对弹窗中的用户名。
2. 输入符合长度要求的新密码，单击重置密码并完成可能出现的验证。
3. 成功后弹窗关闭，通知目标用户使用新密码。

此操作直接设置新密码，不需要目标用户的旧密码或邮箱重置码，也不会显示旧密码。密码重置不清除用户已配置的 2FA、Passkey 或受信任设备；相应维护请查看[双因素认证]({{DOCS_BASE_URL}}/zh-CN/two-factor-authentication)。失败时输入保留，关闭弹窗后清空。

## 进入账户并退出模拟

1. 核对目标用户，单击进入账户并确认。
2. 检查顶部横幅中的用户名和模式，确认身份已切换后再操作。
3. 协助结束后单击退出模拟，核对已恢复原身份。

| 模式 | 行为                                                   |
| ---- | ------------------------------------------------------ |
| 只读 | 禁止变更请求；部分通过 POST 读取数据的功能也可能受限   |
| 操作 | 以目标用户身份操作，仍受目标用户自身权限和业务限制约束 |

系统优先选择获准的操作模式，不能在这个确认窗口手工指定只读模式。操作模式未获准且只读模式另有授权时，才使用只读模式。拥有任一模拟权限可使按钮出现，但不保证能进入目标账户。

不能模拟自己，也不能在模拟会话内再次发起模拟。目标必须可用且层级低于操作者。模拟会话有效期为一小时，不签发刷新令牌，操作有审计记录。

进入过程中若资料加载失败，身份可能已经切换。请先检查顶部横幅和当前账号，再决定退出或重试。退出会尝试恢复原会话；恢复失败时按提示刷新并核实身份，必要时重新登录。

## 删除用户

1. 核对目标账户的余额、权限和关联资源。
2. 单击删除并确认。
3. 重新查询，确认用户不再显示。

删除会将账号标记为已删除并释放原用户名，不等于清除所有关联业务数据；页面没有恢复入口。不能删除自己，也不能删除同级或层级更高的用户。IAM 强制模式下还禁止删除当前认证账户的主用户；禁用用户仍可按相同规则删除。删除会记录业务日志。

## 等级与 IAM 授权范围

等级数值越小层级越高。跨用户编辑、删除和模拟要求目标群组的等级数值大于操作者；能在列表中看到同级用户，不代表可以修改。密码重置使用自身独立的权限检查，不应仅凭这些资料管理规则判断是否获准。

IAM 强制模式下，平台管理操作需要真实、有效部署全局组中的对应管理资格。个人附加权限、私有账户组或账户所有者身份不能替代该资格。管理接口不接受 OAuth 访问令牌；角色会话按角色授权，不继承操作者全局组的策略 Allow，显式 Deny 优先。已认证 AccessKey 也需通过资源检查。

| 操作         | IAM 动作                            | 资源范围                   |
| ------------ | ----------------------------------- | -------------------------- |
| 用户列表     | `quyan:user:ListUsers`              | 每个获准用户               |
| 用户详情     | `quyan:user:GetUser`                | 目标用户                   |
| 创建用户     | `quyan:user:CreateUser`             | 用户目录和系统生成的新用户 |
| 更新资料     | `quyan:user:UpdateUser`             | 目标用户                   |
| 提交邮箱字段 | 另需 `quyan:user:SetUserEmail`      | 目标用户                   |
| 提交状态字段 | 另需 `quyan:user:SetUserStatus`     | 目标用户                   |
| 提交群组字段 | 另需 `quyan:user:AssignUserGroup`   | 目标用户和目标群组         |
| 删除         | `quyan:user:DeleteUser`             | 目标用户                   |
| 只读模拟     | `quyan:user:StartViewImpersonation` | 目标用户                   |
| 操作模拟     | `quyan:user:StartActImpersonation`  | 目标用户                   |

用户资源为 `acs:platform:*:platform:user/<用户 ID>`，群组为 `acs:platform:*:platform:group/<群组 ID>`，目录为 `acs:platform:*:platform:user-directory`。新用户 ID 由系统生成，可按实际策略使用 `user/*` 预先授权。密码重置另用 `quyan:user:ChangeOthersPassword` 检查账户范围用户资源 `acs:quyan:*:<accountId>:user/<用户 ID>`，不能把平台用户管理动作当作其替代。

列表按等级和 RAM 类型筛选，再按授权计算总数与分页，不显示未授权用户总数。列表动作不授予详情权限，详情不存在或被拒绝时返回通用授权错误。读取不会返回密码或权限数组；权限、角色会话或相关用户数据在读取期间变化时，请刷新重试。

### 创建和换组限制

IAM 强制模式下，新主账号只能加入有效全局群组，不能直接指定其他账户的私有组。显式选组还要求对新用户和目标群组的分配动作授权。未选组时，只有普通注册组保持系统预设的确切基础权限，才能直接使用该基础权限例外；组内额外权限、策略和角色仍需委派检查，显式指定同一组也需完整检查。

普通操作者不能创建同级或更高层级用户，也不能通过换组提高目标原有层级、委派未获准权限或移除原组 Deny 来扩大访问。已有用户的目标组须为有效全局组或属于该用户的实际账户。

系统配置的真实全局管理员主账号可执行受控的恢复创建或换组，但不免除动作授权和显式 Deny；角色会话不能使用该恢复例外。替换其他主账户的群组还须保留其已有 IAM 恢复权限，不能引入群组策略或角色中的 Deny。

不能通过此更新接口给自己或当前账户主用户换组、修改恢复邮箱或禁用账户；自己的邮箱应使用[账户设置]({{DOCS_BASE_URL}}/zh-CN/account-settings)的验证流程。更新、创建或删除遇到授权、身份、目标或组配置变化会整体失败，不会只提交一部分字段。

### 模拟会话的持续检查

IAM 强制模式下，每次使用或跨站恢复模拟会话，都会复核原操作者、目标等级、动作、资源、条件和策略。撤销操作模式授权后，已有会话会被拒绝，不会自动降为只读继续使用。角色会话撤销或过期、原 AccessKey 禁用或过期、原操作者被强制下线，也可能使模拟失效。

切换到强制模式前签发、缺少原授权主体信息的模拟会话需要重新建立。legacy/shadow 模式保留旧授权规则；影子评估不会额外创建、更新、删除用户或签发第二份模拟令牌。
