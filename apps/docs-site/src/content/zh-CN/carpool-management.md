# 拼车运营管理

运营人员可以在“拼车套餐管理”维护可购买套餐，在“拼车运营工作台”受理用户已提交的订单，并完成交付或失败退款。

## 开始前

- 进入套餐管理页需要 `CARPOOL_TEMPLATE_WRITE`；查询套餐还需要 `CARPOOL_TEMPLATE_READ`。创建和编辑时，需要可用且有权引用的月卡模板。
- 进入订单管理页需要 `CARPOOL_ORDER_READ`；受理、查询交付渠道、交付和失败退款还需要 `CARPOOL_ORDER_FULFILL`。
- 启用 IAM 强制授权后，各项操作还需要对应 Action 和资源授权，以及部署管理员配置的全局管理组资格。账号自己的策略或用户组不能自行授予该资格。页面按钮可见不代表操作已获授权。

## 创建和发布套餐

1. 进入**拼车套餐管理**，选择**创建套餐**。
2. 填写名称和描述，选择**交付月卡模板**。额度、有效期、额度单位、额度窗口及模型和渠道限制来自所选模板。
3. 设置总售价、总成本、成员上限和成团期限，核对满员测算后选择**保存**。
4. 新套餐保存为草稿。确认配置后，在列表中选择**发布**，用户才能从目录创建订单。

| 配置           | 范围或含义                                                                     |
| -------------- | ------------------------------------------------------------------------------ |
| 名称、描述     | 名称必填，最多 100 字符；描述最多 1000 字符                                    |
| 总售价、总成本 | 售价大于 0，成本不能为负；页面最多输入 4 位小数                                |
| 成员上限       | 1–100 人，创建表单默认 2 人                                                    |
| 成团期限       | 1–720 小时的整数，默认 72 小时；从用户创建订单时计算                           |
| 满员测算       | 单人成交价和成本按人数上限均分，总毛利为总售价减总成本；实际成员份额以订单为准 |

成本仅供运营测算，普通用户页面不显示上游成本。月卡模板选择器加载首批最多 100 条获准查询的模板；未找到模板时，先检查模板状态、查看权限和列表范围，不要选择其他模板代替。

## 编辑、复制和停止销售

- **编辑**：调整后保存。保存时会重新读取所选月卡模板的当前交付配置，即使只修改售价，也应核对额度、有效期和限制。
- **复制**：生成一个新的草稿，保留源套餐的交付快照。检查并按需编辑后，再发布。
- **下线**：套餐变为“草稿/下线”，停止用户从目录创建新订单；之后可再次发布。
- **归档**：确认后，套餐从管理列表和用户目录移除。页面没有恢复归档入口，操作前请确认。

套餐创建或编辑时保存交付快照，用户创建订单时再保存订单快照。后续模板变化不会自动改写套餐快照；套餐编辑、下线或归档也不会改写已有订单的价格、额度、有效期和限制，或自动取消、退款已有订单。

套餐搜索匹配名称和描述；输入或清空关键字后，按 Enter 或选择**搜索**。切换发布状态会重新查询并回到第一页。

## 查找需要处理的订单

1. 进入**拼车运营工作台**，选择“待运营受理”或“采购交付中”状态。
2. 需要定位具体订单时，输入套餐名称、订单号或车主用户名，按 Enter 或选择**搜索**。状态变化会立即查询并回到第一页；清空关键字后仍需执行搜索。
3. 选择**查看详情**，核对状态、成团截止时间、总额度、总售价、成员状态、个人应付金额、冻结金额和订单时间线。失败订单还显示失败原因。

默认不限定订单状态，列表可能同时包含已结束订单，请使用状态筛选定位待处理工作。顶部状态计数基于当前关键字下的订单，切换表格状态不会缩小计数范围。IAM 强制授权下，列表、总数和计数只包含获准查看的订单；列表权限与详情权限分别授予。

详情中的冻结金额为 0 不代表未扣款：提交后冻结已转为扣款，退款后也不再显示为冻结。结合订单状态、事件和成员余额流水核对资金结果。

## 受理和交付

1. 对“待运营受理”的订单选择**受理**并确认。状态变为“采购交付中”。用户已在提交发车时扣款，受理不会再次扣款。
2. 完成实际采购和交付准备后，对该订单选择**完成采购并交付**。弹窗会重新读取最新订单，再查询该订单快照允许的渠道。
3. 按渠道名称或 ID 搜索，必要时翻页，选择可交付渠道。渠道须处于启用状态、已通过审核并开启服务商服务，同时满足订单的渠道限制。
4. 核对订单和所选渠道，选择**完成采购并交付**并再次确认。成功后订单变为“已交付”，每位在车成员分别获得自己的月卡和 Relay Token；月卡有效期从交付完成时开始。

没有可选渠道时，先检查搜索条件、其他分页、渠道状态、快照限制及权限。修改套餐不会放宽已有订单的限制。交付前订单或渠道状态变化可能导致操作被拒绝；重新打开订单核对后再处理。来源模板后来下线或禁用不会改变订单的原有交付份额。

## 失败退款

只能对“待运营受理”或“采购交付中”的订单执行失败退款；不能用此操作撤销已交付订单。

1. 确认无法交付后，对目标订单选择**失败退款**。
2. 填写 1–1000 字符的非空失败原因，再确认。原因会展示给订单成员，请说明可理解的业务原因，不要写入 Relay Token、上游密钥等凭据。
3. 成功后，订单关闭为“失败退款”，已扣款的在车成员分别收到退回自己余额的金额。核对详情中的失败原因、时间线和相关余额流水。

等待处理或超过成团截止时间，不会自动对已提交订单退款。成团到期仅由后台定期关闭尚未提交的订单并释放冻结。成员账号已禁用时，仍可接收其已扣款退款。

## 操作权限与 IAM 资源

以下 Action 均以 `quyan:carpool:` 为前缀。它们分别授权，查看、受理或查询渠道的权限不会自动授予交付或退款权限。

| 操作                 | Action 后缀                                               | 主要资源范围                                                         |
| -------------------- | --------------------------------------------------------- | -------------------------------------------------------------------- |
| 套餐列表             | `ListTemplates`                                           | 获准查看的套餐                                                       |
| 创建、编辑           | `CreateTemplate`、`UpdateTemplate`                        | 创建控制资源或目标套餐、来源月卡模板；创建还检查新套餐               |
| 复制                 | `DuplicateTemplate`                                       | 源套餐、创建控制资源、新套餐                                         |
| 发布、下线、归档     | `PublishTemplate`、`UnpublishTemplate`、`ArchiveTemplate` | 目标套餐                                                             |
| 订单列表、详情、受理 | `ListAdminOrders`、`GetAdminOrder`、`AcceptOrder`         | 目标订单                                                             |
| 查询交付渠道         | `ListDeliveryChannels`                                    | 所选订单、候选渠道                                                   |
| 交付                 | `FulfillOrder`                                            | 订单、渠道、来源套餐和月卡模板、每位接收用户、新月卡和新 Relay Token |
| 失败退款             | `FailOrder`                                               | 订单、每位在车用户及其余额账户、新增退款流水                         |

资源使用部署共享 ARN 前缀 `acs:platform:*:platform:`。常见后缀为 `carpool-template/<templateId>`、`carpool-template-control`、`monthly-pass-template/<templateId>`、`carpool-order/<orderId>`、`relay-channel/<channelId>`、`user/<userId>`、`balance-account/<userId>`、`balance-transaction/<userId>/<transactionId>`、`monthly-pass/<userId>/<passId>` 和 `relay-token/<userId>/<tokenId>`。

普通成员的订单详情权限不授予运营详情权限。显式 Deny 优先；交付或退款所需的任一资源被拒绝时，本次操作整体失败，不会只给部分成员交付或退款。

## 操作失败或结果不确定

列表或详情刷新失败时，旧数据可能仍显示。操作超时、出现成功提示后刷新失败、或提示订单已变化时，重新查询订单状态和时间线；涉及退款时还应核对资金流水。确认结果后再决定是否重试，不要仅因刷新失败重复交付或退款。权限、管理资格或渠道条件变化时，请联系部署管理员处理。
