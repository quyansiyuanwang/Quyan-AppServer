# AI 请求日志

AI 请求日志用于调查中转推理请求的身份、执行结果和已保存内容。遇到调用失败、流式中断或内容问题时，可先按请求 ID 和时间查找记录，再阅读正文及上游尝试。

## 使用前提

- 使用具备 `relay:ai_request_log:read` 权限的账号登录。启用 IAM 强制授权时，还需具备平台全局用户组的读取资格和对应日志的操作权限，详见下文。
- 查看上游尝试或搜索尝试错误，还需要 `relay:request_diagnostics:read`；IAM 强制授权另有独立的诊断操作。
- 本页不接受 OAuth 访问令牌。日志可能包含提示词、工具参数、模型响应和业务数据，应按调查需要授权，复制后同样需要妥善保管。

## 查找请求

1. 打开“AI 请求日志”，设置时间范围。默认查询打开页面时的最近 24 小时，也可选择最近 1 小时、24 小时、7 天、30 天或自定义范围。
2. 输入请求 ID、用户、令牌或正文关键词；需要缩小范围时，展开高级筛选。
3. 单击“搜索”或在搜索表单内按 Enter，从第一页查询。
4. 打开目标记录，分别查看请求、响应和上游尝试。列表默认每页 20 条，可选择 50 或 100 条。

筛选条件组合生效，必须同时满足。主要匹配规则如下：

| 条件                                                    | 匹配方式与注意事项                                                                             |
| ------------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| 统一搜索框                                              | 搜索请求 ID、用户和令牌名称或 ID、模型、错误摘要及已保存正文。上游尝试错误的搜索受诊断权限限制 |
| 用户、令牌、模型、请求 ID、IP                           | 包含输入文字即可匹配；用户和令牌各自同时匹配名称或 ID                                          |
| 格式、HTTP 状态、业务结果、流式、失败阶段、正文省略原因 | 按选择值匹配；HTTP 状态必须为 100～599 的整数                                                  |
| 正文截断                                                | “已截断”表示请求或响应至少一侧被截断；“未截断”只表示两侧均无截断标记，不保证保存了正文         |
| 耗时                                                    | 单位为毫秒，使用非负整数；最小值不得大于最大值                                                 |
| 时间                                                    | 起始时间不得晚于结束时间。清空时间范围会取消时间限制                                           |

修改或清空筛选值本身不会查询。“搜索”返回第一页；“刷新”和翻页使用当前表单值，“刷新”保留当前页。切换每页条数返回第一页。“重置”清除其他条件，重新设置最近 24 小时并立即查询。

时间范围在打开页面或选择快捷项时确定，页面不会自动轮询。“刷新”不会把结束时间推进到现在；查找最新请求时，请重新选择快捷时间后搜索。

用户和令牌身份来自服务端识别，不采信正文中声明的用户。未命名令牌显示 ID；历史未采集的字段显示“未记录”，不会自动补填。

## 判断执行结果

HTTP 状态与业务结果需要一起判断。HTTP 200 仍可能伴随流式中断或响应结束后的结算失败。

| 结果   | 如何理解                                                               |
| ------ | ---------------------------------------------------------------------- |
| 处理中 | 执行尚未形成最终结果；稍后重新查询                                     |
| 成功   | 当前记录未报告执行失败；不代表响应内容一定符合业务预期                 |
| 失败   | 查看错误摘要和失败阶段，区分认证、请求、路由、上游、内容安全或结算问题 |
| 中断   | 连接或执行被中断，结合客户端状态及已保存响应调查                       |
| 未记录 | 旧记录缺少该信息，不能仅根据 HTTP 状态补推业务结果                     |

上游某次尝试失败不一定导致整个请求失败。请结合请求最终结果和其他尝试判断。

## 阅读、搜索与复制详情

1. 打开记录，先核对身份、请求 ID、时间、HTTP 状态和业务结果。
2. 选择“请求”或“响应”。默认进入“解析与格式化”，按消息、工具、参数、输出、用量和错误组织内容；工具默认折叠。
3. 展开所需结构或继续加载。默认只读取首批内容：解析视图每页 20 项，原始内容每段最多 32 KiB，长字段也分段读取。
4. 需要查找文字时，选择详情搜索范围并搜索。匹配不区分大小写，按字面文字查找，不支持正则表达式；范围覆盖该侧全部已保存内容，不限于已加载片段。搜索结果按匹配次数分页，可定位到对应字段或流事件附近。
5. 需要上游尝试时，单独加载并按需继续加载；搜索尝试错误需要额外诊断权限。切换搜索范围后需重新搜索。

“原始内容”展示已保存的脱敏表示，不保证与原始网络字节一致。请求、响应、搜索和上游尝试独立读取，能看到列表不代表所有详情都可读取。

复制按钮的范围如下：

| 操作               | 实际范围                                                                                     |
| ------------------ | -------------------------------------------------------------------------------------------- |
| 复制当前片段       | 当前阅读器中最后加载的一项文字，不是滚动位置对应内容，也不是全部已加载文字                   |
| 加载全部已保存内容 | 默认关闭。启用后分批加载当前请求或响应、当前视图及所选子结构的已保存内容，并显示进度         |
| 复制全部已加载内容 | 需启用加载全部并等待完成后才可用。解析视图包含条目标题和完整条目文字；原始视图拼接已读取片段 |

关闭开关、切换读取范围或离开详情会停止继续加载。“全部”始终限于当前阅读器范围，不会同时导出请求、响应和尝试，也无法恢复截断或未采集内容。剪贴板被浏览器拒绝时，检查页面访问环境和剪贴板权限后重试。

## 采集范围与限制

本页采集中转代理的 POST 推理请求，流式与非流式均适用，涵盖认证拒绝、正文解析或大小拒绝、额度及路由问题、上游错误、超时、内容安全拒绝、中断和结算失败。模型列表、额度查询不作为推理日志记录。

- 正文保存默认上限为请求 **64 KiB**、响应 **256 KiB**，可由管理员调整，以当前服务端生效配置为准。改变配置不会补采旧记录。
- 超过上限时，可能仅保留大小和截断标记，不能保证有正文预览。详情分页是读取已保存内容，不会提高采集上限。
- 身份未知、正文无法安全解析或请求被大小限制拒绝时，只保存安全元数据，不保存该次请求和响应正文。
- 采集队列过载时，可能省略两侧正文并标记截断；仍无法入队或数据库写入失败时，整条记录也可能缺失。查不到日志不能证明请求未发生或未扣费，本页不能作为完整计费账本。
- 二进制内容以类型、大小等元数据表示。系统会脱敏识别到的密码、令牌和密钥字段，认证头不写入 AI 日志；提示词或普通文本中任意格式的敏感信息不保证全部被识别。
- 上游尝试最多保留 100 条；错误摘要单条最多 16 KiB、合计最多 64 KiB，达到限制时显示截断标记。

## 查阅历史归档

热库保留期默认 90 天，可在“数据归档”调整。超过保留期后，记录仍需归档任务实际处理，才会从热库删除；停用策略、任务未运行或执行失败时，旧记录可能仍在热库。AI 请求日志的归档默认不自动到期。

本页只查询热库。查阅旧记录时：

1. 先扩大本页时间范围并搜索。
2. 如记录已归档，前往[数据归档与清理]({{DOCS_BASE_URL}}/zh-CN/data-lifecycle)，检查对应运行结果和归档文件。
3. 下载 gzip NDJSON 文件，在受控环境中查阅。本页不会自动检索或恢复归档内容。

归档上传校验通过后才删除对应热数据。任务可能部分成功后失败，应核对实际归档和删除数量，不能仅根据运行状态判断全部数据去向。

## 配置 IAM 访问

启用 IAM 强制授权时，读取者须由实际所属的平台全局用户组获得 AI 日志读取资格，并对具体日志获得对应操作。账户所有者身份、用户附加权限、账户私有组或通配符策略不能单独提供平台读取资格。

日志资源为 `acs:platform:*:platform:relay-ai-request-log/<logId>`。`<logId>` 是日志记录 ID，与请求 ID 不同。

| 用途           | Action                                     |
| -------------- | ------------------------------------------ |
| 列表查询       | `quyan:relay:ai_request_log:ListLogs`      |
| 元数据         | `quyan:relay:ai_request_log:GetMetadata`   |
| 请求或响应内容 | `quyan:relay:ai_request_log:GetContent`    |
| 内容搜索       | `quyan:relay:ai_request_log:SearchContent` |
| 上游尝试       | `quyan:relay:ai_request_log:GetAttempts`   |
| 兼容详情接口   | `quyan:relay:ai_request_log:GetLog`        |

查看上游尝试或搜索尝试错误，还须拥有同一日志的 `quyan:relay:ai_request_log:ReadDiagnostics`，以及平台全局用户组的诊断读取资格。这些权限不授予渠道、路由或混池拓扑管理能力。

列表先过滤无权读取的记录，再计算总数和分页。列表、元数据、正文、搜索和诊断分别授权，不能互相替代。查询或分段读取期间，记录或授权发生变化可能导致失败；确认当前权限后重新查询。

## 常见问题

| 现象                         | 处理建议                                                               |
| ---------------------------- | ---------------------------------------------------------------------- |
| 查不到最新请求               | 重新选择快捷时间再搜索，检查其他筛选和当前授权范围；不要只单击刷新     |
| 查询报错后列表为空           | 查询请求失败会清空列表和总数，先处理错误再重试；这不等同于成功查得零条 |
| 提示筛选无效但仍有旧列表     | 检查状态码、耗时及时间顺序，修正后重新搜索；旧列表不能代表新条件的结果 |
| 能看列表，正文或尝试报错     | 分别检查元数据、正文、搜索和诊断权限；确认日志仍在热库，再重试失败部分 |
| 正文缺失或加载全部后仍不完整 | 查看省略原因及截断标记；加载操作不能恢复未保存的数据                   |
| HTTP 200 但调用异常          | 检查业务结果、失败阶段、响应内容和上游尝试，不只依据 HTTP 状态判断     |
