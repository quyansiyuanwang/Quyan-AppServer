# IP 定位

IP 定位查询公网 IP 的国家、地区、城市、ASN、运营商等信息，适合地域展示和业务风控辅助。结果取决于供应商数据和缓存，不代表用户的精确位置或真实身份。

## 使用前提

1. 在开发者产品中打开 **IP 定位**，选择可用实例并打开详情。
2. 准备该产品实例的 API Key。Key 和绑定主体均需具有 `product:ip_geolocation:lookup` 权限；移除主体权限后，原 Key 也不能继续查询。
3. 确认实例、产品和主体可用，Key 未过期或撤销，并具有足够额度或余额。
4. 准备要查询的公网 IPv4 或 IPv6 地址。输入单个 IP，不是域名、带协议的 URL 或网段；具体地址族的数据支持还取决于供应商。

创建实例和 Key 的步骤见[开发者产品概览]({{DOCS_BASE_URL}}/zh-CN/developer-products-overview)。产品查询接口使用产品 API Key；浏览器登录凭据、Access Key 或中转令牌不能替代此处所需的产品 Key。

## 在控制台测试

1. 打开实例详情中的 IP 查询测试卡。
2. 输入完整产品 API Key 和要查询的公网 IP。
3. 单击**查询 IP**，等待本次请求结束。
4. 核对结果中的 `ip`、`source` 和各定位字段，再决定是否用于业务。

测试使用真实凭据、权限、额度和超额计费规则，不是模拟请求。仅在可信设备输入 Key，避免分享含凭据的截图；页面不会根据浏览器当前登录状态自动代替你选择 Key。

更改输入后，旧结果不会立即清除。Key 或 IP 留空时页面只显示校验错误，旧结果也可能保留。有效输入发起新请求时才清空旧结果；请确认新请求成功，不要把上一次结果当作当前 IP 的定位。

查询完成不会自动更新旁边的用量和调用记录。需要核对时，关闭并重新打开实例抽屉；页面顶部刷新主要重新加载实例信息，不能据此认定用量区已刷新。用量区加载失败时可使用其中的重试操作，旧值或空记录不代表实际没有调用。

## 调用 API

将 `API_BASE_URL` 设为当前部署的后端 API 地址，将 `PRODUCT_API_KEY` 设为具有查询权限的产品 Key，再在服务端运行以下 Bash 示例。不要使用管理控制台域名或公开状态页地址代替 API 地址。

```bash
curl "${API_BASE_URL}/v1/products/ip-geolocation/8.8.8.8" \
  -H "Authorization: Bearer ${PRODUCT_API_KEY}"
```

接口路径为 `GET /v1/products/ip-geolocation/{ip}`。IP 放在一个路径参数中；程序拼接时对该参数编码。该接口不提供批量 IP、域名解析或自动查询当前访问者 IP 的入口。

响应沿用平台的业务包装，先判断 HTTP 状态及 `code`，成功数据位于 `data`。控制台测试卡只展示 `data`，不是完整响应。通用错误处理见 [API 文档]({{DOCS_BASE_URL}}/zh-CN/api-documentation)。

| 数据字段  | 含义                                                            |
| --------- | --------------------------------------------------------------- |
| `ip`      | 本次查询的 IP。                                                 |
| `country` | 国家或国家名称。                                                |
| `region`  | 省、州或地区。                                                  |
| `city`    | 城市。                                                          |
| `asn`     | 供应商提供的 ASN 信息；没有数据时为 `null`。                    |
| `isp`     | 供应商提供的运营商或组织信息；没有数据时为 `null`。             |
| `source`  | `configured` 表示部署配置的通用供应商，`baidu` 表示百度适配器。 |
| `address` | 百度适配器可能返回的完整地址；不是所有数据源都会提供此字段。    |

缺失字段可为 `null`，不表示查询失败。不同供应商的字段内容和类型可能不同，接入时应允许缺失值，不要假定 ASN 一定为数字或每次都有城市信息。查询成功也不保证定位数据准确或足够新。

## 缓存与数据来源

重复查询可能命中平台缓存，此时不会再次请求供应商，仍计入产品用量。页面和查询接口没有绕过缓存的选项；反复查询相同地址不保证立即更新定位或数据源。

数据源由部署管理员配置，普通产品实例不能自行选择：

- 优先使用 `IP_GEOLOCATION_ENDPOINT` 指定的通用 HTTP(S) 供应商。
- 只有该端点为空且配置了 `BAIDU_IP_LOCATION_AK` 时，才使用百度适配器；查询方不需要提供供应商密钥。
- 通用供应商失败不会自动切换到百度。两者均未配置时，未命中缓存的查询失败；旧缓存仍可能继续返回此前结果。

百度适配器在成功时返回“中国”、供应商提供的省市及地址；`asn` 和 `isp` 为 `null`。这不意味着能够识别所有国家或所有地址族，使用时应检查实际结果。

供应商请求有 5 秒超时和 1 MiB 响应大小限制，不跟随重定向。出现供应商不可用、错误响应或部署配置错误时，请联系管理员检查数据源，重复请求不一定能解决。

## 用量与费用

- 同账户的 IP 定位实例共享该产品的日用量与免费额度，按服务端日历日期统计，不按浏览器本地日期决定重置边界。
- 免费额度、超额开关和单价以当前账户授权及服务端配置为准。超额未启用或余额不足时，请求可能被拒绝。
- 零单价产品仍记录用量，但不因日免费额度用尽而拒绝查询。面板可将剩余额度显示为无上限。
- 成功缓存命中仍是一次产品调用；Key 的调用计数也不等同于成功定位次数，认证后失败的请求可能增加该计数。
- 产品接口先计量，再执行查询。查询执行失败后进入额度和费用退回流程，退回可能延迟；认证或额度检查失败的请求不应按成功查询理解。

调用记录展示最近最多 200 条该账户产品记录，可能跨实例且不是今日全部记录。它不提供完整账单导出，也不一定包含在认证、计量前就失败的请求。测试卡使用的 Key 决定调用所属账户和实例，不由当前打开的抽屉决定；核对用量时请确认账户一致。

## 常见问题

| 现象                           | 处理方法                                                                                                              |
| ------------------------------ | --------------------------------------------------------------------------------------------------------------------- |
| 提示仅支持公网 IP              | 检查输入是否为单个合法 IP。私网、回环及平台禁止的保留地址不会发往供应商，换一个实际需要查询的公网地址。               |
| Key 无效或权限不足             | 检查是否为 IP 定位产品 Key、是否过期或撤销、实例及主体是否可用，以及 Key 和主体是否都具备查询权限。                   |
| 提示服务未配置或供应商请求失败 | 联系部署管理员检查数据源。产品实例中填写供应商密钥不能解决此问题。                                                    |
| 结果缺少 ASN、运营商或城市     | 查看 `source` 和实际供应商数据；`null` 可以是合法成功结果，不要无限重试。                                             |
| 用量或余额未恢复               | 重新加载用量和[余额记录]({{DOCS_BASE_URL}}/zh-CN/balance-history)，保留失败时间和返回信息，仍有差异时联系管理员核查。 |

IP 查询在未命中缓存时会把该 IP 发送给配置的第三方供应商。只查询业务所需地址，分享结果前检查其中的个人或业务信息；不要仅凭定位结果决定访问授权。
