# 渠道余额探针

渠道余额探针用于用一笔最小模型请求核对上游余额变化、实际用量和当前渠道倍率。它面向拥有渠道管理权限的操作人员，不会向浏览器显示或导出余额工作流凭据。

## 使用混池渠道

混池仍以一个逻辑渠道显示，但可以展开查看每个物理账号。每个账号都有独立的凭据状态、最近一次探针和运行操作；探针始终固定在所选账号上执行，不会在同一次任务中切换到其他成员。

混池共享余额工作流和校准参数，但每个物理成员可单独选择支持的探针格式、模型、请求体与串行组。成员可以使用自己的余额工作流凭据，也可以绑定号池账号；未启用、没有可用凭据或不支持所选格式/模型的成员不可运行。已保存的凭据不会回显。

可以逐个运行成员，也可以确认后一次性运行当前所有可用成员。任务会按服务端队列和探针组规则执行，余额读取和最小模型请求可能产生上游实际费用。

## 号池和批量配置

拥有单独号池管理权限的管理员可在探针页的“号池”页签配置上游登录请求、凭据、令牌提取路径、上游过期字段、备用有效期和每账号最短登录间隔。登录工作流和凭据在服务端加密保存，令牌仅供服务端余额工作流通过 `{{accountToken}}` 引用；模型请求仍使用渠道已有的上游 API 凭据。多个渠道或混池成员可绑定同一账号；同账号探针互斥，防止余额变化互相干扰。登录失败、会话过期且仍在冷却期或会话服务不可用时，探针不会绕过限制重复登录。

绑定号池**不会自动移除旧的登录步骤**：请在余额工作流中手动删除旧登录步骤并确认剩余步骤使用号池令牌，否则余额读取仍会执行原登录。旧档案在手动修改前继续沿用原流程。号池修改和手动刷新均需管理权限、二次验证和重放保护，管理员无法从页面读取已存储的登录请求、凭据或令牌。

批量配置可选择一个已有档案作为共享模板，逐个为独立渠道和混池物理成员选择支持的格式、模型、请求体、串行组，并可为其绑定号池。服务器逐项检查并报告失败原因；不会因为某个目标不兼容而阻止其他目标保存。模板复制不携带来源凭据或号池绑定。串行组可在页面筛选；同号池账号即使不在同组也会互斥。

## 查看和应用结果

展开的成员行显示其最新任务状态和建议倍率。打开成员详情可查看该账号自己的历史记录、余额差值、用量和失败原因。独立渠道保持原有的单渠道探针流程。

成员探针的建议倍率不会自动改变价格。拥有倍率调整权限的操作人员必须在确认界面中选择结果后，才会把该建议应用到所属逻辑混池的对外倍率。大幅变更仍需要同一账号的另一条稳定结果确认，除非明确启用强制确认选项。

## 前提和注意事项

- 查看需要渠道探针读取权限；普通档案保存、运行、清理或重置任务需要执行权限，并会触发当前服务配置的二次验证和重放保护。修改或清空已经绑定号池的档案还需要独立的号池管理权限，以防他人改写余额请求并窃取共享令牌。
- 应用倍率需要单独的渠道倍率调整权限。
- 探针档案和任务记录会按当前服务端保留策略清理；历史结果不能代表未来的上游价格或余额。
- 余额工作流凭据仅用于服务端执行；批量配置不会复制来源凭据或号池绑定。旧版独立渠道的复制操作仍按其原有权限处理。

相关页面：`relay-settings`、`upstream-status`。
