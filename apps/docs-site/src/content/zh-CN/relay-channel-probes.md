# 渠道余额探针

渠道余额探针通过实际模型请求比较上游余额变化、用量和渠道倍率，帮助操作人员校准定价。探针会产生上游请求和可能的费用，但不会生成用户账单；建议倍率必须由有权限的人员确认应用。

## 使用前提

| 操作                                       | 所需权限                                                 |
| ------------------------------------------ | -------------------------------------------------------- |
| 查看渠道、档案及结果                       | `relay:channel:probe:read`                               |
| 保存普通档案、运行、重置任务、清理历史     | `relay:channel:probe:execute`                            |
| 管理或绑定号池、修改已绑定号池的共享工作流 | `relay:channel:probe:account:manage`，并满足相应操作要求 |
| 应用倍率                                   | `relay:channel:multiplier:adjust`                        |

渠道必须在当前可访问范围内，已配置支持的格式、模型、上游地址及 API 凭据。本页不接受 OAuth 访问令牌。修改和执行操作要求 2FA 升级认证及重放保护；IAM 强制授权还需平台全局用户组资格和下文列出的资源操作。

余额工作流的密码、密钥和号池令牌由服务端保管，保存后不会回显或导出。应将秘密放入“探针凭据”并在工作流引用，避免直接写入可能展示的普通配置字段。

## 首次探测独立渠道

1. 打开渠道余额探针页面，找到目标渠道，单击“管理探针”并进入“探针档案”。默认列表只显示已启用渠道，找不到时先检查状态筛选和访问权限。
2. 启用档案，选择兼容的请求格式、模型和接口，检查最小请求体。模型调用使用渠道已保存的上游地址和 API 凭据，与余额工作流凭据不同。
3. 配置余额工作流，在且仅在一个步骤中指定数值余额路径。填入需要的探针凭据，核对币种、余额除数、结算比率与采样设置。
4. 保存档案并确认成功，再返回列表单击“执行探针”。任务进入队列，不代表已经测量成功。
5. 查看最新状态，打开“管理探针”中的“执行记录”，核对余额差、用量、校准状态、样本及失败原因。
6. 仅在确认结果和应用条件后，使用“应用”入口调整倍率。探针不会自动改价。

## 配置余额工作流与测量参数

余额工作流支持 1～3 个 GET 或 POST 步骤，按顺序执行。凭据或前序提取变量使用 `{{变量名}}` 引用；绑定号池后可使用保留变量 `{{accountToken}}`。不要把 `accountToken` 配成自定义号池凭据。

余额路径和提取路径指向响应 JSON。例如响应为 `{"data":{"balance":120}}` 时，余额路径可写 `data.balance`。支持对象字段和数组索引，不支持通配符等完整 JSONPath 表达式。余额必须能转换为有限数值。

| 参数                       | 如何填写或判断                                                                                      |
| -------------------------- | --------------------------------------------------------------------------------------------------- |
| 格式、模型、接口与请求体   | 必须相互兼容，且被目标渠道支持。切换格式后重新检查自定义 JSON，页面不会保证所有自定义字段都自动迁移 |
| 原始余额换算除数           | 原始余额除以该值后参与计算；默认 1。例如上游以分返回而需要元时使用 100                              |
| 上游币种与本地币种         | 必须一致才生成可比较建议；填写币种名称不会自动换汇                                                  |
| 上游结算比率、分销倍率     | 都参与目标成本计算，默认各为 1，必须按实际结算关系核对                                              |
| 测量输入 Token 目标        | 默认 1024，范围 0～32768；用于扩展可识别文本以提高测量信号，不保证上游实际 Token 数等于该值         |
| 余额稳定容差、连续读取次数 | 默认容差 0.000001、连续 2 次；系统会反复读取余额，等待扣费及余额稳定                                |
| 采样次数、严格校准验证     | 共同决定样本量和建议验证方式，详见下一节                                                            |
| 串行组                     | 用于协调同组探针；同号池账号即使不同组也互斥                                                        |

探针会在每个样本前后多次执行余额工作流，以判断余额稳定，不是每个任务只读一次。因此，将登录保留在普通余额工作流内可能反复登录；共享登录场景优先使用号池。

独立渠道或单个成员未提交新凭据时保留原值；提交新凭据时，应填写该目标需要的完整键值集合，不要把空白输入理解为删除旧凭据。

## 采样、缓存与费用

采样次数为 1～10，新档案默认 3 次，样本顺序执行。每次测量都会发送模型请求并多次读取余额；测量输入扩展和预热也可能增加上游用量。失败、中断或重置不会撤回已发出的请求及费用。外部并发消费同一上游余额也可能影响测量，运行前应确认余额变化可归因于本次探针。

| 缓存测量             | 行为与限制                                                                                         |
| -------------------- | -------------------------------------------------------------------------------------------------- |
| 避免缓存响应（默认） | 尝试注入唯一提示标记来减少缓存干扰，不保证上游绝不缓存                                             |
| 允许上游缓存         | 不注入缓存规避标记，按上游实际用量测量                                                             |
| 预热后测量缓存命中   | 每个样本先预热，再测量；预热成本单独记录，不参与建议倍率。测量响应须报告缓存读取用量才认可缓存命中 |

无法向自定义请求体注入标记时，默认拒绝运行。优先修正格式或使用最小请求预设；“允许无缓存规避标记”只允许继续请求，不会证明测量没有缓存干扰。

“严格校准验证”默认关闭，一个可比较样本即可得到 `verified`；此状态不代表通过了多样本稳定性检查。开启后至少需要 3 个有效样本，并检查低信号、扣费稳定性、异常值和样本波动。查看结果时同时核对验证开关、接受与丢弃的样本数。

## 查找和查看结果

主列表的名称或 ID 搜索不区分大小写，输入后立即在已加载的渠道行内筛选；不会搜索成员名称或历史正文。串行组、档案状态、启用状态、最近运行状态和建议筛选共同生效，改变筛选会清除当前勾选。

有已知排队或运行任务时，页面约每 3 秒轮询最新状态，完成后停止；手动“刷新”可重新加载概览。加载报错时旧列表可能仍显示，应先处理错误再重试。

混池展开后查看成员自己的最新任务；进入成员详情时，历史仅针对该成员。当前详情读取最近 20 条记录，没有历史翻页控件；查询更早结果需要使用获准的分页历史接口。记录仍受保留期及当前可见范围限制。

任务执行成功不等于可以应用建议。检查原始用量、样本明细、余额快照、校准状态和费用构成；币种不同、缺少本地定价、余额变化太小、缓存命中未验证或余额未稳定，都可能无法形成可用建议。

建议使用的成本关系为：

```text
目标成本 = 换算后的上游余额差 × 上游结算比率 × 分销倍率
建议倍率 = 目标成本 ÷ 本地基础成本
```

本地基础成本按探测时的模型用量及计费配置计算。页面的估算费用不是用户账单，也不是对未来上游价格的承诺。

## 应用建议倍率

1. 单击某条结果的应用入口，或勾选结果后打开批量应用对话框。
2. 检查当前倍率、建议倍率、目标倍率、变更幅度及受影响的对外渠道。可调整目标值和舍入设置，但舍入不会使原本无效的结果变得可应用。
3. 选择真正要提交的结果，完成确认和验证，再检查成功及拒绝项；失败项不会撤销其他已成功项。

只能应用 24 小时内完成、执行成功、校准为 `verified`、尚未应用且具有有效计费快照的结果。当前倍率及计费配置必须仍与探测时一致；模型定价、映射、目标覆盖、接口或时间/上下文倍率变化时应重新探测。

相对当前倍率变更超过 20% 时，默认需要另一条同账号、同计费快照、24 小时内的 `verified` 结果，且建议须与目标值足够接近。明确确认大幅变更只跳过第二条结果要求，不跳过有效期、快照或授权检查。

**混池成员结果应用后修改所属逻辑混池的共享对外倍率，影响整个池，不只影响该成员。** 同一渠道有多条待应用结果时，先应用一条会改变当前倍率，其他结果可能因此过期或冲突；先检查实际结果再重新探测。

## 使用混池、号池与批量配置

混池共享余额工作流和校准参数，每个物理成员可覆盖格式、模型、请求体与串行组，并使用自己的余额凭据或绑定号池。一次任务固定所选成员，不会自动切换到其他成员。禁用、凭据不可用或格式/模型不兼容的成员不能运行。

从成员抽屉修改工作流和校准参数仍会影响共享档案。页面保存依次提交共享档案、成员覆盖和必要的号池绑定，**不是一次整体事务**；后续失败时前面步骤可能已经成功。请刷新并分别核对共享档案、成员设置和绑定，再重试失败步骤。

拥有号池管理权限时，可在“号池”页签创建登录配置：

1. 配置登录请求及凭据，指定令牌提取路径，以及有效期字段或备用有效期。默认备用有效期 1800 秒、最短登录间隔 300 秒。
2. 保存后为目标绑定号池，在余额请求中引用 `{{accountToken}}`。模型调用仍使用渠道 API 凭据。
3. 手动删除余额工作流中的旧登录步骤；绑定不会自动修改工作流，旧步骤会继续执行。
4. 检查会话和下次可登录时间。失败登录也计入冷却，手动刷新不会绕过最短间隔。同一号池账号的探针互斥。

编辑号池时，原登录 URL、方法、请求头、查询和正文不会回显，需重新填写完整登录请求；留空会导致校验失败。省略凭据可保留原值，提供新凭据则整体替换。创建必须填写凭据；`seconds` 有效期表示从登录时起的秒数，`iso` 表示绝对时间，不是 Unix 时间戳。过期信息缺失时使用备用有效期。被绑定的号池不能直接删除。

批量配置可选已有档案作为共享模板，再逐目标选择兼容的格式、模型、请求体、串行组及号池。每个目标独立保存，需检查逐项结果；模板不携带来源凭据或号池绑定。切换格式必须提供兼容请求体，运行中或排队任务可能阻止目标修改。普通独立渠道档案复制的旧授权模式行为另见下文，不能与批量目标配置混为一谈。

## 重置任务、清理历史与清空档案

| 操作         | 后果                                                                     |
| ------------ | ------------------------------------------------------------------------ |
| 重置运行状态 | 取消所选范围的排队或运行任务并尝试清理队列位置；已发出的上游请求不能撤回 |
| 清理失败历史 | 删除失败范围的终态记录，保留成功及活动任务                               |
| 清理全部历史 | 删除所选范围的终态记录，保留排队和运行任务；无法在页面恢复               |
| 清空探针档案 | 删除配置及关联目标设置，历史记录保留但与档案解除关联；活动任务会阻止清空 |

当前服务会周期清理创建超过 90 天的探针任务记录，不承诺到期瞬间删除。清空或停用档案不能撤回已经产生的上游用量。

## IAM 授权参考

以下资源授权说明适用于 IAM 强制模式。平台全局用户组须提供相应的读取、执行、号池管理或倍率调整资格；账户所有者身份、附加权限、私有用户组或通配符策略不能单独提供平台资格。渠道可见性也仍然生效。

读取和操作分别授权：概览能显示渠道，不代表能够读取档案、结果、凭据状态或应用倍率。凭据值不会作为查询结果交付。

### 读取概览、档案与结果

原生 IAM 强制模式下，概览使用 `quyan:relay:ListProbeOverview` 逐渠道授权。被拒绝或不可见的渠道与成员不会展示，也不会通过面向客户的池名称泄露。档案内容另外要求 `quyan:relay:GetProbeProfile`，最新结果另外要求 `quyan:relay:ListLatestProbeRuns`，资源检查与各自的独立查询接口一致；这些内容可以单独隐藏，而不影响其他已获准的渠道信息。目标覆盖配置要求 `quyan:relay:GetProbeTargetConfig` 对父渠道、目标渠道和档案均获准；若绑定共享账号，还须对该账号 ARN 获准，否则不展示覆盖配置及由该绑定推导的凭据状态。当前成员全部被拒绝或不可用时，也不会改用旧成员关系展示内容。

启用 IAM 原生强制授权后，最新结果轮询会对渠道 ARN（`acs:platform:*:platform:relay-channel/<channelId>`）和运行记录 ARN（`acs:platform:*:platform:relay-probe-run/<channelId>/<runId>`）检查 `quyan:relay:ListLatestProbeRuns`。混池目标还必须具有当前物理成员的访问权限。被拒绝的渠道不会返回；最新运行记录被拒绝时，该目标不展示结果，也不会替换成更早的记录。渠道可见性和部署管理员分配的探针读取资格仍然生效。

历史记录使用 `quyan:relay:ListProbeRuns` 检查父渠道、指定的物理成员及每条返回的运行记录。分页和总数仅计算获准的记录；已经离开混池的成员记录不会展示，显式指定的成员必须仍属于当前混池。

在 IAM 原生强制授权下读取探针档案，需要对渠道及 `acs:platform:*:platform:relay-probe-profile/<channelId>/<profileId>` 具有 `quyan:relay:GetProbeProfile`。通过检查后才读取工作流配置和凭据名称，响应不包含凭据值。混池档案的凭据名称仅包含当前仍属于该池、且通过同一 Action 检查的成员；被拒绝或已经移出的成员名称不会返回。

### 保存与删除档案

原生 IAM 强制模式下，保存档案要求 `quyan:relay:SaveProbeProfile` 对渠道及现有档案 ARN（新建时为服务端预留 ARN）均获准。更新混池还须对全部当前物理成员和已配置目标获准；任一拒绝会阻止整次保存。绑定共享账号的档案还要求 `quyan:relay:ModifyBoundProbeProfile` 对每个绑定账号 ARN 获准，并保留部署管理的账号池管理资格。服务端在取得渠道锁后与事务提交前重新检查授权；撤权会回滚创建或更新。未提供独立渠道凭据时保留原值，混池凭据仅保留当前成员；原混池凭据损坏时保存失败，不会静默丢弃。

删除档案需要对渠道、档案、已配置的物理目标及关联历史记录具有 `quyan:relay:DeleteProbeProfile`。历史记录会保留，但解除与档案的关联；若绑定了共享号池，还需要对号池 ARN 具有 `quyan:relay:UnbindProbeAccount`，并具备部署管理员分配的专门号池管理资格。排队或运行中的任务会阻止删除。提交时撤权会完整回滚配置删除和历史关联变更。

### 任务运行与排队有效期

启用 IAM 强制授权时，创建单个任务需要 `quyan:relay:CreateProbeRun` 同时允许渠道、档案、服务端预分配的任务 ARN 和队列位置；混池还需允许所选物理成员，绑定号池时还需允许对应号池 ARN。运行号池探针不等于修改号池，不会因此获得号池管理权限。部署管理员分配的探针执行资格仍是前提。

批量运行使用同一个 `quyan:relay:CreateProbeRun` Action，并逐目标执行相同的授权和排队检查。展开混池时只发现允许访问且当前启用的成员；已存在当前成员关系时，不会退回旧成员配置。显式目标与自动展开结果会去重，单个目标失败不阻止其他目标。单次最多指定 100 个渠道，最多排队 200 个展开后的目标；过大的展开会被拒绝，不会静默截断。失败结果仅返回安全的通用原因，不包含策略内容或内部异常。

任务资源格式为 `acs:platform:*:platform:relay-probe-run/<channelId>/<runId>`，队列位置为 `acs:platform:*:platform:relay-probe-queue-slot/<channelId>/<memberId或channel>`。独立渠道使用末段 `channel`，混池成员使用实际成员 ID。任务 ID 由服务端生成，创建策略通常使用限定渠道的任务通配符；对任一关联资源的显式拒绝会阻止创建。

后台开始执行、等待共享资源后、发起余额/模型/登录请求及发布结果前，都会重新检查任务、身份、配置和授权。重置任务、撤销权限或更改配置后，任务不会继续发起后续探测请求。已经发出的上游请求无法撤回，仍可能产生费用。

AccessKey 发起的任务还会绑定具体密钥的状态：禁用、过期、轮换或转移密钥后，任务不得继续执行；正常使用计数更新不会撤销任务。用户或主账号信息变化也会让旧排队授权失效。

服务端排队授权上下文的有效期最长为两小时。上下文过期、缓存丢失或授权服务不可用时，强制授权模式不会继续执行；请排查原因后重新提交任务。切换到强制授权前，应先处理没有该上下文的旧排队任务。浏览器不会收到排队授权上下文、凭据或令牌。

### 重置与清理历史

原生 IAM 强制模式下，重置排队或运行任务要求 `quyan:relay:ResetProbeRuns` 对渠道、选中或受影响成员、每条活动任务及每个队列槽均获准。队列槽 ARN 为 `acs:platform:*:platform:relay-probe-queue-slot/<channelId>/<memberId>`，父渠道槽使用 `channel`。整池重置包含当前成员槽和仍有活动任务的历史成员槽；尚无任务记录的孤立预留也由队列槽权限控制。任一资源拒绝会阻止整批取消。提交前重新检查授权；队列清理不会移除后来新建的任务预留。若取消已提交而队列清理不可用，接口报错并保留槽值，供后续获准重试。

在 IAM 原生强制授权下清理历史，需要对渠道、涉及的物理成员及每条选中的终态记录具有 `quyan:relay:ClearProbeHistory`。任一选中资源被拒绝，整次清理均不执行。提交时会再次检查授权，撤权会回滚删除。排队和运行中的任务保留，“仅失败”范围也会保留成功结果。

### 管理号池

启用 IAM 强制授权时，号池列表需要 `quyan:relay:ListProbeAccounts` 对指定号池资源 `acs:platform:*:platform:relay-probe-account/<accountId>` 的授权。平台号池管理资格仍是前提；仅给账号绑定策略不能获得平台管理资格。被拒绝的号池不会显示配置、冷却时间或会话状态。列表只展示是否已配置凭据，不读取或返回已保存的登录请求和加密凭据。

删除号池需要 `quyan:relay:DeleteProbeAccount` 对同一号池 ARN 的授权，同时保留平台号池管理资格、二次验证和重放保护。仍被渠道档案绑定的号池不能删除。删除前和提交时会重新检查授权；如果授权已撤销，号池及其缓存会话保留。

修改号池需要 `quyan:relay:UpdateProbeAccount` 对目标号池 ARN 的授权。省略凭据时保留原凭据，填写新凭据时整体替换；登录请求仍加密保存，响应不返回凭据或登录工作流。提交时授权发生变化会回滚配置修改，并保留原缓存会话。

创建号池需要 `quyan:relay:CreateProbeAccount` 同时允许创建入口 `acs:platform:*:platform:relay-probe-account-control/default` 和即将创建的号池 ARN（通常通过 `acs:platform:*:platform:relay-probe-account/*` 授权）。资源 ID 由服务端生成，创建前需通过两项授权，再保存凭据。创建必须提供凭据。

手动刷新需要 `quyan:relay:RefreshProbeAccount` 对目标号池 ARN 的授权，仍需二次验证和重放保护。原生刷新在等待探针结束后、发送登录请求前和发布会话时重新检查授权；失败或撤权不会用新会话覆盖旧的有效会话。登录尝试仍计入冷却时间。shadow 仅预览元数据授权，再执行一次原有刷新流程。

### 逐目标配置与共享模板

IAM 强制授权模式下，批量目标配置使用 `quyan:relay:ConfigureProbeTarget`，检查所选渠道、档案和物理成员；指定来源模板时还检查来源渠道和档案。缺少档案时，服务端预分配档案 ARN，并把新档案和目标设置一起提交；校验失败或撤权不会留下半成品档案。模板只携带共享设置，不携带来源凭据或号池绑定。

仅修改单个目标的格式、模型、请求体或串行组时，保护该目标及其已绑定号池；使用来源覆盖共享档案时，还检查所有受影响的当前成员、已配置目标与绑定号池。绑定号池的设置变更需专门号池管理资格及 `quyan:relay:ModifyBoundProbeProfile`，不能利用普通配置入口改写携带共享令牌的工作流。

目标原有凭据、号池绑定及省略的目标设置保留。更换格式时必须同时提供兼容请求体。每个目标独立事务提交；运行中的任务会阻止修改。配置响应不回传既有号池绑定，需通过获准的查看接口读取。

### 绑定与解绑号池

IAM 强制授权模式下，绑定需要专门的平台号池管理资格，以及 `quyan:relay:BindProbeAccount` 对渠道、档案、所选物理成员和新号池 ARN 的授权。普通探针执行资格或账户自定义的通配符策略不能替代平台号池管理资格。

替换号池或传入 `accountId: null` 解绑时，还必须对旧号池具有 `quyan:relay:UnbindProbeAccount`；只获准绑定新号池不能移除未获准的旧绑定。重复绑定同一号池不要求额外解绑权限。绑定检查不读取登录密文或令牌，响应仅返回所选目标与新绑定的号池 ID。

渠道有排队或运行中任务时不能修改绑定；配置会在等待渠道锁后及提交时重新鉴权。撤权会回滚该目标的修改，不影响已独立成功的其他目标。目标原有格式、模型、请求体和串行组不会因绑定变更被清除。

### 复制独立渠道档案

IAM 强制授权模式下，独立渠道档案复制需要 `quyan:relay:CopyProbeProfile` 同时允许来源渠道、来源档案、每个目标渠道和目标已有或服务端预分配的档案 ARN。仍需部署分配的探针执行资格、二次验证和重放保护。各目标独立提交，一个目标拒绝不会阻止其余目标。混池不支持此复制入口，请使用逐成员配置。

原生复制只复制工作流与校准设置，不读取或复制来源加密凭据，也不传递号池绑定。新档案没有来源凭据；覆盖已有档案时保留目标原有凭据、号池绑定及目标配置。覆盖绑定号池的档案还需专门号池管理资格及对每个目标号池的 `quyan:relay:ModifyBoundProbeProfile`。存在排队或运行中任务的目标不能覆盖。请确认工作流中的变量与目标自身凭据匹配，再运行探针。

legacy/shadow 模式仍保留旧复制流程（包含原来复制的独立渠道凭据）；只有强制授权模式采用上述不传递来源凭据的行为。切换前请核对目标凭据，不能依赖旧复制行为自动补齐凭据。

### 应用结果授权

IAM 强制授权模式下，应用探测结果使用 `quyan:relay:ApplyProbeRun`，需要平台倍率调整资格，以及运行记录、渠道、档案和物理成员 ARN 的授权。逻辑混池倍率会影响整个池，因此还检查所有受影响的当前成员；不能只凭一个成员的权限修改共享倍率。应用入口不读取或返回档案凭据、上游密钥、余额账本或探测样本。

每条结果独立提交，倍率更新和已应用标记在同一事务中；撤权或并发冲突会一起回滚，其他已成功的结果保留。shadow 只预览资源范围，原有应用流程执行一次。

## 常见问题

| 现象                   | 处理建议                                                                         |
| ---------------------- | -------------------------------------------------------------------------------- |
| 找不到渠道或成员       | 清除名称、组和状态筛选，检查当前渠道可见性、成员是否仍在池内以及独立读取权限     |
| 余额或变量路径错误     | 用实际响应结构核对字段路径；确保只有一个余额路径、变量已提前定义且余额为数值     |
| 扣费稳定超时或低信号   | 检查上游记账延迟、余额精度、换算除数和测量输入；不要直接把失败结果用于改价       |
| 无法注入缓存规避标记   | 优先选用兼容的最小请求预设或修正自定义文本结构，再考虑明确允许无标记运行         |
| 号池登录失败或冷却中   | 核对完整登录请求、令牌与有效期路径、凭据和下次可登录时间；不要用重复刷新绕过冷却 |
| 显示成功但应用被拒绝   | 检查校准、完成时间、计费快照、当前倍率、大幅变更确认及相关资源授权               |
| 保存失败但部分配置已变 | 刷新分别核对共享档案、成员覆盖和绑定；分步提交不保证整体回滚                     |
| 重置请求报错           | 任务取消可能已提交但队列清理失败；刷新确认任务状态，再由有权限人员重试           |
