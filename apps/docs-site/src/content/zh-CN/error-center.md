# 错误中心

错误中心将浏览器运行时错误、Vue 组件错误、未处理 Promise 和服务端非预期错误聚合到一起，便于按错误指纹排查。

## 使用前提

- 需要错误报告查看权限才能打开页面。
- 浏览器上报会对部分常见敏感字段和文本模式进行脱敏，服务端也会处理上下文中的部分敏感字段。脱敏无法保证识别所有敏感内容，请避免将密码、令牌或个人信息写入错误信息。
- 生命周期定时清理会删除最近一次发生时间超过 90 天的错误组及其发生记录。清理取决于调度是否启用和成功运行；持续发生的错误组可能保留超过 90 天的旧记录。

## 页面内容

- 错误来源、最近发生时间、路由、错误信息和发生次数。
- 错误状态：`open`、`acknowledged`、`resolved`、`ignored`。
- 错误详情中的指纹、错误信息，以及各发生记录可用的堆栈和上下文。

## 排查流程

1. 使用来源、状态或关键字筛选错误。更改来源或状态会立即查询；输入关键字后按 Enter 查询。
2. 打开错误详情，展开最近发生记录，查看可用的堆栈和上下文。
3. 如从上下文或其他途径获得请求 ID，可在[系统日志]({{DOCS_BASE_URL}}/zh-CN/system-logs)中按该 ID 查找关联记录。错误中心界面不会单独显示请求 ID。
4. 确认处理结果后，在有更新权限时修改错误状态。

打开详情时如果请求失败，抽屉可能仍显示列表中的摘要；请关闭并重新打开，确认详情加载成功后再修改状态。详情页只显示该错误组最近的最多 50 条发生记录，不能在此页面翻阅更早记录。展开具体发生记录可查看可用的堆栈和上下文；如果发生记录加载失败，请关闭详情并重新打开该错误组。仍失败时，请检查发生记录读取权限，或联系管理员排查。顶部“刷新”按当前筛选条件重新加载当前页；“清除筛选”清空关键词、状态和来源并返回第一页。列表加载失败时使用页面提供的重试操作。

错误上报接口是后台受限的匿名入口，达到频率限制时会丢弃后续上报；这不会影响原始页面操作。

## 错误组与发生记录的 IAM 访问

启用 IAM 强制授权后，每个错误组使用 `acs:platform:*:platform:error-group/<groupId>`。`quyan:system:error_report:GetErrorGroup` 读取错误组摘要，`quyan:system:error_report:ListErrorOccurrences` 列出该错误组的有效发生记录，包括堆栈和受限上下文。两个操作独立授权，授予其中一个不会授予另一个。发生记录列表以所属错误组为授权资源，总数只包含该组的有效记录。

操作员还必须由平台全局用户组提供错误报告读取资格。账户所有者、账户私有组、用户附加权限或单独的通配符策略都不能制造这项资格。角色会话使用角色策略，不继承用户组的 Allow 授权。

服务端在加载错误详情前授权，并在返回前复核权限与错误组。权限撤销、角色会话过期或撤销、错误组失效或变化时，读取会失败。错误组浏览逐条评估 `quyan:system:error_report:ListErrorGroups`，先过滤再分页，总数只包含已授权的有效错误组。列表权限不会自动授予详情或发生记录访问。查询期间已授权错误组或权限发生变化时，请重新查询获取当前结果。超出本次查询初始范围的新错误组会在下一次查询中展示。匿名客户端上报仍受频率限制；状态更新使用所选错误组上的 `quyan:system:error_report:UpdateErrorGroupStatus`。由于接口会返回更新后的错误组摘要，还必须对同一资源拥有 `quyan:system:error_report:GetErrorGroup`。操作目录通过 `requiredActions` 列出这项读取要求；授予更新操作不会自动授予读取权限。操作员还需由平台全局用户组同时提供错误报告读取和更新资格，并满足重放保护要求。授权数据或所选错误组发生变化时，更新可能被拒绝；提交前授权复核失败会回滚状态变更。legacy 和 shadow 模式继续保留既有权限与响应行为。
