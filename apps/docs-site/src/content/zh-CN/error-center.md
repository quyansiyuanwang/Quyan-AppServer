# 错误中心

错误中心将浏览器运行时错误、Vue 组件错误、未处理 Promise 和服务端非预期错误聚合到一起，便于按错误指纹排查。

## 使用前提

- 需要错误报告查看权限才能打开页面。
- 错误上报会自动脱敏密码、令牌、Cookie、授权头和密钥。
- 错误详情保留 90 天，过期后自动删除。

## 错误组与发生记录的 IAM 访问

启用 IAM 强制授权后，每个错误组使用 `acs:platform:*:platform:error-group/<groupId>`。`quyan:system:error_report:GetErrorGroup` 读取错误组摘要，`quyan:system:error_report:ListErrorOccurrences` 列出该错误组的有效发生记录，包括堆栈和受限上下文。两个操作独立授权，授予其中一个不会授予另一个。发生记录列表以所属错误组为授权资源，总数只包含该组的有效记录。

操作员还必须由平台全局用户组提供错误报告读取资格。账户所有者、账户私有组、用户附加权限或单独的通配符策略都不能制造这项资格。角色会话使用角色策略，不继承用户组的 Allow 授权。

服务端在加载错误详情前授权，并在返回前复核权限与错误组。权限撤销、角色会话过期或撤销、错误组失效或变化时，读取会失败。错误组浏览逐条评估 `quyan:system:error_report:ListErrorGroups`，先过滤再分页，总数只包含已授权的有效错误组。列表权限不会自动授予详情或发生记录访问。查询期间已授权错误组或权限发生变化时，请重新查询获取当前结果。超出本次查询初始范围的新错误组会在下一次查询中展示。匿名客户端上报仍受频率限制；状态更新继续使用既有权限。

## 页面内容

- 错误来源、最近发生时间、路由、错误信息、发生次数和影响用户数。
- 错误状态：`open`、`acknowledged`、`resolved`、`ignored`。
- 错误指纹下的堆栈、请求 ID、浏览器版本和受限上下文。

## 排查流程

1. 使用来源、状态或关键字筛选错误。
2. 打开错误详情，先查看最近发生记录和请求 ID。
3. 在系统日志中用请求 ID继续检查完整请求链路。
4. 确认处理结果后更新错误状态。

错误上报接口是后台受限的匿名入口，达到频率限制时会丢弃后续上报；这不会影响原始页面操作。
