# 系统统计

系统统计展示处理本次请求的服务实例、应用计数、内存、CPU 和基础设施状态，适合排查重启、资源占用或 Redis 异常。页面只读，不提供历史曲线、告警配置或服务重启操作。

## 使用前提

在核心管理站点打开**系统统计**，需要系统统计读取权限。统计报告包含运行环境、主机和构建信息，分享截图前请检查是否包含不宜公开的部署信息。

## 查看和刷新数据

1. 打开页面，等待首次加载完成。
2. 单击**全部刷新**获取当前报告。桌面端各卡片来自同一次统计请求，不能逐张单独刷新。
3. 需要持续观察时，将**自动刷新**设为大于 0 的秒数，可输入范围为 **0–3600 秒**。默认 0 表示关闭。
4. 停止观察时设为 0；离开页面也会停止自动刷新。重新打开页面后默认仍为关闭。

修改刷新间隔会重新开始计时，在下一次间隔到达时查询，不会立即刷新。自动刷新标记只说明定时器已启用，不代表最近一次查询成功。当前时间和运行时长是上次采样的值，不会在两次刷新之间持续走动。

首次加载失败时，页面可能仍显示初始的零值、空白或不可用状态；刷新失败时则保留上一次数据。请单击**全部刷新**并检查错误提示后再判断，不能仅凭自动刷新标记或零值认定服务健康或故障。

## 理解统计指标

| 指标                               | 含义与使用方法                                                                                                 |
| ---------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| 服务器运行时间、启动时间、运行秒数 | 当前服务实例的启动和运行信息。重启或切换实例后会变化，不是整个部署的连续运行时长。                             |
| 当前时间                           | 服务端采样时间，日期时间按浏览器本地时区显示。不是持续更新的时钟。                                             |
| 用户总数、用户组总数               | 部署中的全部记录数量，未按当前账户或正常状态筛选；可能包含禁用或软删除记录，不是在线人数。                     |
| 权限总数                           | 系统定义的权限项数量，不是当前操作者拥有的权限数量。                                                           |
| 堆内存使用、堆内存总量、堆使用率   | 当前服务进程的堆内存情况；堆使用率为已用堆与已分配堆的比值，不是整机内存使用率。                               |
| 常驻内存（RSS）                    | 当前服务进程驻留在内存中的大小，与堆内存的统计范围不同。                                                       |
| 用户态 CPU、内核态 CPU             | 服务进程自启动以来累计消耗的 CPU 时间，以时间显示，不是 CPU 利用率。数值增长本身不代表负载异常。               |
| 运行时信息                         | Node.js、V8、平台、进程 ID、CPU 核心数、主机名和操作系统内存及运行时长。操作系统指标与服务进程指标应分开理解。 |
| Redis 状态、熔断器状态             | 当前实例所记录的 Redis 可用性及熔断状态，不代表所有 Redis 命令或全部业务功能已通过健康检查。                   |
| 配置信息                           | 运行环境、监听端口、Redis 地址、验证码和令牌有效期等摘要，用于核对部署配置。不是配置编辑入口。                 |
| 构建信息                           | 当前服务提供的版本、分支、提交和构建时间，用于确认发布版本；不是实时发布进度。                                 |

多进程或多实例部署时，相邻请求可能来自不同实例。比较运行时间、内存和 CPU 前，先核对**主机名和进程 ID**。该报告不汇总所有实例，也不保存历史采样。

Redis 熔断状态中，`closed` 表示正常放行，`open` 表示熔断，`half-open` 表示恢复探测阶段。单个状态正常不能证明整条业务链路可用。数据库一栏显示“—”时也不能据此判断数据库连接失败，请结合请求错误和日志检查。

## 使用移动端

移动端通过折叠区显示服务器时间、应用统计、部分内存指标和 Redis 状态，也可手动或自动刷新。CPU 时间、运行时信息、配置和构建卡片等完整内容请使用桌面端查看。

## 管理权限

系统统计是部署级报告。IAM 强制模式下，需要实际平台全局用户组中的 `SYSTEM_STATS_READ` 资格，并允许 `quyan:system:GetStatistics` 操作资源 `acs:platform:*:platform:system/stats`。

账户所有者、账户私有组、用户附加权限或单独的账户策略不能替代平台资格。角色会话使用角色策略，不继承用户组的 Allow 授权；该管理报告不接受 OAuth 访问令牌。显式 Deny、资格撤销、账户禁用、角色会话过期或撤销，以及读取期间相关授权信息变化，都可能使请求失败。服务端在加载前和返回前复核授权；legacy 和 shadow 模式沿用既有权限行为。

页面内的构建信息随系统统计报告一起返回，受上述统计权限保护。**单独调用构建信息接口**时，才另外需要 `DEBUG_ACCESS` 及 `quyan:system:GetBuildInfo` 对 `acs:platform:*:platform:system/build-info` 的授权。这项独立接口权限不会自动授予系统统计访问。

## 排查建议

| 现象                            | 下一步                                                             |
| ------------------------------- | ------------------------------------------------------------------ |
| 运行时长突然变短或 CPU 时间减少 | 核对主机名、进程 ID 和构建版本，确认是否重启或切换实例。           |
| 内存持续增加                    | 在同一实例上比较多个采样，结合系统日志检查。页面本身没有历史曲线。 |
| Redis 显示不可用或熔断          | 手动刷新确认采样有效，再检查服务端日志及相关业务请求。             |
| 自动刷新已开启，但数据未更新    | 单击全部刷新检查错误；确认当前身份和读取权限仍有效。               |
