# 工单管理

审核人员使用本页处理用户提交的建议、问题和其他工单，维护状态与负责人，并通过公开回复或内部备注记录处理过程。提交自己的问题请使用[我的工单]({{DOCS_BASE_URL}}/zh-CN/my-tickets)。

## 使用前提

在“开发者运营”站点打开“工单审核”。查看列表和详情需要 `TICKET_REVIEW_READ`；更新工单、回复、删除和管理分配规则需要 `TICKET_REVIEW_UPDATE`。

IAM 强制模式下，还必须属于具备相应权限的有效平台全局组，并获准执行对应操作。个人附加权限、账户私有组或账户所有者身份不能替代全局组资格。具体操作及资源见下文“权限范围”。

## 查找与查看工单

1. 输入工单编号、标题、描述或提交者用户名中的关键词，点击“搜索”或按 Enter；清空关键词也会重新查询。搜索不检索评论内容。
2. 按状态、类型、优先级或负责人筛选；更改筛选会查询第一页。点击“重置”可清除全部筛选。
3. 点击“查看详情”，确认标题和提交者，阅读原始描述、复现步骤、联系方式及评论时间线。

工单类型包括建议、问题和其他；优先级包括低、中、高、紧急。每页可显示 10、20、50 或 100 条。页面没有时间范围控件；API 查询支持 `startTime` 和 `endTime`。

IAM 强制模式下，列表和总数只包含获准工单，并按最近回复排序。列表权限与详情权限独立，能看到条目不保证能打开详情。

## 更新状态与负责人

1. 在详情的审核表单中调整类型、状态、优先级或负责人。
2. 需要取消分配时清空负责人；点击“重置”会恢复当前已加载详情中的值。
3. 点击“保存审核变更”，核对返回的状态与负责人。调整表单不会自动保存，回复内容也需单独发送。

状态对提交者操作的影响如下：

| 状态                   | 提交者能否编辑或回复                                         |
| ---------------------- | ------------------------------------------------------------ |
| 待处理、处理中、已采纳 | 有相应权限时可以。已采纳不等于问题已处理完毕。               |
| 已拒绝、已完成         | 不可以。需要继续沟通时，审核人员可将状态改回待处理或处理中。 |

审核人员仍可在已拒绝或已完成的工单中追加回复或内部备注。分配负责人不会自动授予其审核权限；手动分配的用户必须有效，实际处理仍需相应权限。

## 发送回复或内部备注

1. 在详情的回复表单中选择“公开”或“仅内部可见”。
2. 填写内容，最多 5000 个字符，不能只包含空白。
3. 点击“发送回复”，在时间线中核对内容和可见范围。

公开回复对提交者和获准的审核人员可见；内部备注不向提交者显示。页面不提供已提交评论的编辑、删除或可见性修改入口，发送前请核对。

切换工单或关闭详情后，未提交的回复及其可见性可能保留。每次发送前确认当前工单、内容和可见性。回复表单的“重置”及成功发送都会清空内容，并将可见性恢复为公开；继续写内部备注时需重新选择“仅内部可见”。

## 配置新工单的自动分配

1. 点击页面顶部的“分配规则”，等待规则加载成功。
2. 添加规则，至少选择类型或优先级中的一项，并选择处理人。两项都选择时，工单需同时匹配。
3. 检查校验摘要后点击“保存”。确认继续保存不完整规则时，缺少匹配条件或处理人的规则会被排除。抽屉中的“重置”会重新加载已保存规则，放弃当前修改。
4. 创建一张符合条件的工单，检查负责人。保存规则不会重新分配已有工单，之后修改工单的类型或优先级也不会自动重新分配。

匹配顺序为：类型与优先级同时匹配、仅类型匹配、仅优先级匹配；同一类匹配取第一条。新工单初始状态为待处理、优先级为中；仅匹配高或紧急优先级的规则不会匹配这些新工单。

匹配后，系统从该规则中筛选有效且具备审核更新权限的用户进行轮转分配。没有匹配规则或所选规则没有可用处理人时，工单保持未分配，不会继续尝试下一条规则。每次最多保存 100 条规则，每条最多 50 个处理人 ID；重复 ID 会去重。

候选用户框支持输入关键词搜索，单次最多加载 50 个结果，不是完整用户目录。搜索失败时可能显示空列表，请确认用户查询权限及连接后重试。规则本身不会授予处理人审核权限。

## 删除工单

在列表中找到目标，点击“删除”并确认。成功后，工单从有效列表中移除，提交者也无法再通过有效工单入口查看；本页没有恢复入口。完成正常处理时应更新状态，无需删除工单。

## 权限范围

IAM 强制模式下，以下操作可分别授权，显式 Deny 优先：

| 操作               | IAM Action                           | 必要的全局组权限       |
| ------------------ | ------------------------------------ | ---------------------- |
| 审核列表           | `quyan:ticket:ListReviewTickets`     | `TICKET_REVIEW_READ`   |
| 审核详情           | `quyan:ticket:GetReviewTicket`       | `TICKET_REVIEW_READ`   |
| 保存审核           | `quyan:ticket:UpdateReviewTicket`    | `TICKET_REVIEW_UPDATE` |
| 发送审核回复或备注 | `quyan:ticket:AddReviewComment`      | `TICKET_REVIEW_UPDATE` |
| 删除工单           | `quyan:ticket:DeleteReviewTicket`    | `TICKET_REVIEW_UPDATE` |
| 读取分配规则       | `quyan:ticket:GetAssignmentRules`    | `TICKET_REVIEW_UPDATE` |
| 保存分配规则       | `quyan:ticket:UpdateAssignmentRules` | `TICKET_REVIEW_UPDATE` |

工单审核资源为 `acs:platform:*:platform:ticket-review/<提交者用户ID>/<工单ID>`。提交者由已保存工单确定，不能通过传入其他用户切换目标。策略可限制到具体工单；列表、详情、修改、回复和删除权限不相互包含。提交者访问自己工单使用另一套权限。

分配规则资源为 `acs:platform:*:platform:config-item/notification.ticketAssignmentRules`。尚未配置时，获准读取返回空规则；首次获准保存可以创建规则。读取与保存分别授权。同一个配置键经通用配置接口读写时也受专用操作授权和全局组资格约束；缺少权限时通用列表隐藏该键，包含它的区块读取或批量保存会被拒绝。该资源上 `Action: "*"` 的 Deny 可限制两个入口。

身份、角色会话、组资格、授权或工单内容在操作期间发生变化时，请求可能被拒绝。刷新并核对最新状态后再重试，不要继续使用旧详情。

## 常见问题

| 情况                           | 处理方法                                                                                         |
| ------------------------------ | ------------------------------------------------------------------------------------------------ |
| 搜索、翻页或刷新失败           | 旧列表和总数可能仍保留。重新刷新并等待成功，再判断筛选结果。                                     |
| 详情加载失败，仍看到上一张工单 | 关闭并重新打开目标，确认标题和提交者正确且加载成功后再保存或回复。                               |
| 分配规则加载失败               | 旧规则可能保留。关闭并重新打开规则抽屉，加载成功后再编辑，避免覆盖其他人的修改。                 |
| 保存、回复或删除后显示异常     | 操作可能已成功而后续刷新失败；请求超时也可能结果不明。先重新加载并核对，避免重复回复或错误重试。 |
| 删除最后一条后当前页为空       | 切换到上一页查看；删除后的刷新不会自动退回上一页。                                               |
| 已分配的用户仍无法审核         | 分配只指定负责人，不授予权限。核对其全局组资格和具体工单授权。                                   |
