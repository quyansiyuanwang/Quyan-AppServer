# 内容安全

内容安全用于检查中转请求和上游响应中的文本，并在命中规则或 AI 审计条件时记录、替换或阻断。请求和响应分别配置；个人策略、令牌策略和系统基线共同决定实际处理结果。

## 使用前准备

在 AI 控制台打开“内容安全”。导航入口要求中转令牌读取权限；能够打开页面不代表可以执行所有操作。在 IAM 强制模式下，读取和保存个人策略、查看和修改规则、导入导出以及查询命中记录分别需要对应的 `quyan:content_safety:` Action。遇到权限错误时，请管理员核对具体操作，而不是只检查菜单权限。

管理员在“系统内容安全”维护系统策略。该入口要求系统配置权限；系统资源授权、管理资格及安全验证要求见后文。

启用 AI 审计前，确认管理员已配置可信的审计渠道、模型、密钥和价格。审计会发送被检查的原始文本，即使本地规则已经命中也仍可能发送；本地替换不会先为 AI 审计脱敏。这里的文本可能包含序列化的请求或响应字段，不局限于聊天消息。此功能不提供图片、音频或其他二进制内容的完整识别保证。

## 配置个人策略

1. 展开“策略设置”，分别检查“用户请求”和“上游响应”的模式、最大动作和 AI 审计设置。
2. 如需自行设置 AI 开关，先为该方向选择明确的启用模式，再调整 AI 审计及 AI 动作。选择“继承”时，页面显示的是个人覆盖值，未勾选的 AI 复选框不证明继承后的 AI 审计已关闭。
3. 点击页面顶部“保存”。保存仅提交个人策略；规则弹窗、规则开关、批量修改和导入各自立即提交，不依赖这个按钮。
4. 使用不含真实凭据的测试请求验证结果，并在“我的命中记录”检查方向、来源和动作。

模式中的“继承”只清除该方向的启用状态和默认动作覆盖，不会同时清除最大动作、AI 开关和 AI 动作。需要清除全部个人策略覆盖时，点击“恢复系统默认”；该操作立即保存，不需要再点击“保存”。它不会删除个人规则、系统规则的个人启用例外或历史命中记录，也不会清除令牌上的覆盖。

顶部“刷新”重新读取策略和当前规则页，会覆盖尚未保存的策略修改；它不会刷新下方独立的命中记录表。规则和命中记录默认每页 20 条，无自动轮询。加载失败时可能保留上次数据；请确认刷新成功后再据此操作。

## 动作与继承

| 设置或动作               | 实际含义                                                                   |
| ------------------------ | -------------------------------------------------------------------------- |
| 关闭                     | 该策略在此方向不执行本地规则或 AI 审计。组合令牌仍可能受其他节点策略约束。 |
| 放行 `allow`             | 命中后保留内容并记录；规则动作、AI 动作和最大动作须分别检查。              |
| 替换敏感内容 `blackhole` | 使用规则或 AI 提供的替换文本，存在下文所述范围限制。                       |
| 报错阻断 `unreachable`   | 拒绝请求或终止响应；不能撤回已经发出的流式内容。                           |
| 最大动作                 | 限制该方向可执行的最高动作，不等同于关闭审计。                             |

启用状态、默认动作、AI 开关和 AI 动作按“令牌明确值 → 个人明确值 → 系统值”继承。最大动作单独按 `allow < blackhole < unreachable`，取系统、个人和令牌三个层级中最低的上限。例如系统上限为 `blackhole` 时，个人选择 `unreachable` 仍最多替换；个人上限为 `allow` 时，该策略的命中最多放行，但检查和 AI 费用仍可能发生。

规则使用自身的动作。将方向模式选为“放行”不会把所有规则改成放行，也不会关闭 AI 审计。某条规则设为“放行观察”后仍记录该规则命中；同一次检查中的 AI 审计仍可独立替换或阻断。规则与 AI 的结果各受最大动作约束，再以阻断、替换、放行的顺序决定该策略的最终动作。

组合令牌的响应可能经过多个节点的策略检查；当前节点放行或关闭，不代表整条组合路径放行。每次上游尝试固定使用开始时的策略和规则；修改从下一次请求、重试或渠道切换生效，运行中的长连接继续使用原设置。

## 新增、调整与停用规则

1. 展开“危险规则”，点击“新增规则”。输入名称、匹配类型、规则内容、方向、动作和优先级，在弹窗中保存。
2. 名称为 1～120 个字符，匹配内容为 2～2000 个字符；方向可选请求、响应或两者。`literal` 按字面内容匹配；`regex` 填写正则表达式正文，不添加 `/.../` 分隔符。正则必须有效且不能匹配空文本，反向引用和部分危险重复结构会被拒绝。
3. 使用较小的优先级让规则先匹配。同优先级按创建时间从早到晚，再按规则 ID 排序；每次检查只采用第一条匹配的本地规则，不会对所有规则逐一替换。个人规则弹窗目前会将优先级 `0` 保存为 `100`，请使用正整数并核对保存结果。
4. 需要批量修改时，只选择自己的私有规则，再使用批量编辑、启用、关闭或放行观察。批量编辑仅修改勾选的字段。混选系统规则后，个人页面不提供批量操作按钮，不会自动跳过系统规则。

系统规则不能在个人页面编辑正文或删除；行开关仅保存自己的启用例外，不修改其他用户。系统已关闭的规则不会出现在个人规则列表中，个人例外不能重新启用它。

**当前版本限制：私有规则显示为关闭时，执行检查仍可能使用该规则。** 如需确保停用某条私有规则，请先导出备份，再删除该规则，并用新的测试请求确认。删除后页面不提供恢复入口；不要只凭行开关或 CSV 中的 `enabled=false` 判断私有规则已停止匹配。

匹配前会规范化 Unicode、移除部分零宽及控制字符并合并空白，匹配不区分大小写。规则替换只尝试替换原文中的第一个匹配片段为 `[REDACTED]`；规范化后的命中也可能无法在原文中直接替换。多个敏感片段、不同规则以及 AI 的替换结果不会自动合并清理，因此 `blackhole` 不能作为完整脱敏保证。替换导致结构化请求或响应无法解析时，请求仍可能被阻断。

## AI 审计、费用与流式响应

AI 审计与本地规则分别执行；本地命中不会省去审计调用。费用按管理员配置的每百万输入、输出 token 单价计算：`(输入 token × 输入单价 + 输出 token × 输出单价) / 1000000`。模型未提供用量时，服务可按文本长度估算；审计放行也可能产生费用，并计入中转用量结算。

缺少渠道参数、文本超过审计长度上限、超时、调用失败或审计结果格式无效时，按审计失败处理，默认产生阻断结果，再受最大动作约束。部分失败会记录估算 token 和费用，即使没有向审计模型实际发出请求。不要把“未调用上游”“未返回回答”或“没有 AI 命中记录”视为零费用证明；阻断路径仍可能结算审计费，以实际用量和账单为准。

| 响应方式                     | 用户可观察到的行为                                                                                                           |
| ---------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| 非流式响应                   | 收到响应后检查；阻断时不返回该响应，替换后的结构化内容须仍可解析。                                                           |
| 开启响应 AI 审计的流式响应   | 先收集完整文本流，再执行检查，通过后才发送响应头和正文；会增加等待时间，并受服务端流缓冲和帧容量限制。                       |
| 未开启响应 AI 审计的流式响应 | 按流帧做本地检查，并结合相邻帧检查；不是完整响应的一次性审计。后续阻断无法撤回已发出的内容，也不能保证识别跨越更多帧的模式。 |

长响应还可能超过 AI 文本长度上限而审计失败。不要通过反复重试验证是否免费；先检查命中记录、用量明细和当前审计配置。

## 导入和导出规则

导出 JSON 可查看当前作用域的策略与规则，CSV 用于规则迁移。导出不局限于当前表格页，也不包含 API Key、令牌凭据、命中原文或完整请求响应。个人导出可包含系统规则，不能将这些系统规则直接作为私有规则覆盖导入；JSON 不提供页面内的一键恢复流程。

1. 准备 UTF-8 CSV，文件不超过 1 MiB，至少包含表头及一行规则。必需列为 `name,type,pattern,direction,action`；可选 `id,enabled,priority`。缺省启用，缺省优先级为 `100`。下例仅用于放行观察：

   ```csv
   name,type,pattern,direction,action,enabled,priority
   Example observation,literal,example-marker,request,allow,true,100
   ```

2. 点击导入 CSV，检查预览中的新增、更新和错误。有校验错误时不会应用任何规则。
3. 按需选择“覆盖已有规则”，确认导入。按 ID 或“类型 + 方向 + 规范化内容”匹配已有规则；不覆盖时只新增。勾选覆盖不会刷新预览，实际应用使用确认时的选项，预览更新数量可能与最终更新数量不同。
4. 重新查看规则并发送测试请求。规则导入不修改策略或 AI 开关，CSV 外的规则也不会被删除。

管理员的默认词库导入可重复执行，只补充缺失的默认规则。当前默认基线仅匹配完整 PEM 私钥材料；一般工具定义、系统提示词、代码、命令和配置路径本身不构成该默认规则的阻断条件。升级不会自动清理历史规则；调整历史系统词库时可保留规则 ID，设置 `enabled=false` 后预览并覆盖导入。AI 审计仍可能独立命中，不应发送完整真实凭据作测试。

## 查看命中记录与通知

展开“我的命中记录”，按时间、请求 ID、令牌名称、渠道名称、方向、来源和处理状态筛选。文本筛选输入后按回车或点击筛选；日期、方向、来源和状态变更会立即查询。筛选及排序回到第一页，表内“刷新”保留当前页码和条件。可按时间、请求 ID、状态码排序，并在“列设置”显示审计模型、token、耗时和费用；列选择保存在当前浏览器，个人与系统表分别保存。

记录以命中项计数，同一次请求可能产生多条规则和 AI 记录。AI 放行不一定生成 AI 命中记录，记录费用也不是整次请求账单。表内片段是有限上下文，不是完整原文；规范化匹配或 AI 命中时可能没有片段。令牌、渠道以及规则背景名称可能反映当前名称。加载失败时旧记录可能仍显示，请确认刷新成功。

修改系统策略只产生操作审计，不因此发送内容安全邮件。用户订阅 `content_safety_blocked` 且最终动作为 `unreachable` 时，才按订阅、冷却时间和邮箱配置尝试通知；放行和替换不会发送该事件。没有收到邮件不证明没有发生阻断。

## 维护系统策略

管理员在“系统内容安全”的策略区域配置请求与响应设置，以及 AI 上游地址、模型、密钥、协议、超时、输入输出单价和文本长度上限，点击该区域的“保存”提交。支持 OpenAI Chat Completions、Anthropic 和 Gemini 审计协议；超时范围为 1000～30000 毫秒，文本长度范围为 1000～100000 个字符。默认超时为 5000 毫秒、文本长度上限为 16000，实际以当前配置为准。

密钥留空表示保留已保存值；输入新值并保存会替换，保存成功后输入框清空，仅显示已配置标记。清空已保存密钥需要 API 的明确清空选项，页面没有对应按钮。策略区域的刷新也会重载规则，命中表须单独刷新。系统规则的编辑、导入和批量操作独立保存，并可能触发二次验证。

## 系统策略读取的资源权限

IAM 强制模式下，系统配置的读取与更新、规则列表和规则导出分别使用以下 Action：

| 操作         | Action                                    | 资源                                                   |
| ------------ | ----------------------------------------- | ------------------------------------------------------ |
| 读取系统配置 | `quyan:content_safety:GetSystemConfig`    | `acs:platform:*:platform:content-safety-config`        |
| 列出系统规则 | `quyan:content_safety:ListSystemRules`    | `acs:platform:*:platform:content-safety-rule/<ruleId>` |
| 导出系统规则 | `quyan:content_safety:ExportSystemRules`  | 同上，可指定规则或使用 `content-safety-rule/*`         |
| 更新系统配置 | `quyan:content_safety:UpdateSystemConfig` | `acs:platform:*:platform:content-safety-config`        |

配置更新为原子操作：授权变化或配置冲突会拒绝整次更新。省略 AI API Key 时保留已有值，替换时加密保存；同时提供替换值和清空选项时，清空优先。更新响应描述已保存的配置，仅返回密钥是否已配置的标记。

通用配置 API 访问这些字段时，也须取得对应的内容安全读取或更新 Action；内容安全资源上的 Deny 同样约束通用配置流程。

操作者仍须属于具有系统配置管理资格的有效全局组。账户策略不能自行赋予这种管理资格；角色会话使用角色本身的 Allow，匹配的显式 Deny 优先。

系统规则列表先检查每个资源，再分页；总数只包含获准规则。系统读取范围只包含系统规则，用户私有规则通过对应的用户规则流程查看。没有匹配 Allow 时列表可以为空，未获准规则的正文不会被读取或导出。

JSON 导出包含系统配置，因此还需独立的配置读取权限。CSV 只包含规则，不需要配置读取权限。配置响应和导出不会返回 API Key，只提供是否已配置的标记。读取期间策略、规则内容、资源归属或配置发生变化时，请求会被拒绝，避免返回混合状态的结果。

`legacy` 和 `shadow` 保留原系统配置权限检查和返回范围；shadow 比较新的资源检查，但不改变旧结果。添加一条指定资源的 Allow 不会自动移除已有的宽泛 Allow，限制范围时还需检查主体的其他策略和组权限。

## 系统规则写入与资源范围

IAM 强制模式将创建、更新、删除和批量更新分别映射为 `quyan:content_safety:` 下的 `CreateSystemRule`、`UpdateSystemRule`、`DeleteSystemRule` 和 `BatchUpdateSystemRules`。这些操作仍要求系统配置管理资格、二次验证和重放保护。

创建规则须同时获得 `acs:platform:*:platform:content-safety-rule-control` 和服务端生成的实际 `acs:platform:*:platform:content-safety-rule/<ruleId>` 的 Allow；仅允许控制资源不足以创建规则。更新和删除检查目标规则，批量更新逐个检查所有 ID，拒绝重复 ID。任何目标被拒绝、不存在或属于用户私有规则时，整批失败，不会部分修改。私有规则使用用户规则流程。

规则写入是原子操作。完成前身份、组归属、授权或目标内容发生变化时，操作被拒绝并回滚。删除会停用规则并将其移出有效规则集；IAM 强制模式的系统规则写入保留优先级 `0`；个人规则弹窗的限制见前文。

系统与私有规则共用 500 条未删除规则和 1 MiB 匹配内容预算，已关闭但未删除的规则也占用容量。写入不能使某一维度新增超限；已有数据超限时，仍允许不恶化该维度的修复操作和删除。

## 导入授权

IAM 强制模式下，CSV 导入使用 `quyan:content_safety:ImportSystemRules`，默认词库导入使用 `quyan:content_safety:ImportDefaultSystemRules`。两者均须取得规则控制资源、使用的已有规则，以及应用时实际生成的每个规则 ID 的权限。

CSV 预览仅返回获准系统规则的旧值。显式指定的 ID 若属于私有规则、不存在或被拒绝，请求会被拒绝，不能用于探测其他规则。预览和含校验错误的导入不写入；关闭覆盖时已有规则保持不变，覆盖默认规则仍保留其默认来源。

应用为原子操作：目标或新资源被拒绝、规则集或授权变化，以及共用容量超限，均会回滚全部写入。默认导入可重复执行，并检查已有默认规则；用户私有副本不视为已安装的系统默认规则。legacy 和 shadow 保留一次旧流程导入，shadow 检查实际创建的 ID。

## 系统命中记录范围

IAM 强制模式下，`quyan:content_safety:ListSystemIncidents` 控制每个 `acs:platform:*:platform:content-safety-incident/<incidentId>`。先逐记录授权，再分页和计数；只有获准记录计入总数并返回匹配片段。原有筛选和排序仍可使用。操作者须保留系统配置管理资格，角色会话须具有自己的策略 Allow。

关联规则的名称与类型用于说明命中背景；读取有效系统规则的当前匹配内容，还须具备该规则的 `ListSystemRules` 权限。被拒绝、私有或已停用规则的匹配内容不返回，页面可显示规则 ID。Token 和渠道名称可作为背景信息显示，但不会返回凭据。读取期间相关记录正文、规则、背景名称或授权变化时，请求会被拒绝。

API 日期仍为 ISO 时间戳，命中记录费用为十进制字符串。legacy 和 shadow 保留原系统记录范围，shadow 比较 IAM 结果但不改变旧响应。
