# OJ API Key 管理

OJ API Key 用于让提交器调用 OJ 问答接口，并使用 Key 所属用户的余额结算。此页管理当前登录用户自己的 Key，不用于管理其他用户，也不能用 OJ Key 登录后台或替代账号访问密钥、中转令牌。

## 使用前提

进入页面需要 `OJ_APIKEY_READ`；创建、编辑和删除分别需要 `OJ_APIKEY_CREATE`、`OJ_APIKEY_UPDATE`、`OJ_APIKEY_DELETE`。IAM 强制模式按下文的动作和资源分别授权，按钮可见不代表操作一定获准。

创建和删除需要按提示完成二次验证及请求保护。选择绑定渠道还要求渠道当前可供该用户使用；渠道选项有独立的读取权限，Key 列表加载成功不代表渠道下拉列表也已加载成功。

## 创建并保存 Key

1. 单击创建 API Key，填写便于识别用途的名称，最多 100 个字符。
2. 按需选择到期时间和渠道。到期时间留空表示不过期；若设置到期时间，请选择未来时间。
3. 确认后完成系统要求的验证。
4. 在创建成功弹窗中复制新凭据，保存到提交器的安全配置。复制失败时，可手动选择只读文本框中的内容。
5. 使用实际请求验证新 Key，并在列表中核对到期时间、渠道和用量。

**创建成功会返回本次新生成的凭据；再次读取已有凭据则需要独立的披露权限。** 不要假设关闭弹窗后一定还能复制，也不要将只有读写管理权限的用户视为一定无法获得其新建的 Key。若成功弹窗内容异常为空，先核对创建结果，避免反复创建；不能将空值作为凭据使用。

未选择渠道时使用部署的默认上游配置。选择渠道并不保证所有模型可用：请求需要有效定价、足够余额，以及可用上游。绑定渠道或池的实际候选还须支持 Anthropic 格式，并允许请求的模型；隐藏渠道和自动代理池不能直接作为此类业务绑定。

## 在提交器中使用

将 API 基础地址和新 Key 填入提交器配置。此处是 OJ 接口的服务地址，不能直接拿管理站或 Relay Base URL 代替。下面的变量须由调用者设置为实际值，模型也须替换为当前部署已定价且可用的模型。

```bash
curl "${API_BASE_URL}/v1/products/oj-submitter/ask" \
  -H "X-API-Key: ${OJ_API_KEY}" \
  -H "Content-Type: application/json" \
  -d '{"question":"请解释这道题的解法","model":"your-enabled-model","maxTokens":256}'
```

问题去除首尾空白后须为 1～10000 个字符；`maxTokens` 是可选的输出上限，范围为 1～32000，默认 4096。成功后返回回答、Token 数和费用。请求会产生费用，按 [OJ 价格管理]({{DOCS_BASE_URL}}/zh-CN/oj-pricing-management)中的模型费率结算；余额检查或最终结算失败时，不会得到成功结果。

## 查看和编辑 Key

列表展示名称、掩码凭据、绑定渠道、累计请求数、累计 Token、最后使用时间及到期时间。过期 Key 仍可能列在其中；页面没有搜索、分页、批量导出或自动刷新，重新进入页面可更新列表。

单击复制 Key 复制的是完整凭据，不是页面上的掩码。仅当响应返回凭据时才显示列表复制按钮；有披露权限时，列表可以再次返回完整 Key。页面掩码不能替代披露权限控制。

编辑操作使用当前列表值，不会先重新查询详情。保存前核对以下差异：

| 字段     | 保存行为                                         |
| -------- | ------------------------------------------------ |
| 名称     | 填新名称可更名；留空会保留原名称                 |
| 到期时间 | 清空会取消原到期限制，不是保留原时间             |
| 渠道     | 清空或选择默认渠道会解除原绑定，改用默认上游配置 |

保存会同时提交到期时间和渠道；多人操作后应重新加载，避免用旧值覆盖新配置。编辑不会生成新凭据或重置用量。创建、编辑失败会保留表单输入，关闭对话框会清空表单；没有自动保存。

## 更换或删除凭据

1. 新建替代 Key 并安全保存。
2. 更新提交器配置，确认新 Key 可用。
3. 在旧 Key 行单击删除，核对目标并确认，完成要求的验证。
4. 重新查询，确认旧 Key 已从列表移除。

删除后旧 Key 不再通过新的凭据校验，没有恢复或撤销删除入口。不要依赖删除取消已经开始的请求；不要以清空到期时间代替吊销。删除也不会清除已结算用量或退还历史费用。

到期会使后续校验失败，但不会自动从管理列表移除记录；需要续用时可更新到期时间，更换凭据则应新建 Key。

## 用量和 IAM 范围

请求数、累计 Token 和最后使用时间在结算成功时更新，不统计所有尝试。Token 是输入与输出之和，不单列缓存 Token。按时间核对费用和请求明细请使用 [OJ 用量统计]({{DOCS_BASE_URL}}/zh-CN/oj-usage-statistics)，该页不能把单条记录归因到某个 Key。

IAM 强制模式下，各操作独立授权，且只管理当前用户拥有的 Key；扩大资源范围也不能越过归属检查。

| 操作             | IAM 动作                  | 资源                           |
| ---------------- | ------------------------- | ------------------------------ |
| 新建             | `quyan:oj:CreateApiKey`   | 当前用户资源                   |
| 列表             | `quyan:oj:ListApiKeys`    | 每个实际 Key                   |
| 详情             | `quyan:oj:GetApiKey`      | 目标 Key                       |
| 再次披露已有凭据 | `quyan:oj:RevealApiKey`   | 目标 Key，还须获准相应读取操作 |
| 编辑             | `quyan:oj:UpdateApiKey`   | 目标 Key                       |
| 删除             | `quyan:oj:DeleteApiKey`   | 目标 Key                       |
| 统计接口         | `quyan:oj:GetApiKeyStats` | 纳入统计的每个 Key             |

当前用户资源为 `acs:quyan:*:<账号 ID>:user/<用户 ID>`，Key 资源为 `acs:oj:*:<账号 ID>:api-key/<用户 ID>/<Key ID>`。账号 ID 是所属主账号 ID，Key ID 是记录 ID，不是完整凭据。

列表只返回获准记录，详情权限不替代列表权限，读取元数据也不自动授予披露权限。编辑响应中的已有凭据同样受披露权限控制；新建时返回新凭据属于签发结果。统计接口只汇总获准、未删除的 Key；其累计数可能随删除或授权变化而减少，不是完整历史账单，页面本身没有这组汇总卡片。

管理接口使用登录认证，不接受第三方 OAuth 访问令牌。角色会话按角色授权，匹配的 Deny 优先；启用状态、身份、授权或目标记录在操作期间变化可能导致拒绝。不存在、已删除、越权的目标在强制模式下会被拒绝，不能通过更换 URL 中的 ID 管理他人 Key。

## 常见问题

| 现象                            | 处理方法                                                   |
| ------------------------------- | ---------------------------------------------------------- |
| 看得到 Key 信息，却没有复制按钮 | 检查已有凭据的披露权限；不能从掩码还原凭据                 |
| 新建后列表找不到记录            | 检查列表授权并重新查询，不要仅凭列表不可见重复创建         |
| 渠道选项为空或加载失败          | 重新进入页面，核对独立渠道读取授权及渠道可用范围           |
| 编辑后 Key 值没变               | 编辑只更新名称、到期时间和渠道；轮换需新建 Key             |
| 保存或删除成功后提示加载失败    | 操作可能已完成，先重新查询结果再重试写入                   |
| 加载失败后仍显示旧列表          | 旧结果不会自动清除，成功刷新后再据此操作                   |
| Key 无法调用                    | 检查完整凭据、到期时间、余额、模型定价及渠道格式和模型限制 |
