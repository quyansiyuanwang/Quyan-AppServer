# 上游状态

在 AI 管理站的**上游状态**查看已配置监控的当前状态、在线率和最近心跳，用于判断转发异常是否与上游可用性有关。本页只读，不提供新增监控、切换渠道或修改限流的操作。

## 开始前

需要上游状态读取权限，且管理员已在[转发设置]({{DOCS_BASE_URL}}/zh-CN/relay-settings)中配置监控源或静态数据。页面只展示配置及权限允许的监控，不代表所有渠道或模型的实时可用性。

IAM 强制模式还要求部署管理全局组资格及资源授权，详见下文。无法打开页面时，先请管理员核对权限。

## 查看最新状态

1. 打开**上游状态**，等待加载完成。页面会测量本次用户到服务端的延迟，再读取监控数据。
2. 查看总览提示，再按分类找到相关监控项。
3. 将鼠标移到心跳条上，查看该次心跳的正常或异常状态、时间和延迟。窄屏下心跳条区域可以横向滚动。
4. 排查过程中点击**刷新**重新获取数据。页面只在进入和手动刷新时加载，不会自动轮询。

总览显示“所有服务运行正常”时，只表示可见监控的当前状态均为正常；出现“部分服务出现问题”时，至少有一个可见监控不正常。它不根据在线率百分比判断，也不保证你的具体转发请求一定成功。

## 理解指标

| 指标             | 含义与边界                                                                               |
| ---------------- | ---------------------------------------------------------------------------------------- |
| 总览状态         | 汇总可见监控的当前状态；使用监控源时取各项最新心跳，没有心跳按异常处理                   |
| 在线率           | 监控源提供最近 24 小时的比例；静态数据使用配置值。百分比不等于当前状态                   |
| 在线率徽标颜色   | 95% 及以上为绿色，80% 至不足 95% 为警示色，低于 80% 为红色                               |
| 心跳条           | 绿色表示该次心跳正常，红色表示异常；最多展示最近 100 条，覆盖时长由监控源采样间隔决定    |
| 上游延迟         | 对应那一次心跳记录中的延迟，并非浏览器到模型接口的完整请求耗时                           |
| 用户到服务端延迟 | 本次页面加载或刷新时的测量值，所有历史心跳提示中共用；不是历史网络延迟，失败时显示 `N/A` |

右端“现在”是图表标签，请以心跳提示中的时间判断数据是否新鲜。最新心跳可能已经过期，历史正常也不能证明此刻仍可用。在线率缺失时可能显示为 0%，需结合心跳和监控源确认。

### 静态备用数据

配置了监控源时，系统优先读取它；读取失败且配置了静态数据时，使用静态数据作为备用。静态数据也可以单独使用。

页面不会标明当前是否正在使用备用数据。刷新成功只能说明本次获得了可展示的数据，静态状态、在线率和心跳不一定反映当前服务。需要实时结论时，请管理员核对监控源及数据时间。

## 排查异常

| 现象                       | 下一步                                                                                              |
| -------------------------- | --------------------------------------------------------------------------------------------------- |
| 总览异常                   | 找到异常监控，核对最近心跳时间和延迟，再结合实际请求错误排查                                        |
| 在线率很高但当前异常       | 在线率是历史比例，以最新有效心跳及实际请求结果判断当前情况                                          |
| 总览正常但转发仍失败       | 核对请求使用的模型、Token、额度和渠道，并查看[AI 请求日志]({{DOCS_BASE_URL}}/zh-CN/ai-request-logs) |
| 显示错误或刷新失败         | 检查网络、权限及监控配置，重试刷新；旧总览可能仍保留，不应当作最新结果                              |
| 成功加载但没有监控         | 可能没有可见监控、被“仅展示已配置”过滤或无权查看具体监控，请管理员确认                              |
| 心跳时间很旧或延迟为 `N/A` | 核对监控源更新时间；延迟缺失不等于 0，也不单独证明服务正常或故障                                    |

没有配置任何可用数据源时，可能显示加载错误，而不是正常的空列表。无法据此判断上游已恢复。

## 访问条件与资源范围

旧权限模式要求 `UPSTREAM_STATUS_READ`。IAM 强制模式使用 `quyan:relay:GetUptimeStatus`，还要求当前身份属于有效的部署管理全局组，且该组具有 `UPSTREAM_STATUS_READ`。个人附加权限、私有组或账号所有者身份不能替代这一资格。此接口使用登录身份，不接受 OAuth 访问令牌。

| 授权对象     | 资源                                                     |
| ------------ | -------------------------------------------------------- |
| 读取监控集合 | `acs:platform:*:platform:relay-uptime-control/default`   |
| 读取指定监控 | `acs:platform:*:platform:relay-uptime-monitor/<监控 ID>` |

先授权集合，再按具体监控过滤；仅返回获准监控及其分类。显式 Deny 优先于 Allow，因此总览也只覆盖可见监控。此 Action 不授予转发配置编辑、模型价格或并发状态读取权限。

管理员为指定监控编写策略时，应使用接口返回的 ID。监控源提供的 ID 保持不变；未指定 ID 的旧静态监控使用由分类名和监控名生成的 `static_<SHA-256>` ID，修改名称会改变资源标识。显式 ID 须以字母或数字开头，只含字母、数字、点、下划线或连字符，最多 200 字符；重复或不安全的 ID 会被拒绝。

读取不会创建配置。请求期间资格、策略、有效角色会话、配置或授权条件变化可能使请求失败，请刷新重试。存储故障不会作为成功的空列表返回。

## 管理员与 API 用户：读取并发状态

`GET /v1/relay-config/concurrency-status` 返回当前并发及排队采样，**上游状态页面不展示这些记录**。它使用独立 Action `quyan:relay:GetConcurrencyStatus`，要求登录身份；IAM 强制模式同样要求具有 `UPSTREAM_STATUS_READ` 的有效部署管理全局组资格。

| 授权对象           | 资源                                                        |
| ------------------ | ----------------------------------------------------------- |
| 读取并发集合       | `acs:platform:*:platform:relay-concurrency-control/default` |
| 指定用户的普通并发 | `acs:platform:*:platform:relay-concurrency-user/<用户 ID>`  |
| 全局图片并发池     | `acs:platform:*:platform:relay-concurrency-scope/image`     |

仅返回获准记录。指定 `userId` 时，用户须有效且其资源获准；这不会自动授予图片池权限。图片池单独授权，即使指定用户，也可能同时返回获准的全局图片池记录。显式 Deny 优先。

IAM 强制模式支持以下分页：

- `page` 从 1 开始，最大 10000；`pageSize` 默认 50，最大 100。
- `items` 为本页获准的聚合记录，`total` 是全部获准聚合记录数，不是请求次数。
- `totals` 汇总全部获准记录，不只本页；`hasNext` 表示是否还有下一页。
- 旧权限及影子模式保留原响应行为，不应假设也按这些字段分页。

采样期间已过期的租约不计入活动记录，分页请求之间也可能因流量变化而改变。并发统计后端不可用时返回 503，不以成功的零值代替。读取不会创建配置；资格、策略、会话、用户归属或配置在请求期间变化时可能失败。
