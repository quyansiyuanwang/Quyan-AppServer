# 权限管理

访问控制按职责拆为概览、身份管理和权限管理。权限管理页面用于查看用户权限摘要，并调整用户级覆盖项。实际请求是否获准还取决于授权模式和请求上下文。

## 页面用途

- 查看某个用户的权限来源。
- 区分群组权限、额外权限和移除权限。
- 对特定用户进行细粒度权限调整。

## 你会看到什么

### 用户列表

- 用户名和所属群组。
- 按关键字、群组和 RAM 用户开关筛选的分页列表。
- 当前操作者不会出现在列表中；刷新会清除筛选并返回第一页。

### 授权

- 仅处理用户级额外授予和移除项。
- 需要 `PERMISSION_ADD` 或 `PERMISSION_REMOVE` 才能编辑。

### 权限策略

- 生效权限。
- 来自群组的权限。
- 单独增加的权限。
- 单独移除的权限。

### 权限诊断

- 与权限策略页展示相同的权限摘要，包括群组、用户级增加和移除项。
- 有助于检查这些来源，但不是针对具体资源和请求条件的完整授权诊断。

### 编辑动作

- 打开用户权限编辑窗口。
- 分类查看权限。
- 按分类或关键字查找权限项。

## 常见操作

1. 先找到目标用户。
2. 在权限策略或权限诊断中确认权限是从哪里来的。
3. 如需特殊授权，再使用用户级增加权限。
4. 如需限制某项能力，再使用用户级移除权限，并保存。清空自定义权限会同时清除用户级增加和移除项，恢复群组对应的基础选择；这可能重新授予此前移除的能力。

## 所需权限

| 操作                 | 所需权限                                         |
| -------------------- | ------------------------------------------------ |
| 查看群组权限         | `PERMISSION_VIEW`                                |
| 为用户或群组添加权限 | `PERMISSION_ADD`                                 |
| 移除用户的权限       | `PERMISSION_REMOVE`                              |
| 清空用户的权限覆盖项 | 同时需要 `PERMISSION_REMOVE` 和 `PERMISSION_ADD` |

已启用 2FA 的操作者修改群组权限时可能需要二次验证；有效的受信任窗口可按当前安全规则通过。

## 说明

- 非 IAM 强制模式下，权限摘要可包含群组、用户级覆盖和角色绑定的影响。IAM 强制模式下，摘要中的有效权限是针对账户资源的策略投影；具体资源、条件、显式 Deny 和角色会话可能产生不同结果，不能只凭此列表断定实际请求一定获准。
- 排查"看得到但不能用"或"本不该看到却看到了"的问题时，此页非常关键。
- 建议与群组管理页配合使用，避免在用户级做过多长期例外。
