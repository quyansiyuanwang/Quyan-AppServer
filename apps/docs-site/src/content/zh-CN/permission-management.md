# 权限管理

权限管理用于查看用户权限来源，以及维护用户级增加、移除项。长期共用的权限应在[群组管理]({{DOCS_BASE_URL}}/zh-CN/group-management)中维护；角色、JSON 策略和授权绑定请到 [RAM 管理]({{DOCS_BASE_URL}}/zh-CN/ram-management)。

## 选择页面与准备权限

访问控制下的三个页面共用用户列表，但用途不同。

| 页面     | 用途                                                         |
| -------- | ------------------------------------------------------------ |
| 授权     | 编辑用户级权限覆盖项                                         |
| 权限策略 | 查看权限数量和来源列表，不编辑策略文档                       |
| 权限诊断 | 查看同一份来源摘要，不提供指定动作、资源和请求条件的完整诊断 |

进入这些页面需要 `PERMISSION_VIEW`。加载用户目录还需 `USER_READ`，群组筛选选项依赖 `GROUP_READ`。能看到用户不代表可以读取或修改其权限。

| 操作                   | 权限条件                                         |
| ---------------------- | ------------------------------------------------ |
| 查看其他用户的权限摘要 | `PERMISSION_VIEW`，并满足目标资源的授权范围      |
| 增加或恢复用户能力     | `PERMISSION_ADD`                                 |
| 移除用户能力           | `PERMISSION_REMOVE`                              |
| 同时增加和移除能力     | IAM 强制模式下同时需要上述两项                   |
| 清空用户级覆盖项       | 同时需要 `PERMISSION_ADD` 和 `PERMISSION_REMOVE` |

legacy/shadow 模式下，页面的完整保存接口还要求 `PERMISSION_ADD`；即使能打开编辑窗口，仅有移除权限也不能通过该接口保存。不要仅根据按钮可见性判断权限是否足够。

保存和清空覆盖项都要求重放保护。操作者已启用 2FA 时可能需要二次验证，有效的受信任窗口按当前安全规则处理。

## 查找目标用户

1. 输入关键词后按 Enter，或选择群组、切换“显示RAM角色”。关键词可匹配用户名、RAM 用户名、姓名、邮箱或用户 ID 的部分文字。
2. 核对目标用户名和所属群组。当前操作者不会出现在列表中；默认也不列出 RAM 子用户。
3. 使用分页继续查找。默认每页 10 条，搜索或调整每页数量会返回第一页。

“显示RAM角色”按用户增加项或群组权限中是否包含 RAM 权限筛选，也会取消默认的 RAM 子用户排除条件。它不是按角色身份或最终生效权限筛选：某项 RAM 权限即使被用户移除，也可能仍使用户符合该筛选。

刷新会清空关键词、群组和 RAM 筛选，并返回第一页；不会重新加载群组选项。群组下拉框缺少选项时，可以清空群组条件继续按关键词搜索。IAM 强制模式下，该下拉框只加载群组接口默认页，不代表全部群组。

列表没有自动刷新或导出。加载失败时旧记录和总数可能保留，请重新查询后再选择目标。

## 查看权限来源

在权限策略或权限诊断页面，找到用户后单击查看来源。弹窗显示以下四组数量和权限项。

| 来源     | 含义                       |
| -------- | -------------------------- |
| 生效权限 | 当前接口计算出的权限摘要   |
| 群组权限 | 用户所属群组配置的基础权限 |
| 额外权限 | 针对该用户单独增加的权限   |
| 移除权限 | 针对该用户配置的移除项     |

普通群组与用户覆盖项可按“群组权限 + 额外权限 − 移除权限”理解。角色、策略绑定还可能提供其他来源，因此前三类来源不能总是完整解释摘要中的每一项。

IAM 强制模式下，生效权限是针对**账户资源**计算的策略投影。具体资源、条件、显式 Deny 和角色会话可能改变实际结果；摘要中有某项，不代表所有对应请求都会获准，摘要缺少某项也不代表其对所有具体资源都被拒绝。查看来源不是一次实际业务请求的授权测试。

详情加载失败时，弹窗可能保留上一位用户的内容，即使标题已经切换。请关闭后重新打开，确认加载成功且目标正确，不要根据失败后的旧内容作授权决定。

## 调整用户级权限

1. 在授权页面找到用户并单击编辑。成功读取权限后才会打开编辑窗口。
2. 核对用户名、群组基础数量、增加和移除数量。
3. 按分类或关键词查找权限，勾选希望保留的项，取消勾选要限制的项。
4. 单击保存，按提示完成验证。保存后重新打开，核对覆盖项，并用目标用户的实际业务请求确认效果。

编辑器初始选择由群组、用户增加项和移除项计算，**不完整纳入角色与 JSON 策略的生效结果**，因此可能与查看来源中的生效权限数量不同。保存按当前选择重新计算并替换两组用户覆盖项：选中但不在群组中的权限成为增加项；群组中未选中的权限成为移除项。它不会修改群组或直接改写 RAM 策略，也不能承诺撤销来自其他策略的所有授权。

搜索只过滤展示，不会清除其他选择。工具栏的全选、清空选择作用于权限树中的可选项，不只作用于当前搜索结果；清空选择后保存可能移除大量群组基础权限。它与下文的“清空自定义权限”是不同操作。

服务端按变更方向校验增加、移除权限，还会校验新增及保留的增加项是否在操作者可委派范围内。IAM 强制模式下，恢复此前移除的权限也视为增加访问，需要相应授权和委派能力。可勾选不代表一定能保存。

保存失败会保留当前选择，取消会放弃未提交修改；没有自动保存或撤销历史。若提示并发变化，关闭后重新加载再修改。保存成功后重新读取摘要也可能失败，应再次核对，不要立即重复保存。

## 清空自定义权限

如需移除该用户的全部例外，在编辑窗口单击清空自定义权限，核对目标后确认。它会立即提交清空操作，不需要再单击保存；未保存的勾选修改不会作为清空结果提交。

此操作同时清除用户增加项和移除项：既会撤掉单独增加的能力，也可能**恢复此前通过移除项限制的能力**。它不删除群组权限、角色或 JSON 策略绑定。IAM 强制模式下，恢复访问还需通过委派检查。

清空提交后重新读取失败，可能显示操作失败，但覆盖项已经清空。应关闭后重新查看来源，确认实际状态再决定下一步。

## 等级与 IAM 边界

不能通过这些变更接口修改自己的权限。目标用户的群组等级数值必须严格大于操作者；数值越小层级越高。例如等级 20 的操作者不能修改等级 20 或 10 的用户。这项用户权限检查没有群组管理页面中的超级管理员等级豁免。

IAM 强制模式下，用户目录与用户权限使用不同资源授权。

| 用途           | IAM 动作                  | 资源                                                                                |
| -------------- | ------------------------- | ----------------------------------------------------------------------------------- |
| 用户目录       | `quyan:user:ListUsers`    | `acs:platform:*:platform:user/<用户 ID>`，并要求真实部署全局组中的 `USER_READ` 资格 |
| 查看权限摘要   | `quyan:permission:Manage` | `acs:quyan:*:<accountId>:user/<用户 ID>`                                            |
| 增加或恢复访问 | `quyan:permission:Add`    | 同上，目标用户资源                                                                  |
| 移除访问       | `quyan:permission:Remove` | 同上，目标用户资源                                                                  |

用户目录按目录读取规则和等级过滤，并只统计获准记录；它可以包含停用用户，但停用、跨账户或其他未获准目标的权限摘要仍可能无法打开。权限变更不允许跨账户，子用户不能修改主账户的恢复权限范围。角色会话按其授权和条件评估，显式 Deny 优先。
