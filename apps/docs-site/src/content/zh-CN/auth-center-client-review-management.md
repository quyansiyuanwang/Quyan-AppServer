# 认证中心应用审核

平台审核人员在此查找认证中心应用、通过或拒绝申请，或删除不再允许使用的应用。维护自己的应用请使用[认证中心应用管理](/zh-CN/auth-center-client-management)。

## 使用前提

- 页面和列表读取需要 `auth_center:client:review:read`；通过、拒绝及审核端删除需要 `auth_center:client:review:update`。
- 启用 IAM 强制授权时，读取要求用户属于实际的平台全局管理组，且组包含审核读取权限；审核或删除要求该组包含审核更新权限。账户所有者、附加权限或账户自建组不能单独提供平台审核资格。
- 还需对审核资源分别获准执行 `quyan:auth_center:ListClientReviews`、`quyan:auth_center:ReviewClient` 和 `quyan:auth_center:DeleteReviewedClient`。资源为 `acs:platform:*:platform:auth-center-review-client/<recordId>`；末尾是应用记录 ID，不是公开 Client ID。
- 显式拒绝和角色会话限制仍然生效。列表条目和总数只包含有权查看的应用；列表权限及自有应用的维护权限不能代替审核或审核端删除权限。OAuth 访问令牌不能调用审核接口。

## 查找申请

1. 选择 `pending` 查看待审核申请，也可按其他状态查找草稿或历史记录。
2. 输入应用名称、所有者用户名或 Client ID 关键字，按 Enter 或单击搜索。仅输入文字不会自动查询。
3. 核对列表中的名称、所有者、Client ID、客户端类型、授权类型、回调摘要、提交及审核时间。

搜索、清空关键字和切换状态会回到第一页。默认每页 20 条，可选 10、20、50 或 100 条，切换每页数量也回到第一页。刷新保留当前页，不会自动轮询。结果按提交时间升序、创建时间降序排列。

## 核对接入资料

列表最多显示前两个回调地址，其余只显示数量。审核弹窗只有决策和审核意见，不展示完整回调、Scope、令牌有效期或 PKCE。审核前向所有者核对未展示的信息，再决定是否通过。

| 检查项         | 核对内容                                                                         |
| -------------- | -------------------------------------------------------------------------------- |
| 客户端类型     | 机密应用是否有可信后端保管密钥；公开应用不应依赖内置密钥                         |
| 授权类型       | 用户流程启用授权码，需刷新时同时启用刷新；机器调用仅机密应用可用                 |
| 回调与授权界面 | 地址归属受控、环境明确、与实际请求精确匹配；部署已提供对应授权界面               |
| Scope          | 申请范围满足业务所需且最小化，不能把可申请范围当作用户已经同意                   |
| PKCE           | 公开应用的授权码流程必须启用；确认接入方使用同一次尝试的 S256 challenge/verifier |
| 有效期和撤销   | 刷新有效期不短于访问有效期，接入方理解本地 JWT 验证无法实时感知撤销              |

表单和服务端会校验授权类型组合及有效期关系。审核仍需确认这些配置是否适合实际业务，不能只以保存成功作为通过理由。

## 通过或拒绝

1. 对 `pending` 记录单击通过或拒绝，核对弹窗中的决策。
2. 填写审核意见。意见可选，最多 2,000 个字符；拒绝时写明具体整改项，避免只写“资料有误”。
3. 提交后检查成功提示和刷新后的状态。所有者在应用管理页查看意见，按需修改并重新提交。

| 状态       | 可否通过或拒绝   | 说明                               |
| ---------- | ---------------- | ---------------------------------- |
| `draft`    | 不可             | 所有者尚未提交                     |
| `pending`  | 可以             | 通过前不可授权或兑换令牌           |
| `approved` | 不可再次直接审核 | 满足其他条件时可用于用户或机器授权 |
| `rejected` | 不可再次直接审核 | 等待所有者整改并重新提交           |

保存已通过或已拒绝的应用会回到草稿，清除原意见及审核信息，即使保存前没有修改字段也一样。待审核应用保存后仍为 `pending`，请审核最新资料。审核通过不会替代用户同意、Scope 校验或接入系统的业务授权。

提交成功后保留当前页，记录不再符合筛选条件时会消失。如提示应用、身份或授权已变化，应刷新核对，不要重复提交旧决策。

## 删除应用

删除操作移除的是应用本身，不是一条审核历史。各状态下都可能出现删除按钮，执行前与所有者协调停用和令牌处理，核对名称与 Client ID，再确认删除。

删除后应用从所有者及审核列表移除，不能再授权、兑换或刷新令牌。本页没有恢复入口。若删除后当前最后一页为空，请返回前一页查看。

**删除应用或撤销令牌不能让纯本地 JWT 验证立即感知变化。** 已签发 JWT 仍可能被接入系统接受至原有效期结束，现有访问需接入方的会话及授权策略配合终止。不要把应用已从列表消失当作全部访问已停止的证明。

## 常见问题

| 现象                         | 处理方法                                                   |
| ---------------------------- | ---------------------------------------------------------- |
| 有页面入口但无法读取列表     | 请平台管理员核对全局组资格、读取权限及审核资源授权         |
| 能读取但不能通过、拒绝或删除 | 分别检查更新权限和审核或删除动作，不能使用自有应用权限代替 |
| 看不到完整资料               | 向所有者核对，审核弹窗不提供完整申请查看功能               |
| 通过或拒绝按钮未显示         | 仅 `pending` 可审核，等待所有者提交或重新提交              |
| 查询失败后仍有旧记录         | 先排除错误并刷新，不要根据旧列表做决定                     |
| 提交失败，不确定是否已审核   | 刷新并核对状态、审核时间后再决定是否重试                   |
