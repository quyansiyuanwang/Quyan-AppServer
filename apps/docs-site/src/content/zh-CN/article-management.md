# 文章管理

此页面用于维护站内文章与知识内容。

## 页面用途

- 创建与编辑文章。
- 调整发布状态。
- 设置默认文章。
- 维护排序和分类。

## 你会看到什么

### 文章列表

- 标题、slug、分类。
- 是否发布、是否默认等标记。
- 拖拽排序提示。

### 编辑动作

- 新建文章。
- 编辑文章。
- 发布或取消发布。
- 设置或清除默认文章。
- 删除文章。

## 常见操作

1. 新建文章并填写标题、slug 和 Markdown 正文，可选填写分类和摘要。
2. 选择访问范围：公开文章在发布后可供未登录访客阅读；非公开文章可设置所需权限。
3. 在编辑器中预览并保存，再使用发布操作发布文章。
4. 需要首页默认展示时，将已发布文章设为默认；读者仍须满足该文章的访问条件。
5. 如需调整浏览顺序，可在桌面列表中拖动排序。

## 所需权限

| 操作                          | 所需权限          |
| ----------------------------- | ----------------- |
| 查看文章                      | `ARTICLE_READ`    |
| 新建文章                      | `ARTICLE_CREATE`  |
| 编辑、排序、设置/清除默认文章 | `ARTICLE_UPDATE`  |
| 删除文章                      | `ARTICLE_DELETE`  |
| 发布 / 取消发布               | `ARTICLE_PUBLISH` |

## 资源级管理列表

IAM enforce 模式下，管理列表使用独立的 `quyan:article:ListArticles`，逐篇授权当前账户中的文章元数据。可以指定单篇文章、文章 ARN 通配符或资源组，包含明确授权的同账户他人草稿。数据库先限制有效账户、作者和文章，再分批评估策略；未授权、显式 Deny、已停用、跨账户或授权后发生变化的文章不出现在结果中。没有可见资源时返回空数组，不代表获得了账户权限。

```json
{
  "Version": "1",
  "Statement": {
    "Effect": "Allow",
    "Action": "quyan:article:ListArticles",
    "Resource": "acs:article:*:account-id:article/article-id"
  }
}
```

请替换实际账户和文章标识。列表只返回元数据，不加载或返回正文，也不提供未过滤的全局总数。`quyan:article:Read` 的 JSON 策略不会隐含授权这一独立列表 Action；编辑、发布、删除和阅读接口仍有各自的规则。仅对账户 ARN 的授权不代表可以查看该账户的每篇文章。响应保持数组格式，服务端按有界数据库批次处理，并保留排序顺序。

文章自身设置的额外访问权限条件仍须满足。旧 `ARTICLE_READ` 在 enforce 模式下兼容为“本人草稿或已发布文章”的列表范围，不会自动授予查看他人草稿的能力；旧移除权限仍全局显式拒绝。legacy／shadow 模式保持原有权限和草稿检查，shadow 只比较结果，不替换旧授权。管理菜单仍使用独立的权限展示，资源级列表授权不等于全局菜单权限。

## 创建权限与账户范围

IAM enforce 模式下，新建文章使用 `quyan:article:Create`，授权资源为可信当前账户 `acs:quyan:*:<accountId>:account`。创建前尚不存在文章 ID，因此指定已有文章 ARN 的授权不会赋予创建权限，指定资源／资源组范围的授权也不会自动扩大为账户创建权限。

```json
{
  "Version": "1",
  "Statement": {
    "Effect": "Allow",
    "Action": "quyan:article:Create",
    "Resource": "acs:quyan:*:account-id:account"
  }
}
```

请替换实际账户标识。作者固定为当前执行用户，包括 AccessKey 和角色会话；角色会话只使用角色授权，不继承调用用户自己的创建权限。服务端仅接受标题、slug、分类、摘要、正文、公开设置和访问权限条件，新文章始终为草稿，不会由创建请求设置为全站默认文章或覆盖状态／计数。创建权限不包含后续编辑、删除、发布或默认文章管理权限。

slug 在全站唯一，包括已停用文章。公开文章不能同时设置非空访问权限条件。写入时会再次检查作者与账户的有效状态及归属；发生变化时请求拒绝，数据库并发冲突需刷新后重试。legacy／shadow 模式继续执行历史创建权限检查，输入字段隔离和草稿初始状态保持一致。

## 资源级发布授权

IAM enforce 模式下，发布与撤回共用敏感原生 Action `quyan:article:Publish`，目标为具体文章资源：

`acs:article:*:<accountId>:article/<articleId>`

可以授权管理同账户其他作者的文章，也可以限定资源组范围。即使策略使用通配符，其他账户的文章、已停用文章／作者／账户，以及非规范资源标识仍会被拒绝。显式 Deny 优先于 Allow；移除资源组成员后，下一次请求立即按新范围判断。

```json
{
  "Version": "1",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": "quyan:article:Publish",
      "Resource": "acs:article:*:account-id:article/article-id"
    }
  ]
}
```

请替换为实际账户与文章标识。仅指定账户 ARN 不代表授权账户下的文章。历史 `ARTICLE_PUBLISH` 权限保留账户级兼容范围；legacy／shadow 模式仍执行历史权限检查。

发布可能使已设为公开的文章可以匿名访问，确认前应检查正文、公开状态与访问限制。发布响应沿用完整文章 DTO，包含正文。写入前服务端再次检查有效归属及已授权的发布快照；状态或公开设置变化时，需要刷新后重新授权。该权限不代表可以新建、编辑、删除文章或修改全站默认文章。迁移期间，文章列表及菜单仍有独立权限要求；公开阅读行为不变。

## 资源级编辑与删除

enforce 模式下，`quyan:article:Update` 与 `quyan:article:Delete` 分别授权同一种具体文章 ARN。策略可以委派同账户其他作者的指定文章，也可以限定到资源组。服务端检查文章、作者及账户的有效状态，并在写入事务内再次复核已授权快照。跨账户资源、标识别名、显式 Deny、缺失策略及过期目标均安全拒绝。

编辑权限不代表可以发布、删除文章或管理全站默认文章；编辑响应包含完整文章 DTO。可编辑字段仅限标题、slug、分类、摘要、正文、公开状态与访问权限条件，请求不能替换作者、修改发布状态／默认设置，或覆盖状态与计数。将已发布文章改为公开可能使正文可以匿名访问；已有权限要求需要在同一次编辑中明确清空。slug 保持全站唯一，包括已停用文章。

删除仅使指定文章不可用，不会删除其他文章，也不会清除其他文章的默认标记。删除后，该文章立即不再符合资源组授权的有效资源条件。legacy／shadow 模式保留历史权限及仅作者可编辑／删除的规则，资源级委派在切换 enforce 后强制执行。迁移期间，列表与菜单权限仍独立判断。

旧权限迁移不会自动扩张编辑／删除范围：来自附加权限、用户组、旧策略绑定或历史回填版本的 `ARTICLE_UPDATE`／`ARTICLE_DELETE` 在 enforce 模式下仍只允许操作当前主体自己创作的文章。角色与 AssumeRole 会话中的旧策略同样按实际执行用户限制作者范围。若需要管理同账号内他人文章，应由有委派权限的身份明确发布资源级 JSON 策略；旧移除权限仍是全局显式 Deny。历史排序和发布不是作者限定权限，保持各自原有范围。仅拥有旧作者权限不能发布或转授不带作者条件的文章管理策略。

## 原子性的资源级批量排序

enforce 模式下，排序请求中的**每一篇**文章都必须具备 `quyan:article:ReorderArticles` 权限。服务端解析当前账户内所有已存储的文章标识，评估整批授权并复核每个已授权快照，随后在同一事务中写入全部排序变化。任何成员被拒绝、缺失、停用、跨账户或发生变化，整批操作都会失败；后续数据库写入失败时，之前的写入也会回滚。

每个文章 ID 只能提交一次，排序值必须是数据库整数范围内的非负整数。请求数量受服务端 IAM 批量上限约束（当前为 500 个资源）。资源组成员关系及可信请求条件对每个成员分别生效。仅包含编辑 Action 的 JSON 策略不授权这一独立能力；此前使用 `quyan:article:Update` 排序的策略草稿需要明确加入 `quyan:article:ReorderArticles`。迁移期间，历史 `ARTICLE_UPDATE` 字段仍映射到这两种能力。排序只改变顺序，不会修改作者、正文、公开设置、发布状态或默认选择。legacy／shadow 模式保留历史编辑权限检查；列表与全站默认文章管理仍是独立能力。

## 说明

- 文章阅读侧通常对应 `home-articles` 页面。
- 发布前建议检查目录结构、标题层级和关键链接。
- 默认文章通常会影响首次进入时的展示内容。
