# 文章管理

此页面用于维护站内文章与知识内容。

## 页面用途

- 创建与编辑文章。
- 调整发布状态。
- 设置默认文章。
- 维护排序和分类。

## 你会看到什么

### 文章列表

- 标题、slug、分类。
- 是否发布、是否默认等标记。
- 拖拽排序提示。

### 编辑动作

- 新建文章。
- 编辑文章。
- 发布或取消发布。
- 设置或清除默认文章。
- 删除文章。

## 常见操作

1. 新建文章并填写标题、slug、分类和正文。
2. 在编辑器中编写 Markdown 内容。
3. 预览无误后发布文章。
4. 需要首页默认展示时，可设置为默认文章。
5. 如需优化浏览顺序，可调整排序。

## 所需权限

| 操作                          | 所需权限          |
| ----------------------------- | ----------------- |
| 查看文章                      | `ARTICLE_READ`    |
| 新建文章                      | `ARTICLE_CREATE`  |
| 编辑、排序、设置/清除默认文章 | `ARTICLE_UPDATE`  |
| 删除文章                      | `ARTICLE_DELETE`  |
| 发布 / 取消发布               | `ARTICLE_PUBLISH` |

## 资源级发布授权

IAM enforce 模式下，发布与撤回共用敏感原生 Action `quyan:article:Publish`，目标为具体文章资源：

`acs:article:*:<accountId>:article/<articleId>`

可以授权管理同账户其他作者的文章，也可以限定资源组范围。即使策略使用通配符，其他账户的文章、已停用文章／作者／账户，以及非规范资源标识仍会被拒绝。显式 Deny 优先于 Allow；移除资源组成员后，下一次请求立即按新范围判断。

```json
{
  "Version": "1",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": "quyan:article:Publish",
      "Resource": "acs:article:*:account-id:article/article-id"
    }
  ]
}
```

请替换为实际账户与文章标识。仅指定账户 ARN 不代表授权账户下的文章。历史 `ARTICLE_PUBLISH` 权限保留账户级兼容范围；legacy／shadow 模式仍执行历史权限检查。

发布可能使已设为公开的文章可以匿名访问，确认前应检查正文、公开状态与访问限制。发布响应沿用完整文章 DTO，包含正文。写入前服务端再次检查有效归属及已授权的发布快照；状态或公开设置变化时，需要刷新后重新授权。该权限不代表可以新建、编辑、删除文章或修改全站默认文章。迁移期间，文章列表及菜单仍有独立权限要求；公开阅读行为不变。

## 资源级编辑与删除

enforce 模式下，`quyan:article:Update` 与 `quyan:article:Delete` 分别授权同一种具体文章 ARN。策略可以委派同账户其他作者的指定文章，也可以限定到资源组。服务端检查文章、作者及账户的有效状态，并在写入事务内再次复核已授权快照。跨账户资源、标识别名、显式 Deny、缺失策略及过期目标均安全拒绝。

编辑权限不代表可以发布、删除文章或管理全站默认文章；编辑响应包含完整文章 DTO。可编辑字段仅限标题、slug、分类、摘要、正文、公开状态与访问权限条件，请求不能替换作者、修改发布状态／默认设置，或覆盖状态与计数。将已发布文章改为公开可能使正文可以匿名访问；已有权限要求需要在同一次编辑中明确清空。slug 保持全站唯一，包括已停用文章。

删除仅使指定文章不可用，不会删除其他文章，也不会清除其他文章的默认标记。删除后，该文章立即不再符合资源组授权的有效资源条件。legacy／shadow 模式保留历史权限及仅作者可编辑／删除的规则，资源级委派在切换 enforce 后强制执行。迁移期间，列表与菜单权限仍独立判断。

## 原子性的资源级批量排序

enforce 模式下，排序请求中的**每一篇**文章都必须具备 `quyan:article:ReorderArticles` 权限。服务端解析当前账户内所有已存储的文章标识，评估整批授权并复核每个已授权快照，随后在同一事务中写入全部排序变化。任何成员被拒绝、缺失、停用、跨账户或发生变化，整批操作都会失败；后续数据库写入失败时，之前的写入也会回滚。

每个文章 ID 只能提交一次，排序值必须是数据库整数范围内的非负整数。请求数量受服务端 IAM 批量上限约束（当前为 500 个资源）。资源组成员关系及可信请求条件对每个成员分别生效。仅包含编辑 Action 的 JSON 策略不授权这一独立能力；此前使用 `quyan:article:Update` 排序的策略草稿需要明确加入 `quyan:article:ReorderArticles`。迁移期间，历史 `ARTICLE_UPDATE` 字段仍映射到这两种能力。排序只改变顺序，不会修改作者、正文、公开设置、发布状态或默认选择。legacy／shadow 模式保留历史编辑权限检查；列表与全站默认文章管理仍是独立能力。

## 说明

- 文章阅读侧通常对应 `home-articles` 页面。
- 发布前建议检查目录结构、标题层级和关键链接。
- 默认文章通常会影响首次进入时的展示内容。
