# 文章管理

文章管理用于创建、编辑和发布站内文章，调整阅读顺序及默认文章。读者入口见[首页 / 文章]({{DOCS_BASE_URL}}/zh-CN/home-articles)；发布法律协议请使用[法律政策管理]({{DOCS_BASE_URL}}/zh-CN/legal-policy-management)。

## 使用前提与页面范围

打开管理站的“文章管理”。需要相应的页面和操作权限；管理列表可见、读取正文、编辑、发布、删除和排序分别授权，看到文章不表示可以执行全部操作。

| 任务                           | 页面权限标识      |
| ------------------------------ | ----------------- |
| 读取正文                       | `ARTICLE_READ`    |
| 创建草稿                       | `ARTICLE_CREATE`  |
| 编辑、排序、设置或清除默认文章 | `ARTICLE_UPDATE`  |
| 发布或取消发布                 | `ARTICLE_PUBLISH` |
| 删除                           | `ARTICLE_DELETE`  |

桌面列表显示标题、Slug、分类、发布状态、作者、浏览量和创建时间，星标表示默认文章；移动端使用卡片。没有搜索、分页、导出或自动轮询。默认先按保存顺序，再按创建时间倒序排列。点击刷新重新加载；加载失败可能保留旧列表，空列表也可能表示没有可见资源。

## 创建草稿

1. 点击“创建文章”，填写标题、Slug 和 Markdown 内容。
2. 按需添加分类和摘要，配置公开访问和所需权限。
3. 在“预览”中检查标题层级、链接及内容。桌面可切换“分栏预览”，移动端使用编辑和预览标签页。
4. 点击“确认”保存。新建文章始终为草稿，之后需单独发布。

| 字段     | 要求或效果                                                                          |
| -------- | ----------------------------------------------------------------------------------- |
| 标题     | 去除首尾空白后为 1～200 个字符                                                      |
| Slug     | 1～200 个小写字母、数字、下划线或连字符；全站唯一，包括已删除或停用文章占用的标识   |
| 分类     | 可添加多个标签，保存为合计不超过 100 个字符的逗号分隔值；不会创建独立的分类管理目录 |
| 摘要     | 最长 500 个字符                                                                     |
| 内容     | 创建时必填；界面使用 Markdown 编辑和预览                                            |
| 公开访问 | 新建默认关闭；启用后仍需发布才可匿名读取                                            |
| 所需权限 | 非公开文章可设置额外阅读条件；保存后的权限字段最长 100 个字符                       |

当前阅读校验将所需权限字段作为一个完整权限值判断。请只选择一个有效权限，不要依赖多选实现“任一”或“全部”匹配，多选保存后可能导致文章无法阅读。

编辑器没有自动保存、版本历史或草稿恢复功能。提交前把正文保存到另一个安全位置；取消、关闭或提交请求失败后表单可能被清空。若响应丢失，先刷新列表核对是否已创建，避免直接重复创建。

## 编辑已有文章

1. 点击目标行或卡片的“编辑”，等标题、正文及访问设置成功加载后再修改。正文读取还有独立权限；获准列出他人草稿也不保证编辑器可以读取其正文。
2. 修改内容并预览。编辑已发布文章时，保存直接更新当前正文，不会另建待发布版本；需要先审阅修改时，可先取消发布再编辑。
3. 点击“确认”，刷新并重新打开核对结果。

读取失败时窗口可能仍然打开且表单为空，请关闭后排查再打开。提交失败后也可能重置表单，不能依赖窗口继续保留原稿。结果不确定时，先核对服务器已保存内容再重试。

清空分类、摘要或所需权限后，界面会省略这些空字段，原值可能继续保留。切换为公开也不会在请求中明确清空已有权限条件，可能被拒绝。需要清除旧条件时，应由有权限的维护者通过文章更新 API 明确提交空字符串并核对结果；不要把界面空选项当成已清除。公开文章不能同时保留非空权限条件。

Slug 修改后，以旧 Slug 定位的链接会失效，平台不自动提供旧标识跳转。保存不会替换作者，也不会改变发布状态、默认标记或浏览计数。

## 发布、撤回与访问范围

| 状态           | 谁能阅读                                       |
| -------------- | ---------------------------------------------- |
| 草稿           | 匿名不可读；登录正文读取还受作者和权限条件限制 |
| 已发布、非公开 | 需登录并满足正文读取授权及额外权限条件         |
| 已发布、公开   | 可从公开阅读入口匿名读取                       |

发布前检查正文和访问范围，再点击“发布”；操作立即提交，没有额外确认。公开文章发布后可能被未登录访客读取。已发布文章改为公开并保存，也可能立即扩大读者范围，无需再次发布。

点击“取消发布”立即改回草稿。它不会删除正文、重置浏览量或清除默认标记，也不会撤回读者已经复制的内容。重新发布会更新发布时间；若默认标记仍在且没有被其他默认设置替换，文章可能再次作为默认展示。发布和取消发布使用同一项发布权限，不自动授予编辑或删除权限。

## 设置默认文章

1. 对已发布文章点击“设为默认”。操作立即提交，并清除其他有效文章的默认标记。
2. 如需取消，在带星标的文章上点击“取消默认”。此操作清除当前部署的有效默认选择，不会删除或撤回正文。
3. 到文章阅读页检查登录和未登录时的实际显示。默认文章不可见时，阅读页会尝试列表中的第一篇，而不会自动放宽阅读权限。

默认选择作用于整个部署，并非每个用户或账号各有一份。设置前确认对其他读者的影响。设置默认使用目标文章上的编辑动作，清除默认使用账号资源上的编辑动作，授权范围不同；资源级编辑授权并不保证能清除全站默认。

## 调整顺序与删除文章

桌面端拖动列表左侧手柄，松开后自动提交，不需要另点保存。移动端没有拖拽排序入口。每次提交包含当前列表中的所有文章，需对每篇文章都有排序权限；只授权被拖动的一篇不一定足够。

IAM 强制模式下，整批排序要么全部成功，要么全部失败，当前单次最多 500 篇；超过上限时，此界面不能完成整表排序。失败会尝试重新加载列表；若再次加载失败，屏幕顺序可能仍未保存。刷新成功后再确认。排序不会改变正文、作者、发布范围或默认选择。

删除需要确认，之后文章从可用列表和阅读入口移除，控制台没有恢复功能。删除不会释放 Slug，也不会删除其他文章或清除其他文章的默认标记。需要保留内容时请先保存副本；临时停止阅读可选择取消发布。

浏览量是正文读取累计次数，包含重复访问和编辑窗口加载等读取，异步更新可能延迟或失败。它不代表独立访客、完整阅读或阅读确认，管理列表自身不会持续刷新计数。

## IAM 资源授权参考

IAM 强制模式支持同账号的资源级管理。文章 ARN 为 `acs:article:*:<accountId>:article/<articleId>`；创建和清除默认使用账号 ARN `acs:quyan:*:<accountId>:account`。使用实际账户和文章 ID，不能用账号 ARN 替代具体文章授权。

| 操作           | Action                          | 授权资源                       |
| -------------- | ------------------------------- | ------------------------------ |
| 列出管理元数据 | `quyan:article:ListArticles`    | 每篇可见文章                   |
| 读取正文       | `quyan:article:Read`            | 目标文章，另受正文阅读条件限制 |
| 创建草稿       | `quyan:article:Create`          | 当前账号                       |
| 编辑或设为默认 | `quyan:article:Update`          | 目标文章                       |
| 清除默认       | `quyan:article:Update`          | 当前账号                       |
| 发布或取消发布 | `quyan:article:Publish`         | 目标文章                       |
| 删除           | `quyan:article:Delete`          | 目标文章                       |
| 批量排序       | `quyan:article:ReorderArticles` | 本次提交的每篇文章             |

列表只返回获准的元数据，不包含正文或未过滤的全局总数。可以授权同账号他人的文章或使用资源组；文章额外权限条件仍会影响列表，跨账号或无效文章、作者和账号不会因此可用。`Read` 不隐含 `ListArticles`，`Update` 不隐含独立的 `ReorderArticles`，创建也不授予后续操作。编辑、发布、设为默认等成功响应可能包含完整正文，应按其实际能力授权。

资源组成员移除影响后续请求，匹配的 Deny 优先。角色会话使用角色自己的授权，作者仍是实际执行用户。创建或更新 API 只接受内容和访问设置，不能借这些请求替换作者、发布状态或计数；需要相应的专用操作。

兼容旧权限时，`ARTICLE_READ` 的列表范围仍是本人草稿或已发布文章，`ARTICLE_UPDATE`、`ARTICLE_DELETE` 的编辑和删除范围仍限实际执行用户自己创作的文章，旧排序和发布保持各自范围。需要管理同账号其他作者文章时，应由有委派权限的身份显式授权对应资源动作；旧移除权限仍优先拒绝。legacy/shadow 部署继续使用其原有检查。菜单展示、列表和正文读取不能相互替代。

资源或归属并发变化可能使操作被拒绝；重新加载核对后再提交。更多策略配置见 [RAM 管理]({{DOCS_BASE_URL}}/zh-CN/ram-management)。

## 常见问题

| 现象                       | 处理方法                                                   |
| -------------------------- | ---------------------------------------------------------- |
| 保存后读者看不到新文章     | 核对是否仍为草稿、是否公开，以及读者权限；保存不等于发布   |
| 列表可见但编辑窗口读取失败 | 检查正文读取授权、草稿作者条件及额外权限；关闭空窗口后重试 |
| 清空权限或切为公开后仍失败 | 界面可能没有提交清除旧条件，需显式清除并重新核对保存结果   |
| 设置默认后部分读者仍看不到 | 默认不绕过发布和访问条件，检查读者身份与文章公开状态       |
| 拖拽后顺序恢复             | 核对全列表排序授权、500 篇上限及刷新结果                   |
| 操作成功提示后列表仍旧     | 写入与后续刷新可能分别成功或失败，先刷新成功再重复操作     |
