# 数据归档与清理

“数据归档”将超过热数据保留期的记录上传到 OSS，校验后删除对应热数据。页面可配置保留策略和定时任务、预览候选记录、查看执行结果与下载归档。“危险数据维护”另行提供历史记录导入和表优化。

归档后，原业务页面通常不再查询这些记录。本页没有一键撤销或完整恢复功能；请在执行前确认调查、报表和历史查询所需的保留时间。

## 使用前提

- 数据归档需要 `system:data_lifecycle:manage`；危险数据维护需要独立的 `system:data_maintenance:manage`。IAM 强制授权还要求平台全局用户组资格及对应资源操作，详见下文。
- 修改策略或定时设置、手动归档和下载文件均需要 2FA 升级认证及重放保护。危险维护的预览和创建任务还需要验证码，执行需输入确认短语。
- 归档及下载需要服务端配置可用的 OSS 归档存储。没有配置时，归档不会继续删除源数据。创建导入任务还需要单独配置 OSS 暂存存储，并确保暂存对象可立即读取。
- 这些管理操作不接受 OAuth 访问令牌。归档文件可能包含业务数据及日志正文，应按原数据的敏感程度控制下载和保存。

## 了解默认保留策略

| 数据集                                                  | 默认热数据保留期 | 默认归档保留期 |
| ------------------------------------------------------- | ---------------- | -------------- |
| API 日志 `api_logs`                                     | 90 天            | 365 天         |
| 业务日志 `business_logs`                                | 180 天           | 365 天         |
| 通知日志 `notification_logs`                            | 90 天            | 365 天         |
| 埋点 `track_events`、热图 `heatmap_points`              | 30 天            | 365 天         |
| AI 请求日志 `ai_request_logs`                           | 90 天            | 不自动到期     |
| 调用用量 `relay_usages`、月卡用量 `monthly_pass_usages` | 180 天           | 365 天         |
| 服务器文件日志 `server_logs`                            | 14 天            | 365 天         |

以页面当前策略及各文件显示的到期时间为准。“永久”表示本功能未设置自动到期时间，不代表对外部存储删除的保护。余额流水不在这些自动归档、导入或表优化数据集中。

## 修改策略

1. 打开“数据归档”，找到数据集，核对热数据保留天数和候选数量。
2. 修改启用状态或热数据保留天数。天数须为 1～3650 的整数，**修改即发起保存**，没有统一的策略保存按钮。
3. 完成验证并确认保存成功。需要恢复天数时，单击该行“恢复默认”；它只重置该数据集的热数据天数，不恢复全部设置。
4. 单击“刷新”，确认服务端实际保存的策略和最新候选数量。保存失败时，不要仅凭输入框或开关的显示判断已生效。

页面不能修改归档保留期。缩短热数据保留期可能增加下次运行的候选数量，但保存策略本身不会立即归档或删除记录。

停用策略会将其排除在定时归档之外；**明确指定该数据集的手动归档仍可执行**，包括手动勾选后的批量归档。停用并不等于禁止任何人执行。

## 手动执行归档

1. 先保存并刷新策略，确认当前保留天数。
2. 单击目标行“执行归档”，在候选对话框中查看记录 ID、时间和脱敏摘要；服务器文件日志显示文件候选。
3. 核对后，在对话框中再次单击“执行归档”，完成验证。
4. 在“执行记录”检查状态、候选数、已归档数、已删除数和失败原因。需要时刷新页面获取当前结果。

批量操作时，勾选目标策略，单击“批量归档所选策略”，核对数据集数量和候选总数后确认。页面必须至少勾选一项。通过 API 未指定数据集或提交空数组时，只选择当次已启用的策略。

候选预览是查询时的结果，不会锁定记录；执行按当时有效策略重新确定范围。页面的“将归档”和“将删除”都显示候选数量，不是两批互不相关的数据。对于服务器文件日志，计数单位是文件，不是文件内的日志行。

数据库记录分批导出为 gzip NDJSON，上传后核对大小和 SHA-256 元数据，再删除对应热记录。服务器文件日志则逐个上传压缩文件，校验后删除本地文件。

任务可能部分成功后失败。已完成批次的删除不会回滚；失败提示、超时或断网也不能证明操作完全未发生。再次执行前先检查运行记录和实际计数，避免把请求报错当成没有执行。上传后、归档明细保存前失败时，可能存在未关联明细的 OSS 对象，需要由存储管理员排查。

## 设置定时归档

默认每天 **03:20（Asia/Shanghai）**执行已启用策略。页面时间按此时区解释，与浏览器所在地无关。

1. 在“定时归档”设置启用状态和时间。
2. 单击“保存定时设置”，完成验证并确认保存成功；只修改表单不会保存。
3. 刷新后核对设置，跨服务实例通常约一分钟同步。

关闭定时归档会停止这项每日计划，不会撤销已经完成的归档，也不会阻止明确发起的手动归档。到期归档文件清理随每日计划执行；关闭计划、OSS 不可用或清理失败时，物理删除可能延后。危险维护的队列处理独立于该每日开关。

## 查看与下载归档

1. 在“执行记录”找到运行，单击“查看归档”，查看文件、校验和、大小、记录数、到期及删除时间。一次运行可生成多个文件，应按需下载全部相关文件。
2. 单击文件的下载按钮，完成验证。已删除文件不再提供下载。
3. 如提示正在从 OSS 恢复，等待存储恢复完成后重新单击下载；页面不会自动轮询或自动完成下载。
4. 在受控环境保存和查阅文件，确认实际格式。

| 数据来源       | 下载内容                                     | 应用内恢复                         |
| -------------- | -------------------------------------------- | ---------------------------------- |
| 数据库数据集   | `.ndjson.gz`，解压后每行是一条 JSON 记录     | 仅危险维护支持的数据集可预览并导入 |
| AI 请求日志    | gzip NDJSON，可能包含已保存正文              | 不支持危险维护导入，仅供下载查阅   |
| 服务器文件日志 | 原日志的 gzip 文件，已压缩文件保持原压缩内容 | 不支持导入为数据库记录             |

归档没有应用内全文检索。私有 OSS 对象的普通 URL 可能拒绝访问，应使用页面生成的临时签名链接；链接有效期为 **300 秒**，过期后重新下载。签名链接交付后，撤销应用权限不能追溯取消该链接，请勿转发。冷归档恢复已经发起时，后续撤权也不会自动撤回 OSS 恢复。

到期时间不保证文件立即从存储删除。IAM 强制授权下，到期、已删除或关联运行失效的文件会被拒绝下载，即使列表仍显示该文件。

## 导入历史记录

导入在“危险数据维护”执行，支持上表中除 AI 请求日志和服务器文件日志外的 7 个数据集。它只写入指定数据集的历史记录，不恢复整个系统，也不重放扣费等业务流程。

1. 选择与文件内容一致的数据集及 `.ndjson.gz` 文件，不要仅凭扩展名判断内容。
2. 单击“预览导入”，完成验证，检查总数、新增、重复、格式无效、外键缺失及错误摘要。
3. 有格式无效或外键缺失时，先修正并重新预览。重复记录会跳过，不覆盖已有记录；预览计数不是执行结果。
4. 确认数据集和文件仍与预览一致，单击“开始导入”，输入 `IMPORT` 并完成验证。
5. 在维护历史检查任务从排队到执行的状态及实际新增、跳过、失败数量。“任务已创建”不代表已经导入完成。

上传压缩大小默认最多 100 MiB，以部署配置为准；解压后最多 512 MiB、单行最多 2 MiB、最多 2,000,000 条。超限文件需要在受控环境中按有效记录拆分为符合限制的 gzip NDJSON 文件，再逐份预览。

调用用量依赖仍存在的中转令牌，以及记录引用的逻辑请求；月卡用量依赖对应的用户月卡。缺失关联会阻止导入。任务创建和实际执行都会重新校验，因此预览通过不保证稍后仍能导入。

导入按批次写入，失败不会撤销已经插入的批次。重新尝试前检查实际结果；已有记录会按重复处理。导入暂存对象使用可立即读取的存储，任务结束或创建失败时会尝试清理；存储不可用时可能残留，需要管理员处理，原归档文件不会因此自动删除。

## 优化数据表

数据库记录归档删除后，空间可能先供数据库复用，磁盘上的表文件不一定立即缩小。需要回收时，可在低峰期使用“危险数据维护”的“优化数据表”：

1. 选择支持的数据表，单击“预览表影响范围”，核对表名、记录数及数据与索引大小。
2. 选择发生变化时重新预览；预览不是对执行范围的锁定。
3. 单击“开始优化”，输入 `OPTIMIZE` 并完成验证。
4. 查看维护历史，等待排队任务执行并检查结果。

表优化可能锁表或占用较多资源，属于独立维护，不会随每次归档自动执行。该页面不支持优化 AI 请求日志或服务器文件日志数据集；服务器文件日志归档成功后直接删除对应本地文件。

## 配置生命周期 IAM 权限

IAM 强制授权要求操作员实际所属的平台全局用户组提供生命周期管理资格。账户所有者身份、附加权限、账户私有组或单独的通配符策略不能代替此资格。读取、预览、修改、执行与下载各自授权。

下表的 Action 前缀均为 `quyan:system:data_lifecycle:`；资源前缀均为 `acs:platform:*:platform:`。

| 操作后缀                        | 资源后缀                                                                        | 用途                             |
| ------------------------------- | ------------------------------------------------------------------------------- | -------------------------------- |
| `ListPolicies`                  | `lifecycle-dataset/<dataset>`                                                   | 列出已授权策略及候选数量         |
| `PreviewPolicy`                 | `lifecycle-dataset/<dataset>`                                                   | 读取候选统计预览，批量确认时使用 |
| `ListCandidates`                | `lifecycle-dataset/<dataset>`                                                   | 分页查看候选摘要                 |
| `UpdatePolicy`                  | `lifecycle-dataset/<dataset>`                                                   | 修改启用状态、热数据天数         |
| `RunPolicy`                     | `lifecycle-dataset/<dataset>`                                                   | 单数据集归档                     |
| `RunBatch`                      | 每个目标的 `lifecycle-dataset/<dataset>`                                        | 批量归档，与单独执行权限不同     |
| `GetSchedule`、`UpdateSchedule` | `lifecycle-schedule/default`                                                    | 分别读取、保存定时设置           |
| `ListRuns`                      | `lifecycle-run/<runId>`                                                         | 查看运行历史                     |
| `ListArtifacts`                 | 同时允许父 `lifecycle-run/<runId>` 和 `lifecycle-artifact/<runId>/<artifactId>` | 列出归档文件                     |
| `DownloadArtifact`              | `lifecycle-artifact/<runId>/<artifactId>`                                       | 单独授权下载                     |

列表先过滤再分页，总数只包含可见资源。运行显示的文件数只统计已授权文件；无文件列表权限时可能显示零，不能据此证明没有归档。

批量执行先授权全部目标，任一拒绝均不启动处理。处理中会复核授权和策略版本，撤权可停止后续处理；已完成上传、删除无法撤销。IAM 强制授权还会在删除数据库记录前核对导出快照及事务内授权，服务器文件删除前核对授权和文件内容。

保存、读取和签发下载链接期间发生撤权或资源变化可能导致失败。策略只能修改启用状态和热数据天数；定时开关与时间一起保存。发生冲突时请刷新确认服务端当前状态，再重试所需操作。

## 配置维护 IAM 权限

危险维护要求独立的平台全局用户组维护资格，不能由生命周期权限替代。Action 前缀为 `quyan:system:data_maintenance:`，资源前缀为 `acs:platform:*:platform:`。

| 操作后缀            | 资源后缀                                 | 用途           |
| ------------------- | ---------------------------------------- | -------------- |
| `PreviewOptimize`   | 每个所选 `maintenance-dataset/<dataset>` | 表优化预览     |
| `CreateOptimizeRun` | 每个所选 `maintenance-dataset/<dataset>` | 创建表优化任务 |
| `PreviewImport`     | `maintenance-dataset/<dataset>`          | 导入校验预览   |
| `CreateImportRun`   | `maintenance-dataset/<dataset>`          | 创建导入任务   |
| `ListRuns`          | `maintenance-run/<runId>`                | 维护历史列表   |
| `GetRun`            | `maintenance-run/<runId>`                | 独立的详情访问 |

预览和历史读取不授予执行权限。多表操作需全部授权；创建任务时身份或授权变化可能导致入队失败。导入只有在文件及临时上传校验通过后才能入队。任务结果不公开私有暂存对象键。

## 常见问题

| 现象                     | 处理建议                                                                   |
| ------------------------ | -------------------------------------------------------------------------- |
| 修改天数后候选数量未变   | 确认保存成功，再刷新；页面不会持续自动刷新统计                             |
| 停用策略后仍能手动归档   | 停用控制定时和未指定数据集的批量选择；明确指定数据集仍可手动执行           |
| 归档失败或请求超时       | 查看运行计数和失败原因；部分批次可能已完成，不要假定全部保留或全部删除     |
| 运行存在但文件数为零     | 可能无候选，也可能无文件列表权限；分别核对运行计数和 IAM 权限              |
| 归档列表加载失败         | 使用抽屉内重载按钮，确认父运行和文件列表权限；失败不代表没有归档文件       |
| 下载提示恢复中或链接过期 | 等待恢复后重新单击下载，或重新生成签名链接；不要反复使用旧 URL             |
| 删除热记录后磁盘仍未释放 | 数据库可能保留可复用空间；在低峰期评估支持数据表的优化任务                 |
| 导入一直排队或失败       | 核对维护历史、后台调度运行状态、暂存存储和关联记录；创建成功不等于执行成功 |
