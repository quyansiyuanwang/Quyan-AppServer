# 数据归档与清理

数据归档页面用于管理臃肿表的热数据保留期，并查看已上传和校验的 OSS 归档文件。

## 使用前提

- 需要数据生命周期管理权限。
- 修改策略、手动执行归档和下载文件需要完成 2FA 升级认证。
- 服务端必须配置阿里云 OSS；未配置时不会执行删除。

## 默认策略

API 日志和通知日志保留 90 天；业务日志、调用用量和月卡用量保留 180 天；埋点和热图保留 30 天。归档文件保留 1 年。

余额流水不纳入自动归档或删除。

## 执行规则

1. 页面会在策略表中显示当前将归档和将删除的记录数。
2. 点击“执行归档”会打开分页预览对话框，列出记录 ID、时间和脱敏摘要；确认后才开始执行。
3. 服务端将候选记录写入 gzip NDJSON 并上传 OSS。
4. 上传对象的大小和 SHA-256 校验通过后，才分批删除热表记录。
5. 运行记录会显示候选、归档和删除数量；失败时保留源数据并可重试。

## 定时归档

系统默认每天 03:20（Asia/Shanghai）执行已启用的策略。管理员可以在页面上修改执行时间或关闭定时任务，保存后约一分钟内生效。

归档明细首版通过管理员下载文件访问，不在应用内全文检索。归档 bucket 默认是私有的，OSS 控制台复制的普通对象 URL 没有签名，直接打开会返回拒绝访问；请使用页面下载按钮生成临时签名地址。如果 OSS 已将对象转为 Archive/冷归档存储，首次点击下载会先发起恢复，等待 OSS 恢复完成后再次点击即可下载。归档文件到期后会自动从 OSS 删除。

下载得到的是 gzip 压缩的 NDJSON 原始记录。可在“危险维护”页面预览后导入指定数据集；导入会使用独立、可立即读取的 OSS 暂存桶，任务完成或失败后都会删除暂存对象。归档桶可使用 Archive/冷归档，不能兼作导入暂存。`relay_usages` 和 `monthly_pass_usages` 依赖仍存在的令牌/套餐记录，缺失时会阻止导入；余额流水不在导入范围内。

数据库记录删除后，InnoDB 会优先将空间标记为可复用，表文件大小不一定立即缩小；需要在低峰期单独执行表重建/`OPTIMIZE TABLE` 才能回收操作系统磁盘空间，这不是每次归档自动执行的步骤。服务器文件日志则会在 OSS 校验成功后从本地磁盘删除。
