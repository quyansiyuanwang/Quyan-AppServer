# 数据归档与清理

数据归档页面用于管理臃肿表的热数据保留期，并查看已上传和校验的 OSS 归档文件。

## 使用前提

- 需要数据生命周期管理权限。
- 修改策略、手动执行归档和下载文件需要完成 2FA 升级认证。
- 服务端必须配置阿里云 OSS；未配置时不会执行删除。

## 默认策略

API 日志、通知日志和 AI 请求日志默认保留 90 天；业务日志、调用用量和月卡用量保留 180 天；埋点和热图保留 30 天。除 AI 请求日志永久归档外，其他归档文件默认保留 1 年。

余额流水不纳入自动归档或删除。

## 生命周期读取权限

启用 IAM 强制授权后，生命周期读取仍要求平台管理的全局用户组提供生命周期管理资格。策略列表使用 `quyan:system:data_lifecycle:ListPolicies`，预览使用 `quyan:system:data_lifecycle:PreviewPolicy`，候选记录使用 `quyan:system:data_lifecycle:ListCandidates`，资源为 `acs:platform:*:platform:lifecycle-dataset/<dataset>`。这些权限分别控制各数据集，不能相互替代，也不包含归档执行或策略修改权限。

列表只包含已授权的有效数据集，服务端在授权后才读取候选数量。被拒绝的数据集不会出现在列表中，其统计和候选内容也不会被读取。候选摘要保持脱敏；未知数据集、安全上下文缺失或加载期间发生撤权时，请求会失败。服务器文件日志同样按 `server_logs` 数据集授权。

调度读取由 `quyan:system:data_lifecycle:GetSchedule` 单独控制，资源为 `acs:platform:*:platform:lifecycle-schedule/default`。它只允许读取计划，不允许修改计划或执行任务。

## 执行规则

1. 页面会在策略表中显示当前将归档和将删除的记录数。
2. 点击“执行归档”会打开分页预览对话框，列出记录 ID、时间和脱敏摘要；确认后才开始执行。
3. 服务端将候选记录写入 gzip NDJSON 并上传 OSS。
4. 上传对象的大小和 SHA-256 校验通过后，才分批删除热表记录。
5. 运行记录会显示候选、归档和删除数量；失败时保留源数据并可重试。

## 定时归档

系统默认每天 03:20（Asia/Shanghai）执行已启用的策略。管理员可以在页面上修改执行时间或关闭定时任务，保存后约一分钟内生效。

归档明细首版通过管理员下载文件访问，不在应用内全文检索。归档 bucket 默认是私有的，OSS 控制台复制的普通对象 URL 没有签名，直接打开会返回拒绝访问；请使用页面下载按钮生成临时签名地址。如果 OSS 已将对象转为 Archive/冷归档存储，首次点击下载会先发起恢复，等待 OSS 恢复完成后再次点击即可下载。归档文件到期后会自动从 OSS 删除。

下载得到的是 gzip 压缩的 NDJSON 原始记录。可在“危险维护”页面预览后导入指定数据集；导入会使用独立、可立即读取的 OSS 暂存桶，任务完成或失败后都会删除暂存对象。归档桶可使用 Archive/冷归档，不能兼作导入暂存。`relay_usages` 和 `monthly_pass_usages` 依赖仍存在的令牌/套餐记录，缺失时会阻止导入；余额流水和 AI 请求日志不在导入范围内，AI 请求日志归档仅供下载审计。

数据库记录删除后，InnoDB 会优先将空间标记为可复用，表文件大小不一定立即缩小；需要在低峰期单独执行表重建/`OPTIMIZE TABLE` 才能回收操作系统磁盘空间，这不是每次归档自动执行的步骤。服务器文件日志则会在 OSS 校验成功后从本地磁盘删除。

## 危险维护执行记录

启用 IAM 强制授权后，维护历史要求平台管理的全局用户组提供危险维护资格。`quyan:system:data_maintenance:ListRuns` 控制列表可见的执行记录，`quyan:system:data_maintenance:GetRun` 单独控制详情访问。账户所有者、用户附加权限或账户自建用户组均不能单独获得平台维护资格。

执行记录资源为 `acs:platform:*:platform:maintenance-run/<runId>`。命中 Deny 的记录不在列表中，分页与总数只包含已授权的有效记录。响应提供进度、计数及执行结果，不返回私有临时导入对象键。加载期间若记录发生变更，或用户组权限、策略、角色会话被撤销，请求会失败。历史读取权限不包含导入或表优化操作。

表优化预览使用 `quyan:system:data_maintenance:PreviewOptimize`，导入预览使用 `quyan:system:data_maintenance:PreviewImport`，分别授权到 `acs:platform:*:platform:maintenance-dataset/<dataset>`。只能选择危险维护支持的数据集。优化预览中的全部数据集必须先通过授权，服务端才读取表统计；任一数据集命中 Deny 时整个请求被拒绝。导入预览返回校验计数和摘要，不返回原始导入记录。两种预览均保留二次验证、重放保护和验证码要求，预览权限不包含执行权限。

创建表优化任务需要对每个选中数据集拥有 `quyan:system:data_maintenance:CreateOptimizeRun`，并具备平台维护资格。预览和历史读取权限不包含任务创建。请求保留 `OPTIMIZE` 确认、二次验证、重放保护及验证码要求，发起人、实际表名和初始排队状态均由服务端设置。入队事务提交前若身份、用户组、角色或授权变化，创建会被拒绝或回滚。此接口创建维护队列任务，不同步执行表优化。

创建导入任务需要对选中数据集拥有 `quyan:system:data_maintenance:CreateImportRun` 并具备平台维护资格，预览或表优化权限不包含导入创建。请求保留 `IMPORT` 确认请求头、二次验证、重放保护及验证码要求。服务端先授权，再校验归档及上传，仅通过验证的临时上传对象才能入队。上传验证或入队授权失败会触发临时对象清理，队列响应不公开私有临时对象键。清理存储不可用时请求仍然失败并记录清理异常，不会转为已授权的导入。
