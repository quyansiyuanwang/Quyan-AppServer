# 通知设置

在**设置 → 事件中心**管理自己的通知邮箱、事件订阅和 Webhook，查看站内通知及外部投递结果。本页配置只作用于当前登录用户；全局默认值由管理员在服务端配置中维护。

## 开始前

打开页面后，先确认事件列表和已有偏好加载完整。读取偏好、保存偏好、管理 Webhook、测试投递和查看历史可以分别授权，能打开页面不代表能执行所有操作。具体授权见下文。

如果事件列表为空或偏好与预期不符，先检查网络和权限，再重新加载页面。不要直接保存空白表单：保存会提交当前事件选择和阈值，可能覆盖已有设置。

## 配置通知偏好

1. 在**通知偏好**中填写**通知邮箱**。它可以与账号邮箱不同；留空保存后停止邮件通知，不会自动回退到账号邮箱。
2. 勾选需要接收的事件。**全选**和**清空**只修改当前表单，需要保存才会生效。
3. 为支持阈值的事件填写触发条件，含义见下表。
4. 设置冷却时长。控件按“天 + 时:分”输入；例如 `0 天 01:00` 表示 60 分钟。
5. 点击**保存偏好**，移动端点击**保存**。成功提示后更改生效，无需重启服务。

首次创建偏好时，邮箱取当前账号邮箱，默认冷却为 60 分钟，订阅和阈值取服务端配置。之后修改账号邮箱或全局默认值不会直接覆盖已保存的通知偏好。

取消某个阈值事件并保存时，该事件原先的自定义阈值也不会保留；重新订阅后请重新核对阈值。

### 告警阈值如何判断

| 事件             | 触发条件                                     | 填写示例                      |
| ---------------- | -------------------------------------------- | ----------------------------- |
| 余额不足         | 余额低于阈值，单位为曲                       | `10`：余额低于 10 曲时提醒    |
| 月卡额度不足     | 剩余额度占总额度的比例小于或等于阈值         | `20`：剩余不超过 20% 时提醒   |
| 月卡日限额提醒   | 当前额度窗口已用量比例大于或等于阈值         | `80`：窗口已用达到 80% 时提醒 |
| 中转令牌额度不足 | 有正数额度上限的令牌，已用比例大于或等于阈值 | `80`：已用达到 80% 时提醒     |

阈值支持两位小数，服务端接受 0–100000；百分比通常填写 0–100。余额和额度告警在相关余额变动或用量结算时检查，修改阈值不会立即执行一次历史扫描，也不是持续实时监控。

“月卡日限额提醒”使用月卡设置的滚动窗口，默认 24 小时，不按自然日零点重置。当前提醒按窗口内的抵扣金额计算，按次或按 Token 计量的月卡不能仅凭该提醒判断用量比例。未设置每日额度的月卡不适用此提醒。

### 冷却与订阅的影响

同一用户的同一事件共用冷却时间，邮件和各个 Webhook 不分别计算。一次普通投递开始后，即使某个渠道发送失败，后续同类事件仍可能受冷却限制；更换收件地址也不会立即清除已有冷却。

**建议使用大于 0 的冷却时长。** 当前版本将其设为 0 后，同类事件首次投递可能留下不自动到期的冷却状态，导致后续普通通知持续被抑制。如果此前设置过 0，请改为正值；仍未恢复时联系管理员检查已有冷却状态，单独修改时长可能无法恢复。

取消订阅会停止相应邮件和 Webhook 通知。部分事件仍会生成站内通知，但余额、月卡等部分告警在生成通知前就检查订阅，因此不能把站内通知当作所有事件的完整记录。进入通知投递流程的事件也可能只生成站内通知，然后因冷却跳过外部投递。

## 添加和维护 Webhook

1. 在 **Webhook** 区域点击**添加 Webhook**，移动端点击**创建**。
2. 填写名称和你能控制的目标 URL，选择通用 JSON、Discord、Slack、飞书或企业微信格式。
3. 按接收端要求填写签名密钥，并选择是否**启用**。名称最多 100 字符，URL 最多 2048 字符，密钥最多 200 字符。
4. 点击**保存**，再从列表发起测试，并到接收端确认结果。

签名密钥不会回显。**编辑已有 Webhook 时，即使只改名称，也需重新填写仍要使用的密钥；留空保存会清除原密钥。** 通过 API 更新时，省略密钥字段会保留原值，显式传入 `null` 才会清除；页面的空白编辑字段会提交 `null`。

签名使用 `X-Webhook-Signature` 请求头，值为 `sha256=<摘要>`；摘要由密钥对实际发送的 JSON 正文执行 HMAC-SHA256 得到。选择机器人格式只改变消息格式，不自动适配各机器人平台的原生签名协议。接收端要求其他签名方式时，请先确认兼容性。

暂时停止普通投递时，编辑目标、取消**启用**并保存。删除时需要确认；删除后不再作为投递目标，页面没有恢复入口，已有投递历史仍可查看。停用并不禁止手动测试。

## 测试已保存的目标

邮箱旁和 Webhook 列表中的**测试**会实际发送通知，使用已保存的邮箱、URL、格式和密钥。编辑已有 Webhook 时，弹窗中的测试也使用保存前的版本；新增目标需要先保存。

测试使用模拟的余额不足通知，内容中的余额和阈值不代表你的真实余额。它绕过普通事件订阅和冷却，测试邮件还会创建一条本人的站内通知。测试不会写入普通投递历史，因此不能用历史中是否出现记录判断测试是否执行。

“发送成功”表示发送请求完成，不保证用户实际收到或阅读。邮件可能进入垃圾箱；Webhook 接收端即使返回 HTTP 成功，也可能在响应正文中报告机器人业务错误。请到目标系统检查实际消息。测试成功也不代表后续普通事件满足订阅、阈值和冷却条件。

## 查看和标记站内通知

1. 在**站内通知**中查看标题、内容、时间和已读状态，可切换**仅未读**。列表优先显示未读消息，每页 20 条。
2. 点击单条消息的**标为已读**，或使用**全部标为已读**处理全部获准的本人未读消息，范围不限于当前页。
3. 如果有“邮件已打开待确认”的消息，可点击**确认邮件已读**，将符合条件且获准处理的消息批量标为已读。
4. 使用该区域的**刷新**获取最新消息和数量；页面不会自动轮询。

邮件打开状态依赖跟踪图片。邮件客户端拦截图片时可能没有记录，自动加载图片也可能产生记录，所以它不能证明收件人实际阅读。图片加载本身不会将站内消息标为已读，需要点击确认或手动标记。页面没有将已读消息恢复未读的操作。

## 查看通知历史

**通知历史**按页展示普通邮件和 Webhook 投递的事件、标题、渠道、状态、时间及错误。每页 20 条，可使用区域内的**刷新**重新加载。

| 状态   | 如何理解和处理                                                 |
| ------ | -------------------------------------------------------------- |
| 成功   | 本次发送请求未报告传输错误；仍需在邮箱或接收系统确认实际消息   |
| 失败   | 查看错误并检查收件地址、服务端邮件配置、目标连通性和接收端要求 |
| 待处理 | 尚无最终结果；刷新查看，不代表已经送达                         |

页面没有重试或补发历史消息的操作，失败也不会自动重试。冷却抑制、未订阅、未配置外部目标及测试投递可能没有普通历史记录；没有记录不能证明事件从未发生。

站内通知或历史加载失败时，旧列表和数量可能保留，即使页码或筛选条件已经变化。刷新并确认加载成功后，再判断消息状态和投递结果。

## 管理员：设置全局默认值

在[服务端配置]({{DOCS_BASE_URL}}/zh-CN/server-configuration)的通知配置中设置**默认订阅事件**和**默认触发阈值**。它们用于初始化尚未创建的偏好，不直接覆盖已有用户设置。

系统新增事件后，后续读取偏好可能自动订阅这些新事件，请重新检查选择。主动取消的已知事件不会因此重新订阅。

## 权限与可用范围

旧权限模式下，偏好、Webhook、测试及历史要求通知管理权限。登录用户可以查看本人的事件目录和站内消息。

IAM 强制模式下，各操作分别授权。下表中的 Action 均以 `quyan:notification:` 开头。

| 操作                           | Action                                                          | 资源                           |
| ------------------------------ | --------------------------------------------------------------- | ------------------------------ |
| 读取、保存偏好                 | `GetPreferences`、`UpdatePreferences`                           | 本人用户资源                   |
| 查看事件目录                   | `ListEvents`                                                    | 本人用户资源，默认本人授权     |
| 新增 Webhook、测试邮件         | `CreateWebhook`、`TestEmail`                                    | 本人用户资源                   |
| 查看、修改、删除、测试 Webhook | `ListWebhooks`、`UpdateWebhook`、`DeleteWebhook`、`TestWebhook` | 对应 Webhook 资源              |
| 查看投递历史                   | `ListDeliveryLogs`                                              | 对应投递日志资源               |
| 查看、手动已读、确认邮件已读   | `ListInbox`、`MarkInboxRead`、`ConfirmPixelOpenedInboxRead`     | 对应站内消息资源，默认本人授权 |

资源格式如下，账号和用户均由服务端认证身份确定：

- 本人用户：`acs:quyan:*:<accountId>:user/<userId>`。
- Webhook：`acs:notification:*:<accountId>:webhook/<userId>/<webhookId>`。
- 投递日志：`acs:notification:*:<accountId>:delivery-log/<userId>/<logId>`。
- 站内消息：`acs:notification:*:<accountId>:inbox-item/<userId>/<itemId>`。

除默认本人授权的操作外，需要明确授权；旧通知管理权限兼容对应操作，其他 Action 不会自动扩大授权。查看或编辑不包含测试权限，新增 Webhook 也不授予偏好读写能力。获准读取偏好、新增 Webhook 或测试邮件时，系统可能初始化缺少的偏好。

所有操作仅作用于当前执行用户本人，通配符、其他用户 ID 或 ARN 不会改变目标。显式 Deny 优先于 Allow，条件和资源组可进一步限制范围；角色会话按有效会话权限执行。身份、会话或偏好失效后无法继续操作，发生并发变更时请刷新重试。

Webhook、日志和站内消息列表先按权限过滤再展示；消息总数、未读数和邮件待确认数只统计可见消息。全部已读和邮件确认只处理各自获准的消息，被拒绝的消息保持原状态。通过 API 指定多个消息 ID 时，任何目标缺失、失效或无权访问都会使整批不更新；重复 ID 只计一次，已读消息不重复计数。

## 常见问题

| 问题                            | 建议                                                         |
| ------------------------------- | ------------------------------------------------------------ |
| 邮箱测试成功，普通通知仍收不到  | 核对已保存的订阅、阈值和正数冷却时长，再确认事件是否实际触发 |
| 输入新邮箱后测试仍发到旧地址    | 先保存偏好，再测试；按钮可点击不代表新地址已经保存           |
| Webhook 修改后验签失败          | 检查是否留空保存而清除了密钥，并确认接收端支持本页的签名方式 |
| 事件列表或 Webhook 列表意外为空 | 先检查网络和读取权限，重新加载；不要直接覆盖已有偏好         |
| 无法测试但能编辑                | 测试需要独立权限，请管理员核对对应测试 Action                |
