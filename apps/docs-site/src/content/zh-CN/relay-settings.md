# 转发设置

此页面用于维护两类配置：

- 转发系统级行为，例如队列、监控映射、全局倍率和模型价格。
- 渠道级行为，例如上游地址、混池路由、白名单可见性、模型限制和分时倍率。

如果你要解决“某个用户能否看到某个渠道”“某个模型走哪个上游”“多个上游如何故障转移”这一类问题，核心都在这里完成。

## IAM 全局渠道拓扑审计

启用严格双层拓扑前，审计需要 `quyan:relay:AuditChannelTopology` 同时允许 `acs:platform:*:platform:relay-configuration/default` 和每一个未删除渠道的 `acs:platform:*:platform:relay-channel/<渠道ID>`。操作者还须具有部署全局组中的 `RELAY_CHANNEL_READ` 资格，且原有渠道可见性规则继续生效。任一参与审计的渠道或配置无权访问时，整个请求返回 403；不会把部分可见渠道的结果当成全局 `canEnableStrict` 结论。

审计包含停用但未删除的渠道，检查旧池成员、缺失或错误的父池、非成员渠道误设父池，以及自动池引用物理渠道等问题。只有完整拓扑无问题时才报告可以启用严格模式；读取期间授权、配置或拓扑变化会拒绝返回结果。此操作只读取拓扑字段，不读取上游凭据或模型价格，也不会创建默认配置。切换模式仍需另行具备全局设置修改权限。

## IAM 渠道修改申请列表

IAM 强制模式下，“我的修改申请”使用 `quyan:relay:ListMyChannelChangeRequests`，资源为 `acs:relay:*:<账户ID>:channel-change-request/<提交者ID>/<申请ID>`。结果仅包含当前提交者自己的申请；即使授权策略包含通配符，也不能读取同账户其他用户或其他账户的个人申请。

审核列表使用 `quyan:relay:ListChannelChangeRequests`，资源为 `acs:platform:*:platform:relay-channel-change-request/<渠道ID>/<申请ID>`。审核员仍须具有部署管理员设置的全局组 `RELAY_CHANNEL_REVIEW` 资格，账户自建组或策略不能自行赋予审核员资格。合格审核员可处理不同提交者的申请，但每条申请仍须获准访问。

两种列表都先按申请逐资源授权，再计算分页和总数；删除的申请或渠道不出现在结果中。配置只返回约定的公开字段和“是否已设置凭据”标志，不返回原始或加密凭据。角色会话只使用角色策略。读取期间身份、资格、策略或会话变化时，请刷新重试。

## IAM 渠道管理列表

启用 IAM 强制授权后，管理表格使用 `quyan:relay:ListManagementChannels` 检查每个 `acs:platform:*:platform:relay-channel/<channelId>`。记录、分页和总数只包含既有可见性与筛选规则下获准查看的渠道；被拒绝的父渠道名称和成员引用会被隐藏。模型筛选只使用获准的渠道池路径，并保留严格子渠道设置覆盖重复旧成员关系的规则；被拒绝的叶渠道不能贡献模型能力。此 Action 授予列表访问权限，渠道修改和交付需要各自的 Action；仍需部署管理员设置的管理资格。加载过程中权限变化时需要刷新重试。

## IAM 渠道健康访问

启用 IAM 强制授权后，独立渠道健康概览使用 `quyan:relay:ListChannelHealth`，详情使用 `quyan:relay:GetChannelHealth`，自动池健康列表使用 `quyan:relay:ListAutomaticPoolHealth`。资源均为 `acs:platform:*:platform:relay-channel/<channelId>`。详情和自动池读取还要求对返回渠道及参与展示的每个成员具有 `quyan:relay:ReadChannelPoolHealthMetadata`。健康访问权限不授予渠道配置或上游密钥访问权限。

概览要求部署全局组中的 `RELAY_CHANNEL_HEALTH_READ` 资格；详情和自动池读取还要求 `RELAY_CHANNEL_POOL_METADATA_READ` 资格。账号所属组、用户附加权限及通配符策略不能自行创建这些平台资格。既有可见性规则仍然有效，策略授权不能让隐藏成员变得可见。

列表和自动池成员只包含逐资源获准且可见的资源。成员健康、名称、分数和展示排名基于这个授权子集，不能作为自动池全局完整拓扑的证明。已停用或供应商暂停服务但尚未删除的渠道仍可用于诊断，并保留原有停用及可选性标记。手动健康覆盖值和排名阈值维持原有配置语义。详情不存在或被拒绝均返回 403；加载期间权限或相关配置变化时拒绝返回结果。这些无 scope 接口不接受 OAuth Token。legacy/shadow 保留原有业务读取，shadow 观察不会再次读取健康或配置内容。

### 修改健康追踪设置

启用 IAM 强制授权后，`PATCH /v1/relay-channels/{id}/health-config` 与 `PATCH /v1/relay-channels/health/batch-config` 都要求对**每个**目标渠道 ARN 具有 `quyan:relay:UpdateChannelHealthConfig`。部署全局组中的 `RELAY_CHANNEL_UPDATE` 资格与既有可见性规则仍然有效。仅支持独立渠道，包括已停用的渠道；不接受 OAuth 令牌。二次验证与重放保护保持不变。

任一目标被拒绝、不存在、已删除或不合法时，整批失败，不会部分写入。非健康相关的路由配置及凭据保留不变。手动模式必须提供可用率和延迟，自动或禁用模式会清除手动覆盖值。单项写入仅返回健康统计，不返回渠道配置或凭据，也不额外要求健康读取 Action。提交前检测到授权或相关配置变化时回滚写入。legacy/shadow 保持原有写入行为，shadow 观察不会重复写入。

### 清空采集的健康统计

启用 IAM 强制授权后，单项和批量清除都要求对**每个**目标 `acs:platform:*:platform:relay-channel/<channelId>` 具有 `quyan:relay:ClearChannelHealth`，并具备部署全局组中的 `RELAY_CHANNEL_UPDATE` 资格。清除权限独立于健康配置修改和健康读取权限。既有可见性规则、二次验证及重放保护保持不变。仅接受未删除的独立渠道，包括已停用渠道；这些无 OAuth scope 的接口不接受 OAuth 令牌。任一目标不存在、已删除、被拒绝或属于池类型时，整批都不会调用 Redis。

不可撤回的操作执行前及接受响应前都会复核授权。最终授权复核失败时，可能在统计**已经清除后**拒绝响应。审计区分“已确认清除”和“存储结果不确定”，并记录请求是否最终被接受，不会声称旧统计已恢复。legacy/shadow 保留原有业务清除，shadow 观察不会额外清除一次。

清空统计不会修改追踪模式或手动覆盖值。批量操作通过一次 Redis 操作清除所有选中渠道保留的时间桶，不再逐渠道独立删除。不影响其他渠道及请求样本去重记录；后续流量可能立即产生新的统计。

Redis 清除不可撤回，数据库事务不能将其回滚。存储连接在确认前失败时，请求会返回错误，但操作可能已完成。请刷新健康视图确认当前状态，不要将错误理解为旧统计已被恢复。

## IAM 渠道配置访问

启用 IAM 强制授权后，`GET /v1/relay-channels` 使用 `quyan:relay:ListChannels`；`GET /v1/relay-channels/{id}` 使用独立的 `quyan:relay:GetChannel`。两者均针对 `acs:platform:*:platform:relay-channel/<channelId>`，并要求操作者具有部署全局组中的 READ 或 REVIEW 资格。仅绑定账号策略不能获得该资格。列表授权不自动授予详情、修改、导出或密钥访问权限。

列表只返回逐项获准且符合业务可见性规则的渠道。被拒绝的父渠道和成员引用会被隐藏；被拒绝或不可见的叶渠道不能贡献池的模型能力。默认列表排除已停用渠道和供应商暂停服务的渠道；`includeDisabled=true` 可包含其配置。详情可显示停用渠道的元数据，但不会宣称其具有活跃能力。密钥字段只返回是否已配置的布尔值，不返回密钥内容。嵌套路由、可见性和倍率配置仅返回已注册字段。旧 JSON 中的未知字段会被忽略，不会因读取而修改保存的配置；已注册字段的值无效时拒绝读取或更新响应，不返回异常的私有数据。管理员配置仍保留合法的重试表达式和模型映射。

列表保留 OAuth 渠道读取 scope 要求；无 scope 的详情接口不接受 OAuth Token。AccessKey 和角色会话使用其原有授权，并在返回前复核。详情不存在或无权访问均返回相同的 403。加载期间身份、策略、可见性、成员关系或会话权限变化时，需要刷新重试。legacy/shadow 保留原有业务读取；shadow 不会额外读取第二份配置内容。

## 页面用途

- 调整全局转发策略和基础限流行为。
- 维护监控展示名称与状态页映射。
- 配置模型价格与支持格式。
- 创建独立渠道、混池渠道或自动代理池。
- 为渠道设置可见性、路由策略、上游凭据和计费倍率。

## 批量启用与停用渠道

在 IAM enforce 模式下，单渠道切换和批量启停对每个选中的 `acs:platform:*:platform:relay-channel/<渠道ID>` 检查 `quyan:relay:SetChannelStatus`。操作者必须通过启用中的部署级全局组具备 `RELAY_CHANNEL_UPDATE` 管理资格；账户自建组、用户附加权限或通配符策略不能自行赋予此资格。角色会话仅使用角色自身授权，并受相同管理资格上限约束。

请求需包含 1–200 个互不重复、存在且未删除的渠道 ID，以及 JSON 布尔值 `enabled`（`true` 或 `false`，不能使用字符串 `"false"`）。全部选中资源都必须获准；任一渠道被拒绝或不存在，或提交前资源、身份、策略、AccessKey、OAuth、角色会话权限发生变化时，整个批次不生效。OAuth 应用与访问令牌必须保留渠道更新 scope。此接口只返回数量，不读取凭据，也不要求渠道读取权限；不会解绑 Token、改变混池成员或服务提供资格。重放保护和二次验证继续有效。legacy/shadow 保留原有授权行为，shadow 不会额外执行第二次状态写入。

## 全局设置

### 全局倍率

- 作用：作为所有渠道价格倍率之前的一层总倍率。
- 影响：最终计费通常会受到“全局倍率 × 渠道倍率 × 分时倍率”共同影响。
- 建议：
  - 日常调价优先使用模型价格或渠道倍率。
  - 只在需要整体抬高或压低全站成本时修改全局倍率。

### 队列开关、最大并发、队列超时

- 作用：控制请求过载时是排队等待还是更快失败。
- 影响：
  - `最大并发` 越小，越容易进入队列，但对上游更温和。
  - `队列超时` 越短，用户越快收到失败；越长，用户等待越久。
- 建议：
  - 对上游额度紧张或容易触发限流的环境，优先保守配置。
  - 生产环境改动后观察状态页与错误率。

### 上游流式超时

- 作用：限制单个流式请求在上游持续占用连接的最长时间。
- 影响：超时过短会中断长回答，过长则会增加慢请求占位时间。

### 监控名称映射

- 作用：把状态页上的监控 ID 映射成管理员更容易识别的显示名称。
- 影响：只改变展示，不改变真实路由逻辑。

页面分别加载中转配置和自定义密钥配置，未能加载的配置组会禁用，保存时不会提交其字段。保存只发送已修改的中转字段，因此修改队列设置不会替换未修改的价格。零价有效；修改价格仍会替换完整有效列表，包括读取权限未展示的记录。若一组配置保存成功、另一组失败，页面会明确提示部分成功，重试时只提交尚未保存的变更。

### 全局配置保存权限

IAM 强制模式下，保存全局设置使用 `quyan:relay:UpdateConfiguration`，需要真实全局组中的 `MODEL_PRICING_UPDATE` 资格，并允许 `acs:platform:*:platform:relay-configuration/default`。

尚未保存配置时，已授权的保存会以读取接口提供的默认设置为基础创建配置，读取本身不会创建配置。并发首次保存会在提交前重新检查；授权被拒绝或保存失败时，不会留下部分配置。

`modelRates` 的含义是替换有效价格列表：省略该字段会保留现有价格；提供空数组会删除全部有效价格；提供列表会更新已有模型、以原 ID 恢复已删除模型、创建新模型，并删除未列出的有效模型。每个受影响记录，包括未列出的删除目标，都需要允许其 `acs:platform:*:platform:model-pricing/<记录 ID>`。新建还需要允许 `acs:platform:*:platform:model-pricing-control/default` 和生成后的实际记录 ARN。

任一资源被拒绝、配置或价格快照过期、权限或角色会话变化时，整个保存失败，不部分更新。严格渠道拓扑切换仍须通过拓扑检查。重复模型名称、无效计价方式或支持格式会被拒绝；按次计费的固定价格可以为零。2FA 验证和重放保护继续适用。

保存成功后的价格列表按 `quyan:relay:GetConfiguration` 逐记录检查读取权限，没有价格读取权限时可返回空列表；这不表示已有价格被删除。保存权限不自动授予价格读取权限。

### 全局配置读取权限

IAM 强制模式下，读取全局设置使用 `quyan:relay:GetConfiguration`，需要真实全局组中的 `MODEL_PRICING_UPDATE` 资格，并允许配置资源 `acs:platform:*:platform:relay-configuration/default`。配置权限与模型价格权限分别判断：价格使用 `acs:platform:*:platform:model-pricing/<记录 ID>`，返回结果只包含获得授权的记录。只允许配置时，价格列表可以为空；只允许价格时，不能读取全局配置。匹配的 Deny 优先。

尚未保存配置时，已授权的读取返回默认设置，不自动创建配置。读取期间资格、策略、角色会话或已授权内容发生变化时，请求失败；存储不可用时不会用默认配置代替成功结果。配置读取权限不包含保存权限。

### 模型定价导出权限

IAM 强制模式下，定价导出需要真实全局组中的 `MODEL_PRICING_READ` 资格，使用 `quyan:model_pricing:ExportModels`，资源为 `acs:platform:*:platform:model-pricing/<记录 ID>`。导出仅包含获得授权的实际记录，匹配的 Deny 优先；读取期间价格、资格、策略或角色会话变化时不会返回导出结果。AssumeRole 只使用角色自身授权。公开模型价格列表继续按原有方式访问。

### 模型定价写入权限

单条新增、更新和删除需要真实全局组中的 `MODEL_PRICING_UPDATE` 资格，分别使用 `quyan:model_pricing:CreatePricing`、`quyan:model_pricing:UpdatePricing` 和 `quyan:model_pricing:DeletePricing`。新增同时检查 `acs:platform:*:platform:model-pricing-control/default` 及实际记录 ARN；更新、删除使用实际记录 ID。恢复已删除模型沿用原 ID，资源上的 Deny 仍有效。

目标价格、身份、资格或授权在保存前变化时，操作失败且不会部分保存。计价方式及支持格式须有效；切换为按次计费需要固定价格，固定价格可以为零。不存在或未授权的修改目标在 IAM 强制模式下返回 403。2FA 验证和重放保护继续适用。

### 模型定价批量导入权限

批量导入使用 `quyan:model_pricing:ImportPricing`，需要真实全局组中的 `MODEL_PRICING_UPDATE` 资格，同时授权固定创建范围和所有受影响记录的 ARN。新模型在保存前使用生成后的实际记录 ARN 再次检查；已删除模型沿用原 ID 恢复，原有 Deny 继续有效。任一记录被拒绝、价格快照过期或授权变化时，整批回滚，不跳过失败项。

单次最多导入 499 个不同模型；去除首尾空格后的重复名称、未知字段及无效计价方式或格式会被拒绝。新模型未指定计价方式时使用按 Token 计费；现有模型保留未指定的计价方式。明确提供的固定价格和支持格式会随导入保存。2FA 验证和重放保护继续适用。

## 渠道配置总览

每个渠道都代表一条可被令牌或系统路由使用的逻辑出口。渠道分为三类：

- `独立渠道`：直接连接真实上游，持有 URL 和 API Key。
- `混池渠道`：把多个已存在渠道组合成一个用户侧只看到一个名称的逻辑渠道。
- `自动代理池`：由管理员或自动化程序统一维护成员、供令牌以自动代理模式选择的特殊逻辑渠道。

### 渠道名称

- 作用：管理员和用户看到的渠道标识。
- 影响：在令牌绑定、日志、详情页、编排页中都会显示。
- 建议：名称体现用途而不是供应商内部细节，例如“OpenAI 主生产池”“Claude 备用低成本池”。

### 渠道类型

#### 独立渠道

- 适用场景：一个上游地址、一套凭据、单一路由出口。
- 影响：需要配置至少一种格式对应的真实上游 URL 与 API Key。

#### 混池渠道

- 适用场景：多渠道故障切换、按权重分流、隐藏多个真实渠道细节。
- 影响：
  - 用户与令牌侧通常只看到这个逻辑渠道。
  - 真实流量由混池成员承载。
- 混池自身不直连上游，不保存实际 upstream 凭据。
- 在严格双层拓扑中，可以直接点击“添加物理成员”，从物理成员列表中批量选择并保存。
- 在旧版拓扑中，从独立渠道选择成员；保存会更新该混池自己的成员列表，并可在编辑器中删除成员。
- 在严格双层拓扑中，保存会将选中的渠道转换为物理成员并归入该逻辑混池，再按列表顺序写入优先级、权重和启用状态；移动成员到其他逻辑混池时，从目标混池编辑器重新选择即可。

#### 自动代理池

- 适用场景：希望统一维护底层渠道，而不要求每个 Token 随成员变动重新编排渠道顺序。
- 成员：可同时加入逻辑混池渠道和独立渠道；不能加入混池物理成员或其他自动代理池。
- 路由与计费：请求由实际命中的成员执行；成员的模型价格、渠道倍率和分时倍率参与计费，Token 所属用户承担费用。
- 可见性：Token 用户只选择自动代理池本身，不查看或编辑其成员。

## 混池成员与路由策略

### 混池成员

- 成员渠道：混池可调用的底层渠道。
- 旧版成员：旧版拓扑以混池编辑器保存成员关系；可直接在编辑器中删除成员。
- 物理成员：严格双层拓扑的物理成员只归属于一个逻辑混池。管理列表会显示其所属逻辑混池，而不是显示成员数量。
- 成员关系：系统会同时识别已有旧版成员关系和严格双层关系；同一成员同时存在两种关系时，以严格双层配置的优先级、权重和启用状态为准。
- 优先级：数字越小越靠前，主要影响优先级故障切换类策略。
- 权重：主要用于加权随机策略，值越大被选中的概率越高。
- 启用状态：关闭后该成员不会参与当前混池调度。

建议：

- 主生产渠道放在更高优先级。
- 明显容量更高或成本更低的渠道可以给更高权重。
- 临时排障时优先关闭成员，而不是直接删除。

### 路由策略

#### 优先级故障转移

- 行为：优先尝试最靠前成员，失败后再切到后续成员。
- 适用：主备结构最清晰、最容易控制成本。

#### 随机

- 行为：每次随机选一个可用成员。
- 适用：多个上游能力接近，追求自然分散流量。

#### 加权随机

- 行为：按权重比例分配请求。
- 适用：需要显式控制分流比例，例如 80% 主渠道、20% 备用渠道。

#### 轮询

- 行为：请求按顺序轮流落到不同成员。
- 适用：渠道性能接近，希望均匀铺开流量。

#### 健康度优先

- 行为：优先选择健康评分更高的成员。
- 适用：你已经建立稳定健康监控，且更看重可用性。

#### 低延迟优先

- 行为：优先选择最近表现更快的成员。
- 适用：对交互响应时间比较敏感的场景。

## 路由参数

页面会预填推荐值，适合大多数混池场景；管理员仍可根据业务调整。

### 最大渠道切换次数

- 推荐默认值：`2`
- 作用：一共最多再尝试几个不同成员渠道。
- 影响：值太小会导致后面的渠道永远没有机会被尝试；值太大则可能放大单次请求延迟。
- 建议：
  - 3 个成员以内通常 `2` 足够覆盖主要主备链路。
  - 如果混池成员更多且顺序很重要，可适当提高。

### 单渠道重试次数

- 推荐默认值：`0`
- 作用：同一成员失败后是否先在该成员继续尝试。
- 影响：
  - `0` 表示失败后尽快切到下一个成员。
  - 更高的值表示更信任单个上游的短暂波动恢复能力。
- 建议：对常见上游 API，优先保持 `0`，减少把失败时间浪费在同一个已异常节点上。

### 触发切换规则

- 推荐默认值：`4xx`、`5xx`
- 作用：决定什么样的上游结果会触发切换或重试。
- 影响：
  - `5xx` 覆盖大部分上游内部错误。
  - `4xx` 可以覆盖限流、鉴权失败或参数不被接受等场景。
- 建议：
  - 大多数环境保留默认值即可。
  - 如果你不希望参数类错误触发切换，可去掉 `4xx` 并只保留更精细规则，例如 `429`、`5xx`。

### 回切冷却时间（分钟）

- 推荐默认值：`5`
- 作用：切换到后续渠道后，后续请求在一段时间内继续优先使用当前渠道，不立刻回到前面的主渠道。
- 影响：避免主渠道刚恢复时来回抖动。
- 建议：主备结构通常保留几分钟冷却较稳妥。

### 健康度阈值

- 推荐默认值：`0`
- 作用：只让健康度达到阈值的成员参与优先选择。
- 影响：阈值越高，越可能把波动中的渠道排除在外。
- 建议：`0` 表示不过滤健康分，适合作为保守默认值；仅在你明确理解健康评分来源时再进一步抬高。

### 延迟阈值（ms）

- 推荐默认值：`30000`
- 作用：限制参与低延迟优先策略的成员延迟上限。
- 影响：过低会导致大量成员被排除，过高则失去筛选意义。
- 建议：`30000ms` 适合作为宽松默认值，先避免把正常渠道过早排除，再按实际链路延迟逐步收紧。

### 熔断阈值

- 推荐默认值：`5`
- 作用：达到指定失败阈值后，短时间内视为该成员不适合继续承接请求。
- 影响：可降低已明显异常节点对整体成功率的拖累。
- 建议：`5` 适合作为常见 API 上游的起点，既不会因为偶发一次失败就切走，也不会长时间容忍持续异常。

### 按模型粘性路由

- 推荐默认值：`关闭`
- 作用：同一模型请求尽量稳定落在同一成员。
- 影响：有利于缓存、同模型行为一致性和问题复现。
- 建议：默认关闭，只有当你确实需要模型级一致性或缓存收益时再开启。

### 按格式粘性路由

- 推荐默认值：`关闭`
- 作用：同一请求格式（如 OpenAI、Anthropic、Gemini）尽量稳定落在同一成员。
- 影响：适合不同底层渠道对不同协议兼容度不完全一致的情况。
- 建议：默认关闭；当不同协议在不同成员上的兼容性明显不一致时再开启。

## 可见性配置

### 公开

- 作用：所有具备相应使用路径的用户都可看到并使用此渠道。
- 适用：标准生产渠道。

### 私有

- 作用：普通用户不可见，通常用于管理员测试、迁移、演练或灰度。
- 适用：临时验证新上游、内部压测、敏感渠道调试。

### 白名单

- 作用：只有指定用户、用户组、角色才能看到此渠道。
- 适用：定向试用、内测、分层客户、专属供应商线路。

#### 用户白名单

- 影响：直接把可见权限授予具体用户。
- 建议：适合小范围点对点测试。

#### 用户组白名单

- 影响：组内成员统一获得可见权限。
- 建议：适合部门、租户、套餐档位等长期管理场景。

#### 角色白名单

- 影响：具备对应 RAM 角色的主体可见。
- 建议：适合通过角色体系统一控制能力边界。

说明：页面会尽量加载用户、用户组和角色列表，管理员也可以直接手动输入未出现在列表中的 ID。

## 格式与模型限制

### 允许格式

- 作用：声明渠道能接受哪些协议格式请求。
- 影响：
  - 只勾选的格式才会在该渠道上被视为可用。
  - 独立渠道会据此要求相应上游 URL 与 API Key 完整可用。

### 模型白名单

- 作用：限制此渠道只接受指定模型。
- 影响：
  - 开启限制后，不在名单内的模型不会落到此渠道。
  - 混池场景下，这会直接影响候选成员集合。
- 建议：当某个上游只支持特定模型、或者你要控制成本时再启用。

### 批量探测并应用模型

渠道管理的批量操作提供“批量探测模型”。选择渠道后，可以分别手动探测 OpenAI、Anthropic、Gemini 上游的 `/v1/models`：

- 仅能选择和应用的模型必须有全局定价；未匹配模型会保留显示但不可选择。
- 应用采用按渠道合并：只把该渠道实际探测到且被选中的模型加入现有限制，不会移除旧模型，也不会给不支持该模型的渠道写入。
- 缺少某格式上游地址或凭据的渠道会标记为跳过，单个渠道探测失败不会中断其他渠道。
- 探测结果只在当前弹窗中使用，不会持久化保存。

自动代理池的“添加成员”窗口可以按渠道当前有效的模型限制筛选候选渠道：

- 支持“任一匹配”和“全部匹配”；默认任一匹配。
- 多选渠道并确认加入后，筛选模型会合并到自动代理池的池级手动模型限制。成员渠道自身的模型限制不会被改写。
- 设置为“全部模型”或“根据混池成员推断”的渠道会按已配置定价匹配全部模型，这不代表上游真实支持这些模型。需要准确筛选时，应先用批量探测把真实支持的模型写入渠道限制。

## 上游配置

### OpenAI / Anthropic / Gemini 上游 URL

- 作用：指定请求实际发往哪个服务端点。
- 影响：URL 决定真实供应商、代理层或私有网关。

### API Key

- 作用：渠道访问对应上游时使用的凭据。
- 影响：凭据缺失或无效会直接导致对应格式请求失败。

建议：

- 一个独立渠道只配置自己真正需要承载的格式。
- 不要把测试凭据放在面向生产用户公开的渠道上。

## 计费与映射

### 渠道倍率

- 作用：在全局倍率之外，对单个渠道再做一层价格调整。
- 影响：适合表达“这个上游更贵”或“这个专属通道需要额外溢价”。

### 输入 Token 包含缓存读取

- 作用：处理某些上游把缓存读取 Token 已经并入 input tokens 的情况。
- 影响：开启后会避免重复计费；关闭则完全按上游回传数字计费。
- 建议：只有在你确认上游计数字段包含 cache read 时才开启。

### 模型映射

- 作用：把请求模型映射到另一个计费或路由目标模型。
- 影响：
  - 可用于兼容上游别名。
  - 可用于把多个近似模型统一到一个计费项。
- 风险：映射配置错误会导致计费模型与真实请求模型不一致。

## 分时倍率

- 作用：在特定星期与时间段，对该渠道应用额外倍率。
- 适用：晚高峰加价、夜间优惠、工作日/周末策略区分。
- 影响：命中的时间规则会进一步改变渠道最终价格。

建议：

- 规则名称写明业务含义，例如“工作日晚高峰”。
- 先确认时区，再发布给生产用户。

### 中国节假日条件与全天倍率

在渠道的分时倍率规则中，可以选择：

- **不区分节假日**：保留原有星期筛选和服务器本地时区行为。
- **排除节假日**：所选星期、时间段都匹配，且当天不是中国节假日时生效。
- **仅节假日**：仅在中国节假日生效，忽略星期选择，但仍遵守时间段。
- **全天**：忽略起止时间，覆盖当天的全部时间，包括 23:59。

“排除节假日”和“仅节假日”按北京时间（Asia/Shanghai）判断日期、星期和时段。节假日包含年度日历公布的连休放假日期。补班标记不会把周六、周日转换为周一至周五。跨午夜时段使用请求发生当天的日期判断。

**DeepSeek 峰谷配置示例**：渠道基础倍率设为空闲倍率；新增忙时规则，选择周一至周五、实际忙时时间段和“排除节假日”，规则倍率填写“忙时价格 ÷ 空闲价格”。这样周末（包括调休上班的周末）及节假日全天保持基础倍率。请自行填写适用的价格和时间，不会自动修改现有渠道。

非全天时段规则的起止时间必须不同；起止相同的历史规则继续视为不命中，编辑时请改为“全天”或设置实际时段。

多条规则同时命中时倍率相乘，不是覆盖；不要重复添加重叠的节假日折扣规则。规则可在管理端、供应商渠道编辑及批量编辑中配置。

日历由后端从外部年度日历服务获取，正常每天刷新，使用 Redis 缓存与进程内快照，预取下一年度；计费不会等待外部接口。同步失败保留最后有效日历。如果当年没有任何有效日历，则跳过依赖节假日的规则并记录告警，普通规则和渠道基础倍率仍生效。首次启动缓存未就绪时也适用这一降级行为；年度日历尚未发布时不会猜测日期。运维应关注后端节假日日历告警。

## 管理建议

## 渠道供应与分成

管理员可以在渠道编辑器中查看审核状态、追加多位提供者，并分别设置 0% 到 100% 的分成比例和结算方式。比例总和允许超过 100%，页面会显示平台补贴提示；收益按实际执行渠道和消费发生时的比例快照结算。用户提交独立渠道和查看收益请使用“渠道供应与收益”页面。

1. 对外生产流量优先使用“混池渠道 + 优先级故障转移 + 少量主备成员”。
2. 把“私有”或“白名单”作为测试渠道默认可见性，避免用户误用。
3. 当上游兼容性不完全一致时，优先用模型白名单和格式限制缩小风险面。
4. 先确定计费策略，再同时检查全局倍率、渠道倍率和分时倍率，避免叠加过高。
5. 每次修改混池路由后，都应观察切换日志和状态页，确认故障切换符合预期。

## 资源级渠道启停

单渠道切换和批量启停使用相同的 `quyan:relay:SetChannelStatus` 及平台渠道 ARN。单渠道切换在一个已授权事务内读取当前状态并反转，不接受客户端指定状态或 Action；返回的安全配置也在同一事务内复核。响应不包含上游凭据值，混池能力仅包含另行获准的关联渠道。只返回数量的批量操作不要求披露渠道配置的权限。

身份、策略、角色会话、AccessKey、授权模式或最终目标发生变化时，整个修改都会取消。单渠道切换保留二次验证和重放保护，不接受 OAuth Token。现有 `RELAY_CHANNEL_UPDATE` 权限自动映射到该 Action；仅使用旧账号级 `quyan:relay:channel:Update` 别名的 JSON 策略，需要显式授权平台 Action 和 ARN。legacy/shadow 模式仅执行一次原业务写入，shadow 不会额外生成原生配置响应。

## 资源级渠道删除

启用 IAM 强制授权后，单个与批量删除渠道都需要对每个目标拥有 `quyan:relay:DeleteChannel`，资源为 `acs:platform:*:platform:relay-channel/<channelId>`。这些渠道是部署共享资源，不使用调用者账号的 ARN。调用者还必须具备部署管理组赋予的渠道删除资格，不能通过账号策略自行获得该资格。二次验证和重放保护仍然生效。

使用旧 `quyan:relay:channel:Delete` 别名和账号内渠道 ARN 的策略，需要先改为上述 Action 与平台 ARN，才能用于原生授权操作。旧 `RELAY_CHANNEL_DELETE` 权限会自动映射；JSON 策略不会仅因资源 ID 相同就自动获得新的平台权限。

请求中的所有渠道都必须通过授权且仍然存在。任一目标被拒绝、不存在、已删除或发生变化，整个请求都会取消。删除与必要的路由引用清理一起提交：清空直接渠道和自动池的令牌引用，移除相关渠道配置及池成员关联，并停用已删除渠道的有效变更申请。无关渠道和历史提供者、收益记录不会被删除。删除权限不授予读取令牌值、上游密钥或其他渠道配置的权限。迁移期间，legacy/shadow 模式仍执行原有业务删除，shadow 评估不会重复删除。

## 资源级批量模型限制

启用 IAM 强制授权后，应用批量模型限制使用 `quyan:relay:ApplyChannelModelRestrictions`，必须对每个目标渠道资源 `acs:platform:*:platform:relay-channel/<channelId>` 授权，包括最终因模型业务校验未通过而不更新的目标。操作者仍须具有部署管理的渠道更新资格；账号策略不能自行授予该资格。二次验证和防重放要求不变。

系统先检查全部目标权限，再按渠道合并已配置定价的模型。手动限制保留现有模型，池的自动模式则切换为本次选择的手动范围，并保留其他路由设置。模型不存在、多个定价名称对应相同请求模型身份或历史限制结构异常时，该渠道返回安全的单项失败，其他合法渠道仍可更新。响应中的单项原因不回显任意用户输入或内部异常。

任意目标被拒绝、身份或权限变化、模型目录变化，或响应数据在操作期间变化，都会让整批操作回滚，而不是仅跳过一个目标。该操作不改变渠道启停、提供者暂停、可见性、密钥、提供者收益配置或 Token 分配。响应不包含密钥值；池的关联能力仅在相关资源授权后展示。旧 `RELAY_CHANNEL_UPDATE` 自动映射为新 Action；legacy/shadow 模式仍只执行一次原有业务写入。

## 资源级批量上游模型查询

启用 IAM 强制授权后，批量查询上游模型需要对**每个**目标 `acs:platform:*:platform:relay-channel/<channelId>` 拥有 `quyan:relay:BatchListUpstreamModels`。操作者还必须保留部署侧授予的渠道更新资格；仅有账号策略不能获得平台管理资格。该操作不授予读取或导出上游凭据及其他渠道配置的权限。

- 所有目标授权通过后，才会读取保存的凭据或发送上游请求。目标不存在、已删除、被拒绝或使用非规范标识时，整批请求失败。
- 只使用所选 OpenAI、Anthropic 或 Gemini 配置。配置不完整时标记为跳过，不会借用其他协议的密钥。上游错误按渠道报告，不返回私有响应体或凭据值；结果顺序与请求渠道顺序一致。
- 每次发送前以及整批返回前，都会重新检查身份、角色会话、AccessKey、策略、请求条件、渠道配置和模型目录。撤销或相关变更会取消全部结果，不会被转换为单个渠道的网络错误。已经发出的请求无法撤回；检测到变更后停止后续排队发送。等待上游响应期间不持有数据库事务。
- legacy/shadow 迁移模式保留原有业务执行。shadow 授权检查不会额外读取一份保存的密钥，也不会重复发送上游请求。

## 资源级单渠道上游模型查询

启用 IAM 强制授权后，单次查询使用 `quyan:relay:ListUpstreamModels`。服务端只选择一个资源范围：

- **本人提交的独立渠道：** `acs:relay:*:<accountId>:channel-submission/<本人用户ID>/<channelId>`。即使操作者同时是平台管理员，也使用这个范围；不能在该范围命中 Deny 后改用平台 ARN 放行。
- **其他已保存的渠道，或非独立渠道：** `acs:platform:*:platform:relay-channel/<channelId>`。除策略 Allow 外，还需要部署侧授予的审核或更新资格；仅有提交资格不够。
- **不带渠道 ID、使用临时 URL 和凭据的预览：** `acs:quyan:*:<accountId>:account`，账号来自认证上下文。此分支不读取任何已保存渠道的凭据，不保存临时凭据，也不授予读取已保存渠道的权限。明确的账号级策略可单独授予预览能力，无需平台管理资格。

带有渠道 ID 时始终使用该渠道的已保存配置；附加的 URL/密钥字段不能覆盖目标，渠道不存在或被拒绝时也不会退回临时预览。所选协议配置不完整时直接失败，不会借用其他协议的密钥。

读取保存的密钥前、实际发送前和返回结果前，服务端检查当前权限及最初选择的资源分支。角色会话或 AccessKey 撤销、归属变化、策略变化、所选配置或模型目录变化都会取消结果。已经发送的上游请求无法撤回。响应不包含密钥、私有上游错误体或其他渠道配置。legacy/shadow 模式只执行一次原有操作，shadow 不会重复探测。

## 服务器资源保护与审计正文

系统管理的服务器配置提供“AI 资源保护”高级面板，可动态调整全站 AI 并发、等待、RSS、上传、响应、审计和连接池预算。保存后本进程立即生效，其他进程最多 5 秒同步；运行中的请求保留开始时的内容预算。每用户并发和图片作用域仍独立执行。

旧资源环境变量仅在尚未保存管理配置时兼容回退。审计正文继续脱敏保存；积压时可能省略正文或丢弃记录并告警。审计日志不能代替计费记录。

### 消费端渠道目录权限

在 IAM 强制模式下，`GET /v1/relay-channels/catalog` 使用 `quyan:relay:ListChannelCatalog`，逐个检查 `acs:relay:*:<当前账号ID>:channel-selection/<渠道ID>`。这是部署渠道的消费端视图权限，不是管理渠道或读取上游配置的权限。账号级资源不能替代具体渠道视图授权。账号由认证身份确定，客户端 Action 请求头不能改变操作。

对于渠道池，需要授权池根节点以及应当参与展示能力和价格区间的各个成员。被拒绝、隐藏、禁用、提供服务已关闭或不可见的成员，不会贡献模型或价格；允许池根节点不能绕过成员的 Deny。模型身份、支持协议与价格始终关联同一条已授权路径。目录不会返回成员身份、路由设置、凭据、上游地址或提供者身份，现有目录展示设置仍然生效。

读取目录不代表可以选择令牌渠道或管理平台渠道，这些操作分别需要自己的 Action。OAuth 调用还需要渠道读取 Scope。策略、角色会话、AccessKey 或 OAuth Scope 被撤销后，结果不再返回；授权或数据读取失败不会回退到不受限制的读取。legacy/shadow 模式保留原目录权限门槛，shadow 不会额外执行一次完整目录读取。

### 路由目录与用户预览

在 IAM 强制模式下，`GET /v1/relay-channels/routing-catalog` 会对展示或参与模型能力计算的每个 `acs:relay:*:<当前账号ID>:channel-selection/<渠道ID>` 检查 `quyan:relay:ListChannelRoutingCatalog`。这个消费端 Action 不授予平台渠道管理、凭据读取或令牌渠道选择权限。池根、逻辑成员和执行叶节点分别检查，允许根节点不能绕过成员 Deny。

路由目录保留屏蔽自动池路线所需的有限成员信息。成员名称、有效倍率及可用模型只来自已授权且可见的节点。即使两个逻辑成员共用执行叶节点，各成员的模型和协议也按照选定根节点下的完整独立路径计算。仅返回受支持的消费端路由字段，不返回内部配置、未知字段、凭据或上游地址。

省略 `targetUserId`、留空或填写自己的 ID 时，使用自己的正常视图。预览同账号内其他正常用户，还需要在 `acs:quyan:*:<当前账号ID>:user/<目标用户ID>` 上允许 `quyan:relay:PreviewChannelRoutingCatalog`。预览其他账号的用户，使用 `acs:platform:*:platform:user/<目标用户ID>` 上的 `quyan:relay:PreviewManagedChannelRoutingCatalog`，并且操作者必须具备部署管理的“读取他人 Relay 令牌”资格。个人策略或账号自建用户组不能自行取得这种平台资格。服务端依据已保存的账号归属选择唯一预览边界，同账号预览被拒绝后不会退回平台预览。

无论预览谁，操作者始终需要自己的渠道视图授权，渠道还必须对操作者和目标用户**双方可见**；隐藏、禁用或已关闭提供服务的节点仍不可用。目标用户的策略不会成为操作者的授权来源，预览也不会创建令牌或委派权限。返回前复查目标身份、账号归属、可见性相关用户组和角色、操作者策略及认证状态，发生变更或撤权时安全失败。OAuth 仍需原渠道读取 Scope；legacy/shadow 模式保留原权限门槛，业务读取只执行一次。

### 渠道选项与可选池详情

启用 IAM 强制授权后，`GET /v1/relay-channels/options` 对每个账户内的 `acs:relay:*:<yourAccountId>:channel-selection/<channelId>` 使用 `quyan:relay:ListChannelOptions`。展示的渠道以及参与能力计算的节点均需分别获得授权并保持业务可见。此选项接口可以包含物理成员；需要排除物理成员的终端用户选择器应使用路由目录。`excludePooled=true` 仅隐藏逻辑混池条目，不会删除自动池中已经授权的能力计算路径。

基础选项不提供渠道类型、成员身份、路由设置和逐成员价格。需要这些可选字段时，还需对相关渠道选择资源授予 `quyan:relay:ReadChannelOptionPoolMetadata`。这是受限的消费者能力，与平台拓扑审计或诊断权限分离。对成员的可选详情 Deny 会移除其拓扑和价格贡献，但不会代替或撤销独立授权的基础模型能力。不能绕过被拒绝的中间节点，披露共享执行叶节点。公开路由设置仅包含支持的字段；正则重试规则展示为等价 HTTP 状态码，而非原始规则文本。接口不返回凭据和上游地址。

预览其他用户还需对所选账户内用户授予 `quyan:relay:PreviewChannelOptions`；跨账户时，对平台用户使用 `quyan:relay:PreviewManagedChannelOptions`，并同时具备部署侧维护的其他用户令牌读取资格。操作者自身授权以及双方的业务可见范围始终生效；路由目录的预览授权不等于选项接口的预览授权。预览不授予令牌修改或平台管理能力。OAuth 仍需渠道读取 scope。

月卡模板指定渠道时，创建、编辑和发布会使用真实登录操作者的已授权渠道选项进行范围校验。模板写入 Action 不能替代渠道选项授权；不可用、被拒绝或没有有效模型能力的渠道不能作为有效范围保存。legacy/shadow 模式保留原有权限检查和兼容读取；enforce 不会退回到缺少请求上下文或不受限的读取路径。

### 可移植渠道导出

在**所有**授权模式下，渠道导出均不包含上游 URL、API Key、提供者身份或凭据。导出 JSON 是可移植配置模板，而不是密钥备份。导入独立渠道或物理成员前，需要为每个启用协议补充目标环境的上游地址及凭据；现有导入校验仍会拒绝缺少上游配置的输入。补充后的导入文件应按敏感信息保管，导出不会代为获取凭据。目标环境的提供者及分成配置应另行设置。

启用 IAM 强制授权后，操作者需要部署侧维护的 `RELAY_CHANNEL_EXPORT` 资格，并对导出中的每个 `acs:platform:*:platform:relay-channel/<channelId>` 获得 `quyan:relay:ExportChannels`。显式选择的根渠道必须全部获准。导出全部时会跳过无关的被拒绝根资源，但已获准的池必须具备完整且获准的依赖闭包：legacy 成员、strict 物理子节点及必要逻辑父节点均分别校验，包括已禁用的依赖。依赖不存在、业务不可见或被拒绝时，整个导出失败，不会生成残缺文件。同一成员同时存在 strict 和 legacy 关系时，以 strict 设置为准。此操作不授予渠道读取、修改、创建或凭据访问能力。

导出只包含已定义的可移植字段，未知嵌套字段会被移除。正则重试规则转换为等价 HTTP 状态码规则，不输出原始规则；较大集合使用仅由状态码生成的规范表达式，以保持规则数量上限。持久化配置无效、策略或管理资格变化、角色会话失效、AccessKey 撤销及请求条件变化都会阻止返回结果。操作仍要求二次验证和重放保护；此无 OAuth scope 的端点不接受 OAuth。shadow 只评估元数据授权，并执行一次兼容导出。旧导入文件仍可显式提供上游配置，但导出不会再输出这些字段。

## 资源级管理员渠道创建

启用 IAM 强制授权后，新建渠道使用 `quyan:relay:CreateChannel`。渠道 ID 由服务端生成，对应 `acs:platform:*:platform:relay-channel/<channelId>`；通常使用新建目标的匹配 ARN 授权。操作者还须具备部署管理的渠道创建资格，不能通过账号策略自行获得该资格。二次验证与防重放要求不变，不接受 OAuth Token。

新目标与已有引用分开授权：指定父池、成员或所需的间接引用时，还需对这些已有渠道授予 `quyan:relay:UseChannelCreationReference`。只允许创建任意新渠道不会自动允许访问任意已有渠道；只允许使用引用也不能创建渠道。操作目录、JSON Schema 与策略编辑器会显示这项跨资源依赖提示，提示本身不授予权限。

四种渠道类型均可创建，仍遵守严格双层模式、父子归属、自动池成员类型、循环及深度限制。父池仅用于确认物理成员归属时，不要求无关兄弟成员权限。配置服务商时，还须在 `quyan:relay:CreateChannel` 下授权 `acs:platform:*:platform:relay-channel-provider/<channelId>/<userId>`；不自动添加服务商，也不授予收款用户的身份管理权限。

管理员新建渠道以启用、已批准、服务商服务开启的状态开始，不产生个人提交或审核身份，不复制结算历史。上游凭据由本次已验证输入提供，响应只返回是否已配置，不返回凭据值。名称冲突、引用未授权、配置无效、安全上下文变化或审计失败时，创建整体取消；成功日志与渠道同事务提交。legacy/shadow 模式只执行一次原创建写入，shadow 不额外保存新渠道。

## 资源级单渠道配置更新

启用 IAM 强制授权后，单渠道编辑使用 `quyan:relay:UpdateChannel`，资源为 `acs:platform:*:platform:relay-channel/<channelId>`。操作者还须保留部署管理的渠道更新资格；账号内的策略和附加权限不能自行建立该部署资格。使用旧账号级 `quyan:relay:channel:Update` 别名的 JSON 策略需要显式授权新的平台 Action 与 ARN。二次验证与防重放要求不变，不接受 OAuth Token。

渠道支持独立渠道、逻辑池、物理成员和自动代理池。修改拓扑时，所需的旧引用、新引用及父池都必须在同一 Action 下获准；仅修改物理成员权重不会要求无关兄弟成员的权限。逻辑池仍拥有物理子渠道时不能改为其他类型；自动池成员类型、循环引用和严格双层拓扑限制仍适用。渠道被中转令牌、OJ API Key 或月卡直接使用时不能隐藏。

更换服务商配置时，还需对被移除、保留或新增的收款关系拥有 `quyan:relay:UpdateChannel`，资源为 `acs:platform:*:platform:relay-channel-provider/<channelId>/<userId>`。停用及重新启用服务商保留原关系标识和结算历史；这不会授予收款用户的 IAM 身份管理权限。

未提交的凭据和关系保持不变。响应不包含凭据值，关联能力只显示另行获准的渠道。未知更新字段会被拒绝，客户端的 Action 或账号提示不能改变授权范围。授权、身份、会话、AccessKey、条件、安全配置或最终校验发生变化时，整个更新取消，不留下部分配置或关系变更。legacy/shadow 模式只执行一次原业务写入，shadow 不额外持久化新路径的修改。

## 资源级批量配置更新

启用 IAM 强制授权后，批量更新使用 `quyan:relay:BatchUpdateChannels`，必须对请求中的每个 `acs:platform:*:platform:relay-channel/<channelId>` 授权，包括最终因业务校验失败而不更新的渠道。操作者仍须具有部署管理的渠道更新资格。客户端提交的 Action 或账号提示不能改变授权边界；二次验证与防重放要求保持不变。

原有批量字段和计费模型迁移继续可用。迁移目标的上游请求模型标识必须与源模型相同；迁移更新渠道映射，保留其他已有映射。渠道仍被中转令牌、OJ API Key 或月卡直接使用时，不允许将其隐藏。普通业务校验失败按渠道返回，且不更改该渠道。授权失败、安全上下文变化、校验依赖不可用或最终响应无法安全授权时，整批取消并回滚，包括先前已经更新成功的渠道。

响应不包含上游凭据值。混池能力信息还要求在同一 Action 下拥有相关渠道权限。仅更新请求指定的批量字段，保留凭据、服务商、拓扑归属及提交者身份。使用旧账号级更新别名的 JSON 策略需要明确授予新的平台 Action。legacy/shadow 模式仍只执行一次原有写入路径。

批量配置和模型限制的拒绝原因使用本地化业务消息。不可预期的存储或校验异常只返回通用错误，不暴露原始异常文本、SQL 或凭据，legacy/shadow 模式也遵守此规则。认证或授权失败会拒绝请求，不会被报告为成功的部分处理。

## 资源级渠道复制

单个和批量复制需要对每个源渠道和复制配置所需的既有引用授予 `quyan:relay:DuplicateChannels`，并对服务端生成的新渠道单独授予 `quyan:relay:CreateChannelCopy`。资源格式为 `acs:platform:*:platform:relay-channel/<channelId>`。新渠道 ARN 可以使用匹配范围，但不会因此放开所有源渠道的复制权限。只授权源渠道或只允许创建副本均不足以完成复制；创建副本能力不会授予普通渠道创建或任意源的复制权限。操作者同时必须保留部署管理的渠道创建资格，账号策略不能自行授予该部署资格；二次验证与防重放要求保持不变。

操作目录和 JSON Schema 通过 `resourceDependencies` 描述这些跨资源检查，便于策略工具和 AI 草稿区分源访问与目标创建；这些元数据本身不会授予权限。

只复制已注册的配置字段，忽略旧 JSON 中的未知字段。复制在服务端保留上游配置和凭据，但不会将凭据值返回浏览器或放入导出文件。新渠道以启用、已批准的管理员创建状态开始。不会复制服务商、结算历史、提交者身份、审核历史或 IAM 授权关系。复制混池保留其配置的成员引用，不递归复制或移动成员渠道。物理成员仍归属于原逻辑父渠道；严格模式下的逻辑池子渠道仍留在原池，因此复制出的严格逻辑池不会带走这些子渠道。批量复制对每个源独立执行相同规则，不会在新副本之间重映射引用；需要重映射导出图时请使用导入流程。

单渠道更新和复制都会检查完整的相关图：循环引用或任意间接路径超出安全深度时拒绝操作；共享成员不能绕过深度检查。校验不展开仅用于确认物理成员归属的父池的无关成员。

未指定单个副本名称时自动生成唯一名称。源渠道或引用资源被拒绝、配置无效、名称冲突、安全上下文变化或最终响应无法安全授权时，整个复制操作取消，不留下部分渠道。响应只包含已授权的相关能力。使用旧账号级创建别名的 JSON 策略需要明确授予两项平台复制 Action；legacy/shadow 模式仍对每个源只执行一次原复制写入路径。

单渠道配置更新、批量配置更新和渠道复制的成功操作日志与业务变更一起提交。若最终授权检查失败，配置变更及该成功日志一并回滚；若无法写入这些操作的成功日志，请求失败，不会无日志地提交业务变更。

### 资源级原子化渠道导入

在 IAM 强制模式下，每次最多导入 200 份配置，需要对**所有由服务端生成的目标渠道**拥有 `quyan:relay:ImportChannels`。包含提供者配置时，还需要对每个目标渠道的提供者关系 ARN 拥有同一 Action。这不会授予已有渠道访问权：引用已有父渠道、成员及间接依赖，仍须单独获得 `quyan:relay:UseChannelCreationReference`。同一批导入的新渠道之间使用目标资源授权，不额外要求已有资源引用权限。

来源 ID 必须全部填写且唯一，或全部省略；来源 ID 只用于重映射引用，目标 ID 始终由服务端生成。父渠道先于物理子渠道创建，支持引用同批中尚未创建的成员，响应顺序与输入一致。重名配置自动添加副本后缀，禁用项保持禁用。已知的导出时间字段不会覆盖新资源的创建时间，未知字段会被拒绝。

整批操作全部成功或全部回滚：引用无效、拓扑不支持、资源授权不足、授权在操作中变化或审计保存失败，都不会留下部分目标或关系。返回的配置摘要不包含上游 API Key。导入与审计处于同一事务，也不会转移提交者身份或结算历史。legacy 和 shadow 模式保留旧兼容路径，不代表已经启用原子化 IAM 强制执行。
