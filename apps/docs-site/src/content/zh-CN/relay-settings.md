# 转发设置

此页面用于维护两类配置：

- 转发系统级行为，例如队列、监控映射、全局倍率和模型价格。
- 渠道级行为，例如上游地址、混池路由、白名单可见性、模型限制和分时倍率。

如果你要解决“某个用户能否看到某个渠道”“某个模型走哪个上游”“多个上游如何故障转移”这一类问题，核心都在这里完成。

## IAM 全局渠道拓扑审计

启用严格双层拓扑前，审计需要 `quyan:relay:AuditChannelTopology` 同时允许 `acs:platform:*:platform:relay-configuration/default` 和每一个未删除渠道的 `acs:platform:*:platform:relay-channel/<渠道ID>`。操作者还须具有部署全局组中的 `RELAY_CHANNEL_READ` 资格，且原有渠道可见性规则继续生效。任一参与审计的渠道或配置无权访问时，整个请求返回 403；不会把部分可见渠道的结果当成全局 `canEnableStrict` 结论。

审计包含停用但未删除的渠道，检查旧池成员、缺失或错误的父池、非成员渠道误设父池，以及自动池引用物理渠道等问题。只有完整拓扑无问题时才报告可以启用严格模式；读取期间授权、配置或拓扑变化会拒绝返回结果。此操作只读取拓扑字段，不读取上游凭据或模型价格，也不会创建默认配置。切换模式仍需另行具备全局设置修改权限。

## IAM 渠道修改申请列表

IAM 强制模式下，“我的修改申请”使用 `quyan:relay:ListMyChannelChangeRequests`，资源为 `acs:relay:*:<账户ID>:channel-change-request/<提交者ID>/<申请ID>`。结果仅包含当前提交者自己的申请；即使授权策略包含通配符，也不能读取同账户其他用户或其他账户的个人申请。

审核列表使用 `quyan:relay:ListChannelChangeRequests`，资源为 `acs:platform:*:platform:relay-channel-change-request/<渠道ID>/<申请ID>`。审核员仍须具有部署管理员设置的全局组 `RELAY_CHANNEL_REVIEW` 资格，账户自建组或策略不能自行赋予审核员资格。合格审核员可处理不同提交者的申请，但每条申请仍须获准访问。

两种列表都先按申请逐资源授权，再计算分页和总数；删除的申请或渠道不出现在结果中。配置只返回约定的公开字段和“是否已设置凭据”标志，不返回原始或加密凭据。角色会话只使用角色策略。读取期间身份、资格、策略或会话变化时，请刷新重试。

## IAM 渠道管理列表

启用 IAM 强制授权后，管理表格使用 `quyan:relay:ListManagementChannels` 检查每个 `acs:platform:*:platform:relay-channel/<channelId>`。记录、分页和总数只包含既有可见性与筛选规则下获准查看的渠道；被拒绝的父渠道名称和成员引用会被隐藏。模型筛选只使用获准的渠道池路径，并保留严格子渠道设置覆盖重复旧成员关系的规则；被拒绝的叶渠道不能贡献模型能力。此 Action 授予列表访问权限，渠道修改和交付需要各自的 Action；仍需部署管理员设置的管理资格。加载过程中权限变化时需要刷新重试。

## IAM 渠道健康访问

启用 IAM 强制授权后，独立渠道健康概览使用 `quyan:relay:ListChannelHealth`，详情使用 `quyan:relay:GetChannelHealth`，自动池健康列表使用 `quyan:relay:ListAutomaticPoolHealth`。资源均为 `acs:platform:*:platform:relay-channel/<channelId>`。详情和自动池读取还要求对返回渠道及参与展示的每个成员具有 `quyan:relay:ReadChannelPoolHealthMetadata`。健康访问权限不授予渠道配置或上游密钥访问权限。

概览要求部署全局组中的 `RELAY_CHANNEL_HEALTH_READ` 资格；详情和自动池读取还要求 `RELAY_CHANNEL_POOL_METADATA_READ` 资格。账号所属组、用户附加权限及通配符策略不能自行创建这些平台资格。既有可见性规则仍然有效，策略授权不能让隐藏成员变得可见。

列表和自动池成员只包含逐资源获准且可见的资源。成员健康、名称、分数和展示排名基于这个授权子集，不能作为自动池全局完整拓扑的证明。已停用或供应商暂停服务但尚未删除的渠道仍可用于诊断，并保留原有停用及可选性标记。手动健康覆盖值和排名阈值维持原有配置语义。详情不存在或被拒绝均返回 403；加载期间权限或相关配置变化时拒绝返回结果。这些无 scope 接口不接受 OAuth Token。legacy/shadow 保留原有业务读取，shadow 观察不会再次读取健康或配置内容。

### 修改健康追踪设置

启用 IAM 强制授权后，`PATCH /v1/relay-channels/{id}/health-config` 与 `PATCH /v1/relay-channels/health/batch-config` 都要求对**每个**目标渠道 ARN 具有 `quyan:relay:UpdateChannelHealthConfig`。部署全局组中的 `RELAY_CHANNEL_UPDATE` 资格与既有可见性规则仍然有效。仅支持独立渠道，包括已停用的渠道；不接受 OAuth 令牌。二次验证与重放保护保持不变。

任一目标被拒绝、不存在、已删除或不合法时，整批失败，不会部分写入。非健康相关的路由配置及凭据保留不变。手动模式必须提供可用率和延迟，自动或禁用模式会清除手动覆盖值。单项写入仅返回健康统计，不返回渠道配置或凭据，也不额外要求健康读取 Action。提交前检测到授权或相关配置变化时回滚写入。legacy/shadow 保持原有写入行为，shadow 观察不会重复写入。

### 清空采集的健康统计

启用 IAM 强制授权后，单项和批量清除都要求对**每个**目标 `acs:platform:*:platform:relay-channel/<channelId>` 具有 `quyan:relay:ClearChannelHealth`，并具备部署全局组中的 `RELAY_CHANNEL_UPDATE` 资格。清除权限独立于健康配置修改和健康读取权限。既有可见性规则、二次验证及重放保护保持不变。仅接受未删除的独立渠道，包括已停用渠道；这些无 OAuth scope 的接口不接受 OAuth 令牌。任一目标不存在、已删除、被拒绝或属于池类型时，整批都不会调用 Redis。

不可撤回的操作执行前及接受响应前都会复核授权。最终授权复核失败时，可能在统计**已经清除后**拒绝响应。审计区分“已确认清除”和“存储结果不确定”，并记录请求是否最终被接受，不会声称旧统计已恢复。legacy/shadow 保留原有业务清除，shadow 观察不会额外清除一次。

清空统计不会修改追踪模式或手动覆盖值。批量操作通过一次 Redis 操作清除所有选中渠道保留的时间桶，不再逐渠道独立删除。不影响其他渠道及请求样本去重记录；后续流量可能立即产生新的统计。

Redis 清除不可撤回，数据库事务不能将其回滚。存储连接在确认前失败时，请求会返回错误，但操作可能已完成。请刷新健康视图确认当前状态，不要将错误理解为旧统计已被恢复。

## IAM 渠道配置访问

启用 IAM 强制授权后，`GET /v1/relay-channels` 使用 `quyan:relay:ListChannels`；`GET /v1/relay-channels/{id}` 使用独立的 `quyan:relay:GetChannel`。两者均针对 `acs:platform:*:platform:relay-channel/<channelId>`，并要求操作者具有部署全局组中的 READ 或 REVIEW 资格。仅绑定账号策略不能获得该资格。列表授权不自动授予详情、修改、导出或密钥访问权限。

列表只返回逐项获准且符合业务可见性规则的渠道。被拒绝的父渠道和成员引用会被隐藏；被拒绝或不可见的叶渠道不能贡献池的模型能力。默认列表排除已停用渠道和供应商暂停服务的渠道；`includeDisabled=true` 可包含其配置。详情可显示停用渠道的元数据，但不会宣称其具有活跃能力。密钥字段只返回是否已配置的布尔值，不返回密钥内容。

列表保留 OAuth 渠道读取 scope 要求；无 scope 的详情接口不接受 OAuth Token。AccessKey 和角色会话使用其原有授权，并在返回前复核。详情不存在或无权访问均返回相同的 403。加载期间身份、策略、可见性、成员关系或会话权限变化时，需要刷新重试。legacy/shadow 保留原有业务读取；shadow 不会额外读取第二份配置内容。

## 页面用途

- 调整全局转发策略和基础限流行为。
- 维护监控展示名称与状态页映射。
- 配置模型价格与支持格式。
- 创建独立渠道、混池渠道或自动代理池。
- 为渠道设置可见性、路由策略、上游凭据和计费倍率。

## 批量启用与停用渠道

在 IAM enforce 模式下，批量启停对每个选中的 `acs:platform:*:platform:relay-channel/<渠道ID>` 检查 `quyan:relay:SetChannelStatus`。操作者必须通过启用中的部署级全局组具备 `RELAY_CHANNEL_UPDATE` 管理资格；账户自建组、用户附加权限或通配符策略不能自行赋予此资格。角色会话仅使用角色自身授权，并受相同管理资格上限约束。

请求需包含 1–200 个互不重复、存在且未删除的渠道 ID，以及 JSON 布尔值 `enabled`（`true` 或 `false`，不能使用字符串 `"false"`）。全部选中资源都必须获准；任一渠道被拒绝或不存在，或提交前资源、身份、策略、AccessKey、OAuth、角色会话权限发生变化时，整个批次不生效。OAuth 应用与访问令牌必须保留渠道更新 scope。此接口只返回数量，不读取凭据，也不要求渠道读取权限；不会解绑 Token、改变混池成员或服务提供资格。重放保护和二次验证继续有效。legacy/shadow 保留原有授权行为，shadow 不会额外执行第二次状态写入。

## 全局设置

### 全局倍率

- 作用：作为所有渠道价格倍率之前的一层总倍率。
- 影响：最终计费通常会受到“全局倍率 × 渠道倍率 × 分时倍率”共同影响。
- 建议：
  - 日常调价优先使用模型价格或渠道倍率。
  - 只在需要整体抬高或压低全站成本时修改全局倍率。

### 队列开关、最大并发、队列超时

- 作用：控制请求过载时是排队等待还是更快失败。
- 影响：
  - `最大并发` 越小，越容易进入队列，但对上游更温和。
  - `队列超时` 越短，用户越快收到失败；越长，用户等待越久。
- 建议：
  - 对上游额度紧张或容易触发限流的环境，优先保守配置。
  - 生产环境改动后观察状态页与错误率。

### 上游流式超时

- 作用：限制单个流式请求在上游持续占用连接的最长时间。
- 影响：超时过短会中断长回答，过长则会增加慢请求占位时间。

### 监控名称映射

- 作用：把状态页上的监控 ID 映射成管理员更容易识别的显示名称。
- 影响：只改变展示，不改变真实路由逻辑。

页面分别加载中转配置和自定义密钥配置，未能加载的配置组会禁用，保存时不会提交其字段。保存只发送已修改的中转字段，因此修改队列设置不会替换未修改的价格。零价有效；修改价格仍会替换完整有效列表，包括读取权限未展示的记录。若一组配置保存成功、另一组失败，页面会明确提示部分成功，重试时只提交尚未保存的变更。

### 全局配置保存权限

IAM 强制模式下，保存全局设置使用 `quyan:relay:UpdateConfiguration`，需要真实全局组中的 `MODEL_PRICING_UPDATE` 资格，并允许 `acs:platform:*:platform:relay-configuration/default`。

尚未保存配置时，已授权的保存会以读取接口提供的默认设置为基础创建配置，读取本身不会创建配置。并发首次保存会在提交前重新检查；授权被拒绝或保存失败时，不会留下部分配置。

`modelRates` 的含义是替换有效价格列表：省略该字段会保留现有价格；提供空数组会删除全部有效价格；提供列表会更新已有模型、以原 ID 恢复已删除模型、创建新模型，并删除未列出的有效模型。每个受影响记录，包括未列出的删除目标，都需要允许其 `acs:platform:*:platform:model-pricing/<记录 ID>`。新建还需要允许 `acs:platform:*:platform:model-pricing-control/default` 和生成后的实际记录 ARN。

任一资源被拒绝、配置或价格快照过期、权限或角色会话变化时，整个保存失败，不部分更新。严格渠道拓扑切换仍须通过拓扑检查。重复模型名称、无效计价方式或支持格式会被拒绝；按次计费的固定价格可以为零。2FA 验证和重放保护继续适用。

保存成功后的价格列表按 `quyan:relay:GetConfiguration` 逐记录检查读取权限，没有价格读取权限时可返回空列表；这不表示已有价格被删除。保存权限不自动授予价格读取权限。

### 全局配置读取权限

IAM 强制模式下，读取全局设置使用 `quyan:relay:GetConfiguration`，需要真实全局组中的 `MODEL_PRICING_UPDATE` 资格，并允许配置资源 `acs:platform:*:platform:relay-configuration/default`。配置权限与模型价格权限分别判断：价格使用 `acs:platform:*:platform:model-pricing/<记录 ID>`，返回结果只包含获得授权的记录。只允许配置时，价格列表可以为空；只允许价格时，不能读取全局配置。匹配的 Deny 优先。

尚未保存配置时，已授权的读取返回默认设置，不自动创建配置。读取期间资格、策略、角色会话或已授权内容发生变化时，请求失败；存储不可用时不会用默认配置代替成功结果。配置读取权限不包含保存权限。

### 模型定价导出权限

IAM 强制模式下，定价导出需要真实全局组中的 `MODEL_PRICING_READ` 资格，使用 `quyan:model_pricing:ExportModels`，资源为 `acs:platform:*:platform:model-pricing/<记录 ID>`。导出仅包含获得授权的实际记录，匹配的 Deny 优先；读取期间价格、资格、策略或角色会话变化时不会返回导出结果。AssumeRole 只使用角色自身授权。公开模型价格列表继续按原有方式访问。

### 模型定价写入权限

单条新增、更新和删除需要真实全局组中的 `MODEL_PRICING_UPDATE` 资格，分别使用 `quyan:model_pricing:CreatePricing`、`quyan:model_pricing:UpdatePricing` 和 `quyan:model_pricing:DeletePricing`。新增同时检查 `acs:platform:*:platform:model-pricing-control/default` 及实际记录 ARN；更新、删除使用实际记录 ID。恢复已删除模型沿用原 ID，资源上的 Deny 仍有效。

目标价格、身份、资格或授权在保存前变化时，操作失败且不会部分保存。计价方式及支持格式须有效；切换为按次计费需要固定价格，固定价格可以为零。不存在或未授权的修改目标在 IAM 强制模式下返回 403。2FA 验证和重放保护继续适用。

### 模型定价批量导入权限

批量导入使用 `quyan:model_pricing:ImportPricing`，需要真实全局组中的 `MODEL_PRICING_UPDATE` 资格，同时授权固定创建范围和所有受影响记录的 ARN。新模型在保存前使用生成后的实际记录 ARN 再次检查；已删除模型沿用原 ID 恢复，原有 Deny 继续有效。任一记录被拒绝、价格快照过期或授权变化时，整批回滚，不跳过失败项。

单次最多导入 499 个不同模型；去除首尾空格后的重复名称、未知字段及无效计价方式或格式会被拒绝。新模型未指定计价方式时使用按 Token 计费；现有模型保留未指定的计价方式。明确提供的固定价格和支持格式会随导入保存。2FA 验证和重放保护继续适用。

## 渠道配置总览

每个渠道都代表一条可被令牌或系统路由使用的逻辑出口。渠道分为三类：

- `独立渠道`：直接连接真实上游，持有 URL 和 API Key。
- `混池渠道`：把多个已存在渠道组合成一个用户侧只看到一个名称的逻辑渠道。
- `自动代理池`：由管理员或自动化程序统一维护成员、供令牌以自动代理模式选择的特殊逻辑渠道。

### 渠道名称

- 作用：管理员和用户看到的渠道标识。
- 影响：在令牌绑定、日志、详情页、编排页中都会显示。
- 建议：名称体现用途而不是供应商内部细节，例如“OpenAI 主生产池”“Claude 备用低成本池”。

### 渠道类型

#### 独立渠道

- 适用场景：一个上游地址、一套凭据、单一路由出口。
- 影响：需要配置至少一种格式对应的真实上游 URL 与 API Key。

#### 混池渠道

- 适用场景：多渠道故障切换、按权重分流、隐藏多个真实渠道细节。
- 影响：
  - 用户与令牌侧通常只看到这个逻辑渠道。
  - 真实流量由混池成员承载。
- 混池自身不直连上游，不保存实际 upstream 凭据。
- 在严格双层拓扑中，可以直接点击“添加物理成员”，从物理成员列表中批量选择并保存。
- 在旧版拓扑中，从独立渠道选择成员；保存会更新该混池自己的成员列表，并可在编辑器中删除成员。
- 在严格双层拓扑中，保存会将选中的渠道转换为物理成员并归入该逻辑混池，再按列表顺序写入优先级、权重和启用状态；移动成员到其他逻辑混池时，从目标混池编辑器重新选择即可。

#### 自动代理池

- 适用场景：希望统一维护底层渠道，而不要求每个 Token 随成员变动重新编排渠道顺序。
- 成员：可同时加入逻辑混池渠道和独立渠道；不能加入混池物理成员或其他自动代理池。
- 路由与计费：请求由实际命中的成员执行；成员的模型价格、渠道倍率和分时倍率参与计费，Token 所属用户承担费用。
- 可见性：Token 用户只选择自动代理池本身，不查看或编辑其成员。

## 混池成员与路由策略

### 混池成员

- 成员渠道：混池可调用的底层渠道。
- 旧版成员：旧版拓扑以混池编辑器保存成员关系；可直接在编辑器中删除成员。
- 物理成员：严格双层拓扑的物理成员只归属于一个逻辑混池。管理列表会显示其所属逻辑混池，而不是显示成员数量。
- 成员关系：系统会同时识别已有旧版成员关系和严格双层关系；同一成员同时存在两种关系时，以严格双层配置的优先级、权重和启用状态为准。
- 优先级：数字越小越靠前，主要影响优先级故障切换类策略。
- 权重：主要用于加权随机策略，值越大被选中的概率越高。
- 启用状态：关闭后该成员不会参与当前混池调度。

建议：

- 主生产渠道放在更高优先级。
- 明显容量更高或成本更低的渠道可以给更高权重。
- 临时排障时优先关闭成员，而不是直接删除。

### 路由策略

#### 优先级故障转移

- 行为：优先尝试最靠前成员，失败后再切到后续成员。
- 适用：主备结构最清晰、最容易控制成本。

#### 随机

- 行为：每次随机选一个可用成员。
- 适用：多个上游能力接近，追求自然分散流量。

#### 加权随机

- 行为：按权重比例分配请求。
- 适用：需要显式控制分流比例，例如 80% 主渠道、20% 备用渠道。

#### 轮询

- 行为：请求按顺序轮流落到不同成员。
- 适用：渠道性能接近，希望均匀铺开流量。

#### 健康度优先

- 行为：优先选择健康评分更高的成员。
- 适用：你已经建立稳定健康监控，且更看重可用性。

#### 低延迟优先

- 行为：优先选择最近表现更快的成员。
- 适用：对交互响应时间比较敏感的场景。

## 路由参数

页面会预填推荐值，适合大多数混池场景；管理员仍可根据业务调整。

### 最大渠道切换次数

- 推荐默认值：`2`
- 作用：一共最多再尝试几个不同成员渠道。
- 影响：值太小会导致后面的渠道永远没有机会被尝试；值太大则可能放大单次请求延迟。
- 建议：
  - 3 个成员以内通常 `2` 足够覆盖主要主备链路。
  - 如果混池成员更多且顺序很重要，可适当提高。

### 单渠道重试次数

- 推荐默认值：`0`
- 作用：同一成员失败后是否先在该成员继续尝试。
- 影响：
  - `0` 表示失败后尽快切到下一个成员。
  - 更高的值表示更信任单个上游的短暂波动恢复能力。
- 建议：对常见上游 API，优先保持 `0`，减少把失败时间浪费在同一个已异常节点上。

### 触发切换规则

- 推荐默认值：`4xx`、`5xx`
- 作用：决定什么样的上游结果会触发切换或重试。
- 影响：
  - `5xx` 覆盖大部分上游内部错误。
  - `4xx` 可以覆盖限流、鉴权失败或参数不被接受等场景。
- 建议：
  - 大多数环境保留默认值即可。
  - 如果你不希望参数类错误触发切换，可去掉 `4xx` 并只保留更精细规则，例如 `429`、`5xx`。

### 回切冷却时间（分钟）

- 推荐默认值：`5`
- 作用：切换到后续渠道后，后续请求在一段时间内继续优先使用当前渠道，不立刻回到前面的主渠道。
- 影响：避免主渠道刚恢复时来回抖动。
- 建议：主备结构通常保留几分钟冷却较稳妥。

### 健康度阈值

- 推荐默认值：`0`
- 作用：只让健康度达到阈值的成员参与优先选择。
- 影响：阈值越高，越可能把波动中的渠道排除在外。
- 建议：`0` 表示不过滤健康分，适合作为保守默认值；仅在你明确理解健康评分来源时再进一步抬高。

### 延迟阈值（ms）

- 推荐默认值：`30000`
- 作用：限制参与低延迟优先策略的成员延迟上限。
- 影响：过低会导致大量成员被排除，过高则失去筛选意义。
- 建议：`30000ms` 适合作为宽松默认值，先避免把正常渠道过早排除，再按实际链路延迟逐步收紧。

### 熔断阈值

- 推荐默认值：`5`
- 作用：达到指定失败阈值后，短时间内视为该成员不适合继续承接请求。
- 影响：可降低已明显异常节点对整体成功率的拖累。
- 建议：`5` 适合作为常见 API 上游的起点，既不会因为偶发一次失败就切走，也不会长时间容忍持续异常。

### 按模型粘性路由

- 推荐默认值：`关闭`
- 作用：同一模型请求尽量稳定落在同一成员。
- 影响：有利于缓存、同模型行为一致性和问题复现。
- 建议：默认关闭，只有当你确实需要模型级一致性或缓存收益时再开启。

### 按格式粘性路由

- 推荐默认值：`关闭`
- 作用：同一请求格式（如 OpenAI、Anthropic、Gemini）尽量稳定落在同一成员。
- 影响：适合不同底层渠道对不同协议兼容度不完全一致的情况。
- 建议：默认关闭；当不同协议在不同成员上的兼容性明显不一致时再开启。

## 可见性配置

### 公开

- 作用：所有具备相应使用路径的用户都可看到并使用此渠道。
- 适用：标准生产渠道。

### 私有

- 作用：普通用户不可见，通常用于管理员测试、迁移、演练或灰度。
- 适用：临时验证新上游、内部压测、敏感渠道调试。

### 白名单

- 作用：只有指定用户、用户组、角色才能看到此渠道。
- 适用：定向试用、内测、分层客户、专属供应商线路。

#### 用户白名单

- 影响：直接把可见权限授予具体用户。
- 建议：适合小范围点对点测试。

#### 用户组白名单

- 影响：组内成员统一获得可见权限。
- 建议：适合部门、租户、套餐档位等长期管理场景。

#### 角色白名单

- 影响：具备对应 RAM 角色的主体可见。
- 建议：适合通过角色体系统一控制能力边界。

说明：页面会尽量加载用户、用户组和角色列表，管理员也可以直接手动输入未出现在列表中的 ID。

## 格式与模型限制

### 允许格式

- 作用：声明渠道能接受哪些协议格式请求。
- 影响：
  - 只勾选的格式才会在该渠道上被视为可用。
  - 独立渠道会据此要求相应上游 URL 与 API Key 完整可用。

### 模型白名单

- 作用：限制此渠道只接受指定模型。
- 影响：
  - 开启限制后，不在名单内的模型不会落到此渠道。
  - 混池场景下，这会直接影响候选成员集合。
- 建议：当某个上游只支持特定模型、或者你要控制成本时再启用。

### 批量探测并应用模型

渠道管理的批量操作提供“批量探测模型”。选择渠道后，可以分别手动探测 OpenAI、Anthropic、Gemini 上游的 `/v1/models`：

- 仅能选择和应用的模型必须有全局定价；未匹配模型会保留显示但不可选择。
- 应用采用按渠道合并：只把该渠道实际探测到且被选中的模型加入现有限制，不会移除旧模型，也不会给不支持该模型的渠道写入。
- 缺少某格式上游地址或凭据的渠道会标记为跳过，单个渠道探测失败不会中断其他渠道。
- 探测结果只在当前弹窗中使用，不会持久化保存。

自动代理池的“添加成员”窗口可以按渠道当前有效的模型限制筛选候选渠道：

- 支持“任一匹配”和“全部匹配”；默认任一匹配。
- 多选渠道并确认加入后，筛选模型会合并到自动代理池的池级手动模型限制。成员渠道自身的模型限制不会被改写。
- 设置为“全部模型”或“根据混池成员推断”的渠道会按已配置定价匹配全部模型，这不代表上游真实支持这些模型。需要准确筛选时，应先用批量探测把真实支持的模型写入渠道限制。

## 上游配置

### OpenAI / Anthropic / Gemini 上游 URL

- 作用：指定请求实际发往哪个服务端点。
- 影响：URL 决定真实供应商、代理层或私有网关。

### API Key

- 作用：渠道访问对应上游时使用的凭据。
- 影响：凭据缺失或无效会直接导致对应格式请求失败。

建议：

- 一个独立渠道只配置自己真正需要承载的格式。
- 不要把测试凭据放在面向生产用户公开的渠道上。

## 计费与映射

### 渠道倍率

- 作用：在全局倍率之外，对单个渠道再做一层价格调整。
- 影响：适合表达“这个上游更贵”或“这个专属通道需要额外溢价”。

### 输入 Token 包含缓存读取

- 作用：处理某些上游把缓存读取 Token 已经并入 input tokens 的情况。
- 影响：开启后会避免重复计费；关闭则完全按上游回传数字计费。
- 建议：只有在你确认上游计数字段包含 cache read 时才开启。

### 模型映射

- 作用：把请求模型映射到另一个计费或路由目标模型。
- 影响：
  - 可用于兼容上游别名。
  - 可用于把多个近似模型统一到一个计费项。
- 风险：映射配置错误会导致计费模型与真实请求模型不一致。

## 分时倍率

- 作用：在特定星期与时间段，对该渠道应用额外倍率。
- 适用：晚高峰加价、夜间优惠、工作日/周末策略区分。
- 影响：命中的时间规则会进一步改变渠道最终价格。

建议：

- 规则名称写明业务含义，例如“工作日晚高峰”。
- 先确认时区，再发布给生产用户。

### 中国节假日条件与全天倍率

在渠道的分时倍率规则中，可以选择：

- **不区分节假日**：保留原有星期筛选和服务器本地时区行为。
- **排除节假日**：所选星期、时间段都匹配，且当天不是中国节假日时生效。
- **仅节假日**：仅在中国节假日生效，忽略星期选择，但仍遵守时间段。
- **全天**：忽略起止时间，覆盖当天的全部时间，包括 23:59。

“排除节假日”和“仅节假日”按北京时间（Asia/Shanghai）判断日期、星期和时段。节假日包含年度日历公布的连休放假日期。补班标记不会把周六、周日转换为周一至周五。跨午夜时段使用请求发生当天的日期判断。

**DeepSeek 峰谷配置示例**：渠道基础倍率设为空闲倍率；新增忙时规则，选择周一至周五、实际忙时时间段和“排除节假日”，规则倍率填写“忙时价格 ÷ 空闲价格”。这样周末（包括调休上班的周末）及节假日全天保持基础倍率。请自行填写适用的价格和时间，不会自动修改现有渠道。

非全天时段规则的起止时间必须不同；起止相同的历史规则继续视为不命中，编辑时请改为“全天”或设置实际时段。

多条规则同时命中时倍率相乘，不是覆盖；不要重复添加重叠的节假日折扣规则。规则可在管理端、供应商渠道编辑及批量编辑中配置。

日历由后端从外部年度日历服务获取，正常每天刷新，使用 Redis 缓存与进程内快照，预取下一年度；计费不会等待外部接口。同步失败保留最后有效日历。如果当年没有任何有效日历，则跳过依赖节假日的规则并记录告警，普通规则和渠道基础倍率仍生效。首次启动缓存未就绪时也适用这一降级行为；年度日历尚未发布时不会猜测日期。运维应关注后端节假日日历告警。

## 管理建议

## 渠道供应与分成

管理员可以在渠道编辑器中查看审核状态、追加多位提供者，并分别设置 0% 到 100% 的分成比例和结算方式。比例总和允许超过 100%，页面会显示平台补贴提示；收益按实际执行渠道和消费发生时的比例快照结算。用户提交独立渠道和查看收益请使用“渠道供应与收益”页面。

1. 对外生产流量优先使用“混池渠道 + 优先级故障转移 + 少量主备成员”。
2. 把“私有”或“白名单”作为测试渠道默认可见性，避免用户误用。
3. 当上游兼容性不完全一致时，优先用模型白名单和格式限制缩小风险面。
4. 先确定计费策略，再同时检查全局倍率、渠道倍率和分时倍率，避免叠加过高。
5. 每次修改混池路由后，都应观察切换日志和状态页，确认故障切换符合预期。

## 资源级渠道删除

启用 IAM 强制授权后，单个与批量删除渠道都需要对每个目标拥有 `quyan:relay:DeleteChannel`，资源为 `acs:platform:*:platform:relay-channel/<channelId>`。这些渠道是部署共享资源，不使用调用者账号的 ARN。调用者还必须具备部署管理组赋予的渠道删除资格，不能通过账号策略自行获得该资格。二次验证和重放保护仍然生效。

使用旧 `quyan:relay:channel:Delete` 别名和账号内渠道 ARN 的策略，需要先改为上述 Action 与平台 ARN，才能用于原生授权操作。旧 `RELAY_CHANNEL_DELETE` 权限会自动映射；JSON 策略不会仅因资源 ID 相同就自动获得新的平台权限。

请求中的所有渠道都必须通过授权且仍然存在。任一目标被拒绝、不存在、已删除或发生变化，整个请求都会取消。删除与必要的路由引用清理一起提交：清空直接渠道和自动池的令牌引用，移除相关渠道配置及池成员关联，并停用已删除渠道的有效变更申请。无关渠道和历史提供者、收益记录不会被删除。删除权限不授予读取令牌值、上游密钥或其他渠道配置的权限。迁移期间，legacy/shadow 模式仍执行原有业务删除，shadow 评估不会重复删除。

## 服务器资源保护与审计正文

系统管理的服务器配置提供“AI 资源保护”高级面板，可动态调整全站 AI 并发、等待、RSS、上传、响应、审计和连接池预算。保存后本进程立即生效，其他进程最多 5 秒同步；运行中的请求保留开始时的内容预算。每用户并发和图片作用域仍独立执行。

旧资源环境变量仅在尚未保存管理配置时兼容回退。审计正文继续脱敏保存；积压时可能省略正文或丢弃记录并告警。审计日志不能代替计费记录。
