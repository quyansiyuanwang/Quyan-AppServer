# 转发设置

此页面用于维护两类配置：

- 转发系统级行为，例如队列、监控映射、全局倍率和模型价格。
- 渠道级行为，例如上游地址、混池路由、白名单可见性、模型限制和分时倍率。

如果你要解决“某个用户能否看到某个渠道”“某个模型走哪个上游”“多个上游如何故障转移”这一类问题，核心都在这里完成。

## 页面用途

- 调整全局转发策略和基础限流行为。
- 维护监控展示名称与状态页映射。
- 配置模型价格与支持格式。
- 创建独立渠道或混池渠道。
- 为渠道设置可见性、路由策略、上游凭据和计费倍率。

## 全局设置

### 全局倍率

- 作用：作为所有渠道价格倍率之前的一层总倍率。
- 影响：最终计费通常会受到“全局倍率 × 渠道倍率 × 分时倍率”共同影响。
- 建议：
  - 日常调价优先使用模型价格或渠道倍率。
  - 只在需要整体抬高或压低全站成本时修改全局倍率。

### 队列开关、最大并发、队列超时

- 作用：控制请求过载时是排队等待还是更快失败。
- 影响：
  - `最大并发` 越小，越容易进入队列，但对上游更温和。
  - `队列超时` 越短，用户越快收到失败；越长，用户等待越久。
- 建议：
  - 对上游额度紧张或容易触发限流的环境，优先保守配置。
  - 生产环境改动后观察状态页与错误率。

### 上游流式超时

- 作用：限制单个流式请求在上游持续占用连接的最长时间。
- 影响：超时过短会中断长回答，过长则会增加慢请求占位时间。

### 监控名称映射

- 作用：把状态页上的监控 ID 映射成管理员更容易识别的显示名称。
- 影响：只改变展示，不改变真实路由逻辑。

## 渠道配置总览

每个渠道都代表一条可被令牌或系统路由使用的逻辑出口。渠道分为两类：

- `独立渠道`：直接连接真实上游，持有 URL 和 API Key。
- `混池渠道`：把多个已存在渠道组合成一个用户侧只看到一个名称的逻辑渠道。

### 渠道名称

- 作用：管理员和用户看到的渠道标识。
- 影响：在令牌绑定、日志、详情页、编排页中都会显示。
- 建议：名称体现用途而不是供应商内部细节，例如“OpenAI 主生产池”“Claude 备用低成本池”。

### 渠道类型

#### 独立渠道

- 适用场景：一个上游地址、一套凭据、单一路由出口。
- 影响：需要配置至少一种格式对应的真实上游 URL 与 API Key。

#### 混池渠道

- 适用场景：多渠道故障切换、按权重分流、隐藏多个真实渠道细节。
- 影响：
  - 用户与令牌侧通常只看到这个逻辑渠道。
  - 真实流量由混池成员承载。
  - 混池自身不直连上游，不保存实际 upstream 凭据。

## 混池成员与路由策略

### 混池成员

- 成员渠道：混池可调用的底层渠道。
- 优先级：数字越小越靠前，主要影响优先级故障切换类策略。
- 权重：主要用于加权随机策略，值越大被选中的概率越高。
- 启用状态：关闭后该成员不会参与当前混池调度。

建议：

- 主生产渠道放在更高优先级。
- 明显容量更高或成本更低的渠道可以给更高权重。
- 临时排障时优先关闭成员，而不是直接删除。

### 路由策略

#### 优先级故障转移

- 行为：优先尝试最靠前成员，失败后再切到后续成员。
- 适用：主备结构最清晰、最容易控制成本。

#### 随机

- 行为：每次随机选一个可用成员。
- 适用：多个上游能力接近，追求自然分散流量。

#### 加权随机

- 行为：按权重比例分配请求。
- 适用：需要显式控制分流比例，例如 80% 主渠道、20% 备用渠道。

#### 轮询

- 行为：请求按顺序轮流落到不同成员。
- 适用：渠道性能接近，希望均匀铺开流量。

#### 健康度优先

- 行为：优先选择健康评分更高的成员。
- 适用：你已经建立稳定健康监控，且更看重可用性。

#### 低延迟优先

- 行为：优先选择最近表现更快的成员。
- 适用：对交互响应时间比较敏感的场景。

## 路由参数

页面会预填推荐值，适合大多数混池场景；管理员仍可根据业务调整。

### 最大渠道切换次数

- 推荐默认值：`2`
- 作用：一共最多再尝试几个不同成员渠道。
- 影响：值太小会导致后面的渠道永远没有机会被尝试；值太大则可能放大单次请求延迟。
- 建议：
  - 3 个成员以内通常 `2` 足够覆盖主要主备链路。
  - 如果混池成员更多且顺序很重要，可适当提高。

### 单渠道重试次数

- 推荐默认值：`0`
- 作用：同一成员失败后是否先在该成员继续尝试。
- 影响：
  - `0` 表示失败后尽快切到下一个成员。
  - 更高的值表示更信任单个上游的短暂波动恢复能力。
- 建议：对常见上游 API，优先保持 `0`，减少把失败时间浪费在同一个已异常节点上。

### 触发切换规则

- 推荐默认值：`4xx`、`5xx`
- 作用：决定什么样的上游结果会触发切换或重试。
- 影响：
  - `5xx` 覆盖大部分上游内部错误。
  - `4xx` 可以覆盖限流、鉴权失败或参数不被接受等场景。
- 建议：
  - 大多数环境保留默认值即可。
  - 如果你不希望参数类错误触发切换，可去掉 `4xx` 并只保留更精细规则，例如 `429`、`5xx`。

### 回切冷却时间（分钟）

- 推荐默认值：`5`
- 作用：切换到后续渠道后，后续请求在一段时间内继续优先使用当前渠道，不立刻回到前面的主渠道。
- 影响：避免主渠道刚恢复时来回抖动。
- 建议：主备结构通常保留几分钟冷却较稳妥。

### 健康度阈值

- 推荐默认值：`0`
- 作用：只让健康度达到阈值的成员参与优先选择。
- 影响：阈值越高，越可能把波动中的渠道排除在外。
- 建议：`0` 表示不过滤健康分，适合作为保守默认值；仅在你明确理解健康评分来源时再进一步抬高。

### 延迟阈值（ms）

- 推荐默认值：`30000`
- 作用：限制参与低延迟优先策略的成员延迟上限。
- 影响：过低会导致大量成员被排除，过高则失去筛选意义。
- 建议：`30000ms` 适合作为宽松默认值，先避免把正常渠道过早排除，再按实际链路延迟逐步收紧。

### 熔断阈值

- 推荐默认值：`5`
- 作用：达到指定失败阈值后，短时间内视为该成员不适合继续承接请求。
- 影响：可降低已明显异常节点对整体成功率的拖累。
- 建议：`5` 适合作为常见 API 上游的起点，既不会因为偶发一次失败就切走，也不会长时间容忍持续异常。

### 按模型粘性路由

- 推荐默认值：`关闭`
- 作用：同一模型请求尽量稳定落在同一成员。
- 影响：有利于缓存、同模型行为一致性和问题复现。
- 建议：默认关闭，只有当你确实需要模型级一致性或缓存收益时再开启。

### 按格式粘性路由

- 推荐默认值：`关闭`
- 作用：同一请求格式（如 OpenAI、Anthropic、Gemini）尽量稳定落在同一成员。
- 影响：适合不同底层渠道对不同协议兼容度不完全一致的情况。
- 建议：默认关闭；当不同协议在不同成员上的兼容性明显不一致时再开启。

## 可见性配置

### 公开

- 作用：所有具备相应使用路径的用户都可看到并使用此渠道。
- 适用：标准生产渠道。

### 私有

- 作用：普通用户不可见，通常用于管理员测试、迁移、演练或灰度。
- 适用：临时验证新上游、内部压测、敏感渠道调试。

### 白名单

- 作用：只有指定用户、用户组、角色才能看到此渠道。
- 适用：定向试用、内测、分层客户、专属供应商线路。

#### 用户白名单

- 影响：直接把可见权限授予具体用户。
- 建议：适合小范围点对点测试。

#### 用户组白名单

- 影响：组内成员统一获得可见权限。
- 建议：适合部门、租户、套餐档位等长期管理场景。

#### 角色白名单

- 影响：具备对应 RAM 角色的主体可见。
- 建议：适合通过角色体系统一控制能力边界。

说明：页面会尽量加载用户、用户组和角色列表，管理员也可以直接手动输入未出现在列表中的 ID。

## 格式与模型限制

### 允许格式

- 作用：声明渠道能接受哪些协议格式请求。
- 影响：
  - 只勾选的格式才会在该渠道上被视为可用。
  - 独立渠道会据此要求相应上游 URL 与 API Key 完整可用。

### 模型白名单

- 作用：限制此渠道只接受指定模型。
- 影响：
  - 开启限制后，不在名单内的模型不会落到此渠道。
  - 混池场景下，这会直接影响候选成员集合。
- 建议：当某个上游只支持特定模型、或者你要控制成本时再启用。

## 上游配置

### OpenAI / Anthropic / Gemini 上游 URL

- 作用：指定请求实际发往哪个服务端点。
- 影响：URL 决定真实供应商、代理层或私有网关。

### API Key

- 作用：渠道访问对应上游时使用的凭据。
- 影响：凭据缺失或无效会直接导致对应格式请求失败。

建议：

- 一个独立渠道只配置自己真正需要承载的格式。
- 不要把测试凭据放在面向生产用户公开的渠道上。

## 计费与映射

### 渠道倍率

- 作用：在全局倍率之外，对单个渠道再做一层价格调整。
- 影响：适合表达“这个上游更贵”或“这个专属通道需要额外溢价”。

### 输入 Token 包含缓存读取

- 作用：处理某些上游把缓存读取 Token 已经并入 input tokens 的情况。
- 影响：开启后会避免重复计费；关闭则完全按上游回传数字计费。
- 建议：只有在你确认上游计数字段包含 cache read 时才开启。

### 模型映射

- 作用：把请求模型映射到另一个计费或路由目标模型。
- 影响：
  - 可用于兼容上游别名。
  - 可用于把多个近似模型统一到一个计费项。
- 风险：映射配置错误会导致计费模型与真实请求模型不一致。

## 分时倍率

- 作用：在特定星期与时间段，对该渠道应用额外倍率。
- 适用：晚高峰加价、夜间优惠、工作日/周末策略区分。
- 影响：命中的时间规则会进一步改变渠道最终价格。

建议：

- 规则名称写明业务含义，例如“工作日晚高峰”。
- 先确认时区，再发布给生产用户。

## 管理建议

1. 对外生产流量优先使用“混池渠道 + 优先级故障转移 + 少量主备成员”。
2. 把“私有”或“白名单”作为测试渠道默认可见性，避免用户误用。
3. 当上游兼容性不完全一致时，优先用模型白名单和格式限制缩小风险面。
4. 先确定计费策略，再同时检查全局倍率、渠道倍率和分时倍率，避免叠加过高。
5. 每次修改混池路由后，都应观察切换日志和状态页，确认故障切换符合预期。
