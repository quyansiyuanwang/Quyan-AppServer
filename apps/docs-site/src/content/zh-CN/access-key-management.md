# 访问密钥管理

此页面用于创建和维护账号级程序访问密钥。

## 使用前提

- 已登录账户；从**设置 → 账户安全**打开访问密钥管理。
- 创建密钥时，账户必须已绑定邮箱；未启用 2FA 时，还需要能接收该邮箱的验证码。
- 查看、创建和删除需要各自的授权。能创建密钥不代表能在列表查看或删除它，权限说明见下文。

## 检查密钥列表

- 密钥名称。
- 已有密钥仅显示脱敏值，不支持再次读取完整明文。
- 请求次数与最后使用时间。
- 到期信息。

请求次数与最后使用时间用于观察密钥的使用情况，不代表对应业务请求全部成功。到期的密钥可能仍显示在列表中，但不能再用于认证。

## 创建并保存密钥

1. 选择创建密钥，填写便于识别的名称（最多 100 个字符），并按需选择将来的到期时间。到期时间留空时密钥不会自动过期。
2. 未启用 2FA 时，点击发送验证码，到当前账户已绑定的邮箱查收六位码并填写；启用 2FA 时，按提示完成二次验证。确认创建并等待结果。
3. 在创建成功的对话框中复制完整密钥并妥善保存。页面提示复制成功不保证剪贴板已写入，请在可信的密钥存储位置粘贴核对；必要时从只读文本框手动选择复制。关闭对话框后无法从列表再次获取。
4. 在需要使用它的应用中配置新密钥，确认应用能正常访问所需接口。密钥不会自动取得额外业务权限。

## 删除或更换密钥

1. 在列表中核对名称和脱敏值，确认需要删除的密钥。
2. 如果业务仍在使用该密钥，先创建并保存替代密钥，更新使用方配置并验证，再删除旧密钥。
3. 点击旧密钥的**删除**并确认；启用 2FA 时，高危删除操作仍需完成验证。
4. 等待删除成功及列表刷新。删除后，旧密钥不能再用于新请求认证；需要恢复访问时应创建新密钥。

## 说明

- 完整密钥仅在创建成功时展示。
- 已存在的密钥列表只用于识别和管理，不用于重新展示完整密钥。
- 创建密钥需要完成安全验证，具体方式见下文。
- 访问密钥应像密码一样保密，不应出现在公开截图或聊天记录中。

## 创建权限和安全验证

启用 IAM 强制授权后，创建访问密钥需要 `quyan:ram:CreateAccessKey`，发送创建验证码需要独立的 `quyan:ram:SendAccessKeyCreationVerificationCode`。这两项操作的资源是当前执行用户，而不是尚未生成的密钥：

```json
{
  "Version": "1",
  "Statement": {
    "Effect": "Allow",
    "Action": ["quyan:ram:CreateAccessKey", "quyan:ram:SendAccessKeyCreationVerificationCode"],
    "Resource": "acs:quyan:*:<accountId>:user/<userId>"
  }
}
```

替换为当前账号和当前执行用户的 ID。两项权限不会自动授予；创建权限不包含列表或撤销权限，也不能替其他用户创建密钥。匹配的 Deny 优先。

未启用二次验证时，创建必须提交有效、未使用的邮箱验证码；验证码使用后不能再次使用；如果创建失败且验证码已失效或已使用，请重新获取验证码再试。启用二次验证后仍需通过已有安全挑战，但不需要额外邮箱验证码，也不会发送该验证码。

验证过程中邮箱、二次验证设置、账户状态或角色会话发生变化，请重新认证并重新发起流程；冲突不会产生新密钥。第三方 OAuth 应用仍可在 `accesskey` scope、用户授权和上述权限约束下发起创建；这不允许它们读取或删除已有密钥。完整新密钥仅在创建成功时返回，请立即保存。

## 撤销权限和资源范围

启用 IAM 策略授权后，删除访问密钥需要 `quyan:ram:DeleteAccessKey`。策略可以限定到当前用户的一把密钥：

```json
{
  "Version": "1",
  "Statement": {
    "Effect": "Allow",
    "Action": "quyan:ram:DeleteAccessKey",
    "Resource": "acs:quyan:*:<accountId>:access-key/<userId>/<keyId>"
  }
}
```

请用当前账号 ID、当前用户 ID 和实际密钥 ID 替换占位符。授予此操作不允许读取完整密钥或管理其他用户的密钥；匹配的 Deny 会覆盖 Allow。

删除仍需通过重放保护；已启用二次验证时，这项高风险操作会要求验证。撤销后，该密钥不能继续用于新请求认证。账号、角色会话或密钥归属在授权后发生变化时，请求会被拒绝；并发变更导致冲突时，请刷新列表后重试。

## 列表权限和分页

启用 IAM 强制授权后，`quyan:ram:ListAccessKeys` 控制当前用户自己的哪些密钥出现在列表中。资源 ARN 与撤销操作相同，但此权限不会授予删除能力或完整明文读取能力；匹配的 Deny 会隐藏对应密钥，即使使用通配符授权也不能列出其他用户的密钥。

页面采用服务端分页，支持上一页、下一页和每页条数。权限过滤后当前页可能为空，但后续页仍可能存在可见密钥；如果下一页可用，请继续翻页。页面不会展示未过滤的资源总数。刷新重试当前页，创建成功后返回第一页。完整密钥只在创建成功的对话框中显示，不会在任何列表接口中返回。

API 客户端建议使用 `GET /v1/accesskeys/page?page=1&pageSize=50`，响应包含 `items`、`page`、`pageSize` 和 `hasNext`。原有 `GET /v1/accesskeys` 数组接口保留兼容性，返回完整的已授权脱敏列表。第三方 OAuth 应用无权读取这两个列表。

## 常见问题

| 现象                                   | 处理方式                                                                                                             |
| -------------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| 无法发送验证码                         | 确认账户已绑定可收信的邮箱，并检查发送权限。发送成功后的按钮有 60 秒倒计时；邮件服务错误需联系管理员处理。           |
| 已启用 2FA，但创建界面仍要求邮箱验证码 | 重新打开创建窗口以获取最新安全状态；加载状态失败时也可能显示邮箱方式，以服务端要求为准。                             |
| 创建请求报错或结果不明确               | 先刷新并检查已授权列表；不能仅凭错误提示判断密钥未创建。列表读取权限不足时，联系管理员确认结果，再决定是否重新创建。 |
| 关闭成功窗口前没有保存完整密钥         | 列表无法恢复完整值。删除这把无法使用的密钥，重新创建并立即保存。                                                     |
| 当前页为空                             | 查看是否可以进入下一页；也可能是权限过滤或列表加载失败，不能仅凭空页判断没有密钥。                                   |
| 删除成功但列表未更新                   | 点击刷新重试当前页；删除最后一项后可返回上一页检查。                                                                 |
