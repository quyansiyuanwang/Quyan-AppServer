# 验证页面

登录、注册、安全变更或高风险操作需要 2FA 时，会在当前页面显示全屏验证层；页面内容和未提交的编辑保持原样。直接访问 `/auth/verify` 时仍可使用独立验证页。Captcha 使用独立的 `/auth/captcha` 页面。

## 完成二次验证

1. 先阅读当前操作为何需要验证。
2. 选择可用的验证方式。
3. 输入对应验证码。
4. 提交后等待登录完成，或等待原操作继续执行。请查看原页面的最终结果；验证通过不代表原操作一定成功。

### 选择验证码方式

- 使用验证器应用时，输入应用显示的六位动态码。无法使用验证器时，可在该方式下选择**使用恢复码**，输入保存的恢复码；每个恢复码只能使用一次。
- 使用邮箱验证时，切换到邮箱方式，点击**发送邮箱验证码**，再输入收到的六位码并提交。发送成功后按钮有 60 秒倒计时；发送可能要求先完成人机验证。
- 关闭 2FA 的验证界面使用动态码或恢复码，不提供邮箱方式。

邮箱验证码发送到当前账户已绑定的邮箱，发送成功后页面会显示脱敏地址；不能在此临时指定另一个收件地址。未绑定邮箱或无法使用该邮箱时，请使用动态码或未使用的恢复码。

## 完成人机验证

登录、注册、发送验证码、找回密码或重置密码时，系统可能要求先完成人机验证（Captcha）。按验证组件提示操作；独立的 `/auth/captcha` 页面使用 Turnstile，通过后会返回原入口。

人机验证通过只表示满足本次操作的人机验证要求，并不代表已完成登录或身份验证。系统可能在配置的信任窗口内免去重复的人机验证，具体以当前服务端配置为准。

## 常见问题

| 现象                   | 处理方式                                                                                                                  |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| 动态码被拒绝           | 确认使用当前账户的验证器条目，检查设备时间，并输入当前六位动态码。                                                        |
| 恢复码被拒绝           | 确认该代码尚未使用。每个恢复码只能使用一次，切勿与动态码同时提交。                                                        |
| 没收到邮箱验证码       | 核对页面显示的脱敏地址，检查垃圾邮件；倒计时结束后再重发。发送失败时按提示处理人机验证或联系管理员检查邮件服务。          |
| 提示操作过于频繁       | 按页面提示等待后重试。注册、找回密码、2FA 验证及验证码发送有各自的服务端限制，60 秒按钮倒计时结束不保证服务端限制已解除。 |
| 提示验证挑战缺失或过期 | 重新发起登录或原操作以取得新的验证挑战，不要反复提交旧验证码。直接打开独立验证页不会自动创建挑战。                        |
| 验证成功但原操作报错   | 阅读原页面的错误提示，处理权限、参数或服务异常。结果不明确时先检查是否已生效，再决定是否重试。                            |

## 说明

- 全屏验证层可能在登录、注册、关闭 2FA、邮箱变更或高风险操作（step-up）中出现；升级验证成功后继续当前页面的待处理请求，不会重新打开该页面。
- 刷新页面后如仍有待处理的验证挑战，会重新显示验证层；页面内未提交的数据和待处理的原请求不会跨刷新保留，验证完成后需重新发起原操作。已过期的挑战也需重新发起原操作。
- 恢复码应离线妥善保存，每个恢复码仅可使用一次。
- 如果页面中展示了政策同意内容，请先阅读后再继续。
- 独立验证页提供返回按钮；全屏验证层不能通过遮罩、Esc 或界面返回按钮关闭。
