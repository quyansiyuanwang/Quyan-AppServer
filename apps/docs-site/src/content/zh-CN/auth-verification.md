# 验证页面

登录、注册、安全变更或高风险操作需要 2FA 时，会在当前页面显示全屏验证层；页面内容和未提交的编辑保持原样。直接访问 `/auth/verify` 时仍可使用独立验证页。Captcha 使用独立的 `/auth/captcha` 页面。

## 页面用途

- 完成双重验证（2FA）。
- 通过 step-up 安全校验（高风险操作前二次确认）。
- 在常规二次验证不可用时使用恢复码。
- 完成验证码（Captcha）信任验证。

## 你会看到什么

### 验证方式

- 验证器应用动态码（TOTP）输入。
- 邮箱验证码输入。
- 恢复码输入（如支持）。
- 验证方式切换入口。

### Captcha 验证

在注册、发送验证码、找回密码、重置密码等操作前，系统可能要求完成 Captcha 验证：

- 独立验证页面使用 Turnstile；按页面提示完成验证。
- 完成后，系统可能在配置的信任窗口内免去重复的 Captcha 验证。

### 频率限制

系统对以下操作设置了频率限制，具体限制维度和等待时间取决于操作及服务端配置：

- 注册邮箱验证码发送。
- 找回密码验证码发送。
- 2FA 验证码验证（按 IP + 挑战令牌双维度）。
- 2FA 邮箱验证码发送。

超出限制时请按页面提示等待后重试。

### 操作区

- 提交按钮。
- 独立验证页提供返回按钮；全屏验证层不能通过遮罩、Esc 或返回按钮关闭。
- 当前为什么需要验证的提示信息。

## 常见操作

1. 先阅读当前操作为何需要验证。
2. 选择可用的验证方式。
3. 输入对应验证码。
4. 提交后等待系统继续完成受保护操作。

### 选择验证码方式

- 使用验证器应用时，输入应用显示的六位动态码。无法使用验证器时，可在该方式下选择**使用恢复码**，输入保存的恢复码；每个恢复码只能使用一次。
- 使用邮箱验证时，切换到邮箱方式，点击**发送邮箱验证码**，再输入收到的六位码并提交。发送成功后按钮有 60 秒倒计时；发送可能要求先完成人机验证。
- 关闭 2FA 的验证界面使用动态码或恢复码，不提供邮箱方式。

## 说明

- 全屏验证层可能在登录、注册、关闭 2FA、邮箱变更或高风险操作（step-up）中出现；升级验证成功后继续当前页面的待处理请求，不会重新打开该页面。
- 刷新页面后如仍有待处理的验证挑战，会重新显示验证层；页面内未提交的数据和待处理的原请求不会跨刷新保留，验证完成后需重新发起原操作。已过期的挑战也需重新发起原操作。
- 恢复码应离线妥善保存，每个恢复码仅可使用一次。
- 如果页面中展示了政策同意内容，请先阅读后再继续。
- 如果验证失败，请检查验证码和设备时间；挑战过期时重新发起原操作。
