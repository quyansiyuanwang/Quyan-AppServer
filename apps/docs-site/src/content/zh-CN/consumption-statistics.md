# 消耗统计

消耗统计用于查看部署范围的消费趋势，按用户、模型、渠道及中转令牌筛选报表。页面内标题为“消费统计”。它适合定位消费集中点；逐笔对账、请求成功率及 OJ 用量应结合各自的明细页面核对。

## 使用前提

进入页面需要 `SYSTEM_CONSUMPTION_STATS_READ`。IAM 强制模式还要求该资格来自真实部署全局管理组，并允许 `quyan:system:GetConsumptionStatistics` 访问 `acs:platform:*:platform:system/consumption-stats`。个人附加权限或账号内策略不能替代全局组资格。

授权覆盖整份部署报告，包括筛选候选和各维度明细。选择某个用户只缩小报表内容，不会将接口变成个人查询。查看自己的用量，请使用[消费记录]({{DOCS_BASE_URL}}/zh-CN/consumption-records)或 [OJ 用量统计]({{DOCS_BASE_URL}}/zh-CN/oj-usage-statistics)。

## 查询报表

1. 打开页面，等待初始报告加载。默认范围为含今天在内的最近 7 个自然日。
2. 选择开始和结束日期；更改日期会立即查询。
3. 在用户、模型、渠道或令牌中勾选条件，单击应用筛选。
4. 核对汇总与下方时间范围，再比较趋势和维度明细。
5. 需要更新时单击刷新；需要取消资源筛选时单击清空全部筛选，日期范围会保留。

页面没有自动刷新。选择超过 30 天的范围时，会分段查询后合并，加载时间可能增加；这些分段不是同一时刻的快照，核对变动中的数据时应缩小范围后刷新。

日期在浏览器本地选择并转换为时间戳，服务端再按服务器时区的自然日边界统计，日报也按服务器日期归类。浏览器和服务器时区不同时，日期边界可能与本地预期不同；跨页面对账时请统一时间范围和时区。

## 使用筛选

同一维度选中的多项为“或”，不同维度之间为“且”；某维度没有选中项表示不限该维度。

打开筛选框后，输入内容可匹配候选名称或标识。默认按不区分大小写的正则表达式搜索，例如 `gpt-4.*`；也可用 `/pattern/i`。无效正则会退回普通文本匹配。**搜索只缩小候选列表，不会自动勾选或查询。**

全选、反选和清空只作用于当前搜索结果，其他已选项保留。若要操作整个维度，先清除搜索；若要取消全部维度，使用清空全部筛选。

筛选候选来自所选日期内的可统计数据，不是所有用户、模型或渠道的目录。没有候选可能表示该时段没有对应记录。日期变化或刷新后，已不存在的候选会从选择中移除，页面可能再次查询；加载结束后重新核对范围。每个维度的接口选择上限为 1000 项，选择过多导致校验失败时应减少条件。

选择数量及标签反映当前勾选，应用前可能与旧报告不同。刷新或更改日期也会提交当前勾选。查询失败后，不要将旧结果或同步中的中间结果视为新筛选的报告。

## 理解统计口径

报告使用所选日期内的有效 API 使用扣费及月卡覆盖记录，按消费关联标识归并，不包括充值、转账、赠送及所有失败尝试。请求数是归并后的记录数，不是 HTTP 请求日志条数，也不能用于计算全部调用的成功率。

**此报告不能作为完整 OJ 账单。** 同一 OJ Key 的多次调用可能被归并，请求数、Token 和费用都可能不等于 OJ 逐笔合计。OJ 对账请使用 OJ 用量统计及对应余额交易，不要仅按这里的总量判断漏扣或多扣。

没有可匹配的中转使用详情，并不一定排除消费记录；部分记录仍可计入，但无法按中转令牌归属。开启令牌筛选后，这类记录可能不再显示。历史数据归档或删除也可能改变可统计范围，报表不承诺永久完整历史。

| 指标       | 含义                                                 |
| ---------- | ---------------------------------------------------- |
| 总消费     | 实际余额扣费与月卡覆盖金额之和，不等于余额实扣       |
| 实际扣费   | 纳入统计记录的余额扣费金额                           |
| 月卡覆盖   | 被月卡覆盖的金额，不是另一次余额扣款                 |
| 消费用户数 | 总消费大于 0 的去重用户数                            |
| 活跃用户数 | 在当前报告中有记录的去重用户数，不表示在线或登录人数 |
| 请求数     | 归并后的记录数；均摊消费以此为分母                   |
| Token 数   | 记录中保存的总 Token；缓存 Token 在独立卡片中展示    |

页面“零扣费请求”按**总消费为 0**统计；全部由月卡支付、但总消费大于 0 的请求不属于这一项。不要将它理解为所有未扣余额的请求。

金额显示四位小数，单次平均 Token 保留两位。汇总来自已记录金额，不会因当前渠道改名或价格调整重新定价。

## 阅读图表和明细

- 每日趋势展示总消费、请求数和消费用户数；金额和数量使用不同坐标轴。没有记录的日期可能不显示，不代表当天曾经发生查询失败。
- 渠道饼图只显示消费最高的前 8 项，其扇区百分比相对这 8 项计算；渠道表中的占比相对整个当前报告计算，两者可能不同。
- 模型和用户图各显示消费最高的前 10 项；完整返回维度看下方明细表。
- 渠道按名称归并，同名渠道可能合并；名称可能来自历史消费记录，不能直接视为当前渠道 ID。用户名称取当前可解析名称，无法解析时可显示用户 ID。

桌面端显示四组图表及较完整的渠道、模型、用户表。移动端仅显示每日趋势，明细在折叠区域中，字段也更精简；需要查看扣费、覆盖、请求及占比时可使用桌面端。

页面没有按令牌的明细表、原始请求详情或导出按钮。需要检查单次请求或财务调整时，继续查看消费记录、余额管理和业务日志；这份报告本身不会修改余额。

## 授权和常见问题

管理查询使用登录身份，不接受第三方 OAuth 访问令牌。服务端在读取前和返回前检查权限及全局组资格；角色会话使用角色自身授权，匹配的 Deny、身份失效或会话撤销会拒绝返回整份报告。

| 现象                         | 处理方法                                             |
| ---------------------------- | ---------------------------------------------------- |
| 勾选后数字没变化             | 单击应用筛选，确认查询成功；标签不代表已应用         |
| 某用户或模型没有出现在候选中 | 检查日期及统计口径，候选不是全量资源目录             |
| 结果突然扩大                 | 检查无效选择是否被移除；空选择表示不限该维度         |
| 总消费大于余额扣款           | 检查月卡覆盖，以及是否存在 OJ 归并口径差异           |
| 渠道饼图占比与表格不同       | 饼图仅计算前 8 项，表格占比使用全报告总消费          |
| 加载失败后仍有旧数据或初始 0 | 成功刷新前不要据此判断无消费或完成对账               |
| 需要个人记录却提示无权限     | 转到个人消费记录，不要申请部署范围报告来替代个人查询 |
