# 群组管理

此页面用于维护用户群组以及群组级权限集合。已启用 2FA 的操作者执行写入时可能需要二次验证。

## 页面用途

- 创建和编辑群组。
- 调整群组名称、等级和说明。
- 配置群组拥有的权限。
- 删除不再使用的群组。

## 你会看到什么

### 群组列表

- 群组名称。
- 等级、说明。
- 权限数量。

### 管理动作

- 新建群组。
- 编辑群组。
- 删除群组。
- 打开权限编辑器。

## 常见操作

1. 创建群组前先明确该群组的职责范围。
2. 使用编辑功能维护群组名称和说明，便于后续识别。
3. 打开权限编辑器批量勾选该群组应拥有的权限。
4. 删除群组前先确认没有用户仍依赖该群组。

## 权限要求

| 操作                | 所需权限                                           |
| ------------------- | -------------------------------------------------- |
| 查看群组列表 / 详情 | `GROUP_READ`                                       |
| 创建群组            | `GROUP_CREATE`                                     |
| 编辑群组            | `GROUP_UPDATE`                                     |
| 删除群组            | `GROUP_DELETE`                                     |
| 修改群组权限        | `GROUP_PERMISSION_ADD` / `GROUP_PERMISSION_REMOVE` |

## IAM 资源范围

enforce 模式下，查看列表需要账户目标的 quyan:group:Read；每个返回的群组还要通过其 acs:quyan:\*:<accountId>:group/<groupId> 的 Read 检查。编辑和删除分别检查同一个群组的 Update 和 Delete。创建群组检查账户目标的 Create，群组归属从当前认证账户生成，客户端不能指定其他账户。

列表先限制当前账户与既有等级范围，再逐组进行 IAM 过滤；过滤后可能出现空页，仍可通过“下一页”继续查看。此模式使用有上限的服务端分页，不显示未授权群组的总数。未指定分页参数时也返回默认页，API 使用者通过 hasMore 决定是否读取下一页。详情中的用户数只统计本账户用户。legacy/shadow 保留原来的分页总数和迁移行为。

添加群组权限要求该群组上的 quyan:group:permission:Add；移除要求 Remove，混合变更需要两者。保存时还会证明操作者可以委派保留或新增的完整权限范围，菜单可见性不能替代该证明。跨账户群组与未完成账户归属迁移的群组均拒绝访问；旧无归属恢复组仅向真实主账户恢复身份开放，子用户和角色会话不能借用该例外。

## 层级限制

群组拥有数字等级字段（level），操作受以下规则约束：

- 非超级管理员只能管理**等级高于自身**的群组（即数值更大）。
- 不能创建与自身同级或更高级别（数值更小或相等）的群组。
- 不能修改或删除与自身同级或更高级别的群组。
- 不能将群组等级调整为与自身同级或更高。

## 说明

- 群组权限通常会影响同组所有用户，legacy 模式按群组权限 + 用户附加权限 - 用户移除权限计算；enforce 还会评估 JSON 策略、资源范围和条件，显式 Deny 优先。
- 已启用 2FA 时，创建、编辑、删除及权限修改可能触发二次验证；有效的受信任窗口可按当前安全规则通过。
- 若用户存在额外权限或移除权限，最终效果应再到权限管理页确认。
