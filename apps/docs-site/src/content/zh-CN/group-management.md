# 群组管理

群组管理用于创建用户群组、设置等级和维护群组权限。同组用户共享群组的基础权限；用户级增加、移除项及 IAM 策略还可能改变实际授权结果。调整成员所属群组请使用[用户管理]({{DOCS_BASE_URL}}/zh-CN/user-management)。

## 使用前提

进入运营管理站的群组管理页面，确认具备目标操作权限。

| 操作                     | 所需权限                  |
| ------------------------ | ------------------------- |
| 查看列表、详情和群组权限 | `GROUP_READ`              |
| 新建群组                 | `GROUP_CREATE`            |
| 编辑名称、等级、说明     | `GROUP_UPDATE`            |
| 删除群组                 | `GROUP_DELETE`            |
| 增加群组权限             | `GROUP_PERMISSION_ADD`    |
| 移除群组权限             | `GROUP_PERMISSION_REMOVE` |

创建、编辑、删除和权限保存均要求重放保护。已启用 2FA 的操作者还可能需要二次验证，有效的受信任窗口按当前安全规则处理。

## 查找群组

列表显示群组标识、名称、等级、说明及配置的权限数量。这里的权限数量不是成员数量，也不代表某个成员对具体资源最终可执行的操作数。

- 输入名称或群组标识的部分文字后按 Enter 搜索，清空输入框也会重新搜索。关键词不用于查询群组资源 ID 或说明。
- 打开“显示RAM角色”只保留配置了 RAM 权限的群组，不是列出所有 IAM 角色。
- 默认每页 10 条。搜索或切换筛选会返回第一页；刷新同时清空关键词和 RAM 筛选，并返回第一页。
- 页面不会自动刷新，也没有导出功能。列表加载失败时会清空当前记录，请根据错误提示重试，不要把空列表当作没有群组的证明。

IAM 强制模式下，页面可能只显示上一页、下一页，不显示总数。权限过滤后本页可能为空，但仍有下一页，应继续翻页确认。

## 理解等级限制

等级为 0～100 的整数，**数值越小，层级越高**。新建表单默认 50，不代表当前操作者一定能创建这个等级。

非超级管理员通常可看到数值大于或等于自身等级的群组，但只能创建、编辑、删除或修改权限于**数值严格大于自身等级**的群组。也不能把目标群组调整为与自己同级或层级更高。例如，自身等级为 20 时，可以管理等级 50 的群组，不能管理等级 20 或 10 的群组。

超级管理员的等级例外不替代操作权限、账户范围和受保护群组限制。列表或按钮可见不代表服务端会批准操作。

## 新建与编辑群组

1. 单击新建群组，填写标识和等级；名称、说明可选。
2. 单击确认，按提示完成验证。
3. 在列表中核对结果。新建群组的权限集合为空，需要另行配置权限；创建群组不会自动把用户加入其中。
4. 如需调整已有群组，单击编辑，修改名称、等级或说明后确认。

| 字段 | 限制                                                                                  |
| ---- | ------------------------------------------------------------------------------------- |
| 标识 | 去除首尾空格后为 2～30 个字符，仅字母、数字、下划线和连字符；须避开已有有效群组的标识 |
| 名称 | 可选，最多 50 个字符                                                                  |
| 等级 | 0～100 的整数，另受操作者等级限制                                                     |
| 说明 | 可选，最多 200 个字符                                                                 |

编辑表单不提供修改标识的入口。将已有名称或说明清空再保存，会保留原值；需要清除时，可由有更新权限的集成通过更新接口显式提交空字符串并核对结果。

提交失败会保留表单输入；关闭会清空输入，页面不自动保存。编辑使用列表中已加载的内容，其他管理员修改后，应先重新加载再编辑，避免以旧值覆盖新值。新建或编辑成功后会重新加载当前页，不会自动定位到目标群组；筛选条件或等级变化可能让它不再显示。

## 配置群组权限

1. 找到目标群组，单击权限。页面成功读取当前权限后才打开编辑窗口。
2. 按分类或关键词查找权限，检查选中集合及数量。
3. 勾选增加的权限，取消勾选要移除的权限。只具备增加权限时不能移除现有项，反之亦然；混合变更需要两种权限。
4. 单击保存，重新打开权限窗口核对结果。没有变更时不能保存。

保存会提交**完整选中集合**。搜索只帮助查找，不会清除搜索范围外的选择。操作前应确认影响，因为群组权限变更会影响同组用户的基础权限。

服务端还会检查操作者是否能够委派所有保留或新增的权限。权限树中可见或可勾选的项目，不代表均可授予。即使只删除一项，如果仍保留了超出操作者委派范围的权限，也可能无法保存。

权限读取失败时不会打开编辑窗口；保存失败时保留当前选择。遇到并发或授权变化提示，应关闭后重新打开，核对最新集合再修改，不要反复提交旧选择。页面不提供变更历史或撤销操作。

## 删除群组

1. 先在用户管理中处理仍归属此群组的用户。
2. 回到群组管理，核对目标标识，单击删除并确认。
3. 按提示完成验证，确认该记录已从列表移除。

仍关联用户的群组不能删除，包括关联用户已停用的情况。由当前服务端配置保护的群组不能删除。删除不会替你迁移成员，页面也没有恢复入口。

操作成功后列表重新加载仍可能失败。此时应重新查询确认结果，不要直接重复创建、删除或保存权限。

## IAM 资源范围

IAM 强制模式下，动作与资源分别按下表检查。

| 操作               | IAM 动作                        | 资源                     |
| ------------------ | ------------------------------- | ------------------------ |
| 列表               | `quyan:group:Read`              | 账户目标及每个返回的群组 |
| 详情、读取群组权限 | `quyan:group:Read`              | 目标群组                 |
| 创建               | `quyan:group:Create`            | 当前认证账户             |
| 编辑               | `quyan:group:Update`            | 目标群组                 |
| 删除               | `quyan:group:Delete`            | 目标群组                 |
| 增加权限           | `quyan:group:permission:Add`    | 目标群组                 |
| 移除权限           | `quyan:group:permission:Remove` | 目标群组                 |

账户资源为 `acs:quyan:*:<accountId>:account`，群组资源为 `acs:quyan:*:<accountId>:group/<groupId>`。创建归属由认证账户确定，不能通过请求指定其他账户。列表先限制账户和等级，再过滤各群组授权；API 使用者需按 `hasMore` 翻页，未指定分页也只返回默认页，不返回未授权群组的总数。详情中的用户数量仅统计本账户用户。

保存权限还需通过完整权限范围的委派检查，匹配的 Deny 优先。跨账户或尚未完成账户归属迁移的群组会被拒绝；旧无归属恢复组只向真实主账户恢复身份开放，子用户和角色会话不能使用此例外。legacy/shadow 模式保留原有可见范围和分页总数规则。
