# Relay Token 管理

此页面用于管理转发 Token、渠道路由、额度窗口和故障转移策略。

## 页面用途

- 创建和维护转发 Token。
- 查看 Token 用量、到期时间与额度窗口。
- 控制渠道顺序与故障转移逻辑。
- 在不立即删除的情况下先停用 Token。
- 批量导入/导出 Token 和渠道配置。

## 你会看到什么

### Token 列表

- Token 名称与可搜索的 Token 信息。
- 请求次数与累计 Token 用量。
- 到期时间、状态与额度使用情况。
- 分页模式或全部展示模式。

### 额度窗口（Quota Windows）

每个 Token 可配置一到多个滚动时间窗口限制，例如每分钟、每小时或每天的最大用量：

- 启用 / 禁用额度窗口总开关。
- 每个窗口独立显示已用量 / 上限与重置时间。
- 达到上限时该 Token 请求会被拒绝，直至窗口重置。

### IP 白名单

- 为 Token 绑定允许访问的 IP 或 CIDR 范围。
- 留空表示不限制来源 IP；填写后仅白名单内的 IP 可使用该 Token。

### 请求格式转换

每个 Token 最多可配置 3 条转换规则，且每种来源格式只能配置一次。可在 Anthropic Messages、OpenAI Chat Completions 与 OpenAI Responses 之间转换；空规则列表表示关闭转换。

- 调用方仍使用来源格式的普通响应、错误和流式事件；渠道筛选、上游路径、认证和计费按目标格式执行。
- 目标渠道和模型必须启用目标格式。转换会带来少量 CPU 与内存开销，且协议间的语义与计费可能不同。
- 无法安全等价的专有字段会被拒绝而不是静默丢弃，例如异步/会话请求、托管工具、文件或音视频输入、缓存控制等。
- Chat Completions 或 Responses 转 Anthropic 时必须提供可映射的最大输出 Token；不会自动补默认值。

### Anthropic 请求整流

每个 Token 都可单独启用 Anthropic 请求整流。它只影响使用该 Token 发出的 Anthropic Messages 请求，不会修改其他 Token、渠道设置或模型目录。

- 总开关关闭时不改写或重试请求。
- 可分别启用 Thinking 签名、Thinking Budget 和不支持图片的整流。签名整流会移除不兼容的 thinking 块或签名；Budget 整流会将 thinking 规范为启用状态、使用 32000 的预算，并在必要时提高最大输出 Token。
- 图片降级只在上游明确返回不支持图片时，将图片块替换为 `[Unsupported Image]` 后用同一 Token 重试。若要在发送前处理，可在当前 Token 中维护明确的纯文本上游模型 ID；系统不会根据模型名称猜测图片能力，因此未配置的新模型默认原样转发。
- 每个请求最多执行一次整流重试，始终使用原 Token 和当前渠道。流式响应已经开始输出后不会重试；整流重试仍失败时不会触发普通故障转移。

### 上游 `/v1` 路径模式

每个 Token 都可单独控制转发到上游时的 `/v1` 前缀。此设置独立于 Anthropic 请求整流总开关，默认使用“自动适配”。

- `关闭`：保留调用方请求的路径，不增加或移除 `/v1`。
- `自动适配`：上游路径始终保留一个 `/v1`。例如 `/responses` 会转发为 `/v1/responses`，而重复的 `/v1/v1/responses` 会规范为 `/v1/responses`。
- `始终添加`：无论原路径是否已有前缀，都会再添加一个 `/v1`。需要兼容要求重复版本前缀的特殊上游时才使用。

### 渠道与故障转移

- 有序渠道列表。
- 故障转移摘要（主用渠道不可用时自动切换）。
- 额度窗口详情面板。

### 路由模式

每个 Token 只能选择一种渠道模式：

- `有序渠道`：维护渠道顺序并使用故障转移配置。
- `自动代理池`：选择一个自动代理池，不显示或保存有序渠道列表；池成员由管理员或自动化程序统一维护。令牌可屏蔽池内个别渠道，屏蔽仅影响该令牌，不会修改池的全局成员。

自动代理池中的实际命中成员决定上游、模型能力和计费倍率。Token 用户只能查看成员并为自己的令牌选择屏蔽项，不能编辑自动代理池的全局成员配置。

### 管理动作

- 新建 Token。
- 编辑 Token（含额度窗口和 IP 白名单）。
- 克隆 Token（复制全部配置生成新 Token）。
- 刷新 Token 值（生成新密钥，旧密钥立即失效）。
- 启用或停用 Token。
- 删除 Token。
- **批量操作**：导入 / 导出 Token 列表（JSON 格式）。
- **渠道批量操作**：导入 / 导出渠道配置，或批量选择渠道并按选择顺序追加到有序列表。

## 常见操作

1. 创建具有可识别名称的 Token。
2. 配置渠道顺序和故障转移策略；需要兼容 Anthropic 上游差异时，在编辑页开启该 Token 的请求整流。
3. 如需限速，开启额度窗口并设置各时间维度的上限。
4. 如需来源限制，填写 IP 白名单。
5. 定期查看额度使用情况，避免意外限流。
6. 想先停止流量时，可优先停用而不是直接删除。
7. 批量迁移或备份配置时使用导入/导出功能。

## 创建后如何调用 AI

创建成功后，先复制令牌创建抽屉顶部显示的 **Relay Base URL**，再将新令牌保存到调用方的服务端环境变量。不要将令牌提交到代码仓库、放进浏览器前端代码，或当作后台登录凭证使用。

调用前可先请求 `Relay Base URL + /v1/models` 确认可用模型。调用 OpenAI Chat Completions 时，完整地址是 `Relay Base URL + /v1/chat/completions`，并携带：

```text
Authorization: Bearer <relay_token>
Content-Type: application/json
```

请求格式必须与令牌渠道中启用的格式一致，或在该 Token 上配置对应的请求格式转换。需要完整的 curl 示例、Responses 格式和图片请求说明时，继续查看 `api-documentation`；需要调整渠道、模型或格式时查看 `relay-settings`。

## 说明

- 刷新 Token 值会立即使旧 Token 字符串失效，调用方需同步更新。
- **额度窗口与总配额的区别**：每个 Token 有一个永不重置的总配额上限（`quotaLimit`，按创建以来的累计用量计算），这与上文的额度窗口是两套独立机制——额度窗口会按各自周期（每分钟/每小时/每天）自动重置。两者可同时启用：总配额一旦用尽会永久停止该 Token，而额度窗口只会限流到下一次重置为止。
- 批量导入时现有 Token 不会被覆盖，导入内容作为新条目追加。
- "全部展示"模式适合审计，但阅读负担更高。
