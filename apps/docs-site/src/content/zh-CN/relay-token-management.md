# Relay Token 管理

此页面用于管理转发 Token、渠道路由、额度窗口和故障转移策略。

## 页面用途

- 创建和维护转发 Token。
- 查看 Token 用量、到期时间与额度窗口。
- 控制渠道顺序与故障转移逻辑。
- 在不立即删除的情况下先停用 Token。
- 批量导入/导出 Token 和渠道配置。

## 你会看到什么

### Token 列表

- Token 名称与可搜索的 Token 信息。
- 请求次数与累计 Token 用量。
- 到期时间、状态与额度使用情况。
- 分页模式或全部展示模式。

### 资源级访问与凭据披露

启用 IAM 强制模式后，列表使用 `quyan:relay:ListTokens`，单个 Token 查询使用 `quyan:relay:GetToken`。服务端逐项评估 Token 资源 `acs:relay:*:<accountId>:token/<userId>/<tokenId>`，没有读取权限的记录不会出现在当前页或总数中；知道 Token ID 不代表获得访问权限。已停用但获准读取的 Token 仍可见，已删除的 Token 不可见。

允许读取 Token 元数据不等于允许获取凭据。这两个读取接口只有在同一资源也获准执行 `quyan:relay:RevealToken` 时才返回 `token` 字段；显式 Deny 优先于 Allow。没有披露权限时，页面仍可展示获准读取的用量和配置，但凭据位置显示不可用提示。复制凭据、打开余额脚本、导入受支持客户端都需要接口实际返回凭据。批量复制时，只要任一选中项没有凭据就停止，不会用 Token ID 替代，也不会悄悄漏掉部分选中项。

读取其他用户的 Token（包括同账户内其他用户）还需要平台管理资格，以及目标用户和 Token 资源上的 `ListManagedTokens` / `GetManagedToken` 授权；披露凭据另需 `RevealManagedToken`。账户策略中的 `"*"` 不能自行赋予平台管理资格。OAuth 访问还受应用和访问令牌当前的 scope、有效期与撤销状态限制。

导出要求每个选中 Token 同时获准执行 `quyan:relay:ExportTokens` 和 `RevealToken`。管理其他用户的导出，还需平台管理资格、当前用户的接口准入，以及目标平台资源上的 `ExportManagedTokens` / `RevealManagedToken`。显式选中 ID 时按提交顺序导出；未指定时导出已启用的 Token，`includeDisabled: true` 可同时包含停用项，但不会包含已删除项。任一指定 Token 不存在或未获准，或组合 Token 引用的成员无法导出，整个请求都会失败，不会静默生成不完整的备份。导出的组合配置保留获准的成员引用，但只有成员本身也被选中且获准披露时才导出其凭据。

以上披露规则覆盖列表、单个 Token 读取和导出。刷新、复制和修改仍属于独立操作，具有各自的授权要求；不能因为只授予了元数据读取，就假定其他已授予的操作不会返回凭据。在 legacy 或 shadow 模式下，原有权限检查仍决定是否放行，shadow 对比本身不会启用 IAM 强制授权。

### 删除与批量删除

启用 IAM 强制模式后，单个和批量删除均逐资源检查 `quyan:relay:DeleteToken`。删除不要求额外拥有读取或凭据披露权限；删除响应也不返回凭据。管理其他用户的 Token（包括同账户内其他用户）还需平台管理资格、当前用户的删除接口准入，以及目标平台用户和每个 Token 上的 `quyan:relay:DeleteManagedToken`。仅有管理读取资格不足以删除。

批量删除最多接受 200 个互不重复的 Token ID。任一目标不存在、已删除、不属于选定用户、被拒绝授权，或执行期间身份、授权或资源状态发生变化，整个请求失败，不会留下部分删除。已停用或过期的 Token 仍可在获准后删除。单个删除同样受这些检查约束。

删除会使 Token 不再可用，不会删除组合 Token 中已有的成员引用或历史用量。引用该 Token 的组合分支随后不可用，需另行编辑组合配置。删除接口保留重放保护和二次验证要求。在 legacy / shadow 模式下，仍执行原有删除逻辑；上述资源级和整批原子性保证适用于 enforce 模式。

### 额度窗口（Quota Windows）

每个 Token 可配置一到多个滚动时间窗口限制，例如每分钟、每小时或每天的最大用量：

- 启用 / 禁用额度窗口总开关。
- 每个窗口独立显示已用量 / 上限与重置时间。
- 达到上限时该 Token 请求会被拒绝，直至窗口重置。

### IP 白名单

- 为 Token 绑定允许访问的 IP 或 CIDR 范围。
- 留空表示不限制来源 IP；填写后仅白名单内的 IP 可使用该 Token。

### 请求格式转换

每个 Token 最多可配置 3 条转换规则，且每种来源格式只能配置一次。可在 Anthropic Messages、OpenAI Chat Completions 与 OpenAI Responses 之间转换；空规则列表表示关闭转换。

- 调用方仍使用来源格式的普通响应、错误和流式事件；渠道筛选、上游路径、认证和计费按目标格式执行。
- 目标渠道和模型必须启用目标格式。转换会带来少量 CPU 与内存开销，且协议间的语义与计费可能不同。
- 无法安全等价的专有字段会被拒绝而不是静默丢弃，例如异步/会话请求、托管工具、文件或音视频输入、缓存控制等。
- Chat Completions 或 Responses 转 Anthropic 时必须提供可映射的最大输出 Token；不会自动补默认值。

### Anthropic 请求整流

每个 Token 都可单独启用 Anthropic 请求整流。它只影响使用该 Token 发出的 Anthropic Messages 请求，不会修改其他 Token、渠道设置或模型目录。

- 总开关关闭时不改写或重试请求。
- 可分别启用 Thinking 签名、Thinking Budget 和不支持图片的整流。签名整流会移除不兼容的 thinking 块或签名；Budget 整流会将 thinking 规范为启用状态、使用 32000 的预算，并在必要时提高最大输出 Token。
- 图片降级只在上游明确返回不支持图片时，将图片块替换为 `[Unsupported Image]` 后用同一 Token 重试。若要在发送前处理，可在当前 Token 中维护明确的纯文本上游模型 ID；系统不会根据模型名称猜测图片能力，因此未配置的新模型默认原样转发。
- 每个请求最多执行一次整流重试，始终使用原 Token 和当前渠道。流式响应已经开始输出后不会重试；整流重试仍失败时不会触发普通故障转移。

### 上游 `/v1` 路径模式

每个 Token 都可单独控制转发到上游时的 `/v1` 前缀。此设置独立于 Anthropic 请求整流总开关，默认使用“自动适配”。

- `关闭`：保留调用方请求的路径，不增加或移除 `/v1`。
- `自动适配`：上游路径始终保留一个 `/v1`。例如 `/responses` 会转发为 `/v1/responses`，而重复的 `/v1/v1/responses` 会规范为 `/v1/responses`。
- `始终添加`：无论原路径是否已有前缀，都会再添加一个 `/v1`。需要兼容要求重复版本前缀的特殊上游时才使用。

### 渠道与故障转移

- 有序渠道列表。
- 故障转移摘要（主用渠道不可用时自动切换）。
- 额度窗口详情面板。
- 启用自动切换且最大渠道切换次数低于建议值时，保存前会询问是否采用建议值。也可以保留当前值后继续保存；关闭确认框会取消本次保存。

### 路由模式

每个 Token 只能选择一种渠道模式：

- `有序渠道`：维护渠道顺序并使用故障转移配置。
- `自动代理池`：选择一个自动代理池，不显示或保存有序渠道列表；池成员由管理员或自动化程序统一维护。令牌可屏蔽池内个别渠道，屏蔽仅影响该令牌，不会修改池的全局成员。

自动代理池中的实际命中成员决定上游、模型能力和计费倍率。Token 用户只能查看成员并为自己的令牌选择屏蔽项，不能编辑自动代理池的全局成员配置。

### 管理动作

- 新建 Token。
- 编辑 Token（含额度窗口和 IP 白名单）。
- 克隆 Token（复制全部配置生成新 Token）。
- 刷新 Token 值（生成新密钥，旧密钥立即失效）。
- 启用或停用 Token。
- 删除 Token。
- **批量操作**：导入 / 导出 Token 列表（JSON 格式）。
- **渠道批量操作**：导入 / 导出渠道配置，或批量选择渠道并按选择顺序追加到有序列表。

## 常见操作

1. 创建具有可识别名称的 Token。
2. 配置渠道顺序和故障转移策略；需要兼容 Anthropic 上游差异时，在编辑页开启该 Token 的请求整流。
3. 如需限速，开启额度窗口并设置各时间维度的上限。
4. 如需来源限制，填写 IP 白名单。
5. 定期查看额度使用情况，避免意外限流。
6. 想先停止流量时，可优先停用而不是直接删除。
7. 批量迁移或备份配置时使用导入/导出功能。

## 创建后如何调用 AI

创建成功后，先复制令牌创建抽屉顶部显示的 **Relay Base URL**，再将新令牌保存到调用方的服务端环境变量。不要将令牌提交到代码仓库、放进浏览器前端代码，或当作后台登录凭证使用。

调用前可先请求 `Relay Base URL + /v1/models` 确认可用模型。调用 OpenAI Chat Completions 时，完整地址是 `Relay Base URL + /v1/chat/completions`，并携带：

```text
Authorization: Bearer <relay_token>
Content-Type: application/json
```

请求格式必须与令牌渠道中启用的格式一致，或在该 Token 上配置对应的请求格式转换。需要完整的 curl 示例、Responses 格式和图片请求说明时，继续查看 `api-documentation`；需要调整渠道、模型或格式时查看 `relay-settings`。

## 自动代理池屏蔽成员

如果令牌使用自动代理池，可以在成员设置中屏蔽暂不希望使用的成员。保存和回显使用成员 ID；屏蔽同时适用于直接成员和嵌套成员，不会改变令牌的计费规则。服务端会拒绝池外、禁用或会导致没有可用成员的配置。

## 说明

- 刷新 Token 值会立即使旧 Token 字符串失效，调用方需同步更新。
- **额度窗口与总配额的区别**：每个 Token 有一个永不重置的总配额上限（`quotaLimit`，按创建以来的累计用量计算），这与上文的额度窗口是两套独立机制——额度窗口会按各自周期（每分钟/每小时/每天）自动重置。两者可同时启用：总配额一旦用尽会永久停止该 Token，而额度窗口只会限流到下一次重置为止。
- 批量导入时现有 Token 不会被覆盖，导入内容作为新条目追加。
- "全部展示"模式适合审计，但阅读负担更高。

## 组合令牌：把自己的令牌作为有序成员

在新建或编辑抽屉选择“组合令牌”，搜索并加入自己拥有的 Relay Token，再调整顺序、启停成员。成员既可以是有序渠道或自动代理池令牌，也可以是另一个组合令牌。系统引用成员 ID，不复制成员密钥或渠道配置；管理员代管也不能把不同用户的令牌组合在一起。

- 保存前会确认成员及顺序。编辑时切换模式会清理原模式的绑定，但保留当前令牌值和历史用量，不修改源令牌。
- 最多支持 **4 层组合节点**，末端普通令牌不计入层数；每个组合最多 **20 个直接成员**，每个入口最多 **100 条末端路径**。禁止自引用和环路；禁用的绑定也会接受图结构校验。
- 点击“加载可用模型”查看成员的 Chat Completions、Responses、Anthropic 和 Gemini 协议目录，点击“预览模型与路由”查看聚合模型及某个模型的候选路径。目录不会把全局定价表当作渠道模型清单；组合中明确配置的别名会在对应路径验证后展示。
- 实际请求按成员顺序深度优先选择支持协议和模型的路径。禁用、过期、删除、IP 不匹配或额度耗尽的成员分支不可用；入口自身的限制失败直接终止。
- 默认跨成员故障转移状态为 `408、429、500、502、503、504`，每层仅控制直接成员之间的切换，普通令牌内部保持原来的渠道策略。一条客户端请求最多执行 **100 次实际上游尝试**，含内部重试。响应已经提交后不会重发或切换。

### 高级配置与安全

请求的模型映射、协议转换及适用的规范化从外层到内层执行，随后由末端普通令牌选择物理渠道；响应协议转换按相反顺序执行。每层模型白名单、有效期、IP 与额度规则独立生效，不能由下层关闭上层的安全要求。安全拒绝不会通过备用成员绕过。协议转换只支持现有转换器已支持的字段，无法安全转换的请求会明确拒绝；流式预检上限取命中路径中各层的最小值。

“预览”反映模型能力和配置顺序，不保证实时可用：IP、额度、安全与上游健康仍会在实际请求时检查。成员修改、禁用会影响后续请求；成员密钥刷新不要求重新配置组合入口，引用按 ID 保持。已开始的请求沿用当时的路由快照。

### 用量与费用

入口组合、命中的中间组合和末端令牌都记录对应用量，并执行各自的总额度及滑动窗口限制。**同一次调用的余额、月卡和渠道收益只结算一次**；未尝试分支不计量，失败尝试沿用现有失败用量规则。

各层显示的是同一调用在不同令牌上的归因，**不能把组合和成员的用量相加作为总费用**。财务总额以消费流水为准。历史普通令牌记录仍可正常查询，无需回填。

### 与 Quyan CLI 本地 Router 配合

组合令牌可以直接作为一个 Router Profile：先创建组合令牌，再运行 `quyan router profile add --token-id <组合令牌ID> --yes`，刷新模型目录即可。修改服务端组合成员和优先级无需重启已接入本地 Router 的 Agent；模型目录变更后使用 `quyan router models --refresh` 更新本地缓存。

复制组合令牌保留同一用户的合法成员引用；导入只接受目标用户已经存在且能验证的成员 ID，不按名称猜测或自动创建缺失成员。
