# 设置

**设置**是侧边栏的一个顶级导航项，展开后包含四个子页面。点击设置旁边的箭头展开子菜单，然后跳转到所需页面。

## 子页面

### 个人资料

路径：**设置 → 个人资料**

查看用户名，并分别修改显示名称和邮箱。

- 编辑显示名称。
- 通过发送到新邮箱的验证码修改邮箱。
- 查看用户名（只读）。

#### 修改显示名称

1. 输入新的显示名称，最多 50 个字符。
2. 点击名称旁的**保存**，等待成功提示。名称修改不会更改登录用户名。

清空名称输入框再保存不会删除原显示名称。邮箱需要通过下方的独立流程修改，点击名称旁的保存不会保存邮箱。

#### 更换邮箱

1. 输入可以收信的新邮箱，点击**发送验证码**。如要求人机验证或 2FA，请先完成验证。
2. 到新邮箱查收六位验证码，填写后点击**修改邮箱**。
3. 等待成功提示，并核对页面显示的当前邮箱。发送验证码本身不会更换邮箱。

新邮箱不能与当前邮箱相同，也不能已被其他未删除账户占用。成功更换后，最近 24 小时内不能再次更换；跨过零点不会重置这个限制。发送成功后的按钮倒计时为 60 秒，验证码有效期以当前服务配置为准。

### 偏好设置

路径：**设置 → 偏好设置**

调整界面外观并清理本地缓存数据。

- 切换亮色或暗色主题。
- 切换界面语言。
- 按项清理浏览器中的 LocalStorage 和 SessionDB 数据。

#### 清理本地缓存

1. 在偏好设置中选择 **清理缓存**，查看当前可清理的项目及其大小。
2. 勾选需要清理的项目或项目组，选择 **清理所选**。至少需要选择一项。
3. 清理认证令牌等登录数据会显示需要重新登录的提示并重新加载页面；清理主题、语言或用户信息缓存等项目也会重新加载页面。请在操作前保存尚未提交的内容。

此操作针对当前浏览器中所选的本地数据，不会删除服务器上的账户数据。未列出的浏览器数据不在此页面的清理范围内。清理按项执行；如果出现错误，之前已清理的项目不会自动恢复。请重新打开清理窗口检查剩余项目，再决定是否重试；如登录数据已被清除，可能需要重新登录。

### 账户安全

路径：**设置 → 账户安全**

管理凭证和认证方式。

- 修改密码（需要 `user:change_self_password` 权限）。
- 创建、复制和删除访问密钥。
- 注册和删除用于无密码登录的通行密钥（Passkey）。
- 启用或关闭双重验证（TOTP）。
- 管理可跳过重复 2FA 验证的受信任设备。
- 绑定或解绑部署已启用的外部账号。

#### 修改密码

1. 输入新密码和确认密码，确保两次一致。
2. 点击**修改密码**；如要求 2FA，按提示完成验证并等待原请求继续。
3. 修改成功后，当前页面会退出登录，请使用新密码重新登录。修改密码不会关闭已启用的 2FA。

#### 绑定和解绑外部账号

1. 在外部账号区域选择可用的 GitHub 或微信绑定入口。是否显示入口取决于部署配置。
2. 按认证站和外部平台提示完成授权，返回账户安全页后检查绑定列表。
3. 解绑前确认仍有其他可用的登录方式，再点击该绑定项的**删除**。此按钮直接发起解绑，请先核对提供方和账号信息。

同一提供方不能同时绑定多个外部账号；需要更换时先解绑原账号。解绑只解除本站的账号关联，不会删除外部平台账号。发生错误或返回后未看到预期结果时，重新打开账户安全页检查当前绑定状态，再决定是否重试。

### 事件中心

路径：**设置 → 事件中心**

配置通知偏好、邮件推送和 Webhook。详见 [通知设置]({{DOCS_BASE_URL}}/zh-CN/notification-settings)。

## 说明

- 修改邮箱和密码可能需要验证步骤或 2FA 挑战。
- 清理主题、语言等缓存可能重置相应的本地偏好；清理认证令牌后可能需要重新登录。这里的缓存清理不用于撤销所有设备的登录会话。
- 访问密钥、通行密钥和受信任设备在账户安全页的抽屉中进行管理，详见 [访问密钥管理]({{DOCS_BASE_URL}}/zh-CN/access-key-management)、[通行密钥管理]({{DOCS_BASE_URL}}/zh-CN/passkey-management)、[受信任设备管理]({{DOCS_BASE_URL}}/zh-CN/trusted-device-management)。

## 个人资料权限和资源范围

启用 IAM 强制授权后，读取当前资料使用 `quyan:user:GetCurrentUser`，资源为 `acs:quyan:*:<accountId>:user/<userId>`。已认证身份默认只能读取本人资料，匹配的显式 Deny 仍会阻止读取；这个能力不允许查询其他用户或管理账号。

修改显示名称需要独立的 `quyan:user:UpdateProfile` 权限，不会因为能读取资料就自动获得。策略可限制到当前用户：

```json
{
  "Version": "1",
  "Statement": {
    "Effect": "Allow",
    "Action": "quyan:user:UpdateProfile",
    "Resource": "acs:quyan:*:<accountId>:user/<userId>"
  }
}
```

请替换为实际账号和当前用户 ID。修改显示名称不允许修改邮箱、密码、账户状态或所属用户组，即使使用通配符授权也不能通过个人资料接口修改其他用户。

资料在请求过程中变化时，读取或修改可能返回冲突；刷新后再确认修改，系统不会自动覆盖并发变更。账户或角色会话失效后操作会被拒绝。第三方 OAuth 应用还需要 `profile` scope（兼容对应历史权限 scope）；这个 scope 不能代替修改资料的 IAM 权限。

## 邮箱权限与资源范围

启用 IAM 强制授权后，发送邮箱变更验证码需要 `quyan:user:SendEmailChangeCode`，提交验证码完成修改需要 `quyan:user:ChangeEmail`。两个操作均使用当前用户的 `acs:quyan:*:<accountId>:user/<userId>` 资源，权限相互独立：可以发送验证码不代表可以修改邮箱。修改姓名或读取资料也不会自动获得邮箱操作权限。

策略可以对当前用户 ARN 授予这两个 Action。匹配的显式 Deny 优先于 Allow，即使授予通配符权限，也不能通过个人接口修改其他用户的邮箱。已有验证码、双因素、人机验证、重放保护、邮箱唯一性和最近 24 小时内最多更换一次的限制仍然生效。第三方 OAuth 应用还必须具备 `email` scope，仅有 `profile` scope 不足以操作邮箱。

发送验证码或提交邮箱写入前会再次复核授权和用户状态。操作期间账户、授权、角色会话或 OAuth 凭证状态发生变化时，请求可能被拒绝或返回冲突；请刷新会话后重新确认。`legacy` 与 `shadow` 保留原有效邮箱权限，`shadow` 同时记录 IAM 决策。

## 常见问题

| 现象                                   | 处理方式                                                                                            |
| -------------------------------------- | --------------------------------------------------------------------------------------------------- |
| 名称或邮箱按钮不可用，或操作提示无权限 | 联系管理员检查对应操作的授权。读取资料、修改名称、发送邮箱验证码和修改邮箱是独立能力。              |
| 邮箱验证码发送成功，但修改被拒绝       | 检查是否具备修改邮箱权限，以及邮箱占用、24 小时限制和会话状态。能够发送验证码不代表一定能完成修改。 |
| 收到验证码后又更换了新邮箱输入值       | 验证码必须用于它所发送到的邮箱。确认目标地址后重新发送，不要使用另一个邮箱收到的代码。              |
| 提交提示冲突或结果不明确               | 刷新页面核对当前资料，确认是否已生效；需要继续修改时重新提交。验证码已被使用或过期时，需重新获取。  |
| 缓存只清理了一部分                     | 已清理的项目不会自动恢复。重新打开清理窗口核对剩余项目；若已清理登录数据，可能需要先重新登录。      |
