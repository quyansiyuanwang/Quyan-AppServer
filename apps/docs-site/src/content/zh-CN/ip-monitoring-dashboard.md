# IP 监控面板

使用 IP 监控面板查询某个 IP 的错误权重与封禁状态，处理误封，并维护黑名单和白名单。

## 使用前提

从控制台进入 **系统 → IP 监控**。页面入口需要 `ip_blacklist:read`；页面中的其他操作分别需要以下权限。

| 操作                           | 所需权限              |
| ------------------------------ | --------------------- |
| 查看监控、黑名单和指定 IP 状态 | `ip_blacklist:read`   |
| 调整或重置权重、编辑黑名单     | `ip_blacklist:update` |
| 手动封禁                       | `ip_blacklist:create` |
| 解封                           | `ip_blacklist:delete` |
| 查看白名单                     | `ip_whitelist:read`   |
| 添加白名单                     | `ip_whitelist:create` |
| 移除白名单                     | `ip_whitelist:delete` |

IAM 强制模式还会分别检查实际平台全局组资格、操作 Action 和目标资源，详见本文后半部分。能打开页面不代表能读取每个标签页或操作任意 IP。操作者启用 2FA 时，写入可能触发二次验证；受信任窗口及重放保护按当前安全规则执行。

## 查询指定 IP

1. 在监控标签页输入 IP 地址，单击 **查询** 或按 Enter。页面可能预填服务端识别的当前客户端 IP，但不会自动查询。
2. 查看 **封禁状态**、**错误权重**、**当前等级**及三个等级的阈值。
3. 查看错误类型明细，结合业务日志判断原因；需要确认到期时间时，到黑名单标签页查看相应记录。
4. 完成权重或黑白名单操作后，重新查询该 IP，确认最新状态。

**当前等级按查询时的错误权重计算，封禁状态按已有黑名单记录判断，两者可能不同。** 权重已经衰减到正常范围时，已有封禁仍可能有效；手动封禁的记录也可以没有自动封禁等级。有效白名单不会删除黑名单记录，因此查询仍可能显示“已封禁”，而请求已获得白名单豁免。

错误明细中的数值是各错误类别的累计权重贡献，占比按这些贡献计算，不是请求次数或恶意概率。明细不会随总权重同步衰减，手动设置权重也不会重写明细，因此明细之和可能不等于当前权重。

### 理解衰减和趋势估计

错误权重达到对应阈值时，自动封禁检查可以创建或升级封禁。实际判断还会考虑当前小时错误计数，取它与衰减后累计权重的较大值。是否启用自动封禁、各级阈值及封禁时长，以 **服务端配置 → IP 封禁** 中的当前设置为准；三级不固定等于永久封禁。

启用错误衰减后，累计权重按配置的间隔和比例降低，低于最小阈值时清零。查询会计算已到期的衰减；页面不是实时倒计时。

- **衰减估计**：假设没有新错误，估算权重降至阈值或归零所需的时间。它不代表确定的解封时间；衰减不会降低已有封禁记录的等级，也不会提前解除封禁。
- **趋势估计**：根据同一 IP 最近两次成功手动查询的权重变化推算下一等级。两次查询至少相隔约 3 秒，且权重上升时才显示；它不是持续流量监控，也不保证之后仍按相同速度增长。

调整服务端阈值或关闭自动封禁不会删除已有封禁。请重新查询权重，并单独确认黑名单记录和到期时间。

## 选择权重调整或解封操作

| 操作           | 实际结果                                                       | 是否移除已有封禁 |
| -------------- | -------------------------------------------------------------- | ---------------- |
| 设置正整数权重 | 替换累计权重，重新开始计算衰减时间；保留错误明细及当前小时计数 | 否               |
| 设置权重为 `0` | 清除累计权重和衰减起算时间；保留错误明细及当前小时计数         | 否               |
| 重置权重       | 清除累计权重、衰减起算时间、错误明细及当前小时计数             | 否               |
| 黑名单中解封   | 移除该黑名单记录；保留错误权重                                 | 是               |
| 添加有效白名单 | 豁免 IP 黑名单拦截；保留封禁记录和权重                         | 否               |

处理误封时，先核对来源和错误明细，再按需 **重置权重**，随后到黑名单中 **解封**。只解封而保留高权重，之后仍可能再次触发自动封禁；出现新错误也会重新累积权重。

在查询成功后单击 **调整权重**，输入非负整数并确认，或单击 **重置权重**。界面输入上限为当前三级阈值的两倍；接口另有限制，接受 `0`～`1000000` 的整数，超过接口范围仍会被拒绝。

设置和重置使用 `PUT /v1/ip-blacklist/error-status/{ip}` 与 `DELETE /v1/ip-blacklist/error-status/{ip}`；查询使用 `GET /v1/ip-blacklist/error-status/{ip}`。修改后页面会再次查询。若先收到修改成功提示、随后查询失败，不能据此认定修改已回滚，应重新查询确认。

## 维护黑名单

1. 切换到黑名单标签页，查看 IP、封禁类型、等级、原因和到期时间。列表也保留过期但未移除的记录；有记录不等于仍在拦截。
2. 手动封禁时，单击 **封禁 IP**，填写地址和原因，选择 1 小时、24 小时、7 天或永久，确认提交。默认 1 小时，原因最多 500 个字符。当前新增对话框仅接受 IPv4 形式的地址，不支持输入 IPv6。
3. 修改已有记录时，单击 **编辑**，调整原因或到期时间。不能在此更改 IP、封禁类型、等级或原操作者；清空到期时间不会把记录改为永久。
4. 解除封禁时，单击对应行的 **解封**，核对 IP 并确认。该操作只移除黑名单记录，不会清除错误权重。

“永久”采用系统的长期到期时间表示，当前创建为 `2099-12-31`，并非没有到期字段。已有未删除记录时，再次新增同一 IP 会冲突，即使旧记录已到期；可编辑原记录，或在确认后移除再新增。

### 搜索与分页限制

黑名单搜索只对**当前已加载的记录**按 IP 子串筛选，不是全库搜索；连续搜索会继续缩小当前结果，分页总数不会随本地筛选改变。找不到某个 IP，不能据此认定它未被封禁，请用监控标签页的指定 IP 查询确认。

清空搜索会重新加载当前页。刷新或切换页码会获取该页的未筛选数据，搜索框中保留的文字不会自动应用。默认每页 20 条，可选 10、20、50、100 条；修改每页条数会回到第一页。

## 维护白名单

**有效白名单会跳过 IP 黑名单拦截，包括手动封禁记录。** 它不会授予登录身份、API 权限或其他业务访问权，也不表示绕过所有限流与安全规则。请只添加已核实且需要豁免的可信来源 IP。

1. 切换到白名单标签页，单击添加按钮，填写 IP 和用途说明。
2. 按需设置到期时间；留空表示不设到期时间。当前新增对话框仅接受 IPv4 形式，白名单 API 支持有效 IPv4 和 IPv6 地址；不要把 API 支持误认为界面也支持。
3. 提交后检查列表中的地址和到期时间。列表可以包含已过期记录，已过期记录不再豁免。
4. 无需豁免时，单击移除并确认。已有黑名单若仍有效，移除白名单后可能重新拦截该 IP；操作前先核对黑名单。

页面没有白名单编辑操作。需要变更原因或有效期时，核对影响后移除再添加；两步之间会暂时失去豁免。IAM 强制模式下，未删除的已有记录（包括过期记录）再次添加会返回 409；恢复已删除地址时沿用原记录 ID。

白名单默认每页 20 条，可选 10、20、50、100 条；修改条数回到第一页。

## 刷新与统计范围

监控总览每 30 秒刷新，也可手动刷新。**总览刷新不更新单个 IP 查询、黑名单或白名单**：查询需再次单击查询，两个列表需分别刷新。加载总览或列表失败时可能保留上次数据，请结合错误提示判断，不能把旧数据当作当前状态；单 IP 查询失败则清除本次查询结果。

总览展示有效封禁总数、三级封禁数量及高频封禁 IP。手动封禁可以没有自动等级，因此三级数量之和未必等于总数。Top IP 基于最近 7 天最多 1000 条封禁活动事件，最多显示 10 个地址，不是完整的历史排名。

监控 API 还返回最近封禁、24 小时和 7 天活动总数及时间线；这些字段不一定全部在当前页面展示。最近封禁最多 20 条，时间线同样受 1000 条事件采样限制；活动总数可以高于采样数量。IAM 强制模式下，所有结果只反映当前获准查看的 IP，详见下文。

## 白名单读取权限

启用 IAM 强制授权时，白名单管理读取需要实际部署全局组中的 `IP_WHITELIST_READ`。列表使用 `quyan:ip_whitelist:ListEntries`，状态查询使用 `quyan:ip_whitelist:GetStatus`；两者的资源格式均为 `acs:platform:*:platform:ip-whitelist/<记录 ID>`。IPv4 / IPv6 地址用于查找已有记录，资源 ID 始终来自数据库，不从地址或客户端提供的账号拼接。

列表先按记录检查权限，再分页；`total` 只统计已授权记录。状态查询读取记录的当前有效期，已存在但过期的记录返回 `false`。不存在、被删除或未获授权的记录无法安全解析授权资源，在强制模式下返回 403。权限、角色会话或记录在读取期间失效时，结果不会返回。服务端自动防滥用检查仍使用其内部白名单读取流程。

## 白名单写入权限

IAM 强制模式下，新增记录需要真实全局组中的 `IP_WHITELIST_CREATE` 资格，以及 `quyan:ip_whitelist:CreateEntry` 对 `acs:platform:*:platform:ip-whitelist-control/default` 的授权。事务提交前还会检查实际记录 `acs:platform:*:platform:ip-whitelist/<record-id>`。移除记录需要真实全局组中的 `IP_WHITELIST_DELETE` 资格，以及 `quyan:ip_whitelist:DeleteEntry` 对该记录 ARN 的授权。账户所有者和账户内自建组不能授予平台资格。写入仍受二次验证和重放保护规则约束。

白名单 API 输入必须为有效 IPv4 或 IPv6 地址。已存在且未删除的记录（包括过期记录）返回 409；重新加入已删除地址会恢复原记录 ID，保留资源级 Deny 的约束。强制模式下，目标不存在或没有移除权限时返回 403。事务内会再次校验身份、用户组、记录和策略，校验失败时整批回滚。自动封禁使用的白名单查询会用数据库确认缓存中的允许结果，过期或删除的记录不会因旧缓存继续豁免。

## 指定 IP 的 IAM 查询权限

IAM `enforce` 模式下，封禁查询使用 `quyan:system:ip_blacklist:CheckIPAddress`，实时错误状态使用独立的 `quyan:system:ip_blacklist:GetIPAddressErrorStatus`。两者都针对 `acs:platform:*:platform:ip-address/<地址标识>` 授权，并要求当前用户在有效全局组中具备 `IP_BLACKLIST_READ`。私有组、用户附加权限或账户策略不能替代这项平台资格。

IPv4 地址直接作为标识，例如 `acs:platform:*:platform:ip-address/192.0.2.1`。IPv6 使用小写压缩写法并将冒号替换为下划线，例如 `2001:db8::1` 对应 `acs:platform:*:platform:ip-address/2001_db8__1`。IPv4 映射的 IPv6 地址归一为 IPv4；IPv6 回环地址与现有 IP 规范一致，归一为 `127.0.0.1`。查询仍使用你提供的原始地址查找现有记录和权重。

匹配的显式 Deny 优先，没有匹配 Allow 时拒绝查询。两项权限互不替代，也不授予列表、面板或修改权重的权限。未封禁或已过期的 IP 不返回封禁详情；实时状态仍按既有配置计算错误衰减。读取期间策略、资格、角色会话或封禁记录变化时拒绝返回结果。`legacy` 和 `shadow` 保留原查询权限，`shadow` 同时记录 IAM 决策。

## 黑名单列表的资源权限

IAM `enforce` 模式下，列表使用独立的 `quyan:system:ip_blacklist:ListBlacklists` Action，逐条检查记录对应的 `acs:platform:*:platform:ip-address/<地址标识>`。仍需有效全局组中的 `IP_BLACKLIST_READ` 资格；封禁查询或实时错误状态的权限不能代替列表权限。

列表的总数、`offset` 和 `limit` 都以允许访问的记录为准，显式 Deny 优先。没有匹配 Allow 时返回空列表。允许查看的过期封禁记录仍保留，只有当前页的详情会被读取。单次查询固定截止位置；读取期间授权或参与总数计算的记录变化时，请求会被拒绝，需要重新查询。`legacy` 和 `shadow` 保留原列表行为，`shadow` 同时记录 IAM 决策。

## 按记录 ID 获取黑名单详情

`GET /v1/ip-blacklist/{id}` 可返回记录详情，包括过期但仍有效保留的历史记录。IAM `enforce` 模式使用独立的 `quyan:system:ip_blacklist:GetBlacklist` Action，由服务端从记录 ID 解析实际 IP，并按该 IP 的资源 ARN 授权。它同样要求有效全局组中的 `IP_BLACKLIST_READ`；列表和封禁查询权限不能代替详情权限。

缺失、删除或无法安全解析的记录在 `enforce` 模式下被拒绝，不会退化为全资源授权。返回前会复核记录的地址、版本与当前授权。`legacy` 和 `shadow` 按原有效权限提供详情，找不到记录时返回 404；`shadow` 额外记录 IAM 决策。

## 指定 IP 的权重修改权限

IAM `enforce` 模式下，设置权重使用独立的 `quyan:system:ip_blacklist:SetIPAddressErrorWeight`，重置使用 `quyan:system:ip_blacklist:ResetIPAddressErrorWeight`。两者都检查目标 IP 的资源 ARN，并要求当前用户在有效的全局用户组中具备 `IP_BLACKLIST_UPDATE`。只读授权、私有组和用户附加权限不能替代这项平台资格；设置与重置权限也不能互相替代。

设置为正整数会替换权重并更新衰减起算时间；设置为 `0` 仅清除权重和衰减时间，保留错误明细及当前小时计数。重置会同时清除这四项数据。两种操作都保留二次验证和请求重放保护，不会自动解除已有封禁。

服务端在修改前复核当前主体、用户组资格、角色会话和策略；复核不通过时不执行修改。修改结果必须由 Redis 确认。若返回“修改结果未确认”，请先查询当前状态，再决定是否重试：该响应不能证明数据已修改，也不能证明数据未修改。服务端不会自动重试修改。`legacy` 和 `shadow` 保留原有权限及修改行为，`shadow` 另外记录 IAM 诊断。

## 指定 IP 的封禁记录更新权限

IAM `enforce` 模式下，修改封禁原因或到期时间使用独立的 `quyan:system:ip_blacklist:UpdateBlacklist` Action，并检查目标 IP 的资源 ARN。当前用户仍须在有效的全局用户组中具备 `IP_BLACKLIST_UPDATE`。权重设置、重置或只读权限不能替代封禁记录更新权限。

允许更新仍有效的记录及保留的过期历史，不改变封禁等级、封禁类型或原封禁操作者。不存在和已删除的记录在 `enforce` 模式下返回权限拒绝，即使有通配符 Allow 也不会恢复记录；`legacy` 和 `shadow` 保留原有更新行为，对不存在记录返回 404。服务端在事务中复核记录版本、主体、平台资格及策略，并保留二次验证和重放保护。记录或授权在修改前变化时拒绝更新，可在确认当前状态后重新提交。

## 手动封禁与解封的资源权限

IAM `enforce` 模式下，手动封禁使用 `quyan:system:ip_blacklist:CreateBlacklist`，解封使用 `quyan:system:ip_blacklist:DeleteBlacklist`。两项 Action 分别检查目标 IP 的 ARN，并要求当前用户在有效的全局用户组中具备对应的 `IP_BLACKLIST_CREATE` 或 `IP_BLACKLIST_DELETE`。创建、更新、解封和权重操作的权限相互独立。

手动封禁以当前认证用户记录操作者；永久封禁沿用系统的长期到期时间。再次封禁已软删除的 IP 会复用原记录 ID；已有未删除记录（包括过期记录）时返回冲突，不会覆盖原因或等级。解封只移除未删除的封禁记录（包括过期记录），不清除错误权重；权重如需清除，应另行执行重置。`enforce` 下缺失或已删除的解封目标返回权限拒绝；`legacy` 和 `shadow` 保留原有行为，不存在有效记录时返回 404。

两项操作保留二次验证、重放保护和业务日志；修改前发生撤权或记录变化时拒绝执行。系统根据错误阈值进行的后台自动封禁继续使用服务端配置，不通过这些手动操作权限执行。

## 监控面板的 IP 资源范围

IAM `enforce` 模式下，面板使用独立的 `quyan:system:ip_blacklist:GetMonitoringDashboard` Action，逐一检查封禁记录和封禁活动事件所对应的 IP 资源 ARN。仍须在有效的全局用户组中具备 `IP_BLACKLIST_READ`；列表、详情和状态查询授权不能替代面板授权。

面板先排除没有 Allow 或命中 Deny 的 IP，再计算有效封禁总数、等级和类型分布、24 小时与 7 天活动总数。最近封禁最多展示 20 条；时间线和 Top IP 基于最近 7 天内最多 1000 条已授权事件，Top IP 最多展示 10 个。活动总数统计全部已授权事件，因此事件很多时可以高于时间线采样数量。Top IP 的当前状态也仅根据已授权的有效封禁判断。

有效封禁摘要沿用现有到期时间规则：过期记录和到期时间为空的记录不计入该摘要；系统手动永久封禁使用的长期到期时间仍可计入。查询固定时间截止点，若影响结果的记录、事件或授权在读取中变化，则拒绝返回这次结果。无法安全确认事件对应的 IP 时也会拒绝请求，不会扩大到全部资源。`legacy` 和 `shadow` 保留原有聚合行为，`shadow` 另外记录 IAM 诊断。
