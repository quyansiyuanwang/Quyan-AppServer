# 认证中心应用管理

在此管理自己的认证中心应用：创建配置、提交审核、查看意见、轮换密钥和删除应用。令牌获取与 JWT 验证流程见[认证中心应用接入](/zh-CN/auth-center-app-management)。

## 使用前提

- 页面需要 `auth_center:client:read`；创建、编辑和删除分别需要 `auth_center:client:create`、`auth_center:client:update`、`auth_center:client:delete`。提交审核及密钥轮换属于更新操作。
- 创建、编辑、提交审核、轮换及所有者删除均要求相应的双因素验证和请求重放保护。按控制台提示完成验证；有页面入口不代表操作已获准。
- Scope 由当前账户可授予的动态目录提供。目录未加载完成或出错时不能提交，先在弹窗重试；使用角色会话时按角色权限校验。
- 本页只维护当前用户自己的应用。通过或拒绝申请在独立的[认证中心应用审核](/zh-CN/auth-center-client-review-management)页面完成。

## 创建并提交应用

1. 单击创建，填写应用名称、用途和客户端类型。能在可信服务端保存密钥的选机密应用；SPA、移动端、桌面端等无法保密的选公开应用。
2. 根据实际用途勾选授权类型。新建机密应用默认勾选三种授权类型，请取消不需要的项目。
3. 用户授权流程至少登记一个完整回调地址，设置 PKCE 和令牌有效期，选择最小 Scope。
4. 按需填写主页、Logo、隐私政策及服务条款 URL，保存配置。
5. 机密应用创建成功后立即保存弹窗中的完整 Client Secret；公开应用不签发密钥。不要等到审核通过才寻找密钥。
6. 核对列表中的配置，对草稿应用提交审核。状态变为 `pending`，通过后才可授权和兑换令牌。

### 授权类型和 PKCE

| 配置                 | 要求和结果                                                                  |
| -------------------- | --------------------------------------------------------------------------- |
| `authorization_code` | 用户授权流程，至少一个回调地址，签发用户 JWT                                |
| `refresh_token`      | 必须同时启用 `authorization_code`；授权码兑换时签发刷新令牌，刷新成功后轮换 |
| `client_credentials` | 仅机密应用可用，签发代表应用的 JWT，不签发刷新令牌                          |
| 公开应用 + 授权码    | PKCE 自动启用且不能关闭；切换为公开应用时自动移除机器授权类型               |
| 机密应用 + 授权码    | 可设置 PKCE；建议保持开启并使用 S256，密钥不能替代已要求的 verifier         |

表单至少选择一种授权类型和一个 Scope。授权码回调需与请求值精确匹配，包括协议、域名、端口、路径和末尾斜杠。纯机器应用可不填回调地址。

### 字段与有效期

| 字段                               | 限制及默认值                                                  |
| ---------------------------------- | ------------------------------------------------------------- |
| 应用名称、描述                     | 名称必填，1–100 个字符；描述可选，最多 2,000 个字符           |
| 回调地址                           | 最多 20 个完整 URL，每个最多 500 个字符；启用授权码时至少一个 |
| 访问令牌有效期                     | 单位秒，60–86,400；新建默认 3,600                             |
| 刷新令牌有效期                     | 单位秒，300–31,536,000；新建默认 2,592,000（30 天）           |
| 主页、Logo、隐私政策、服务条款 URL | 可选，每项最多 500 个字符，清空并保存会移除原值               |

刷新令牌有效期不能小于访问令牌有效期，即使只启用机器授权也必须满足填写值的关系；这不代表机器授权会签发刷新令牌。新签发令牌采用当时的应用配置，调整有效期不会改写已经签发 JWT 的过期声明。

## 查看和修改配置

桌面列表显示审核状态和意见、Client ID、客户端类型、授权类型、回调摘要、密钥预览、PKCE、最近使用时间等；移动卡片显示回调及 Scope 数量、两种有效期等资料。完整回调和有效期可在编辑弹窗核对，本页没有关键字搜索或分页。

| 状态       | 含义                         | 下一步                               |
| ---------- | ---------------------------- | ------------------------------------ |
| `draft`    | 新建或修改后待提交           | 核对资料并提交审核                   |
| `pending`  | 等待审核                     | 等待处理；如继续修改，请通知审核人员 |
| `approved` | 已通过，满足其他条件时可接入 | 变更前安排重新审核时间               |
| `rejected` | 未通过                       | 按意见修改后重新提交                 |

**保存已通过或已拒绝的应用会回到 `draft`，即使字段未改变也一样。** 原审核意见、提交时间和审核信息会清除；重新通过前授权码、刷新和机器授权都不可用。待审核应用保存后仍保持 `pending`，审核人员需核对最新资料。

### 切换客户端类型

与普通 OAuth 管理页不同，本页允许编辑客户端类型。切换为公开应用会清除原有密钥，并重新检查授权类型和 PKCE；原机密应用的接入配置不能直接继续使用。

公开应用改为机密应用时，保存不会自动生成 Client Secret。若列表没有轮换入口，可由有权的接入方通过 `POST /v1/auth-center/clients/{id}/regenerate-secret` 创建新密钥，或重新创建机密应用。路径中的 `{id}` 是应用记录 ID，不是公开 Client ID；API 调用仍需权限、双因素验证和重放保护。不要把保存成功当作密钥已准备好。

## 轮换密钥

1. 确认受影响的接入方，单击轮换密钥并完成确认及验证。按钮仅在应用已有密钥时显示。
2. 保存弹窗中的新密钥，立即更新所有服务端配置。旧密钥当即失效，没有并行有效期。
3. 验证后续令牌兑换、刷新或机器授权。密钥丢失后应重新轮换，列表和详情无法找回完整明文。

轮换不改变审核状态，不撤销已签发的访问或刷新令牌。完整密钥只在创建或轮换当次提供；后续桌面列表只有预览。不要将密钥放入浏览器代码、用户设备或版本库。

## 删除和停用接入

删除前协调业务停用及令牌撤销，确认应用名称和 Client ID 后执行删除并完成验证。应用会从管理和审核列表移除，不能再授权、兑换或刷新令牌。本页没有恢复入口，重新创建会获得新的 Client ID。

**删除不会让接入系统的本地 JWT 验证立即失效。** 已签发 JWT 的签名和有效期不因列表删除而改变。停止现有访问还需接入方的会话、授权及撤销策略配合；服务端令牌撤销也不能由纯本地验签实时感知。

## IAM 操作与资源

启用 IAM 强制授权后，列表按自有应用的 `quyan:auth_center:ListClients` 授权过滤，单项读取需要 `quyan:auth_center:GetClient`。应用资源为 `acs:auth-center:*:<accountId>:client/<userId>/<recordId>`；末尾是记录 ID，不是公开 Client ID。账户和用户由当前身份确定，策略不能让本页读取他人的应用。

创建使用 `quyan:auth_center:CreateClient`，目标是当前用户父资源 `acs:quyan:*:<accountId>:user/<userId>`。编辑、提交、轮换及删除分别检查 `quyan:auth_center:UpdateClient`、`quyan:auth_center:SubmitClientReview`、`quyan:auth_center:RotateClientSecret` 和 `quyan:auth_center:DeleteClient` 对应用资源的授权；创建权限不自动授予后续读取或维护。

Scope 变更还会校验当前身份能否授予相应范围。OAuth 访问令牌调用管理接口时需要 `auth_center_client` 或其受支持的等价 Scope，仍不能替代 IAM 授权。显式拒绝、角色限制及操作期间的身份或应用变化可能使请求被拒绝，请刷新后重新核对。

## 常见问题

| 现象                         | 处理方法                                                                |
| ---------------------------- | ----------------------------------------------------------------------- |
| 表单不能提交                 | 检查 Scope 目录、至少一项 Scope 和授权类型、回调及有效期关系            |
| 已通过的应用突然不能换令牌   | 检查是否保存资料后回到草稿，重新提交审核                                |
| 机密应用没有密钥或轮换按钮   | 检查是否从公开应用切换；保存不会签发密钥，按上述 API 流程或重新创建处理 |
| 修改有效期后旧 JWT 仍可使用  | 已签发令牌保留原过期声明，接入方需按自己的策略处理                      |
| 刷新或修改后出现旧列表内容   | 加载失败可能保留上次结果，排除错误并刷新后再判断                        |
| 有页面入口但不能维护某个应用 | 分别检查操作、资源、Scope、角色及双因素验证条件                         |
