# 推送聚合

推送聚合将一条业务消息发送到所选渠道，并逐渠道返回投递结果。你可以配置通用 Webhook、钉钉、飞书或企业微信类型，使用[密钥托管]({{DOCS_BASE_URL}}/zh-CN/developer-product-secret)保存可选的渠道 Bearer 凭据。

## 使用前提与权限

先创建启用的推送产品实例，并准备可接受请求的目标地址。实例和产品 API Key 的创建方法见[开发者产品总览]({{DOCS_BASE_URL}}/zh-CN/developer-products-overview)。

| 任务                   | 产品权限                      |
| ---------------------- | ----------------------------- |
| 查看和管理渠道配置     | `product:push:channel:manage` |
| 发送及显示控制台测试卡 | `product:push:send`           |
| 查看投递日志           | `product:push:delivery:read`  |
| 管理实例和 Key         | `product:push:manage`         |

这些权限相互独立。发送时，产品 Key 的动作授权及其绑定身份的有效权限都需要允许发送。只有发送权限时，可在测试卡手动输入已知渠道 ID，不一定能查看渠道目录。绑定托管密钥还涉及密钥读取、写入或使用资格，见下文。

## 配置渠道

1. 打开推送产品实例详情，点击添加渠道。
2. 填写 1～100 个字符的名称，选择类型，填写最长 2000 个字符的 HTTP(S) 目标地址。同一实例内名称不能重复；内网、无法解析或含用户名密码的地址会被拒绝。
3. 如需 Bearer 认证，选择同一存储所有者的可用密钥托管实例和别名；不需要时同时留空这两项。
4. 保存后核对渠道类型、目标地址和引用，再发送测试消息。

渠道类型只在新建时选择，编辑可修改名称、地址和引用。启用、停用按钮立即提交，不额外确认。删除需要确认，会同时删除该渠道的投递记录，无法从控制台恢复。

### 请求格式与目标兼容性

| 类型         | 平台发出的 JSON                                                                              |
| ------------ | -------------------------------------------------------------------------------------------- |
| 通用 Webhook | `{"title":"标题","content":"正文"}`                                                          |
| 钉钉         | `msgtype: "text"`，`text.content` 为标题、换行、正文                                         |
| 飞书         | `msg_type: "text"`，`content.text` 为标题、换行、正文                                        |
| 企业微信     | 当前与通用 Webhook 相同，发送 `title` 和 `content`；没有自动转换成企业微信原生机器人文本格式 |

请确认目标端接受所选格式；需要适配企业微信原生机器人或供应商加签规则时，由兼容的接收端处理。托管密钥作为 `Authorization: Bearer ...` 请求头发送，不是机器人专用签名算法。

平台只发送 POST，每次 HTTP 请求超时为 10 秒，不跟随重定向，响应体限制为 1 MiB。HTTP 成功即视为投递成功，不进一步判断响应体中的供应商业务错误，也不证明消息已展示或被阅读。

### 引用或写入托管密钥

选择托管实例和别名后，后续投递会读取该别名的当前值。只向可信目标绑定凭据。拥有渠道配置和密钥使用能力的用户可以使平台携带凭据请求目标，即使不能回读明文，也应按这个能力授权。

渠道编辑器内写入密钥会立即保存到托管实例，并自动选中别名；已有别名会被覆盖，影响其他引用方。取消渠道编辑不会撤销这次写入。还需单独保存渠道才能应用引用。切换托管实例会清空当前别名选择，请重新核对。

产品控制台保存或启停已有密钥引用的渠道时会检查托管实例的读取和使用资格；写入密钥另需写入权限。列出可选实例、列出别名与保存渠道是不同操作，选择框加载失败时应先核对对应权限，不要随意删除原引用。

## 在控制台测试

1. 在实例详情的“推送在线测试”中输入具有发送权限的产品 API Key。
2. 选择渠道或输入渠道 ID，填写标题和正文，点击发送。
3. 核对本次返回记录中的 `channelId`、`status` 和 `success`；成功提示不代表每个渠道成功。

测试按输入 Key 的实例和账号发送，而渠道选项来自当前打开的实例。两者不一致时可能没有可用渠道，请使用匹配的 Key。更改输入不会清除旧结果，页面校验失败也会保留；有效提交后清空旧结果。

测试会发送真实消息并计量。每次点击都生成新的幂等键，重复点击会创建新投递。成功返回后会尝试重新加载当前实例的投递日志，但日志加载失败仍可能保留旧记录；测试结果也不会随后台重试自动更新。超时后先检查接收端和日志，避免直接重复发送。

## 接入发送 API

在可信服务端使用产品 Key 请求当前部署的 API 服务。登录令牌、AccessKey 或中转令牌不能替代产品 Key。

```http
POST /v1/products/push/send
Authorization: Bearer <PRODUCT_API_KEY>
Content-Type: application/json

{
  "channelIds": ["channel_id_1", "channel_id_2"],
  "title": "部署完成",
  "content": "应用已更新",
  "idempotencyKey": "deploy-event-001"
}
```

| 字段             | 要求                                                                           |
| ---------------- | ------------------------------------------------------------------------------ |
| `channelIds`     | 1～20 个渠道 ID；使用该 Key 所属实例的渠道                                     |
| `title`          | 去除首尾空白后为 1～200 个字符                                                 |
| `content`        | 去除首尾空白后为 1～10000 个字符                                               |
| `idempotencyKey` | 可选，去除首尾空白后为 1～100 个字符；同一业务事件稳定复用，不同事件使用不同值 |

检查 HTTP 状态和业务码，再逐项检查响应 `data` 数组。只会为所选渠道中有效且启用的渠道创建记录，其余 ID 可能被跳过；没有可用渠道时请求失败。返回顺序不保证与输入一致，请按 `channelId` 对应结果。

| 状态或字段                  | 如何判断                                                                   |
| --------------------------- | -------------------------------------------------------------------------- |
| `pending`                   | 已建记录，尚无完成结果；不等于已送达                                       |
| `success` / `success: true` | 渠道 HTTP 请求成功，不保证供应商业务接受或消息展示                         |
| `failed` / `success: false` | 本次投递失败；`failureReason` 为 `dispatch_failed`                         |
| `attemptCount`              | 已记录的尝试次数，包括失败的配置检查                                       |
| `nextRetryAt`               | 计划重试时间，不是保证执行时间；达到尝试上限后即使仍有值也不会继续自动重试 |

接口正常返回时，所有渠道也可能都是失败。响应不包含标题、正文、幂等键、目标地址或上游原始错误；不要依赖旧 `error` 字段，控制台错误列为空也不代表成功。

## 幂等与后台重试

同一实例下复用 `idempotencyKey` 会返回已有投递记录，不按新请求的标题、正文或渠道重新发送。首次仍在处理中时可能返回空或不完整记录，后续调用可能看到更新后的状态。记录删除后，同一幂等键也不保证重新创建投递；不要用旧事件键发送新消息。

幂等只控制新建投递，不保证外部接收端恰好收到一次。网络中断或投递后记录状态失败可能导致后续重复投递；接收端需要时也应按业务事件去重。查询同一幂等键会再次经过产品额度检查和计量，不是免费的状态查询。

后台任务扫描失败投递，最多记录 3 次尝试，包含首次；失败后计划约 60 秒再试，实际还取决于任务扫描、队列和运行状况。重试使用渠道当前地址和密钥值，修改渠道或轮换密钥可能影响尚未完成的消息。

当前没有控制台手动重试、取消单条投递或重置尝试次数的功能。长期停留在 `pending`、达到上限或重复失败时，请联系管理员排查，再决定是否作为新业务事件发送。

停用实例、产品或撤销发送 Key 不保证取消已经排队的后台重试。要停止后续渠道发送，先停用相关渠道，再停用实例；已经开始的请求仍可能完成。停用渠道会使重试失败并消耗尝试次数，重新启用不会重置上限。删除渠道会删除其投递记录。

## 用量与日志

产品发送按完成的 API 调用计量，不按渠道数逐个计费：一次选择多个渠道仍是一次调用。所有渠道失败但接口正常返回时仍计量；同幂等键返回已有记录也计量。执行抛错才进入额度退回流程，恢复可能延迟。后台自动重试不另走产品发送计量接口。

同一账号的推送实例共享每日额度，按服务端日历日期统计。免费额度、超额开关和单价以当前产品配置为准，单价为零时仍会累计请求数。不要把 Key 请求数、渠道尝试次数或投递日志条数当作计费次数。

控制台投递日志最多显示当前实例最近 100 条，按创建时间倒序，没有分页、搜索或自动轮询。它不提供消息内容回读或完整历史导出。关闭并重新打开详情可重新加载；顶部刷新只更新实例列表。渠道或日志加载失败时可能保留旧数据，包括其他实例的数据，应使用对应错误提示中的重试并成功加载后再操作。

## 项目管理 API 与授权范围

实例控制台的渠道列表 `/v1/products/push/instances/{instanceId}/channels` 和投递列表 `/v1/products/push/instances/{instanceId}/deliveries` 分别在关联项目上检查 `ListPushChannels`、`ListPushDeliveries`，不逐条资源过滤。它们与下面的项目管理分页接口不同。

IAM 强制模式的项目管理 API 支持同账号内逐资源授权：

| 任务                                 | 动作与资源                                                                                |
| ------------------------------------ | ----------------------------------------------------------------------------------------- |
| 创建渠道                             | 项目 ARN 上的 `quyan:developer:CreatePushChannel`                                         |
| 查看、修改、删除渠道                 | 渠道 ARN 上分别授予 `ListPushChannels`、`UpdatePushChannel`、`DeletePushChannel`          |
| 列出投递记录或读取详情               | 投递 ARN 上分别授予 `ListPushDeliveries`、`GetPushDelivery`                               |
| 绑定密钥、保留引用修改目标或重新启用 | 具体密钥 ARN 上另需 `quyan:developer:UseSecret`；仅改名或停用的项目管理请求可不需要此动作 |

渠道 ARN 为 `acs:developer:*:<accountId>:push-channel/<projectId>/<channelId>`，投递 ARN 为 `acs:developer:*:<accountId>:push-delivery/<projectId>/<deliveryId>`。密钥 ARN 为 `acs:developer:*:<accountId>:secret/<vaultProjectId>/<ALIAS>`，引用必须来自同一存储所有者的有效托管实例。具体 ID 和别名应使用响应中的原值，优先复制 `resourceArn`。

渠道配置读取包含目标地址，地址中可能含你填写的查询凭据，因此应谨慎授权。投递元数据读取不包含消息正文或渠道凭据。列表不自动授予修改、发送或单条详情，创建也不自动授予新资源的后续权限；匹配的拒绝规则仍优先。

项目管理分页入口分别为 `GET /v1/developer/projects/{projectId}/push-channels/page` 和 `GET /v1/developer/projects/{projectId}/push-deliveries/page`，返回 `items`、`page`、`pageSize`、`hasNext`，没有 `total`。先分页候选再过滤，空页可能仍有下一页；强制模式下旧数组入口只返回默认第一页。单条投递详情使用 `GET /v1/developer/projects/{projectId}/push-deliveries/{id}`，读取不会触发发送。

项目管理 API 校验密钥引用时只读取元数据，不更新最后使用时间；产品控制台校验引用可能读取密钥。配置冲突或引用失效时，重新加载并核对后再提交。资源组成员移除会影响后续授权；暂停渠道仍可查看历史，删除渠道则连同历史一起删除。更多授权规则见 [RAM 管理]({{DOCS_BASE_URL}}/zh-CN/ram-management)。

## 常见问题

| 现象                         | 处理方法                                                                       |
| ---------------------------- | ------------------------------------------------------------------------------ |
| 请求成功但消息未到           | 先看逐渠道状态，再查目标端业务响应；HTTP 成功不表示消息已展示                  |
| 无可用渠道                   | 核对 Key 所属实例、渠道 ID、启用状态，不能只凭当前控制台目录判断               |
| 机器人返回业务错误但显示成功 | 核对渠道实际 JSON 格式和目标兼容性，必要时使用适配接收端                       |
| 保存或启停被拒绝             | 分别检查渠道操作、托管实例元数据及密钥使用资格，确认原引用仍有效               |
| 日志看起来没更新             | 成功重新加载后再判断；日志和在线测试结果不会自动跟随后台重试                   |
| 重复发送或用量增加           | 核对是否重复点击在线测试、复用了旧幂等键，或自动重试发生在不确定的外部投递之后 |
