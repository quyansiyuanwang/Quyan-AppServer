# 密钥托管

密钥托管用于保存第三方 API Key、Webhook 凭据等，并供平台支持的功能按别名引用。控制台和管理 API 只返回别名、版本及时间等元数据，不提供密钥明文回读。当前可在[推送聚合]({{DOCS_BASE_URL}}/zh-CN/developer-product-push)中选择托管密钥作为渠道的 Bearer 凭据。

## 使用前提

先创建启用的密钥托管实例，并确认管理员已配置密钥托管加密能力。未配置时，列表仍可能可见，但写入或使用密钥会失败。实例管理见[开发者产品总览]({{DOCS_BASE_URL}}/zh-CN/developer-products-overview)。

| 操作                         | 产品权限                                                   |
| ---------------------------- | ---------------------------------------------------------- |
| 查看别名、版本和最后使用时间 | `product:secret:read`                                      |
| 新增密钥或轮换已有值         | `product:secret:write`                                     |
| 将密钥绑定到支持的功能       | `product:secret:use`，另需该功能的配置权限和所需元数据权限 |
| 删除密钥                     | `product:secret:manage`                                    |

查看元数据不等于可使用、轮换或删除密钥。这些管理操作通过登录会话完成；产品 API Key 不提供通用的明文取密接口。

## 写入密钥

1. 打开密钥托管产品控制台，进入目标实例详情。
2. 点击“写入密钥”，填写别名和密钥值。
3. 核对实例与别名后点击“保存”。成功后检查列表中的别名和版本。

| 字段   | 要求                                                                                        |
| ------ | ------------------------------------------------------------------------------------------- |
| 别名   | 1～100 个字符，以大写英文字母开始，后续只能包含大写字母、数字和下划线，例如 `WEBHOOK_TOKEN` |
| 密钥值 | 1～20000 个字符；按原内容保存，首尾空白不会自动去除                                         |

控制台会将输入的别名转为大写。写入已有别名会直接替换密钥值并增加版本，没有额外的覆盖确认。请在保存前检查别名，避免误覆盖。保存结果不会包含密钥明文，业务需要时请在自己的凭据管理流程中保留原始来源。

列表按别名排序，没有分页或自动轮询。页面顶部刷新只更新实例列表；关闭并重新打开实例详情可重新加载密钥元数据。

## 轮换与删除

选择已有别名的“轮换”，输入新值并保存。轮换时别名不能修改，也不会读取旧值。首次写入版本为 1，覆盖或轮换后递增，并清空最后使用时间。平台不提供历史版本查看或回退；需要恢复旧凭据时，必须再次写入你自行保存的旧值。

引用的是别名，并未固定到某个版本。轮换后，后续使用该别名的渠道会读取新值，已开始的投递可能仍使用此前读到的值。请先让接收方接受新凭据，再轮换并测试依赖渠道；轮换托管值不会替你在第三方服务中创建或撤销凭据。

删除需要确认，且不可恢复。删除前先移除或修改渠道引用，否则后续使用该别名会失败。停用或删除整个托管实例也会使引用不可用。以后重新写入同一别名，仍保留的引用可能使用新写入的值；这不等于恢复旧版本。

## 在推送渠道中引用

1. 在推送聚合的渠道配置中，选择与你的推送资源属于同一存储所有者的密钥托管实例。
2. 选择别名，或在具备写入权限时通过渠道表单写入密钥。
3. 保存渠道并发送测试消息，检查各渠道的实际投递结果。

平台会在投递时读取托管值，并将其作为 `Authorization: Bearer ...` 发送给渠道目标。只应向你信任的地址绑定密钥。能够配置渠道并引用密钥的用户具有使用该凭据的能力，即使不能回读明文，也应按此能力授予权限。

选择实例和别名、写入值、保存渠道涉及不同权限。在 IAM 强制模式下，项目管理 API 保存引用需要对具体别名具有 `quyan:developer:UseSecret`；产品控制台保存引用还检查所选托管实例的读取及使用资格。详细前提见[推送聚合]({{DOCS_BASE_URL}}/zh-CN/developer-product-push)。

## 如何理解最后使用时间

最后使用时间用于辅助判断平台近期是否读取过密钥，不能证明消息成功送达。通过产品控制台创建或编辑带引用的推送渠道时，平台也会读取密钥来检查引用，因此尚未发送消息也可能出现使用时间。IAM 强制模式的项目管理 API 只检查引用元数据，不会因为该检查更新使用时间。

投递读取密钥后仍可能失败；使用时间更新也不应当作完整审计记录。轮换会清空该时间，显示“从未使用”不代表这个别名历史上从未被使用。确认送达请检查发送结果和可见的投递日志。

密钥写入、轮换和元数据列表不经过产品调用计量接口。使用密钥发送推送时，按推送产品的当前配额和费用规则处理，详见推送聚合指南。

## 项目管理 API 与授权范围

管理 API 不返回密钥值。可以分别按别名授予 `quyan:developer:ListSecrets`、`PutSecret`、`DeleteSecret` 和引用所需的 `UseSecret`；项目授权不自动覆盖所有别名。别名资源为 `acs:developer:*:<accountId>:secret/<projectId>/<ALIAS>`，优先使用项目管理响应中的 `resourceArn` 配置策略。

实例控制台的 `GET /v1/products/secret/instances/{instanceId}/secrets` 在关联项目上检查 `ListSecrets`，返回该实例的元数据列表，不逐别名过滤。

需要细粒度列表时，使用 `GET /v1/developer/projects/{projectId}/secrets/page`。它接受 `page`、`pageSize`，返回 `items`、`page`、`pageSize`、`hasNext`，没有 `total`。IAM 强制模式会逐别名过滤，空页也可能有后续页；请以 `hasNext` 继续。强制模式下旧数组接口只返回默认第一页。更多策略规则见 [RAM 管理]({{DOCS_BASE_URL}}/zh-CN/ram-management)。

## 常见问题

| 现象                     | 处理方法                                                                                 |
| ------------------------ | ---------------------------------------------------------------------------------------- |
| 提示密钥托管未配置       | 联系管理员配置独立加密主密钥；普通用户不需要填写或获取该主密钥                           |
| 提示别名无效             | 使用大写字母开头及允许字符，核对自动大写后的别名                                         |
| 写入成功但无法查看密钥值 | 属于预期行为；需要验证时，通过依赖该密钥的渠道测试                                       |
| 加载失败后仍看到列表     | 可能是上次结果，包括切换实例前的数据；点击错误中的“重试”，成功后再操作                   |
| 轮换或删除成功但列表未变 | 后续刷新可能失败；重试并核对别名、版本，避免直接重复轮换                                 |
| 渠道引用不可用或投递失败 | 检查托管实例是否启用、别名是否存在、使用权限及目标端是否接受当前凭据                     |
| 列表可读但无法解密使用   | 联系管理员检查加密配置；已有密钥依赖原加密主密钥，不能通过普通修改配置完成历史数据重加密 |
