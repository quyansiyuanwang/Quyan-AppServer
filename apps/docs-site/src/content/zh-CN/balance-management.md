# 余额管理

余额管理用于查询用户余额、手工增加或扣减余额，以及核对交易流水。手工调整会直接改变用户的站内余额，请先确认用户 ID、金额和调整原因。

## 使用前提

进入页面需要 `BALANCE_READ`。页面还会读取用户目录，因此需要相应的用户读取权限；调整需要独立的 `BALANCE_RECHARGE`。启用两步验证的账号提交调整时，可能需要完成二次验证。

IAM 强制模式下，余额和交易查询受账号归属及资源授权约束。能在用户目录看到某个人，不代表有权读取或调整其余额，详见下文。

## 查询用户余额

1. 在 **用户 ID** 中填写目标用户的完整 ID，单击 **搜索**。
2. 核对列表中的用户 ID、用户名、当前余额和更新时间。列表每页 20 人，可通过分页继续查看。
3. 保留筛选重新查询时，单击 **搜索**。**刷新** 会清空用户 ID 并返回第一页。

列表没有返回余额账户时会显示 0，并使用当前时间作为更新时间。这个时间不能证明账户刚发生变动，0 也不能单独证明已有余额账户被清空。本页不显示拼车预留金额，不能把显示余额直接当作全部可转出金额。

读取失败时旧列表可能仍保留，请先处理错误并重新查询，再进行调整。

## 增加或扣减余额

1. 在目标用户行单击 **调整余额**，再次核对用户 ID 和当前余额。
2. 填写 **金额**：正数增加，负数扣减，不能为 0；单次范围为 -100000～100000，最多 4 位小数。也可填写 **增减后余额**，页面会按当前显示余额计算差额。
3. 核对 **计入统计**。默认开启，增加计入累计充值，扣减的绝对值计入累计花销；关闭后仍会变更余额并保留交易流水，只是不增加这两项累计统计。
4. 填写调整原因，便于后续核对；最多 500 字符。留空时页面使用默认的管理员充值或扣减说明。
5. 单击 **确认** 并完成页面要求的验证。成功后对话框关闭，列表重新加载；单击 **查看历史** 核对调整流水和实际余额。

**增减后余额是估算值，提交的是差额。** 例如窗口中余额为 10，目标设为 15，提交金额为 +5；如果提交前另一次消费已把余额变成 8，调整后将为 13。需要精确核对时请刷新后重新计算，不能把该字段视为锁定目标余额。

手工扣减没有“余额不足则拒绝”的保底，可能产生负余额。提交前请核对扣减后结果；已有拼车预留或并发消费时还应核对相关订单。重复提交同一差额会再次增减余额，页面没有撤销按钮。需要更正时，先确认原流水，再按实际差额创建一笔说明清楚的新调整。

## 查看交易历史

1. 在用户行单击 **查看历史**。默认加载该用户最近 7 天的获准记录。
2. 根据需要选择最近 1 天、7 天、30 天，或 **加载全部**；加载全部需要确认。
3. 在已加载数据中按交易类型、Token、渠道、模型或时间筛选，核对金额、变动前后余额和说明。可切换表格与图表查看。
4. 查看新交易时单击历史窗口中的 **刷新**；需要重新按时间范围加载时，重新选择加载范围。

服务器仅返回最近 30 天内的有效流水，**加载全部不会取得更早的完整账本**。历史窗口中的日期和其他筛选只过滤已加载数据，不会自动补查范围外记录。图表和记录数也仅基于当前已加载、获准且经过筛选的记录，不能代替账户全生命周期统计。

历史刷新会追加自上次加载以来的新记录，不会重新计算或裁剪原时间范围。增量刷新失败可能没有单独提示；需要确认最新数据时重新选择范围。范围加载失败时应先处理错误，不要将旧记录或空列表当作最新查询结果。

## 权限与资源范围

| 任务                   | 所需权限           |
| ---------------------- | ------------------ |
| 读取页面使用的用户目录 | `USER_READ`        |
| 查看余额和交易记录     | `BALANCE_READ`     |
| 增加或扣减余额         | `BALANCE_RECHARGE` |

IAM 强制模式下，用户目录使用 `quyan:user:ListUsers` 和部署共享的 `acs:platform:*:platform:user/<userId>` 资源，并需要部署管理全局组的用户读取资格。余额和流水则按当前账号归属授权，仅可处理同一账号内的有效用户；为其他账号写一条 Allow 不会改变其归属。

下表中的 `accountId` 是当前账号 ID。

| Action                               | 资源 ARN                                                         |
| ------------------------------------ | ---------------------------------------------------------------- |
| `quyan:balance:GetUserBalance`       | `acs:quyan:*:<accountId>:user/<userId>`                          |
| `quyan:balance:RechargeUserBalance`  | `acs:quyan:*:<accountId>:user/<userId>`                          |
| `quyan:balance:ListUserTransactions` | `acs:balance:*:<accountId>:transaction/<userId>/<transactionId>` |

读取和调整分别授权。页面按当前用户列表批量读取余额，任一目标不在账号范围内或未获准时，整次余额查询可能失败，而不是自动跳过。此时可按一个有权管理的用户 ID 缩小查询，并请管理员检查用户目录与余额范围是否一致。

交易列表只统计和分页获准流水；当前没有可见记录不代表该用户没有消费。角色会话失效、账号状态或权限在请求期间改变时，需要重新登录或刷新后再核对。

## 常见问题

| 现象                           | 处理建议                                                       |
| ------------------------------ | -------------------------------------------------------------- |
| 页面可见，但列表加载失败       | 分别检查用户目录权限、当前页所有用户的余额读取权限和账号归属   |
| 目标余额与提交后余额不同       | 检查差额、并发消费或其他调整，以交易流水中的变动前后余额为准   |
| 关闭计入统计后仍有流水         | 这是正常行为；该开关只控制累计充值和花销，不隐藏余额变动       |
| 调整后连接中断，不确定是否成功 | 先重新搜索用户并查看历史，确认原操作结果后再决定是否提交新调整 |
| 加载全部后仍无较早记录         | 服务端仅查询最近 30 天，局部日期筛选无法扩大该范围             |
