# 数据分析

数据分析提供数据总览、漏斗分析和热力图，用于理解已采集的站点事件。结果反映成功送达且仍保留的数据，不是完整访问日志、真实人数证明或计费依据。

## 使用前提

在管理站进入相应分析页面，需要 `ANALYTICS_READ`。IAM 强制模式还要求这一资格来自真实部署全局组，并具有所需报表的独立授权，详见下文。

数据依赖浏览器采集和成功上报。采集未初始化、页面不采集相应事件、网络失败或历史数据已清理，都可能使结果为空或不完整。刷新分析页只重新查询已保存的数据，不会补采过去事件；页面没有统一的追踪开关或数据补录入口。

## 查看数据总览

1. 打开数据总览，等待默认的最近 30 天结果。
2. 选择今天、7 天、30 天或 90 天快捷范围，会立即查询。
3. 使用自定义日期时，选择后单击刷新；仅更改日期不会更新图表。
4. 核对汇总，再比较每日趋势、热门事件和页面排行。

今天从浏览器本地零点到当前时间；其他快捷范围为从当前时间向前推相应天数，并非整段自然日。自定义结束日期通常为当天零点，不会自动扩展到全天。要包含目标日全天，可选择次日作为结束日期，并注意次日零点也可能包含。查询按服务端接收时间筛选，日报按数据库日期归类，时区或上报延迟可能造成日期差异。

| 页面指标                | 实际含义                                                                     |
| ----------------------- | ---------------------------------------------------------------------------- |
| 总 PV、页面 PV、PV 趋势 | 当前查询中的事件数量，包含页面浏览、点击及其他已采集事件，不限于 `page_view` |
| 独立会话（UV）          | 按会话 ID 去重，不是独立账号或真实人数                                       |
| 活跃页面数              | 当前查询中出现过事件的不同页面路径数                                         |
| 热门事件 Top10          | 当前时间范围内数量最多的 10 个事件名，不是完整事件目录                       |

概览页面没有事件类型、用户或页面路径筛选控件。需要只统计某页面或某事件类型时，有权限的集成可在 `POST /v1/track/stats` 请求中指定 `page` 或 `eventType`；这仍是部署级报表接口。

路径按采集时的页面路径统计，通常不包含域名、查询参数和锚点。同一部署的不同站点使用相同路径时，记录可能合并；不能用这里的页面排行证明某个域名单独的流量。

## 分析转化漏斗

1. 打开漏斗分析，填写至少两个非空事件名。
2. 按业务顺序添加、删除或上下移动步骤，选择时间范围，默认最近 7 天。
3. 单击分析，再核对右侧表格中的会话数量与转化率。
4. 修改步骤或日期后，重新单击分析；离开页面不会保存漏斗定义。

事件名去除首尾空格后精确匹配，注意大小写。空步骤会被忽略，少于两个有效步骤时不会提交查询。候选仅来自最近 90 天热门事件的前 10 项；没有候选不代表事件从未发生，可以手动输入实际事件名。候选读取需要概览报表授权；只有漏斗授权时仍可能手动输入并分析。

漏斗按同一会话的**服务端接收顺序**匹配步骤，中间可以穿插其他事件。它不会跨会话拼接，也不按客户端点击时间重新排序；批量上报或延迟可能影响顺序，同批事件也可能具有相同接收时间。

页面“用户数”实际是通过该步骤的会话数。每步转化率相对前一步计算，第一步固定显示 100%，即使第一步会话数为 0；应先检查数量，再解读比例。重复填写同一事件名要求该会话重复发生对应事件，不是对一次事件重复计数。

## 查看热力图

1. 打开热力图，选择或输入已采集的页面路径，例如 `/your-page`。
2. 选择时间范围和点击热力或滚动停留，默认最近 7 天、点击热力。
3. 单击查询，等待成功后再解读热力点。
4. 更改路径、日期或类型后，再次单击查询。

页面候选来自最近 90 天的概览数据，不保证该路径已有热力数据。候选读取需要概览报表授权；候选为空时可手动输入已知路径。路径精确匹配采集值，完整 URL 或带查询参数的地址不一定匹配。

背景是内嵌加载的当前页面，不是采集时的截图。相对路径在当前管理站域名下打开，不会自动定位数据原来的站点；跨站同名路径、登录状态、页面版本及嵌入限制都可能使背景不同或无法加载。背景失败不等于热力查询失败。

**更改路径会立即切换背景，热力点却只在查询成功后更新。** 查询失败时旧点可能仍叠加在新背景上；先确认条件和成功提示，再使用结果。页面背景用于展示，不能直接在内嵌页面中操作业务。

热力点把相近比例坐标归并，最多返回数量最高的 2000 个位置。底部点数是返回的聚合位置数，不是点击数或会话数；红色强度相对当前结果，不适合直接比较两次查询的绝对流量。

点击坐标按采集时的视口比例计算；滚动停留使用页面高度比例及视口中心位置。预览按桌面宽度缩放，原始设备尺寸、滚动位置或布局变化可能使点与元素错位。滚动停留也不等于完整阅读时长或真实关注度。

## IAM 报表授权

三个查询接口使用登录认证，不接受第三方 OAuth 访问令牌。IAM 强制模式下，需要真实部署全局组中的 `ANALYTICS_READ` 资格，加上相应动作和资源授权：

| API                      | IAM 动作                                | 资源 ARN                                         |
| ------------------------ | --------------------------------------- | ------------------------------------------------ |
| `POST /v1/track/stats`   | `quyan:analytics:GetTrackingStatistics` | `acs:platform:*:platform:system/tracking-stats`  |
| `POST /v1/track/funnel`  | `quyan:analytics:GetFunnelStatistics`   | `acs:platform:*:platform:system/tracking-funnel` |
| `POST /v1/heatmap/query` | `quyan:analytics:GetHeatmap`            | `acs:platform:*:platform:system/heatmap-stats`   |

日期、页面和事件只筛选数据，不会将报表授权缩小为某个用户或页面资源。账号内策略或个人附加权限不能替代部署组资格。匹配的 Deny 优先，角色会话使用角色自身授权；读取期间身份、资格、策略或会话失效时，整份结果会被拒绝。公开采集与受保护的报表查询是独立操作，能上报不代表能读取分析结果。

## 常见问题

| 现象                         | 处理方法                                                   |
| ---------------------------- | ---------------------------------------------------------- |
| 自定义日期变了，概览数字没变 | 单击刷新；快捷日期与自定义日期触发行为不同                 |
| PV 高于预期页面浏览量        | 页面统计包含全部匹配事件，需要纯浏览时按事件类型查询       |
| 漏斗候选或页面下拉为空       | 检查概览授权和最近 90 天数据，必要时手动输入精确名称或路径 |
| 漏斗第一步为 100% 但人数是 0 | 固定起始比例不是有转化的证据，核对事件名、日期和采集       |
| 背景正确但没有热力点         | 核对采集、路径精确值、类型、日期和查询是否成功             |
| 热力点与元素错位             | 核对站点、布局版本、设备尺寸和滚动位置                     |
| 查询失败后仍有旧图或初始 0   | 保留结果或默认值不能证明新条件下无数据，成功重试后再判断   |

页面没有自动刷新、导出、保存漏斗或历史页面截图功能。历史事件及热力数据的保留以部署的数据生命周期配置为准。
