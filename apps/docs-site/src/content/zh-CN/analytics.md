# 数据分析

数据分析包含概览、漏斗和热力图，用于查看已采集的站点事件。数据取决于追踪是否启用以及用户是否产生相应事件。

## 概览

选择时间范围并刷新，可查看页面事件总数、独立会话数（页面称为 UV）、活跃页面数、每日趋势、热门事件和页面排行。UV 按会话 ID 去重，不等同于独立账号数。页面提供今天、近 7 天、30 天、90 天快捷范围及自定义日期；概览页面没有事件类型或路径筛选控件。

## 漏斗

1. 输入至少两个事件名，并按需添加、删除或调整步骤顺序。
2. 选择时间范围，点击**分析**。
3. 查看各步骤的会话数量和转化率。系统按同一会话中事件的发生顺序匹配步骤；每一步的转化率相对于前一步，第一步显示 100%。

页面上的“用户数”实际按会话统计，不代表独立账号数。页面没有保存漏斗定义的功能，离开后需要重新填写。修改步骤或时间范围后需要再次点击**分析**；若查询失败，页面可能仍显示上一次成功的结果。

## 热力图

选择或输入页面路径、时间范围以及点击或滚动停留类型，点击**查询**。页面通过内嵌框架加载目标页面，并在其上叠加热力点；红色越明显表示相对密度越高。目标页面无法嵌入或加载时，背景可能无法显示；没有采集数据时也不会出现热力点。更改路径会立即切换背景，但热力点只有在再次查询成功后才更新；查询失败时可能仍显示上一次的热力点，请勿将其视为新条件的结果。

## 所需权限

查看三个报表需要 `ANALYTICS_READ`；IAM 强制模式下还需要下列各报表的独立授权。

## IAM 报表授权

JWT 查询 API 需要 `ANALYTICS_READ`。IAM 强制模式下，这一资格必须来自真实部署全局组。三个报表分别使用独立 Action 和资源：

| API                      | IAM Action                              | 资源 ARN                                         |
| ------------------------ | --------------------------------------- | ------------------------------------------------ |
| `POST /v1/track/stats`   | `quyan:analytics:GetTrackingStatistics` | `acs:platform:*:platform:system/tracking-stats`  |
| `POST /v1/track/funnel`  | `quyan:analytics:GetFunnelStatistics`   | `acs:platform:*:platform:system/tracking-funnel` |
| `POST /v1/heatmap/query` | `quyan:analytics:GetHeatmap`            | `acs:platform:*:platform:system/heatmap-stats`   |

这些资源代表部署级聚合报表。日期、页面和事件筛选只选择报表数据，不会把权限缩小为某一页面，也不会将报表变成账户级资源。账户策略不能授予平台资格。匹配的 Deny 优先于 Allow；读取过程中资格、策略或当前角色会话失效时，结果不会返回。AssumeRole 使用角色自身的授权。匿名采集接口保留现有采集行为。

## 注意事项

- 分析结果依赖实际采集到的事件，未启用追踪或没有匹配数据时可能为空。查询失败后请重试，并以成功返回的结果为准。
- 页面路径、时间范围和事件名用于筛选数据，不改变报表的授权范围。
