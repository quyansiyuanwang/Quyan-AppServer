# 验证码

验证码产品为你的应用发送邮件或短信验证码，并提供一次性校验接口。校验成功只表示验证码有效且已被使用；注册、登录、修改资料等业务操作仍由你的应用完成。平台账号的二次验证请参见[安全验证]({{DOCS_BASE_URL}}/zh-CN/auth-verification)。

## 使用前提

- 已开通验证码产品并创建启用的实例，当前产品和账号均可用。
- 已创建该实例的产品 API Key。发送需要 `product:verification:send`，校验需要独立的 `product:verification:verify`；Key 的授权和其绑定身份的有效权限均须满足要求。
- 平台已配置所需投递渠道。邮件使用平台 SMTP，短信需要管理员启用供应商通道。

产品 API 使用产品 Key 认证。登录令牌、AccessKey 或中转令牌不能替代它。请在自己的服务端保存 Key，并按业务流程限制接收方和用途；不要将 Key 嵌入公开网页或移动应用。实例和 Key 的创建方法见[开发者产品总览]({{DOCS_BASE_URL}}/zh-CN/developer-products-overview)。

## 在控制台发送并校验

1. 打开验证码产品控制台，进入实例详情，在测试卡中输入产品 API Key。
2. 选择邮件或短信，填写接收方和用途，例如 `signup`。用途必须实际填写，输入框中的示例不是默认值。
3. 点击“发送验证码”，确认结果为 `success: true`，并检查接收方是否收到消息。
4. 保持相同的渠道、接收方和用途，输入收到的六位数字，点击“校验验证码”。
5. 查看本次结果中的 `valid`：`true` 表示校验成功；`false` 表示未通过。请求成功提示也会出现在 `valid: false` 时，不能单独作为验证成功的依据。

测试调用使用你输入的 Key 所属实例和账号，不会自动改为当前打开的实例。更改输入不会清除旧结果；输入未通过页面校验时也保留旧结果。提交有效输入后会清除旧结果，请以新响应判断本次操作。

测试是真实调用，会实际投递并按发送规则计量。测试后用量和调用记录不会自动刷新；关闭并重新打开实例详情可重新加载。页面顶部的刷新只更新实例列表。

## 接入 API

发送请求：

```http
POST /v1/products/verification/send
Authorization: Bearer <PRODUCT_API_KEY>
Content-Type: application/json

{ "channel": "email", "recipient": "user@example.com", "purpose": "signup" }
```

收到验证码后，用同一实例下具有校验权限的 Key 校验。将示例中的 `123456` 替换为实际验证码：

```http
POST /v1/products/verification/verify
Authorization: Bearer <PRODUCT_API_KEY>
Content-Type: application/json

{ "channel": "email", "recipient": "user@example.com", "purpose": "signup", "code": "123456" }
```

向当前部署的 API 服务地址发送请求，并将 `<PRODUCT_API_KEY>` 替换为自己的 Key。检查 HTTP 状态和响应中的业务码；接口成功后，发送结果在 `data.success`，校验结果在 `data.valid`。控制台测试卡直接展示 `data` 内的数据。

| 参数        | 要求                                                               |
| ----------- | ------------------------------------------------------------------ |
| `channel`   | `email` 或 `sms`；发送和校验时一致                                 |
| `recipient` | 去除首尾空白后为 3～320 个字符；填写渠道供应商支持的邮箱或电话号码 |
| `purpose`   | 去除首尾空白后为 1～100 个字符；由应用约定，发送和校验时一致       |
| `code`      | 仅校验时需要，必须是六位数字字符串，不要转换成数字                 |

验证码属于实例。同一实例的不同 Key 在具备相应权限时可以配合发送、校验；换用另一实例的 Key 无法校验原实例的验证码。接口不提供查询验证码明文的功能。

## 有效期、重发与尝试次数

- 验证码有效期为生成后 10 分钟，生成发生在投递前。投递延迟会减少收到后的可用时间，页面没有剩余有效期倒计时。
- 每个验证码最多允许 5 次错误尝试，耗尽后不能再通过。格式不合法的请求会返回参数错误。
- 校验成功立即消耗验证码，不能重复使用。并发提交同一正确验证码时，也只能有一次成功。
- 在同一实例中，向同一接收方成功发送相同用途的新验证码，会使旧验证码失效，即使新旧渠道不同。请使用最新成功发送的验证码。

校验中断或超时且没有明确结果时，验证码可能已经被使用。不要将结果不确定视为验证成功；需要继续时，等待限流允许后发送新验证码。应用应将验证结果与自己的接收方、用途和业务操作关联。

## 发送频率与投递结果

当前发送限制按实例最近 10 分钟内保存的发送记录计算。已使用或过期的验证码在这个窗口内仍参与计数。

| 范围                   | 达到以下记录数后拒绝新的发送            |
| ---------------------- | --------------------------------------- |
| 同一实例               | 20 条                                   |
| 同一实例、接收方和用途 | 3 条，邮件和短信合并计算                |
| 同一实例、来源 IP      | 10 条，仅在服务端取得有效来源 IP 时适用 |

这些限制用于抑制频繁发送，不替代应用自己的业务限流。被拒绝后请等待窗口内旧记录移出，再尝试发送；不要连续点击重发。

SMTP 或短信服务接受请求不保证最终送达。短信接口返回 HTTP 成功时，平台不会进一步判断供应商响应体中的业务投递状态。当前产品没有投递回执查询、模板编辑或自动切换渠道的控制台功能。

发送报错也不一定表示消息未发出：投递后保存验证码或记录调用仍可能失败，收到的验证码可能无法使用。处理错误并等待可重发后，使用最新成功发送的验证码；持续无法收到消息时联系管理员检查渠道，而不是反复重试。

## 用量与费用

发送计入产品用量，校验接口不计入产品用量，也不会生成同类产品调用记录。Key 的请求计数仍可能因校验请求增加，因此它不等于计费发送次数或验证成功次数。

每日额度由同一账号下的验证码产品实例共享，按服务端日历日期统计；免费额度、超额开关和单价以当前产品配置为准。单价为零时仍可累积请求数。发送调用先占用额度，后续执行失败会进入退回流程，退回可能延迟；费用或用量持续未恢复时请联系管理员核查。

用量面板的调用记录最多展示账号下该产品最近 200 条记录，可能包含其他实例和历史日期。认证、参数校验或额度检查前失败的请求不一定有记录，列表也不能作为完整投递清单。

## 常见问题

| 现象                          | 处理方法                                                                     |
| ----------------------------- | ---------------------------------------------------------------------------- |
| 无权限或认证失败              | 检查是否使用启用且未过期的产品 Key，并分别核对发送、校验权限及绑定身份权限   |
| 接口成功但 `valid` 为 `false` | 核对实例、渠道、接收方、用途和最新验证码，检查是否过期、已使用或耗尽尝试次数 |
| 提示发送过于频繁              | 等待最近 10 分钟内的记录移出限流窗口；切换渠道不会重置同接收方、同用途的限制 |
| 提示 SMTP 未配置或短信未启用  | 联系管理员配置所需渠道，再重新发送                                           |
| 成功发送但未收到              | 检查垃圾邮件、接收方格式及供应商送达状态；投递接受不代表送达                 |
| 测试后用量没有变化            | 重新打开实例详情，并核对输入 Key 的账号；校验请求本身不计产品用量            |
