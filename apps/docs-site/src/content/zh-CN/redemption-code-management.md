# 兑换码管理

管理员可在此生成固定金额的余额兑换码，交给用户在 [账户余额与转出]({{DOCS_BASE_URL}}/zh-CN/balance-history) 兑换。兑换码原文具有领取价值，请只交给预期收款人。

## 使用前提

进入 **兑换码管理** 需要读取权限；生成和删除需要各自独立的权限。按钮可见不代表操作已获授权。启用两步验证的账号生成或删除时，可能需要完成二次验证。

此页面管理管理员生成的兑换码。用户从自己余额创建的礼品码，应在其账户余额页面管理。

## 生成并发放兑换码

1. 单击 **生成兑换码**。
2. 填写 **金额** 和 **生成数量**。金额为每个码的面额，范围为 0.01～100000；管理页面每次生成 1～100 个。
3. 按需设置过期时间。留空表示不设置到期时间；填写时必须晚于提交时的当前时间。
4. 核对后单击 **确认**，并完成页面要求的验证。
5. 生成成功后，页面返回列表第一页。根据创建时间、创建者、金额和过期时间核对新记录；一批记录可能跨多页。
6. 单击每个兑换码复制。发送前在可信位置粘贴，核对完整内容；复制成功提示不保证剪贴板已写入，必要时手动选择复制。手机列表可能省略显示长码，不能只发送可见片段。

页面没有批量导出或自动发送功能。创建响应不会在页面显示为独立的结果清单，需要通过列表取得完整兑换码；创建权限不包含列表读取权限。

生成兑换码不会扣减创建者的账户余额。用户成功兑换时，面额记入其余额与累计充值，并生成兑换流水。兑换码不绑定指定收款人，持有码且有兑换权限的用户可领取；请勿公开发布仍可用的完整兑换码。

## 检查状态与使用人

列表按创建时间从新到旧排列，默认每页 20 条。桌面端可调整每页数量，并查看使用者、使用时间和创建者；手机端显示精简信息，需要完整核对时可使用桌面端。页面没有关键词或状态筛选。

| 显示状态 | 含义与处理                                                   |
| -------- | ------------------------------------------------------------ |
| 未使用   | 尚无使用者，且页面判断未过期；实际能否兑换仍以服务器校验为准 |
| 已使用   | 已记录使用者；检查使用人和使用时间，再对照用户余额流水       |
| 已过期   | 尚未使用且已超过过期时间，不能继续兑换                       |

已使用的码即使后来超过有效期，也仍显示为已使用。到期提示按浏览器时间计算，页面不会持续轮询使用状态；处理用户反馈前请重新进入页面或切换分页加载最新记录。查不到记录还可能是权限过滤或记录已删除，不能仅凭空列表断言从未生成。

## 删除兑换码

删除前核对完整兑换码、金额、使用者与过期时间。单击目标行的 **删除** 会直接提交，页面没有额外的删除确认框；按要求完成二次验证后，删除成功会重新加载当前页。

未使用的码删除后不能再兑换；已使用的码也可删除，但不会撤销已到账余额或删除用户的余额流水。页面没有恢复、编辑面额或延长有效期的入口。删除是移除兑换码记录，不是对用户余额退款或扣款。

## 所需权限与资源授权

| 操作       | 所需权限                 |
| ---------- | ------------------------ |
| 查看兑换码 | `REDEMPTION_CODE_READ`   |
| 批量生成   | `REDEMPTION_CODE_CREATE` |
| 删除       | `REDEMPTION_CODE_DELETE` |

IAM 强制模式下，操作者还需属于有效的部署管理全局组，且该组具有对应操作资格；个人附加权限、私有用户组或账号所有者身份不能替代该资格。

以下路径使用前缀 `acs:platform:*:platform:`，兑换码 ID 为记录 ID，不是兑换码原文。

| Action                              | 需允许的资源路径                                                       |
| ----------------------------------- | ---------------------------------------------------------------------- |
| `quyan:redemption_code:ListCodes`   | 集合 `redemption-code-control/default` 与各记录 `redemption-code/<id>` |
| `quyan:redemption_code:CreateCodes` | 集合 `redemption-code-control/default` 与新记录 `redemption-code/<id>` |
| `quyan:redemption_code:DeleteCode`  | 目标 `redemption-code/<id>`                                            |

新记录 ID 由服务端生成，可用 `redemption-code/*` 声明创建范围。集合授权不会覆盖记录级 Deny。未获准记录不会进入列表、分页或总数；强制模式不返回停用记录。

强制模式下，批量生成中任一新记录未获准，整批回滚。直接通过 API 生成时每批上限为 1000，管理页面仍为 100。权限、管理资格或目标内容在请求期间改变时，操作可能失败；请重新核对再操作。生成和删除保留二次验证与重放保护。

## 常见问题

| 现象                         | 处理建议                                                                       |
| ---------------------------- | ------------------------------------------------------------------------------ |
| 生成成功，但没有看到全部新码 | 检查第一页及后续分页，并核对读取权限；不要直接重复生成                         |
| 生成后断线，不确定是否成功   | 先重新加载列表，按创建时间、创建者、面额和数量核对；仍不确定时结合业务日志排查 |
| 用户提示已使用               | 核对使用者和使用时间，再检查余额流水；删除记录不会撤销兑换                     |
| 用户提示不存在或已过期       | 核对完整码、过期时间及是否已被删除；不要发送页面截断的片段                     |
| 删除最后一条后当前页为空     | 回到上一页查看；当前分页不一定自动前移                                         |
