# OJ 价格管理

OJ 价格管理用于维护提交器的模型费率和缓存倍率。定价按模型在整个部署中共用，修改会影响使用该定价的后续请求；供应商字段仅为说明，不会配置上游凭据或自动开通模型。

## 使用前提

进入 OJ 价格管理页面。读取需要 `OJ_PRICING_READ`，新增、编辑和删除需要 `OJ_PRICING_UPDATE`；IAM 强制模式还分别检查资源动作。写入要求重放保护。

列表展示模型、供应商、输入和输出价格、整体倍率、缓存创建倍率和缓存读取倍率，按创建时间从新到旧排列。没有搜索、分页、导入、导出或自动刷新；需要重新获取数据时可重新进入页面。

## 新增模型价格

1. 单击新增模型。
2. 填写与提交器请求完全一致的模型名，按需填写供应商。
3. 核对输入、输出单价及三个倍率，单击保存。
4. 在列表中核对结果，使用实际请求和[用量统计]({{DOCS_BASE_URL}}/zh-CN/oj-usage-statistics)验证费用。

模型名去除首尾空格后为 1～200 个字符，供应商最多 100 个字符。输入和输出价格须为非负数，三个倍率范围为 0～100；页面数字控件使用两位小数。

新建表单的输入、输出价格默认为 0，整体倍率为 1，缓存创建倍率为 1.25，缓存读取倍率为 0.1。请确认这些初始值符合实际收费规则，不要把空白新表单直接当作正确报价。

模型名用于精确查找，不会因填写供应商而自动添加或去除前缀。计费使用客户端请求的模型名；渠道映射到另一个上游模型，不会自动改用映射后模型的定价。没有有效价格记录会导致请求失败，单独新增定价也不保证渠道支持该模型。

## 理解单价和倍率

**输入、输出单价按“曲 / 百万 Token”计算，填写时请使用每百万 Token 的价格。**

| 参数         | 作用                            | 新建默认值 |
| ------------ | ------------------------------- | ---------- |
| 整体倍率     | 调整普通输入与输出 Token 成本   | 1          |
| 缓存创建倍率 | 缓存创建 Token × 输入单价的系数 | 1.25       |
| 缓存读取倍率 | 缓存读取 Token × 输入单价的系数 | 0.1        |

单次费用为以下各项之和，再向下保留四位小数。

```text
(输入 Token × 输入单价 × 整体倍率
 + 输出 Token × 输出单价 × 整体倍率
 + 缓存创建 Token × 输入单价 × 缓存创建倍率
 + 缓存读取 Token × 输入单价 × 缓存读取倍率) / 1,000,000
```

缓存部分不再乘整体倍率。把整体倍率设为 0，不保证有缓存用量的请求费用也为 0；如需调整缓存费用，应分别检查两个缓存倍率。Token 数来自上游返回的用量字段，页面用量汇总的总 Token 只统计输入与输出，不单列缓存 Token。

例如，仅作计算演示：输入单价为 2、输出单价为 8、整体倍率为 1.5，输入 1000 Token、输出 200 Token，另有缓存创建 400 Token、缓存读取 600 Token；使用默认缓存倍率时，计算结果为 0.00652 曲，保存费用为 0.0065 曲。此示例不是当前报价。

请求使用开始时读取的定价，成功保存的历史用量保留当时费用，不会随价格修改重新计算。即使配置得到零费用，OJ 请求仍有余额等使用条件，不能仅凭单价为 0 判断一定可调用。

## 编辑价格

1. 在目标模型行单击编辑。
2. 核对全部价格和倍率，修改后保存。
3. 重新查询并核对列表及新请求费用。

模型名在编辑时不可更改。供应商留空保存会保留原值；如需清除，可由有更新权限的集成通过更新接口显式提交空字符串并核对。

编辑表单使用列表已加载的全部费率，保存会提交这些值。其他管理员修改后应先重新加载，避免覆盖新价格。保存失败会保留输入；关闭或重新打开不代表输入已保存，页面没有自动保存、审批、定时生效或价格历史回滚。

## 删除价格

单击删除并确认后，该记录不再作为有效模型价格使用。它不会删除已有用量记录，但新请求可能因找不到定价而失败。

**已删除模型不能直接重新新增，页面也没有恢复入口。** 调整收费应编辑现有记录，不能先删除再创建相同模型。新增提示重复但列表中找不到时，可能是已删除记录占用模型名，或当前权限隐藏了已有记录，应联系相应管理员核对。

## IAM 资源范围

IAM 强制模式下，读取需要真实部署全局组中的 `OJ_PRICING_READ` 资格，写入需要 `OJ_PRICING_UPDATE` 资格。个人附加权限或单独的策略 Allow 不能替代该全局组资格。

| 操作 | IAM 动作                 | 资源             |
| ---- | ------------------------ | ---------------- |
| 列表 | `quyan:oj:ListPricing`   | 每个实际价格记录 |
| 详情 | `quyan:oj:GetPricing`    | 目标记录         |
| 新增 | `quyan:oj:CreatePricing` | 控制资源和新记录 |
| 编辑 | `quyan:oj:UpdatePricing` | 目标记录         |
| 删除 | `quyan:oj:DeletePricing` | 目标记录         |

记录资源为 `acs:platform:*:platform:oj-pricing/<记录 ID>`，新增控制资源为 `acs:platform:*:platform:oj-pricing-control/default`。模型名及供应商字段不能替代实际记录 ID 作为授权资源。

列表只返回获准记录，列表动作不授予详情或修改权限；不存在、已删除或未获准的详情、修改目标在强制模式下返回 403。管理接口不接受 OAuth 访问令牌，角色会话按角色自身授权，匹配的 Deny 优先。权限、身份或目标价格在操作期间变化可能导致失败，写入不会部分保存。内部请求计费仍按有效模型价格查找，不受管理员列表可见范围替代。

## 常见问题

| 现象                             | 处理方法                                           |
| -------------------------------- | -------------------------------------------------- |
| 列表加载失败但仍有旧价格         | 重新进入页面核对后再编辑，不要依赖旧结果           |
| 保存成功后又提示加载失败         | 写入可能已经完成，重新查询确认，避免重复新增或覆盖 |
| 编辑、删除按钮可见但操作被拒绝   | 检查对应动作、全局组资格和记录授权                 |
| 调整整体倍率后缓存费用未同比变化 | 缓存部分使用独立倍率，按完整公式核对               |
| 历史费用没有随新价格变化         | 历史记录保留原费用，只用新请求验证修改效果         |
