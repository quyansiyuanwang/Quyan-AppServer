# 我的月卡

在“我的月卡”查看已分配的权益，也可切换到 **月卡购买中心** 购买已发布方案。

## 页面用途

- 查看生效中、待生效或已过期的月卡。
- 查看总额度与剩余额度。
- 检查有效期、渠道限制和模型限制。

## 你会看到什么

### 月卡列表

- 月卡名称或模板名称。
- 状态标签。
- 生效与结束时间。
- 剩余、已用和总额度。

### 限制信息

- 额度窗口及其限制。
- 允许渠道。
- 允许模型。
- 在小屏上会以更适合阅读的卡片布局展示。

## 常见操作

1. 新月卡未显示时重新加载整个页面；顶部刷新按钮会更新页头余额，但不会刷新已分配月卡列表或购买中心的方案卡片。
2. 通过状态筛选区分生效中、待生效、已过期和已禁用的月卡。
3. 大量使用前先确认剩余额度。
4. 遇到请求受限时，检查可用渠道和模型范围。

## 抵扣与余额扣费

转发 API 结算时，系统会自动查找已启用、处于有效期内、有剩余额度，且匹配本次渠道和模型的月卡。存在多张适用月卡时，优先使用到期时间较早的月卡；到期时间相同时优先使用创建较早的月卡。

月卡未覆盖的费用会继续从账户余额扣除，购买月卡不会关闭余额扣费。例如，一次请求费用为 5，适用的金额额度月卡只能覆盖 3，则剩余 2 从余额扣除。请求仍需满足转发 Token 的状态、权限、额度窗口和路由限制。

在[消费记录]({{DOCS_BASE_URL}}/zh-CN/consumption-records)中核对“月卡抵扣”和“API 调用”记录，查看本次抵扣与余额扣费。月卡购买价格是购买权益的费用，与后续每次请求的抵扣额不同。

## 常见问题

| 现象                           | 检查方法                                                                                                             |
| ------------------------------ | -------------------------------------------------------------------------------------------------------------------- |
| 状态为“生效中”，但未抵扣       | 状态标签根据月卡是否启用和有效期判断，不代表额度充足。核对剩余额度、窗口限制、渠道和模型范围；模板停用也会影响使用。 |
| 月卡还有额度，但本次请求仍扣费 | 月卡可能不适用于本次渠道或模型，或只能覆盖部分费用。核对消费明细，而不是只看月卡状态。                               |
| 新月卡未显示或列表为空         | 重新加载页面并确认加载成功。页面只加载前 100 条记录，且可能受权限过滤；缺少记录时联系管理员核查。                    |
| 页头余额显示 `-`               | 可能是余额为零，也可能是读取失败。到[账户余额与转出]({{DOCS_BASE_URL}}/zh-CN/balance-history)确认。                  |

## 说明

- 月卡可能会先显示出来，但要到开始时间后才真正可用。
- 限额既可能覆盖整段有效期，也可能包含按金额、请求数或 Token 数计量的额度窗口。窗口按配置的小时数从当前时间向前滚动统计；例如 24 小时窗口不是在每天零点统一重置，历史用量离开窗口后可用额度才会相应恢复。
- 页面当前只加载月卡列表的前 100 条；状态筛选仅作用于已加载的记录。

## IAM 权限

启用 IAM 强制授权后，“我的月卡”按 `quyan:monthly_pass:ListMyPasses` 逐条授权 `acs:monthly-pass:*:<accountId>:assignment/<userId>/<passId>`，不会读取其他用户的月卡。自己的月卡、模板和用量子资源默认可读，但显式 Deny 仍优先。模板详情使用 `acs:monthly-pass:*:<accountId>:template/<userId>/<templateId>`；额度窗口用量需要允许所有相关的 `acs:monthly-pass:*:<accountId>:usage/<userId>/<passId>/<usageId>`。模板或用量被拒绝时，相应的详情或窗口统计会留空，已授权月卡自身的额度仍可显示。
