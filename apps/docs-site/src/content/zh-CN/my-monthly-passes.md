# 我的月卡

在“我的月卡”查看已购买或获分配的权益。需要购买方案时，切换到**月卡购买中心**，操作步骤见[月卡购买]({{DOCS_BASE_URL}}/zh-CN/monthly-pass-purchase)。

## 查看月卡与可用状态

1. 登录后打开“我的月卡”，选择**查看我的月卡**。
2. 使用状态筛选查找生效中、待生效、已过期或已禁用的月卡。
3. 核对开始和结束时间、额度单位、总额度、已用和剩余额度，再检查额度窗口、渠道和模型范围。小屏幕使用卡片展示同类信息。

| 状态   | 含义与下一步                                               |
| ------ | ---------------------------------------------------------- |
| 生效中 | 月卡已启用且当前时间在有效期内；仍需检查剩余额度和适用范围 |
| 待生效 | 尚未到开始时间；等待生效或请管理员核对分配时间             |
| 已过期 | 已超过结束时间，不能再抵扣                                 |
| 已禁用 | 月卡未启用；需要管理员核查，不能自行启用                   |

状态标签不代表请求一定被抵扣。即使显示“生效中”，额度耗尽、窗口限额或模板停用等条件仍可能使月卡无法使用。

## 更新列表和核对新月卡

新购、获分配或拼车交付的月卡未显示时，重新加载整个页面，并确认没有加载失败提示。顶部**刷新**会重新查询页头余额和方案数据，不会刷新已分配月卡列表，也不会刷新购买中心当前显示的方案卡片。

列表当前仅加载前 100 条获准查看的月卡，按结束时间从早到晚排列，并非最近购买的 100 条。状态筛选仅作用于已加载记录；切换筛选不会再向服务端加载更多月卡。记录较多时，新月卡可能未包含在当前列表中，请联系管理员核查。切换标签页也不会自动重新加载已分配列表。

## 抵扣与余额扣费

转发 API 结算时，系统会自动查找已启用、处于有效期内、有剩余额度，且匹配本次渠道和模型的月卡。存在多张适用月卡时，优先使用到期时间较早的月卡；到期时间相同时优先使用创建较早的月卡。

| 额度单位 | 抵扣方式                                                   |
| -------- | ---------------------------------------------------------- |
| 金额     | 按本次可抵扣费用消耗额度，可部分抵扣                       |
| 请求数   | 有至少 1 次可用额度时，消耗 1 次额度抵扣本次尚未覆盖的费用 |
| Token 数 | 按本次 Token 用量消耗额度；额度不足时可按比例抵扣部分费用  |

月卡未覆盖的费用会继续从账户余额扣除，购买月卡不会关闭余额扣费。例如，一次请求费用为 5，适用的金额额度月卡只能覆盖 3，则剩余 2 从余额扣除。请求仍需满足转发 Token 的状态、权限、额度窗口和路由限制。

在[消费记录]({{DOCS_BASE_URL}}/zh-CN/consumption-records)中核对“月卡抵扣”和“API 调用”记录，查看本次抵扣与余额扣费。月卡购买价格是购买权益的费用，与后续每次请求的抵扣额不同。

## 常见问题

| 现象                           | 检查方法                                                                                                             |
| ------------------------------ | -------------------------------------------------------------------------------------------------------------------- |
| 状态为“生效中”，但未抵扣       | 状态标签根据月卡是否启用和有效期判断，不代表额度充足。核对剩余额度、窗口限制、渠道和模型范围；模板停用也会影响使用。 |
| 月卡还有额度，但本次请求仍扣费 | 月卡可能不适用于本次渠道或模型，或只能覆盖部分费用。核对消费明细，而不是只看月卡状态。                               |
| 新月卡未显示或列表为空         | 重新加载页面并确认加载成功。页面只加载前 100 条记录，且可能受权限过滤；缺少记录时联系管理员核查。                    |
| 页头余额显示 `-`               | 可能是余额为零，也可能是读取失败。到[账户余额与转出]({{DOCS_BASE_URL}}/zh-CN/balance-history)确认。                  |

## 说明

- 月卡可能会先显示出来，但要到开始时间后才真正可用。
- 限额既可能覆盖整段有效期，也可能包含按金额、请求数或 Token 数计量的额度窗口。窗口按配置的小时数从当前时间向前滚动统计；例如 24 小时窗口不是在每天零点统一重置，历史用量离开窗口后可用额度才会相应恢复。
- 窗口额度恢复不会补回已经消耗的月卡总额度，也不会延长有效期。
- 普通月卡的模型和渠道范围由关联模板当前规则决定；管理员修改这些限制或停用模板可能影响已有月卡，请以当前可用范围和实际结算为准。

## IAM 权限

启用 IAM 强制授权后，“我的月卡”按 `quyan:monthly_pass:ListMyPasses` 逐条授权 `acs:monthly-pass:*:<accountId>:assignment/<userId>/<passId>`，不会读取其他用户的月卡。自己的月卡、模板和用量子资源默认可读，但显式 Deny 仍优先。模板详情使用 `acs:monthly-pass:*:<accountId>:template/<userId>/<templateId>`；额度窗口用量需要允许所有相关的 `acs:monthly-pass:*:<accountId>:usage/<userId>/<passId>/<usageId>`。

模板或用量被拒绝时，相应详情或窗口统计可能不完整，但已授权月卡自身的额度仍可显示。模板详情未获授权时，名称可能为空，渠道和模型字段可能显示“全部”；这不能证明月卡没有限制，请管理员核查详情权限和模板实际规则。
