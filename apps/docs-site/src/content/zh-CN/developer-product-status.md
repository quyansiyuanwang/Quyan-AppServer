# 状态监控

状态监控定期检查公开 HTTP(S) 服务，并提供可公开访问的状态页。它适合展示 API、网站或依赖服务的可用性和延迟趋势，不替代完整的应用性能监控或日志平台。

## 配置监控目标

在控制台填写名称、HTTP(S) 目标 URL、请求方法、检查间隔、成功状态码和告警延迟（1 到 1440 分钟，默认 5 分钟）。检查间隔为 60 至 86400 秒。请求经过 SSRF 防护：仅允许 HTTP(S)，内网、回环和链路本地目标会被拒绝；状态检查最多跟随 5 次重定向，每一跳都会重新校验目标，并拒绝重定向循环和 `file://` 等非 HTTP 协议。

可选的响应正文匹配支持“包含”或“完全匹配”；启用后，状态码和正文均需满足配置才视为正常。`HEAD` 不支持正文匹配。`POST`、`PUT`、`PATCH` 和 `DELETE` 可填写请求正文，非空正文必须是有效 JSON；定期检查和手动检测都会向目标发送请求，使用可能修改数据的方法前请确认目标接口允许重复调用。编辑时切换到不支持请求正文的方法会清空正文；切换到 `HEAD` 还会清空响应正文匹配设置。保存后这些清除会生效，请在切换方法前确认。

检查记录包含状态码、延迟和经过脱敏的错误摘要。目标可以暂停、恢复或手动检测；手动检测只影响当前行。检测到异常持续达到配置延迟后，后续检测会触发一次异常通知；此前已发出异常通知的目标恢复时才发送恢复通知。通知沿用平台通知/Webhook 体系和现有通知偏好。

## 加载或操作失败

如果控制台显示加载错误，监控列表和发布状态可能仍是上一次加载的结果，切换实例后也可能如此。点击错误提示中的“重试”，等待加载成功后再根据当前状态操作；加载失败时显示空列表也不能说明没有监控项。

创建、修改、删除、手动检测或切换发布状态后，控制台会重新加载数据。如果操作请求已完成但刷新失败，先重试加载并核对结果，再决定是否重复操作；手动检测会再次向目标发送请求。

## 公开状态页

发布状态页后，地址为 `/status/{slug}`。页面展示已启用监控项的当前状态、最近延迟、状态码和最近检测记录。可用率按最近最多 30 次检测中正常结果的比例计算，并非按时间计算的服务可用率；尚无检测记录时页面显示 0%。关闭发布后不再公开；产品或实例停用也会使状态页不可用。发布状态页需要独立的“发布状态页”RAM 权限，和读取、写入、删除监控目标的权限分离。

## 监控项资源授权

在 IAM enforce 模式下，JWT 管理接口使用本系统的操作和资源，不使用阿里云 DNS 权限。监控项 ARN 为 `acs:developer:*:<accountId>:status-monitor/<projectId>/<monitorId>`；标识符须与已存储资源完全一致，accountId 来自认证上下文。

- `quyan:developer:CreateStatusMonitor`：在指定项目 ARN 上授权创建；不自动授予新监控项的管理权限。
- `quyan:developer:ListStatusMonitors`：逐监控项控制配置和状态的查看。返回的配置可包含请求负载，授权前应检查其中是否包含敏感内容。
- `quyan:developer:UpdateStatusMonitor`、`DeleteStatusMonitor`：分别控制指定监控项的修改和删除。
- `quyan:developer:CheckStatusMonitor`：独立控制手动外发 HTTP 检查；列表或修改权限不自动包含此操作。

`GET /v1/developer/projects/{projectId}/monitors/page` 接受 page/pageSize，返回 items、page、pageSize、hasNext。候选记录先限定到当前账户的有效项目，再逐项授权，响应包含可用于策略编辑的 resourceArn，不返回未授权总数。空页仍可能有下一页；enforce 下旧数组接口只返回默认第一页。

同账户身份可以被授予某个监控项的权限，资源组也可包含指定监控项。移除成员后下一次请求即按新范围判断。跨账户、错误项目、大小写不一致及已禁用资源均被拒绝；暂停自动检查的监控项仍可管理。手动检查保留 SSRF 与逐跳重定向校验，并在外发前和结果写入时重新核实资源有效性。公开状态页、定时任务和产品凭据接口继续使用各自的访问边界；legacy/shadow 模式保留个人项目归属约束。
