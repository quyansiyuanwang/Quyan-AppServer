# 状态监控

状态监控定期检查公开 HTTP(S) 服务，并可发布无需登录的状态页。适合展示网站、API 或依赖服务的最近检查结果；检查之间的故障不一定被捕获。

## 使用前提

1. 在开发者产品中打开**状态监控**，选择一个可用实例并打开其管理或查看抽屉。
2. 按任务确认权限：读取 `product:status:read`、添加或修改及手动检测 `product:status:write`、删除 `product:status:manage`、发布 `product:status:publish`。IAM 强制模式还要求对应操作的资源授权。
3. 准备平台能访问的公开 HTTP(S) 地址。内网、回环、链路本地等目标会被 SSRF 防护拒绝；不能通过此功能检测私网服务。

实例、产品配额和产品凭据的通用用法见[开发者产品概览]({{DOCS_BASE_URL}}/zh-CN/developer-products-overview)。控制台的实例 ID 与资源策略中的项目 ID 不是同一个标识，编写策略时使用接口提供或管理员确认的实际资源标识。

## 添加监控目标

单击**添加目标**，填写下列配置后单击**保存**。

| 配置         | 填写方法与限制                                                                                                                          |
| ------------ | --------------------------------------------------------------------------------------------------------------------------------------- |
| 名称         | 必填，最多 100 个字符。公开页会展示名称，避免写入敏感信息。                                                                             |
| 目标 URL     | 先选择 `https://` 或 `http://`，再输入主机和路径，无需在文本框重复协议。完整地址最多 2000 个字符。                                      |
| 请求方法     | 支持 GET、HEAD、POST、PUT、PATCH、DELETE；默认 GET。                                                                                    |
| 请求负载     | POST、PUT、PATCH、DELETE 可选。非空内容必须是合法 JSON，最大 20000 字节。页面不提供自定义请求头或登录流程配置。                         |
| 检查间隔     | 60–86400 秒，新建默认 60 秒。定时任务约每分钟检查哪些目标已到期，不保证按所填秒数精确执行。                                             |
| 告警延迟     | 1–1440 分钟，默认 5 分钟。不是 HTTP 请求超时时间。                                                                                      |
| 成功状态码   | 默认只有 `200`；多个状态码用英文逗号分隔，如 `200, 201, 204`，最多 100 项。页面会忽略无效项，只要还剩有效项就可能保存成功，请逐项核对。 |
| 响应正文匹配 | 可选“包含”或“完全匹配”，填写预期文本，最大 10000 字节。启用后必须同时满足成功状态码和正文条件。HEAD 不支持。                            |

正文匹配按文本区分大小写，不支持正则表达式或 JSON 字段选择；“完全匹配”会比较整个正文，空格和换行也可能导致不匹配。GET 和 HEAD 不发送请求负载。

保存配置不等于已完成检测。新目标等待调度，或通过行内**检测**立即执行。`up` 表示满足检查规则，`down` 表示不满足或请求失败；尚未检测时可能没有最近状态。

## 检测、编辑和暂停

| 操作       | 结果与注意事项                                                                                                                              |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| 检测       | 立即向目标发送一次真实请求，暂停的目标也可手动检测。只触发所选行，但完成后会重新加载列表。操作成功提示只说明检查完成，目标仍可能是 `down`。 |
| 编辑       | 保存后应用新配置。切换到 GET 或 HEAD 会清空请求负载；切换到 HEAD 还会清空正文匹配设置。保存前确认这些移除符合预期。                         |
| 暂停／恢复 | 直接提交，无需确认。暂停后停止后续定时检查，并从公开页隐藏；保留已有记录，恢复不会清空历史。已经发出的检查可能仍会完成。                    |
| 删除       | 需确认，删除目标及关联检测记录，页面没有恢复入口。                                                                                          |

定时检查和手动检测都会发送真实 HTTP 请求。POST、PUT、PATCH 或 DELETE 可能改变目标数据，使用前应确认接口允许重复调用。一次请求的超时为 10 秒，响应大小上限为 1 MiB；重定向最多 5 次且逐跳检查目标，整个检测的延迟可能超过 10 秒。重定向也可能按 HTTP 规则改变请求方法。

需要停止定时检查时，请**先暂停监控目标**。取消发布只改变公开访问；停用实例也不能替代目标暂停，已启用目标仍可能被后台调度检查。请在停用实例前完成暂停。

控制台列表展示目标配置、最近状态和启用情况，没有检测历史或延迟曲线入口。定时任务更新结果后，关闭并重新打开实例抽屉获取当前内容；页面不自动轮询。

## 用量和费用

产品实例的手动检测和正常计量路径中的定时检测都会消耗产品调用量。免费额度、是否允许超额和单价以当前账户授权及服务端产品配置为准。同账户该产品的实例共享产品额度；免费额度用尽后，可能按配置扣除账户余额，或拒绝本次检查。

一次检测将目标判为 `down`，仍然是已完成的产品调用，不能把“目标异常”理解为免费或退款。重复单击检测会产生新请求及相应用量。配置为零单价时仍记录用量，但不因免费调用额度用尽而阻止调用。

## 告警通知

首次检测到异常后开始计算持续时间。后续一次检测仍为异常且达到告警延迟时，系统尝试触发一次异常通知；恢复后重置此轮状态，只有此前触发过异常通知才尝试发送恢复通知。

通知不是在延迟到达的瞬间独立触发，仍需下一次检测。检查间隔、调度延迟和配额不足都可能推迟发现或通知。事件触发也不等于已经送达：订阅、通知冷却和收件目标以[通知设置]({{DOCS_BASE_URL}}/zh-CN/notification-settings)为准，不保证失败投递会再次触发同一轮异常告警。

## 发布公开状态页

1. 在实例抽屉单击**发布状态页**，发布会直接提交，无需额外确认。
2. 成功后单击**打开状态页**，核对内容并分享实际打开的地址，路径为 `/status/{slug}`。
3. 不再公开时，单击**取消发布状态页**。

任何获得链接的人都可查看已启用目标的名称、最近状态、检查时间、延迟、HTTP 状态码和最近检查结果。公开页不展示目标 URL、请求负载、正文匹配文本或错误摘要；管理列表仍包含这些配置，不应作为公开分享入口。

公开页使用最近最多 **30 次**检查中正常结果的比例计算可用率，不是按时间加权的 SLA 或固定 24 小时可用率。无检查记录时界面显示 0%，并不表示已测得 100% 故障；所有可见目标均为 `up` 才显示全部正常，空列表或尚未检测也可能显示部分服务异常。

历史条从旧到新排列，详细记录区域只展示最近最多 5 条。页面打开时读取一次，不自动刷新；需要最新结果时重新加载浏览器页面，并检查最近检测时间。旧的 `up` 不代表刚刚检查过。

取消发布或停用产品、实例后，公开页不可用。检测历史会在调度成功运行时清理超过 90 天的记录；公开页仍只取最近 30 次，页面不提供完整历史导出或恢复。

## 加载和操作失败

列表或发布状态加载失败时，页面可能保留上一次结果，包括切换实例后。使用错误提示中的**重试**并等待成功；空列表和旧的发布状态都不能证明当前实际状态。

添加、编辑、删除、检测或切换发布后会重新加载。操作可能已完成而刷新失败，甚至仍出现成功提示。先重新打开实例抽屉或重试加载，再决定是否重复提交；重复检测会再次向目标发出请求并计量。

## IAM 资源授权

本系统使用自己的操作和资源。项目资源为 `acs:developer:*:<accountId>:project/<projectId>`，监控项资源为 `acs:developer:*:<accountId>:status-monitor/<projectId>/<monitorId>`。账户来自认证上下文，标识必须与已保存资源一致。

**实例控制台**使用以下授权边界：

| 任务             | 操作                                  | 资源范围                                                                         |
| ---------------- | ------------------------------------- | -------------------------------------------------------------------------------- |
| 列出目标         | `quyan:developer:ListStatusMonitors`  | 实例对应的项目资源；此入口返回该项目的监控配置，不按监控项过滤。                 |
| 创建目标         | `quyan:developer:CreateStatusMonitor` | 项目资源；不自动授予新监控项的后续管理权限。                                     |
| 修改、暂停或恢复 | `quyan:developer:UpdateStatusMonitor` | 目标监控项。                                                                     |
| 删除目标         | `quyan:developer:DeleteStatusMonitor` | 目标监控项。                                                                     |
| 手动检测         | `quyan:developer:CheckStatusMonitor`  | 目标监控项，与列表、修改操作分别授权。                                           |
| 读取发布状态     | `quyan:developer:GetProject`          | 项目资源；有发布权限的页面会同时加载此信息，缺少该读取授权也可能使面板加载失败。 |
| 发布或取消发布   | `quyan:developer:UpdateStatusPage`    | 项目资源。                                                                       |

管理列表会返回请求负载等配置，授予读取前需确认其中是否包含敏感数据。只授予某条监控项的列表权限，不能替代实例控制台需要的项目级列表授权。

**项目管理 API** 的 `GET /v1/developer/projects/{projectId}/monitors/page` 使用另一种列表边界：按候选页逐监控项检查 `ListStatusMonitors`，返回 `items`、`page`、`pageSize` 和 `hasNext`，并带 `resourceArn`；不返回未授权总数。空页仍可能有下一页，应按 `hasNext` 继续请求。IAM 强制模式下，该 API 的旧数组入口只返回默认第一页，不能当作全量列表。这些分页行为不适用于实例控制台入口。

项目管理 API 可按同账户的指定监控项及资源组成员授权；成员移除后按新范围判断。跨账户、错误项目、大小写不一致或失效目标会被拒绝。其手动检查会在外发前和结果写入时复核有效资源，暂停自动检查的目标仍可管理。公开页、后台任务和产品凭据接口各有访问边界；管理授权不等于授予这些入口相同能力。legacy 和 shadow 的项目管理 API 保留个人项目归属行为。
