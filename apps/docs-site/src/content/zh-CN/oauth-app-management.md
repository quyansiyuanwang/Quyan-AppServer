# OAuth 应用管理

在此注册第三方应用、登记回调地址、选择授权范围并提交审核。审核通过后，应用才能发起用户授权或兑换令牌。应用所有者使用本页；平台审核人员使用 [OAuth 应用审核](/zh-CN/oauth-app-review-management)。

## 使用前提

- 使用具备 `oauth:client:read` 权限的账户打开 OAuth 应用管理。列表只包含当前用户有权查看的自有普通应用，系统 OAuth 应用由独立页面管理。
- 创建、编辑和删除分别需要 `oauth:client:create`、`oauth:client:update` 和 `oauth:client:delete`。提交审核及轮换密钥使用更新权限；页面可见不代表所有操作均已获准。
- 创建、编辑、提交审核、轮换密钥及所有者删除均受双因素验证和请求重放保护约束。按控制台提示完成验证；接口接入需遵循对应的安全要求。
- 在使用 IAM 策略的部署中，还需要相应操作与资源授权，显式拒绝和角色会话限制仍然生效。列表读取、单项读取、编辑、提交审核和轮换密钥是不同操作。

## 创建并提交应用

1. 单击创建，填写能让授权用户识别的应用名称和用途。
2. 根据凭据保管方式选择客户端类型。类型创建后不能在本页编辑。
3. 逐条登记接收授权结果的完整回调地址，选择实际需要的 Scope。
4. 按需填写主页、Logo、隐私政策和服务条款 URL，然后保存。
5. 机密应用创建成功后，在密钥弹窗中复制完整 Client Secret，并保存到服务端的安全存储。公开应用没有 Client Secret。
6. 对草稿应用提交审核。状态变为 `pending` 后等待审核；通过后再按 [OAuth 授权码示例](/zh-CN/oauth-demo)验证接入。

### 选择客户端类型

| 类型                       | 适用部署                             | 凭据要求                                         |
| -------------------------- | ------------------------------------ | ------------------------------------------------ |
| 机密应用（`confidential`） | 能在受信任服务端保管密钥的网站或服务 | 兑换及刷新令牌需要 Client Secret，仅存放在服务端 |
| 公开应用（`public`）       | SPA、移动应用、桌面程序或浏览器扩展  | 不签发客户端密钥，不向用户设备分发机密应用的密钥 |

本页创建的两类应用都要求 PKCE。授权时发送 challenge，兑换授权码时发送对应 verifier；示例使用 S256。客户端密钥不能替代 PKCE。

### 填写字段

| 字段                               | 要求与用途                                                     |
| ---------------------------------- | -------------------------------------------------------------- |
| 应用名称                           | 必填，去除首尾空白后为 1–100 个字符                            |
| 应用描述                           | 可选，最多 2,000 个字符，说明接入用途                          |
| 回调地址                           | 1–20 个完整 URL，每个最多 500 个字符；与授权请求中的值精确匹配 |
| Scope                              | 控制台至少选择一项，以当前账户可授予的动态目录为准             |
| 主页、Logo、隐私政策、服务条款 URL | 可选，每项最多 500 个字符；用于应用资料，清空后保存会移除原值  |

回调地址的协议、域名、端口、路径和末尾斜杠都必须一致。生产接入使用受控的 HTTPS 地址，开发、测试和生产分别登记；本地示例使用明确登记的回环地址。

Scope 目录加载失败时，先在弹窗重试，目录未就绪时不能提交。应用可申请的范围受所有者当前权限及角色会话限制；编辑时也会重新校验。不要照抄其他账户的 Scope 清单。应用获准申请某个 Scope 后，仍需用户同意，访问接口还要满足账户权限、资源授权和其他安全条件。

## 查看和修改应用

列表显示名称、Client ID、类型、审核状态和意见、回调地址摘要、密钥预览及最近使用时间。桌面列表最多列出前两个回调地址，移动端显示数量；打开编辑弹窗可核对完整列表。本页没有关键字搜索或分页。

| 状态       | 含义                         | 授权及令牌兑换       |
| ---------- | ---------------------------- | -------------------- |
| `draft`    | 新建或修改后等待提交         | 不可                 |
| `pending`  | 已提交，等待审核             | 不可                 |
| `approved` | 已通过审核                   | 在其他条件满足时可用 |
| `rejected` | 已拒绝，按意见整改后重新提交 | 不可                 |

**保存已通过或已拒绝的应用会使其回到 `draft`，即使字段未改变也一样。** 原审核意见、提交时间和审核信息会清除。已通过应用的授权码兑换和刷新令牌也要求审核通过，请提前安排变更、重新提交及审核时间。

待审核应用仍可编辑，保存后保持 `pending`。如修改了回调地址或授权范围，请告知审核人员，确保审核依据为最新资料。列表加载失败时可能保留上次内容，修复错误并刷新后再确认当前状态。

## 保存和轮换密钥

完整 Client Secret 只在机密应用创建或轮换成功时提供，后续列表及编辑窗口只有预览，不能找回旧明文。关闭弹窗前确认已安全保存；复制失败时可手动选中复制。

1. 确认接入方可以更新服务端凭据，单击轮换密钥并完成验证。
2. 保存弹窗中的新密钥，更新使用该应用的所有服务端配置。
3. 使用新密钥验证令牌兑换或刷新。旧密钥立即失效，没有新旧密钥并行有效期。

轮换不改变审核状态，也不撤销已经签发的令牌。若密钥丢失或疑似泄露，应轮换并检查接入方的令牌使用情况；不要把轮换当作撤销用户授权。

## 删除应用及管理令牌

删除前确认 Client ID、应用名称及所有接入方，完成确认与验证后，该应用会从管理列表移除，不能再用于新的授权或令牌兑换。本页没有恢复入口，重新创建会获得新的 Client ID。

编辑、轮换密钥或删除应用都不能代替撤销已签发的访问令牌。已有令牌仍可能有效至过期或撤销，并继续受账户及接口权限检查约束。需要撤销时使用 API 的 `POST /v1/oauth/revoke`，按接口要求提交令牌及客户端认证信息；计划删除应用时，应先处理仍需撤销的令牌。

本页创建的普通应用启用授权码及刷新令牌流程，创建时访问令牌有效期为 3,600 秒、刷新令牌为 30 天；本页不能调整这些值。实际过期时间以令牌响应和服务端记录为准。刷新成功会轮换刷新令牌，接入方需保存新值，避免并发刷新或重复使用旧值。

## 常见问题

| 现象                     | 处理方法                                                  |
| ------------------------ | --------------------------------------------------------- |
| 创建后不能授权           | 确认已提交且状态为 `approved`，再核对实际使用的 Client ID |
| 保存资料后原接入失败     | 检查是否回到草稿，重新提交审核；不要反复使用旧授权码      |
| 回调地址不匹配           | 逐项比较协议、域名、端口、路径及末尾斜杠，确认环境一致    |
| 密钥找不到或旧密钥失效   | 创建或轮换后立即保存；丢失后重新轮换，并更新服务端配置    |
| 能看列表但操作被拒绝     | 分别核对操作权限、资源授权、角色会话及双因素验证要求      |
| 审核拒绝后不知道如何修改 | 阅读列表中的审核意见，必要时联系审核人员，修改并重新提交  |
