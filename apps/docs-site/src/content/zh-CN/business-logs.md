# 业务日志

此页面用于查看业务层面的审计记录。

## 页面用途

- 查看是谁执行了某项业务操作。
- 按类型、操作者、目标对象或状态筛选记录。
- 查看变更详情、元数据和错误信息。

## 你会看到什么

### 筛选区域

- 操作类型与分类。
- 操作者、目标对象、状态和 IP 筛选。
- 时间范围：选择的起止时间跨度最多为 30 天；不选择时间范围时可查询历史记录。

### 日志列表

- 描述信息。
- 成功或失败标签。
- 分页列表。
- 在需要时提供适配移动端的卡片布局。

### 桌面端统计

- 汇总数量及按日期、操作类型、分类和状态展示的图表。
- 统计使用当前筛选条件，移动端不展示统计区。

### 详情区域

- 展开的变更记录。
- 元数据。
- 错误详情。

## 常见操作

1. 先按操作类型或操作者筛选。
2. 打开失败记录查看错误详情。
3. 需要查看记录的变更、元数据或请求 ID 时展开详情；可用字段取决于该条记录。
4. 使用时间范围隔离事件窗口；超过 30 天时分段查询，或清除时间范围查询历史记录。

## 说明

- 更改筛选条件会重新加载列表和统计；顶部“刷新”只重新加载当前列表，不刷新统计图。需要更新统计时，可重新设置筛选或重新加载页面。列表和统计各自加载，失败时留意提示，旧数据可能仍然显示。
- 此页更偏向审计和业务行为，而不是原始基础设施日志。
- 当你需要知道“是谁改了什么”时，此页比系统日志更直接。
- 完整排障时，建议结合用户、权限或余额页面一起追踪。

## 筛选目录权限

IAM `enforce` 模式下，操作类型与分类选择器使用独立的 `quyan:system:business_log:GetFilterOptions` Action，资源为 `acs:platform:*:platform:system/business-log-options`。接口返回已有静态目录，不读取业务日志记录，也不会授予列表或统计访问权限。

当前用户必须在有效全局组中具备 `SYSTEM_BUSINESS_LOG_READ`。账户策略、私有组和用户附加权限不能替代这项部署级资格。匹配的显式 Deny 会阻止访问；读取期间失去资格或策略评估拒绝时不返回结果。`legacy` 和 `shadow` 保留原有效权限，`shadow` 同时记录 IAM 决策。

## 列表资源权限

IAM `enforce` 模式下，列表使用独立的 `quyan:system:business_log:ListLogs` Action，逐条检查 `acs:platform:*:platform:business-log/<日志 ID>`。你仍需在有效全局组中具备 `SYSTEM_BUSINESS_LOG_READ`；账户策略、私有组和用户附加权限不能代替这项资格。

只有允许访问的记录进入列表，`total` 和分页也以这些记录为准。匹配的显式 Deny 优先于 Allow；没有匹配 Allow 的记录不会返回。未指定日期范围时保留历史日志查询能力。单次查询固定截止时间；读取期间策略、资格或参与结果计算的记录发生变化时，请求会被拒绝，需要重新查询。

列表权限不授予统计或筛选目录访问权限。变更详情和元数据仍会隐藏敏感凭据。`legacy` 和 `shadow` 保留原列表行为，`shadow` 额外记录 IAM 决策。

## 统计资源权限

IAM `enforce` 模式下，统计使用独立的 `quyan:system:business_log:GetLogStatistics` Action，对每条 `acs:platform:*:platform:business-log/<日志 ID>` 授权后才纳入统计。列表的 `ListLogs` 权限不能代替统计权限；统计同样要求有效全局组中的 `SYSTEM_BUSINESS_LOG_READ` 资格。

总数、成功/失败数量、不同操作者、目标、IP 及每日/操作/分类分布都只计算允许访问的记录。显式 Deny 优先；没有匹配 Allow 时返回空统计。没有日期筛选时可统计历史记录；指定日期范围仍沿用原有边界和百分比计算。读取期间授权或参与统计的记录发生变化时拒绝返回结果。`legacy` 和 `shadow` 保留原统计行为，`shadow` 额外记录 IAM 决策。
