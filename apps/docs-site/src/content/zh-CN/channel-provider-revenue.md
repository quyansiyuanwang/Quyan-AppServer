# 渠道供应与收益

在此页面提交独立中转渠道、跟踪审核结果、暂停或恢复自己供应的渠道，并查看分成收益及转入余额的结果。提供渠道不代表一定有收益：渠道需要通过审核、可用且有实际余额扣费，并为你配置非零分成。

## 使用前提

进入控制台的 **渠道供应与收益** 页面。页面入口接受以下前两项权限之一，操作按钮和数据仍分别检查权限。

| 用途                                                 | 控制台权限                      |
| ---------------------------------------------------- | ------------------------------- |
| 提交渠道、查看本人提交、提交修改、暂停或删除本人渠道 | `relay:channel:submit`          |
| 查看本人收益                                         | `relay:channel:provider:read`   |
| 将手动结算收益转入余额                               | `relay:channel:provider:settle` |
| 进入渠道供应审核、处理审核                           | `relay:channel:review`          |

IAM 强制模式会进一步检查独立的 Action 和资源，详见后半部分。能查看收益不代表能提交渠道；拥有分成关联也不代表是原提交人，修改、服务开关和删除仍只允许原提交人操作。没有 OAuth scope 的这些接口不接受 OAuth 令牌。

## 提交独立渠道

1. 单击 **提交渠道**，填写渠道名称，选择支持的协议格式。此入口只创建独立渠道，不能创建渠道池。
2. 为每个启用的上游类型填写基础 URL 和 API Key。OpenAI Chat Completions 与 Responses 共用 OpenAI 上游配置；选择协议不保证上游实际兼容，提交前请核实供应能力。
3. 按需设置允许的模型、模型映射、渠道倍率、缓存读取计费、时段倍率和上下文长度倍率。倍率影响消费者计费，与提供者分成比例不同；具体计费规则见[转发设置]({{DOCS_BASE_URL}}/zh-CN/relay-settings)。
4. 如需分配收益，填写提供者的用户名、分成百分比及结算方式。用户名必须对应有效用户，不能重复。可配置多位提供者，每位比例为 0%～100%；总比例可以超过 100%，超出部分由平台补贴，提交前核对表单中的总比例与平台剩余比例。
5. 提交后，在本人提交列表确认审核状态为待审核。新渠道处于停用状态，管理员通过审核后才能提供服务。

首次提交时，若没有显式配置原提交人为提供者，系统会补充一条本人 **0% 分成、手动结算** 的关联。**0% 不产生收益**，自动关联不等于自动获得非零分成。

密钥提交给服务端后，列表和配置响应只返回“是否已配置”的标记，不回显原文。不要把密钥填写到名称、审核原因或其他说明字段。

### 探测上游模型

在格式和模型区单击模型探测按钮，从上游读取 `/v1/models` 模型列表；基础路径已以 `/v1` 结尾时会追加 `/models`。与平台模型定价匹配的结果可勾选并加入模型限制，未匹配结果仅展示，不能通过该按钮加入。探测结果不代表模型实际可调用，也不代表渠道已通过审核。

- **首次提交表单**：使用当前填写的 URL 和密钥进行临时探测，不因探测而保存凭据或创建渠道。
- **已有渠道的修改表单**：使用该渠道在服务端已保存的对应上游配置，忽略本次表单中尚未审核的新 URL 和密钥。探测成功不能证明新填凭据有效。

探测有独立的 IAM 授权。强制模式下使用 `quyan:relay:ListUpstreamModels`：新建预览针对 `acs:quyan:*:<accountId>:account`，原提交人的已有独立渠道针对本人提交 ARN。允许提交或读取渠道不会自动授予探测权限。

## 理解审核与服务状态

| 审核状态         | 原提交人可执行的主要操作     | 服务含义                                   |
| ---------------- | ---------------------------- | ------------------------------------------ |
| 待审核           | 提交或替换修改申请、删除     | 等待管理员审核，尚未上线                   |
| 已上架／审核通过 | 提交修改申请、暂停或恢复     | 仍须管理员启用且提供者未暂停，才处于服务中 |
| 已拒绝           | 查看原因、提交修改申请、删除 | 不提供服务；重新申请后回到待审核           |
| 已下架           | 删除                         | 不提供服务，当前供应表单不接受修改申请     |

审核状态与服务状态分开显示。已审核通过也可能显示管理员停用或供应者暂停；恢复供应者服务不能覆盖管理员停用。

### 提交或替换修改申请

1. 在本人提交列表对应行单击 **提交修改申请**，适用于待审核、已上架和已拒绝的独立渠道。
2. 核对完整配置后再提交。表单从当前渠道配置填充，**不会自动加载或合并上一份待审核申请的内容**。需要保留上一份未应用的改动时，请重新填写。
3. 密钥留空表示保留当前已保存密钥；需要更换时输入新值。替换上一份申请时，上一份申请中未应用的新密钥也不会自动沿用。
4. 已有待审核申请时，确认替换提示。提交成功后，旧申请被替代，不再作为待审核申请展示；新申请仍需管理员审核。
5. 在列表的修改申请列查看状态和原因。已上架渠道在等待期间继续使用原配置，服务开关不受申请本身影响。

界面会提交当前表单中的完整提供者列表；删除全部提供者后提交，表示提议移除全部关联，不是“保持不变”。API 省略列表才表示保留原配置。修改申请不会自动补充提交者；请确认需要保留的收益接收者仍在列表中。

被拒渠道重新申请会回到待审核且保持停用；批准后应用配置并启用服务。原本已通过审核的渠道批准修改时，保留当时的管理员启用状态和供应者暂停状态，不会因批准修改而自动恢复。恢复申请被拒时，恢复经服务端确认的原状态。

### 暂停、恢复与删除

- 对已通过审核的渠道，单击 **暂停服务** 或 **恢复服务** 并确认。暂停不改变审核结果、待审核申请或已有收益。它控制渠道可用性，不应当作取消已开始请求的操作。
- 管理员停用时，供应者不能自行恢复服务；先联系管理员确认启用状态。
- 待审核、已拒绝和已下架渠道可以删除；已上架渠道不能由供应者直接删除。删除不可恢复，渠道及其修改申请不再出现在供应或审核列表，相关 Token 的渠道引用也会被清理。

提交列表每页 20 条。当前页面只额外读取最近 100 条可见修改申请，并为每个渠道显示其中最新一条；修改申请列为空不证明没有申请。页面不自动轮询，请重新进入或刷新浏览器获取审核变化；收益也不会随提交列表翻页自动刷新。加载失败可能保留旧数据，请结合错误提示判断。

## 查看收益与转入余额

### 收益如何产生

分成基数是消费者**实际从余额扣除**的金额。失败请求、零扣费及月卡完全覆盖的请求不产生收益；月卡部分覆盖时，只对剩余余额扣费分成。每笔按每位提供者的比例计算并保留 4 位小数，结果为 0 时不生成收益记录。

例如，一笔实际余额扣费为 10、你的分成为 20%，收益为 2；如果该笔费用全部由月卡覆盖，则没有这笔分成。收益保存发生时的扣费金额、分成比例和收益金额，之后修改比例不重算历史金额。列表中的渠道名称读取当前名称，不是历史名称快照。

收益区展示渠道名称、实际扣费基数、分成比例、收益金额和结算状态，每页 20 条。待结算与已结算汇总覆盖当前获准查看的全部本人收益，不限于当前页。提供者关联停用后，历史收益仍可查询，但仍受 IAM 授权限制。

### 结算方式

| 方式         | 结果与时间                                                            |
| ------------ | --------------------------------------------------------------------- |
| 实时         | 新产生的收益直接结算到可消费余额                                      |
| 每 N 天      | N 为 1～365 的整数；按当前结算计划到期处理，不是每笔收益分别等待 N 天 |
| 每日固定时刻 | 按 `Asia/Shanghai` 时区的 `HH:mm` 到期处理，与浏览器所在时区无关      |
| 手动         | 由收益接收者在此页面单击 **转入余额**                                 |

定时结算由后台约每分钟检查到期计划，不保证在指定秒数到账；服务不可用或任务失败时可能延迟。重新配置提供者会重新计算其后续结算计划。已产生的待结算收益不会因为切换为实时方式就保证立即全部补结。

### 将手动收益转入余额

1. 核对待结算金额及收益记录，确认有 `relay:channel:provider:settle` 权限和所需 IAM 授权。
2. 单击 **转入余额**。当前页面没有按渠道或明细选择领取的步骤；此操作尝试领取本人所有**当前有效且采用手动结算**的提供者关联下尚未结算的收益。
3. 成功后收益列表回到第一页，核对已结算状态，并到余额流水查看 **渠道分成** 入账。它增加可消费余额，不记作充值。

**待结算汇总不等于可手动领取金额**：它可能包含定时结算收益或已停用关联下的历史收益。即使按钮可点，也可能本次转入为 0；关联已停用时请联系管理员核对是否需要恢复及选择结算方式。

收益读取与领取是独立权限。IAM 强制模式下，领取针对全部候选收益检查权限，任何一项被拒绝会取消整次领取；不会只领取列表中可见的子集。重复领取不会重复转入已结算记录。请求失败或成功后刷新失败时，先重新查询收益和余额流水，再决定是否重试。

## 管理员审核与配置

1. 进入 **渠道供应审核**。默认筛选待审核渠道；查看已上线渠道的修改申请时，需要把审核状态改为全部或已上架。渠道名称搜索按 Enter 执行，状态筛选修改后重新查询。
2. 有待审核修改申请时，先查看变更并审核该申请；存在待审核申请时直接审核初始提交会冲突。批准会应用整份提案，拒绝必须填写原因。
3. 没有待审核修改申请的待审核渠道，可直接通过或拒绝初始提交。初始上架会启用渠道和供应者服务；下架会禁用渠道。
4. 单击 **配置**，核对倍率、提供者用户名、分成总比例及结算方式，再保存。此保存独立于修改申请审核，直接改变当前配置；保存空提供者列表会停用全部关联。
5. 操作后刷新确认审核结果和当前服务状态。页面无自动轮询，刷新按钮会回到渠道列表第一页；待审核申请仅额外加载最近 100 条，未展示的申请仍可能阻止初始审核。

查看管理列表、打开配置和读取修改申请，与执行审核或保存配置使用独立授权；只有审核 Action 不保证能完成全部界面流程。IAM 强制模式下，审核或提供者配置更新会在同一事务中复核授权及相关数据，失败则不应用部分配置；后面的权限参考列出了额外资源检查。

## 我的渠道提交的 IAM 权限

启用 IAM 强制授权后，“我的渠道提交”使用 `quyan:relay:ListMyChannelSubmissions`，资源为 `acs:relay:*:<accountId>:channel-submission/<submitterUserId>/<channelId>`。账号及提交者字段来自已认证身份。这是个人提交访问权限，不是平台渠道管理权限，不要求部署全局管理组资格。仅 JSON 策略也可授予指定本人提交的读取权限，不会同时授予创建、审核、删除渠道或健康访问权限。

列表始终只包含当前用户自己提交且未删除的独立渠道，包括待审核、已拒绝、已停用和提供者暂停服务的记录。即使策略使用通配符，也不能列出其他提交者的渠道。授权过滤先于分页和总数计算，总数只代表获准的提交。私有可见性不会让原提交者看不到自己的提交。扮演角色时只使用该角色的策略，不继承用户自身策略。这些无 OAuth scope 的接口不接受 OAuth 令牌。

响应保留审核信息、有效模型及上游密钥是否存在的布尔标记，不返回密钥原文。独立渠道提交不暴露池父节点或无关成员。读取过程中身份、授权或相关资源数据发生变化时，拒绝返回结果。

### 创建待审核提交

启用 IAM 强制授权后，创建提交使用 `quyan:relay:CreateMyChannelSubmission`。服务端预分配渠道 ID，并要求此 Action 同时允许：

- 新渠道提交：`acs:relay:*:<accountId>:channel-submission/<submitterUserId>/*`；
- 每个提供者关联：`acs:relay:*:<accountId>:submission-provider/<submitterUserId>/*/<providerUserId>`。

关联 ARN 中的 `*` 是服务端分配的渠道 ID。即使请求未显式配置提供者，也会添加原提交者的零比例、手动结算关联，因此策略需要允许本人的关联。要限制可配置的其他提供者，逐个填写其用户 ID，而不是放宽为任意提供者。关联仅代表本次提交中的收益配置，不授予目标用户的账号或 IAM 管理权限；提供者用户名由服务端解析为真实用户 ID 后再授权。

新提交固定为待审核、停用的独立渠道，请求不能指定资源 ID、冒充其他提交者或自行设为审核通过。创建、提供者关联和响应投影在同一事务内校验；授权、身份或关联数据变化导致校验失败时，不保留部分提交。响应只包含上游密钥是否存在的标记，不返回密钥内容。原有 `RELAY_CHANNEL_SUBMIT` 在迁移期间仅映射为当前提交者范围。

### 删除与服务开关

删除本人提交需要 `quyan:relay:DeleteMyChannelSubmission`，暂停或恢复服务需要 `quyan:relay:SetMyChannelSubmissionServiceStatus`。两个 Action 均使用上述提交资源 ARN，可只授予指定渠道的操作权限；列表读取、审核及平台管理权限不会被一并授予。通配符也不能绕过原提交者归属检查。

删除仅适用于待审核、已拒绝或已下架的本人独立渠道；删除与相关令牌渠道引用清理一同提交或取消。服务开关仅适用于已审核通过的独立渠道；管理员停用后，供应者不能自行恢复。请求保留二次验证和重放保护，不接受 OAuth 令牌。写入期间身份、角色会话、AccessKey、策略或目标状态发生变化时，整次数据库修改取消，不产生部分更新。服务开关响应仍只返回密钥存在标记，不返回密钥原文。

### 读取修改申请

本人修改申请列表使用 `quyan:relay:ListMyChannelChangeRequests` 和 `acs:relay:*:<accountId>:channel-change-request/<submitterUserId>/<requestId>`，只返回本人提交、渠道未删除且仍可见的申请，不要求平台全局组资格。管理员申请列表使用独立的 `quyan:relay:ListChannelChangeRequests`，逐条检查 `acs:platform:*:platform:relay-channel-change-request/<channelId>/<requestId>`，并要求实际部署全局组中的审核资格。

两类列表都先过滤授权再计算总数及分页，且不返回密钥；读取、创建和审核 Action 互不替代。IAM 拒绝或列表尚未刷新时，不能把没有显示申请理解为不存在申请。

### 创建和替换修改申请

启用 IAM 强制授权后，原始提交者需要对以下全部资源拥有 `quyan:relay:CreateMyChannelChangeRequest`：

- 现有自有渠道：`acs:relay:*:<accountId>:channel-submission/<submitterUserId>/<channelId>`；
- 服务端分配的新申请：`acs:relay:*:<accountId>:channel-change-request/<submitterUserId>/*`；
- 每条将被替换的旧待审核申请，使用其各自的修改申请 ARN；
- 每条显式提议的提供者关联：`acs:relay:*:<accountId>:submission-provider/<submitterUserId>/<channelId>/<providerUserId>`。

提案不会修改线上提供者，也不会自动加入提交者。省略提供者列表表示保留现有配置供审核；显式空列表表示提议移除全部提供者。接收者可以属于其他账号，但提案不授予管理其账号的权限。服务端固定解析后的接收者身份；用户名被改名、停用或转给其他用户后，不能静默将已授权的提案转向另一用户。接收者身份失效时，请重新提交申请。

新密钥单独加密保存，不会出现在公开响应或审计记录中。密钥留空表示保留现有密钥，返回标记仅表示是否存在。已上架渠道在申请待审核期间继续使用当前配置；被拒渠道重新进入待审核并保持禁用。授权、身份、接收者、模型目录或响应数据发生变化时，新申请、旧申请替换及被拒渠道恢复会一起取消。

例如，以下策略允许对一个自有渠道和指定提供者提交修改提案；请将所有占位符替换为真实标识：

```json
{
  "Version": "1",
  "Statement": {
    "Effect": "Allow",
    "Action": "quyan:relay:CreateMyChannelChangeRequest",
    "Resource": [
      "acs:relay:*:<accountId>:channel-submission/<submitterUserId>/<channelId>",
      "acs:relay:*:<accountId>:channel-change-request/<submitterUserId>/*",
      "acs:relay:*:<accountId>:submission-provider/<submitterUserId>/<channelId>/<providerUserId>"
    ]
  }
}
```

申请通配符也允许替换该提交者的待审核申请，但不授予读取、审核、删除或平台管理 Action。显式 Deny 仍优先。二次验证和重放保护仍然必需，不接受 OAuth Token。现有 `RELAY_CHANNEL_SUBMIT` 权限自动映射到新 Action；仅使用旧账号级 `quyan:relay:channel:Submit` 别名的 JSON 策略，需要采用新 Action 和资源类型。

## 收益读取与领取的 IAM 权限

启用资源级 IAM 强制授权时，收益明细需要 `quyan:relay:ListMyProviderEarnings` 同时允许本人的提供者资源（`acs:relay:*:<accountId>:provider/<userId>/<providerId>`）和收益资源（`acs:relay:*:<accountId>:provider-earning/<userId>/<earningId>`）。被拒绝的收益不会计入明细、总数及待结算／已结算汇总。宽泛策略也不能读取他人的收益。提供者配置停用后，历史收益仍可查询，但同样受资源授权约束。

启用 IAM 强制授权时，“转入余额”需要 `quyan:relay:ClaimMyProviderEarnings` 同时允许本次涉及的所有手动结算提供者、待结算收益、本人的余额账户（`acs:balance:*:<accountId>:account/<userId>`）及新结算和流水资源（`acs:relay:*:<accountId>:provider-settlement/<userId>/*`、`acs:balance:*:<accountId>:transaction/<userId>/*`）。任何资源被拒绝或授权发生变化，整次转入都会取消，不会留下部分提供者已结算或余额已增加的结果。重复领取不会再次转入已结算收益。实时和定时结算继续遵循其配置的结算方式。

## 资源级提交审核

启用 IAM 强制授权后，上架、拒绝和下架已提交渠道，需要对 `acs:platform:*:platform:relay-channel/<channelId>` 拥有 `quyan:relay:ReviewChannelSubmission`。上架还会对每条拟议提供者关联 `acs:platform:*:platform:relay-channel-provider/<channelId>/<providerUserId>` 检查同一 Action，包括提交者隐含的零比例关联。关联权限控制收益配置，不授予管理接收者账号的权限。审核者还必须保留部署管理组赋予的审核资格，账号策略不能自行创建该资格。二次验证和重放保护仍然生效。

上架会启用渠道和提供者服务。拒绝必须填写原因；拒绝与下架会禁用渠道，不替换现有提供者。存在有效的待审核变更申请时，必须先审核该申请。审核、提供者变更与安全配置响应在同一事务内完成：最终权限、身份、接收者、待审核申请或响应数据发生变化时，审核回滚。响应不包含上游密钥值。混池响应只包含另行通过授权的关联渠道及其贡献的能力，不会因审核权限泄露无关渠道。

旧 `RELAY_CHANNEL_REVIEW` 权限会自动映射到新 Action。使用旧 `quyan:relay:channel:Review` 和账号内渠道 ARN 的 JSON 策略，需要显式改为平台 Action 与资源范围。

## 资源级提供者配置

启用 IAM 强制授权后，修改渠道倍率或提供者列表，需要对 `acs:platform:*:platform:relay-channel/<channelId>` 拥有 `quyan:relay:UpdateChannelProviderConfig`。替换提供者时，还需对每条当前有效和拟议关联 `acs:platform:*:platform:relay-channel-provider/<channelId>/<providerUserId>` 拥有同一 Action，移除提供者同样受授权控制。仅修改倍率时，不要求无关提供者关联的权限。

提供者用户名由服务端解析为真实接收者 ID。接收者可以属于其他账号，但关联权限不授予管理该账号的权限。提交空提供者列表会停用全部现有关联，不会自动加入编辑者或提交者。重新配置保留已结算收益历史，并采用选定的结算计划。操作期间身份、权限、接收者或响应数据发生变化，整个写入（包括倍率修改）都会取消。响应仅暴露凭据是否存在，不返回未获授权的混池贡献。

操作者还必须保留部署管理组赋予的渠道审核或渠道更新资格。现有 `RELAY_CHANNEL_REVIEW` 和 `RELAY_CHANNEL_UPDATE` 权限会映射到新 Action；仅使用旧账号级 `quyan:relay:channel:Review` 或 `quyan:relay:channel:Update` 别名的 JSON 策略，需要显式改用新 Action 及平台渠道、提供者关联资源。二次验证和重放保护仍然必需，不接受 OAuth Token。

## 资源级修改申请审核

启用 IAM 强制授权后，审核修改申请使用 `quyan:relay:ReviewChannelChangeRequest`，必须同时允许申请资源 `acs:platform:*:platform:relay-channel-change-request/<channelId>/<requestId>` 和渠道资源 `acs:platform:*:platform:relay-channel/<channelId>`。审核者仍须具有部署管理的审核资格；账号策略不能自行授予该资格。二次验证和防重放要求保持不变。

批准还需要逐一允许每个当前及拟议提供者关联 `acs:platform:*:platform:relay-channel-provider/<channelId>/<providerUserId>`，包括被移除的关联。该授权不授予接收者的账号管理权限。明确的空提供者列表会停用全部关联；省略列表则保持现有关联，不会自动添加提交者。新的修改申请固定提供者身份，用户名改变或被他人重新使用后不能把分成转给其他人。既有已结算记录保留。

批准只应用申请中的渠道配置及明确提供的新凭据，不改变路由、可见性或关联 Token。对已获批渠道，当前管理员停用及提供者暂停状态仍然有效，不会因批准修改而恢复服务。拒绝必须填写原因，不会解密待应用凭据或检查失效的上游、模型及提供者配置；申请本身仍须具有可安全展示的合法结构。恢复申请被拒绝时，按经服务端校验的原状态恢复。已完成的审核请求仍会重新检查访问权限。

审核状态、配置、提供者变更及安全响应在同一事务内完成。期间权限、身份、接收者、申请、模型目录或响应数据发生变化会撤销整个操作，响应不会包含密钥或内部绑定信息。旧 `RELAY_CHANNEL_REVIEW` 自动映射为此 Action；仅使用旧 JSON Action 的策略须明确改用上述平台资源范围。
