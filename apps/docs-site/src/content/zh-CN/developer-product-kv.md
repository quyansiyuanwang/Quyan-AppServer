# KV 存储

KV 存储用于按键保存 JSON 配置、功能开关和短期数据。每个实例有独立的键空间，可通过控制台管理，也可由自己的后端使用产品 API Key 读写。

## 使用前提与限制

先创建启用的 KV 实例，并取得所需权限。查看列表和读取值需要 `product:kv:read`，写入和删除需要 `product:kv:write`。创建实例和管理 Key 使用独立的管理权限，详见[开发者产品总览]({{DOCS_BASE_URL}}/zh-CN/developer-products-overview)。

| 项目   | 限制与说明                                                                                          |
| ------ | --------------------------------------------------------------------------------------------------- |
| 键     | 产品 API 支持 1～191 个字符，使用英文字母、数字、点、下划线、冒号和连字符；建议控制台也使用相同规则 |
| 值     | 有效 JSON；序列化后的 UTF-8 大小不超过 64 KiB，中文等字符可能占多个字节                             |
| 条目数 | 每实例最多 1000 个条目；过期但尚未清理的记录也可能占用容量                                          |
| TTL    | 可选的整数秒数，范围为 1～2592000 秒（30 天）；省略表示不设置到期时间                               |
| 版本   | 新键从 1 开始，每次覆盖递增；用于观察变化，不支持按版本条件写入或历史版本恢复                       |

KV 没有计数器原子递增、队列消费或多键事务接口。多个调用方先读后写可能互相覆盖，需要应用自行协调。不要把产品 API Key 或其他机密作为 KV 值保存；平台代管凭据请使用[密钥托管]({{DOCS_BASE_URL}}/zh-CN/developer-product-secret)。

## 在控制台创建和修改

1. 打开 KV 产品控制台，进入目标实例的详情。
2. 点击“新建 KV 条目”，填写键名和有效 JSON，例如键 `ui.theme`、值 `{"mode":"dark"}`。
3. 按需填写 TTL 秒数；留空表示不设置到期时间。
4. 点击“保存”，确认成功后在列表中核对键、版本和到期时间。

写入已有键会直接覆盖原值，没有额外的覆盖确认。新建前请检查键名。列表只展示元数据，不包含值；点击“编辑”会先读取当前值，再打开表单。编辑时不能修改键名。即使能打开编辑表单，保存仍需要写入权限；只有写入权限时也可以通过新建表单写入已知键。

编辑过期条目可能提示键不存在。编辑有到期时间的条目时，表单填入打开时的剩余秒数；保存会从保存时刻重新计算到期时间。窗口停留较久后应重新检查 TTL。留空 TTL 保存会移除到期时间，不能用 `0` 表示立即到期。

列表没有轮询或分页。页面顶部刷新只更新实例列表；需要重读条目时可关闭并重新打开实例详情。

## 删除与过期清理

点击条目的“删除”并确认后，条目永久删除，控制台没有撤销或恢复功能。再次删除不存在的键会返回键不存在。

达到到期时间后，读取按键不存在处理。加载产品实例的 KV 列表会清理该实例的过期记录；产品 API 的列表调用也执行此清理。读取单个过期键只会清理该键。不要假定到期后容量立即释放。

创建新键提示容量不足时，先成功重载条目列表以清理过期记录，再重试。仍然达到上限时，请删除不再需要的条目。下文 IAM 强制模式的项目管理列表和读取接口不会执行这种过期清理。

## 使用产品 API

在自己的可信后端调用当前部署的 API 服务，使用该实例的产品 Key。Key 的授权及其绑定身份的有效权限都必须允许对应动作。登录令牌、AccessKey 和中转令牌不能替代产品 Key。向浏览器提供配置时，由自己的后端按业务权限返回所需数据，不要把 Key 放入前端代码或浏览器存储。

```http
POST /v1/products/kv/entries/ui.theme
Authorization: Bearer <PRODUCT_API_KEY>
Content-Type: application/json

{ "value": { "mode": "dark" }, "ttlSeconds": 86400 }
```

将 `<PRODUCT_API_KEY>` 替换为自己的 Key。请求 JSON 的 `value` 为必填；不要省略整个值。除 HTTP 状态外，还要检查响应业务码。

| 操作       | 请求                                   | 成功结果中的 `data`                                                         |
| ---------- | -------------------------------------- | --------------------------------------------------------------------------- |
| 列表       | `GET /v1/products/kv/entries`          | 按更新时间倒序排列的元数据数组，不含值，也没有分页                          |
| 读取       | `GET /v1/products/kv/entries/{key}`    | `key`、`value`、`version`、`updateTime`，以及设置了到期时间时的 `expiresAt` |
| 写入或覆盖 | `POST /v1/products/kv/entries/{key}`   | 写入后的值与元数据；响应丢失时操作仍可能已完成                              |
| 删除       | `DELETE /v1/products/kv/entries/{key}` | `success: true`                                                             |

每次写入都会重设 TTL；不提供 `ttlSeconds` 就会移除原到期时间。请求超时后不要无条件重复写入：重试会再次增加版本并重设到期时间。先读取目标键，核对值和元数据，再决定是否重试。

## 用量与费用

产品 Key API 的列表、读取、写入和删除均计入用量；控制台通过登录会话管理条目，不通过这些计量接口。不要将页面点击次数、Key 请求计数或版本号当作计费调用数。

同一账号的 KV 实例共享每日产品额度，按服务端日历日期统计。免费额度、超额开关和单价以当前产品配置为准；单价为零时仍会累积请求数。执行失败会进入额度退回流程，恢复可能延迟；认证、参数或额度检查阶段拒绝的请求不等于完成一次操作。

## 项目管理 API 与细粒度授权

使用登录会话管理资源时，管理员可以分别委派 `quyan:developer:ListKv`、`GetKv`、`SetKv` 和 `DeleteKv`。列表权限不自动赋予读取值、覆盖或删除权限。

实例控制台的 `GET /v1/products/kv/instances/{instanceId}/entries` 按关联项目检查 `ListKv`，返回该实例的条目元数据，不逐键过滤。这与下面的项目管理分页接口不同，配置委派时请明确使用哪套入口。

`GET /v1/developer/projects/{projectId}/kv/entries/page` 返回 `items`、`page`、`pageSize`、`hasNext`，没有值和 `total`。IAM 强制模式下会按键过滤可见条目；空页也可能有后续页，请以 `hasNext` 判断是否继续。强制模式下旧数组接口 `GET /v1/developer/projects/{projectId}/kv` 只返回默认第一页。

键资源 ARN 为 `acs:developer:*:<accountId>:kv-item/<projectId>/<encodedKey>`，末段是原键 UTF-8 的无填充 base64url 编码。优先直接使用项目管理响应中的 `resourceArn`。读取单个键仍使用 `GET /v1/developer/projects/{projectId}/kv/{key}`，名为 `page` 的键也使用此路径。更多策略规则见 [RAM 管理]({{DOCS_BASE_URL}}/zh-CN/ram-management)。

## 常见问题

| 现象                         | 处理方法                                                                         |
| ---------------------------- | -------------------------------------------------------------------------------- |
| JSON 无法保存                | 检查引号、逗号及 JSON 语法；检查序列化后的字节大小，而非只看字符数               |
| 列表有记录，但无法编辑       | 条目可能已过期或已删除，也可能缺少读取值的权限；重新加载并检查授权               |
| 加载失败后仍显示列表         | 可能保留上次结果，包括切换实例前的数据；点击错误提示中的“重试”，成功加载后再操作 |
| 保存或删除成功，但列表没更新 | 后续刷新可能失败；重试加载并读取条目确认结果，再决定是否重复操作                 |
| 创建新键提示数量上限         | 成功重载列表以清理过期记录，仍满时删除不再需要的键                               |
| 版本增加但值与预期不符       | 核对其他写入方及并发读写；版本不是条件更新锁，也不提供旧值恢复                   |
