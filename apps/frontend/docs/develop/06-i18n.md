# 国际化 (i18n)

前端支持 `zh-CN`、`en` 和 `emoji`。消息的唯一数据源是 `src/locales/base/` 与 `src/locales/sites/`；完整的 `en.ts` / `zh-CN.ts` / `emoji.ts` 只作为类型规范和测试入口，不进入应用启动的运行时依赖。

## 页面加载

`scripts/generate-domain-view-manifests.ts` 读取真实路由、Vue 页面、组件及本地模块依赖，生成每条路由所需的消息命名空间。命名空间从现有语言包推导，不维护另一份站点与翻译 key 对照表。可选页面、产品页面 barrel export、自动注册组件和动态 key 前缀也参与分析。

生成物位于 `src/router/.gen/i18n/`，由开发、构建、测试和类型检查的既有 `domain-views:generate` 流程更新。不要修改或提交生成物。开发服务器会在翻译数据或页面依赖变化时重新生成并刷新；普通组件修改保留 Vue HMR，覆盖错误会显示开发错误提示。

启动只等待基础消息和共享界面依赖；导航守卫在页面挂载前等待该路由及父路由的所有消息。所有请求按“语言 + 命名空间”缓存和去重，失败请求可以重试。页面消息加载失败会中止导航；初始化的默认语言也加载失败时会拒绝启动。

切换语言先加载已访问页面的所有消息，再更新当前语言和共享偏好 Cookie。切换期间的新页面依赖也会被补齐，较早的异步切换不会覆盖用户的最后一次选择。

## 使用与类型

所有业务代码使用统一的 typed translator：

```typescript
import { i18ns, type I18nENAvailableKeys } from '@/locales'

// 模板或 computed 内调用会随语言/消息变化更新。
i18ns.t('save')
i18ns.t('relay.tokenManagement')

// 响应式只读 Ref，语言切换和懒加载完成时自动更新。
const title = i18ns.tref('relay.tokenManagement')

// 动态标签保持 key 的联合类型，不使用 any/string 断言绕过检查。
const labelKey: I18nENAvailableKeys = 'relay.tokenManagement'
i18ns.t(labelKey)

// 英文复数后缀 s 是可选语言规则，不要求中文保留。
i18ns.tf('NotificationSettingsView.cooldownDayOption', { count: 3 }, 3)
```

共享 schema 在 `src/locales/schema.ts` 中：

- 递归提取所有叶子 key，typed translator 会拒绝不存在的 key。
- 三种语言必须具有完全一致的叶子 key；每个拆分语言包用 `as const satisfies DeepStringify<typeof en>` 保留实际字面量类型并校验结构。
- 递归比较插值参数，任何携带业务数据的参数缺失或多出都会造成类型错误。英文后缀 `{s}` 允许语言差异。
- 生成的命名空间 loader 必须完整覆盖 schema 中的全部命名空间与语言。

语言包文本必须保留实际插值参数。API 示例中的花括号应按 Vue I18n 的 literal interpolation 转义，例如 `/models/{'{model}'}`；它表示路径文字，不需要调用方传入 model。

不要在模块初始化或非 computed 的缓存对象中提前保存 `t()` 的结果。使用 computed、`tref()` 或 `tc()`，避免语言切换后仍显示旧文本。不要用 key 格式化出来的英文标题掩盖缺失消息。

## 强制覆盖校验

```bash
pnpm --filter @quyan/frontend run i18n:check
pnpm --filter @quyan/frontend run type-check
pnpm --filter @quyan/frontend run lint:check
```

`i18n:check` 检查所有源文件和语言包，缺失/多余 key、空翻译、重复命名空间、重复消息、插值不一致、非法消息语法、未定义的静态翻译引用、无法解析的页面依赖均报错并以非零状态退出。未注册页面的引用也会检查。

`type-check` 在 vue-tsc 前重新审计并生成加载清单；`lint:check` 与 `lint` 也先执行覆盖校验。新增页面和语言包无需再手工登记翻译加载表。

回归测试集中在 `tests/node/locales/`、`tests/dom/locales/` 和语言 Store 测试，包含所有路由的三语加载，以及去重、失败重试、语言切换和覆盖检查负例。
